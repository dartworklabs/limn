# 뷰어 — 화면 규칙과 근거

이 문서는 브라우저 뷰어가 어떻게 보이고 어떻게 움직여야 하는지를 정한다. 레이아웃, 컴포넌트, 디자인 토큰, 화면에 드러나는 상태, 입력과 렌더링 규칙을 다루고 규칙마다 왜 그렇게 정했는지를 함께 적는다. 뷰어 화면이나 입력 동작을 바꾸기 전에 읽고, 바꾼 diff에서 함께 고친다. 공저자에게 안내할 조작 요약도 이 문서(§조작 한눈에)가 맡는다. 서버 API·핀 형식은 [api.md](api.md), 역변환·범위 사다리·앵커·저장소 같은 핀의 뜻은 [domain.md](domain.md)가 맡는다. 이 문서의 규칙은 서버 API·핀 형식을 건드리지 않는 뷰어 쪽 규칙이다.

> **한눈에**
>
> - 고치기 전에 볼 곳과 가드: §뷰어 규칙을 바꿀 때
> - 공저자에게 안내할 조작 요약: §조작 한눈에
> - 화면 크기·방향·입력 장치에 따른 배치: §레이아웃 (모바일 레이아웃, 펼친 화면 레이아웃)
> - 오른쪽 패널·시트·목록: §패널과 목록 (패널 정리, 패널 폭과 시트 높이, 보관함)
> - 알림·상태 점·배지·링크 모양: §상태와 표시
> - 스레드·검토·변경 보기·@태그·담당·브라우저 알림: §협업 UI
> - 한 뷰어에서 문서 여러 개 전환: §여러 문서 전환
> - 색·radius·글자·간격 토큰, 컴포넌트, 아이콘, Limn 로고·파비콘: §디자인 토큰과 컴포넌트
> - PDF.js 벡터 렌더링과 PDF 영역 확대: §렌더링과 확대
> - 재지 못한 것과 화면·입력의 한계: §알려진 제약

## 뷰어 규칙을 바꿀 때

뷰어는 [`src/limn/viewer/parts.txt`](../../src/limn/viewer/parts.txt)의 정적 파일을 서버가 한 장의 HTML로 조립한다. 번들러·모듈 로더·CDN은 쓰지 않는다. [`parts.txt`](../../src/limn/viewer/parts.txt)가 CSS·JS 조각의 실행 순서와 책임을 정한다. `start()`가 조각을 읽어 인스턴스 라벨·색·영어 메시지를 채우므로 import만으로 뷰어 자원이 생기지 않는다. 조각의 누락·중복이나 잘못된 자리 표시자는 서버 시작과 [`test_viewer_files.py`](../../src/limn/viewer/tests/test_viewer_files.py)가 거절한다.

> **주의**
>
> 조각은 모듈이 아니다. JS 조각은 모두 고전 스크립트 하나의 범위를 나눠 쓴다. 함수 선언은 어느 조각에서나 보이지만, 최상위 코드(`let`·`const`, 리스너 등록, 바로 부르는 함수)는 목록 순서대로 실행된다. 그래서 위쪽 조각의 `let`·`const`만 쓸 수 있고, 순서를 바꾸면 페이지가 시작하다 멈출 수 있다. 새 코드는 맡은 일이 같은 조각에 넣고, 새 조각을 만들면 `parts.txt`에 줄을 더한다.

조각은 마지막 줄바꿈으로 끝나야 한다. 그래야 이어 붙일 때 앞 조각의 끝 줄이 다음 조각의 첫 줄과 붙지 않는다. `css/`·`js/`에 있는데 목록에 없는 파일, 목록에 두 번 나온 파일, 형식에 맞지 않는 목록 줄은 테스트나 서버 시작에서 실패한다. 조각은 제 내용을 가리키는 구역 배너 주석으로 시작한다(예: `i18n.js`는 'UI language', `card-parts.js`는 'Pin card parts').

> **핵심**
>
> 화면 규칙을 바꾸면 세 곳을 같은 diff에서 맞춘다: `src/limn/viewer/`의 파일, `src/limn/viewer/tests/test_viewer.py`의 `Frontend*` 가드, 그리고 이 문서의 해당 절.

**CSS는 조각 여러 개지만, 페이지에는 인라인 `<style>` 하나로 들어간다.** 그 맨 앞, 첫 조각 `css/tokens.css`에 토큰 블록 세 개가 있다. 다크 테마 `:root`, 라이트 테마 `:root[data-theme=light]`, 테마와 무관한 척도 `:root`이다. 테마 색 리터럴은 앞의 두 테마 블록 안 변수 정의에만, 테마와 무관한 색(브랜드 색 `--limn-*`, 이름표 위 글자 `--brand-foreground`)은 척도 블록에만 둘 수 있다. 나머지 규칙은 모두 `var(--…)`를 쓴다(§토큰).

**UI 문자열은 한국어가 원본이고, 영어는 메시지 표로 바꾼다.** 템플릿과 JS에 적힌 한국어 문자열이 정본이다. 영어 화면에서는 [`src/limn/viewer/ui_en.json`](../../src/limn/viewer/ui_en.json)의 "한국어 → 영어" 표를 찾아 바꾼다. 동작 방식은 이렇다.

- 서버가 시작할 때(`server.read_viewer()`) `load_ui_messages()`(`limn/viewer/assemble.py`)가 표를 읽고, `viewer_html()`이 `__UI_EN_JSON__` 자리를 JS 객체 `I18N_EN`으로 채운다. 거부된 첫 화면도 같은 표(`ServedViewer.messages`)를 읽는다.
- 영어 모드에서 `tr()`·`trMsg()`가 표를 찾는다. `trMsg()`는 문자열 전체가 표에 없으면 ` — ` 또는 ` · `로 나눈 조각마다 다시 찾는다. 그래서 조합한 문구도 조각 단위로 번역된다.
- `MutationObserver`가 새로 그려지는 글자 노드와 UI 속성(`data-tip`·`aria-label`·`title`·`placeholder`)을 번역한다. 알림(`toast`)도 `trMsg`를 거친다.
- 실행 중에 조합하는 문구는 `tl('<한국어 틀>', {값})`으로 만든다. 틀 안의 `{name}` 자리에 값을 넣는다(예: `tl('{n}쪽', {n: 3})`). 영어 값은 `{"one": ..., "other": ...}` 복수형일 수 있고, `n`으로 고른다. 문서 탭 이름·메모·답글·원고처럼 사용자가 쓴 글은 번역하지 않는다. 문서 이름·메모·작성자·스레드 글, 원문 조각과 소스 diff, PDF 목차 제목과 절 표시줄, 인스턴스 이름표는 `translate="no"` 요소 안에 그리고, `i18nTree`·`i18nText`와 속성 번역이 그 아래를 건너뛴다(`i18nUser`). 설명 상자(`#tip`)와 브라우저 알림의 토스트(`toast(…, {literal: true})`)도 `translate="no"`다. 둘 다 이미 화면 언어로 된 글을 받고, 그 글이 메모나 문서 이름을 인용하기 때문이다. 그래서 이름이 `그림`인 문서나 `완료` 한 낱말 메모가 표의 낱말과 같아도 그대로 보인다. 그 안에 함께 그리는 UI 낱말(`(메모 없음)`, `(나)`, 설명)은 그리는 코드가 `tr()`로 미리 옮긴다(`EnglishChrome.test_user_text_reads_as_written_even_when_it_is_a_ui_word`).
- 표에 없는 문자열은 한국어로 남는다.
- 화면 언어는 저장한 선택(localStorage `limnLang`) → 인스턴스 기본값(시작 인자 `--ui-lang`, 서버가 머리 스크립트의 `__UI_LANG__`에 채운다. 없으면 건너뛴다) → 브라우저 언어(`navigator.language`가 `ko`로 시작하면 한국어, 아니면 영어) 순으로 정한다. `?lang=ko|en` 링크는 그 값을 저장한 선택으로 적고 쓴다. [더보기]의 언어 분절(`#m-lang`)이 저장한 선택을 바꾸고 다시 읽는다. 쓰던 초안은 탭에 남는다. 분절의 두 이름은 제 언어로 쓰고 번역하지 않는다.
- pins.md와 API는 번역하지 않는다. 에이전트가 읽는, 언어가 고정된 계약이기 때문이다.
- API 오류는 `errText()` 한 함수를 거친다. 한국어 화면은 서버의 `error` 문장을 그대로 보인다. 영어 화면은 오류 본문의 `reason` 코드로 표의 `reason:<코드>` 영어 문장을 찾고, 없으면 서버 문장을 표로 옮긴다(`trMsg`). 알림(`api()`), 작성 패널과 위치 다시 잡기 배너의 pick 오류, 편집 카드의 원문 칸, 비교 PDF 상태 줄이 이 함수를 쓴다. 코드 목록은 [api.md](api.md) §오류 응답에 있다. 영어 문장은 거절을 가르는 값(한도·줄 수)을 싣지 않는다. 그 값은 한국어 `error` 문장에만 있다.
- pick의 `warn`(작성 패널의 경고 한 줄, 오류 본문이 아니다)은 서버가 문장 한두 개를 공백으로 이어 보낸다. 영어 화면에서는 `warnText()` 가 문장마다 `PICK_WARNS` 의 한국어 틀(숫자 자리 `{x}`)과 맞춰 `tl()` 로 옮긴다. 한국어 화면은 서버 글 그대로다. 서버에 새 경고 문장을 더하면 `PICK_WARNS` 와 표에도 더한다(`test_i18n.PickWarnings` 가 `limn/web/answers.py` 의 `PICK_WARNINGS` 문장과 틀을 대조한다).

[`src/limn/viewer/tests/test_i18n.py`](../../src/limn/viewer/tests/test_i18n.py)가 이 연결을 지킨다. 정적 마크업(`<body>`부터 첫 `<script>`까지)의 한국어 글자와 UI 속성은 전부 표에 있어야 한다. `trMsg()`처럼 ` — `·` · ` 조각 단위로 찾아도 된다. 표의 값에는 한글이 없어야 하고, 키에는 `__` 자리표가 없어야 한다. `tl()` 틀에 번역이 없어도 실패하고, 실제 뷰어를 영어로 띄워 사용자 글 밖에 한글이 남으면 실패하는 브라우저 테스트(데스크톱·폴더블·휴대폰)도 있다. 같은 브라우저 테스트가 흔한 거절(`403` 보기 권한, `409` `base_rev` 충돌, `400` 입력 검사, `404` 없는 핀, `422` 핀 단위 비교)의 오류 알림도 본다. 영어에서는 `reason` 의 영어 문장이고 한글이 없어야 하며, 한국어에서는 서버 문장 그대로여야 한다. [`src/limn/web/tests/test_errors.py`](../../src/limn/web/tests/test_errors.py)는 서버가 내는 코드마다 영어 문장이 있는지 본다. 그래도 `tl()`·`tr()`을 거치지 않은 JS 문구는 잡히지 않을 수 있으니, 새 문구는 늘 이 함수들을 거치고 `viewer/ui_en.json`에 추가한다.

화면 규칙은 [`test_viewer.py`](../../src/limn/viewer/tests/test_viewer.py)의 구조·순수 판단 검사와 실제 Chromium 레이아웃 검사로 확인한다. [`test_viewer_files.py`](../../src/limn/viewer/tests/test_viewer_files.py)는 조각 목록·조립 결과와 내보낸 스크립트의 `node --check`를, [`test_viewer_source.py`](../../src/limn/viewer/tests/test_viewer_source.py)는 중복·죽은 함수와 주석에 삼켜진 코드를 본다. 브라우저·node 실행 조건과 합격 범위는 [verification.md](verification.md) §1이 정한다. 번역 대응과 영어 화면은 [`test_i18n.py`](../../src/limn/viewer/tests/test_i18n.py)가 확인한다.

**리터럴 예외를 바꾸면 두 곳을 고친다.** 토큰 밖에 리터럴을 허용하는 자리는 §리터럴 예외(허용 목록)의 표와 `src/limn/viewer/tests/test_viewer.py`의 허용 목록 상수(`TOKEN_SELECTORS`·`INLINE_STYLE_OK`·`RADIUS_OK`)에 함께 있다. 한쪽만 고치면 문서와 가드가 어긋난다. JS가 재서 넣는 CSS 변수(`--kb`·`--side-w` 등)는 따로 적지 않는다. 가드가 코드의 `setProperty('--…')` 호출에서 목록을 뽑는다.

### 닫힌 값 표

뷰어가 상태·모드를 비교하는 값은 문자열 리터럴로 쓰지 않고 `core.js` 맨 앞의 얼린 표(`Object.freeze`) 멤버로 쓴다. 비교하는 자리(`b.state===BUILD_STATE.RUNNING`)도, 그 값을 만드는 자리(`return LAYOUT_MODE.NARROW`)도 같다. 핀의 상태는 `pinState(p)` 한 곳에서만 읽는다. API의 `state`가 있으면 그 값을, 없는 옛 응답이면 `done`·`review` 표시에서 서버와 같은 규칙으로 정한다. 다른 코드는 `done`·`review` 표시를 직접 읽지 않는다.

| 표 | 값 | 출처 |
| --- | --- | --- |
| `PIN_STATE` | open · review · done | `pins.model.StateName` |
| `BUILD_STATE` | idle · running · ok · ok_errors · fail | `GET /api/build`의 `state`(`build.BUILD_STATES`, 시작 값 idle 포함) |
| `PULL_STATE` | ok · up_to_date · skipped · error | 빌드의 `pull.state`(`pull.pull_record()`) |
| `SYNC_STATE` | disabled · checking · deferred · updating · updated · current · blocked · error | meta의 `sync.state`(`sync/rules.py`의 `SyncState`와 감시가 쓰는 상태) |
| `REVISION_STATE` | idle · running · ready · error | 비교 PDF 상태(`revisions/jobs.py`) |
| `SCOPE_MODE`, `SCOPE_SOURCE` | pin · commit, changes · inferred · none | `scope.ScopeMode`, `scope.ScopeSource` |
| `THREAD_EV` | close · reopen · confirm · assign | `pins.model.ThreadEv` |
| `RANGE_REL` | equal · inside · contains · partial | `pins.position.selection_rel()` |
| `KIND_REQ` | fix · question | `pins.model.KindReq` |
| `ROLE` | owner · editor · viewer · agent | `access.ROLES` |
| `EVENT_TYPE` | mention · review_requested · replied · reopened · assigned · dropped | `events.EventType` |
| `VIA` | synctex · text · map | pick과 핀의 `via`(`pins.location.mapping.Via`) |
| `DOC_KIND` | tex · pdf · figure | 문서의 `kind`(`/api/docs`·`/api/meta`, `runtime.documents.DocKind`) |
| `EL_SYNC` | ok · moved · lost | 그림 핀의 `el_sync`(`builds.figure_map.ElSync`) |
| `LOCAL_LOGIN`, `ASSIGNEE_AGENT` | local, agent | `access.LOCAL_LOGIN`, `pins.edit.ASSIGNEE_AGENT` |
| `LAYOUT_MODE` | wide · mid · narrow | 뷰어(대역에서 정함, `BAND_MODE`) |
| `LAYOUT_BAND` | phone · tablet-sheet · short · mid-overlay · mid-side · wide | 뷰어(창 폭·높이·주 포인터, `layoutFor()`) |
| `CARD_DOT` | open · claimed · review · lost | 뷰어(카드의 상태 점, CSS 클래스와 같다) |
| `DIFF_FORMAT`, `VIEW_MODE` | pdf · source, manuscript · revisions | 뷰어(`index.html`의 `data-format`·`data-mode`) |
| `UI_LANG` | ko · en | 뷰어(`LANG`) |
| `NOTIFY_STATE` | on · off · blocked · unsupported · local | 뷰어(`notifyState()`) |
| `STATUS_KIND` | failed · errors · offline · building · rendering · sync-blocked · unchanged · stale · sync · png | 뷰어(상태 줄, `statusList()`) |

서버에서 오는 표는 서버 문자열과 정확히 같아야 한다. [`src/limn/viewer/tests/test_viewer_source.py`](../../src/limn/viewer/tests/test_viewer_source.py)의 `ClosedSets`가 표마다 서버의 `Literal`·튜플·생성 함수와 대조한다. 부르는 멤버가 표에 있는지도 본다(`PIN_STATE.REVEIW` 같은 오타는 오류 없이 `undefined`가 된다). `done`·`review`를 직접 읽거나 `pinState()`를 문자열과 비교하는 곳이 없는지도 본다. 사람이 읽는 글, 사유 코드, 브라우저가 정한 이름(키, 태그, 이벤트 종류, 알림 권한)은 표에 두지 않는다. 목록 구획 이름(`SEC.open`)과 표의 값을 키로 쓰는 조회표(`ST_NAME`, `EV_LABEL`, 알림 문구)의 키도 글자 그대로 둔다. 새 표는 `core.js`의 닫힌 값 구획에 더하고, 같은 테스트의 서버 표(`SERVER_SETS`)나 뷰어 표(`VIEWER_SETS`)에 올린다. 어느 쪽에도 없으면 테스트가 실패한다.

### 휴대폰·태블릿

휴대폰과 세로 태블릿에서는 사이드바가 **하단 시트**, 가로 태블릿·펼친 폴드·가로 휴대폰에서는 **패널**이 된다. 어느 쪽인지는 창 폭·높이·방향과 입력 장치로 정한다(§모바일 레이아웃).

| 동작 | 방법 | 자세히 |
| --- | --- | --- |
| 패널 · 시트 펴고 접기 | 도구 줄의 [핀 N]을 누른다. N은 열린 핀 수다. 옆의 보라 [검토 M]은 검토 대기 수이고, 누르면 목록의 검토 대기로 간다. 휴대폰·태블릿 시트, 펼친 화면, 짧은 화면이 모두 이 칩이다. 시트는 처음에 접혀 있다 | §모바일 레이아웃 |
| 문단 하나 고르기 | PDF를 **길게 누른다**. 스크롤은 평소대로 된다 | §모바일 레이아웃 |

| `wide` | 1100px 이상 | 높이 480px 이상, 폭 1367px 이상 | `wide` | 오른쪽 패널, 기본 348px, 폭 조절, 손잡이로 접기(§패널 폭과 시트 높이) | 탐색 줄 | 없음 | 왼쪽 고정 패널; 접힘·폭 저장값 유지. 저장값이 없으면 마우스는 펼침, 터치는 접힘에서 시작한다 |

`mid` 대역은 위 탐색 줄과 아래 동작 줄 사이에서만 패널을 펴고 접는다(§펼친 화면 레이아웃). `short`는 두 줄을 위 한 줄로 합친다.

**레이아웃 고르기.** JS가 창 폭·높이와 주 포인터(`pointer:coarse`)로 대역을 고른다(`layoutFor(w, h, coarse)`, `FrontendMobileLogic.test_layout_for_bands`). 마우스는 폭만 본다. 그래서 마우스 창은 701–1099px이면 `mid`이고 1100px 이상이면 `wide`다. 터치는 높이와 방향(높이 > 폭이면 세로, 같으면 가로)도 보고, 1100–1366px의 터치 태블릿 가로는 데스크톱 구조 대신 문서 옆 패널(`mid-side`)이다. 거기서는 도구 줄이 아래 동작 줄 한 줄이 되고 카드가 접히며 목차가 접힌 오버레이라, 1180×820에서 PDF가 패널 옆 폭 전부를 받는다. 버튼 크기와 선택 입력도 같은 주 포인터를 따르므로, 레이아웃과 크기는 한 입력으로 정해진다. 대역은 `body`의 클래스(`band-*`, `lay-*`, 겹친 패널이면 `mid-overlay`)로 걸고, 레이아웃을 바꾸는 CSS는 이 클래스에만 건다. 폭 미디어 쿼리가 남으면 JS가 고른 대역과 CSS가 따로 바뀐다. 휴대폰 도구 줄의 폭 예산(400px 미만이면 `[핀 N | 검토 M]`의 좌우 패딩을 8px로, 360px 미만이면 오른쪽 칸의 틈을 4px로 줄인다)처럼 배치를 바꾸지 않는 꾸밈만 미디어 쿼리로 둔다. 접기·펴기·회전으로 크기가 바뀌면 `resize`·`ResizeObserver`가 다음 프레임에 대역을 다시 본다. 대역이 바뀌면 보던 자리(`topAnchor`)를 지킨 채 쪽 폭을 다시 맞춘다. 마크와 선택 상자는 쪽 안 % 좌표라 따로 옮기지 않는다. 작성·편집·답글·위치 다시 잡기 중이면 패널이나 시트를 열어 둔다.

**흔들림 막기(터치).** 터치에서는 경계에서 대역이 떨지 않게, 마지막으로 대역을 정할 때 쓴 입력(`BAND_IN`, `{w, h, coarse}`)과 새 관측을 견준다(`settleBand`, `FrontendMobileLogic.test_band_settle_rules`). 첫 부팅은 바로 정한다. 입력 칸(`textarea`, 글자 `input`, `contenteditable`)에 초점이 있는 동안은 대역을 바꾸지 않고, 초점이 빠진 뒤 다시 본다. 안드로이드 키보드가 레이아웃 높이를 줄여 가로 태블릿(1024×768)이 1024×388의 `short`가 되는 것을 막고, 회전하거나 펴도 쓰던 메모와 커서를 지킨다. 폭과 포인터가 같고 높이가 정한 높이와 96px 미만으로 다르면 그대로 둔다(주소창·도구 막대). 지난 프레임이 아니라 정한 높이와 견주므로 천천히 끌어도 96px을 넘으면 다음 규칙으로 간다. 그 밖에는 새 입력이 200ms 그대로일 때 정하고, 그동안은 이전 대역과 쪽 폭을 둔다. 그래서 회전·펼침 한 번에 레이아웃은 한 번만 바뀐다. 마우스 창은 매 프레임 바로 다시 고른다. 96px과 200ms는 흉내로 고른 시작값이다.

**주 포인터가 바뀔 때.** 주 포인터(`pointer:coarse`)만 보고 `any-pointer`는 보지 않는다. 터치스크린 노트북은 주 포인터가 fine이라 마우스 규칙을 쓰고, 트랙패드를 붙인 iPad는 주 포인터를 coarse로 알리는 것으로 알려져 터치 대역과 터치 크기에 남는다. 안드로이드·크롬OS에서 마우스를 붙이거나 떼어 주 포인터가 실제로 바뀌면 `change`를 받아 크기 변화처럼 200ms 뒤에 대역을 바꾼다. 버튼 크기는 CSS가 같은 순간에 바꾼다. 묻는 대화상자나 전환 버튼은 없고, 기기를 떼면 원래 대역으로 돌아온다.

**태블릿 시트.** 세로 태블릿(터치, 높이 480px 이상에서 폭 600–839px이거나, 840–900px이면서 세로)은 `tablet-sheet`다. 오른쪽 오버레이는 768px 쪽의 오른쪽 43%를 덮고 마크를 잘랐다. 아래 시트는 쪽 폭 전체를 남긴다. 위에는 `mid`와 같은 탐색 줄(목차 토글·문서 링크·보기 전환·쪽 표시)이 있고, 아래는 휴대폰과 같은 시트(제스처·높이 단계)다. 작성 중에는 80%로 올라오지 않고 45%에 머물러, 방금 끌어 고른 쪽이 시트 위에 보인다. 키보드가 올라와 위치 줄·메모 칸·저장 줄이 들어가지 않을 때만 들어갈 만큼, 60%까지 올라온다(§패널 정리). 시트 상자는 화면 폭 전체이고 그 안의 내용은 최대 640px로 가운데 둔다. 도구 줄은 휴대폰과 같은 3칸 격자를 640 칸 안에 두고 버튼을 늘이지 않는다. 문서·보기·쪽·목차는 탐색 줄이 맡으므로 오른쪽 칸에는 [⋯]만 있다. 목차는 문서 위 오버레이이고, 목차를 열면 시트가 접히고 시트를 열면 목차가 닫힌다. 알림은 시트 위 최대 640px로 가운데 뜬다.

**짧은 화면.** 터치 화면의 높이가 480px 미만이면(가로 휴대폰) `short`다. 탐색 줄과 아래 동작 줄을 위 44px 한 줄로 합친다. 순서는 `[목차] [문서 링크…] │ [원고 | 변경사항] [상태] [3 / 25쪽] ··· [⬚ 선택] [⋯] [핀 N | 검토 M]`이다. 도구 줄이 탐색 줄의 오른쪽 끝에 겹쳐 그려지고, 문서 링크는 도구 줄이 시작하는 곳에서 끝난다(`--bar1-w`). `[PDF 재빌드]`는 모든 compact 대역처럼 `[⋯]` 안에 있고, 절 표시줄과 아래 동작 줄은 없다. 상태가 있으면 보기 전환과 쪽 표시 사이에 짧은 글로 끼고, 넘치는 폭은 문서 링크 줄이 가로 스크롤로 받는다. 그래서 크롬은 한 줄이고, 높이 390px 화면에서 나머지가 PDF와 패널에 간다. 엄지는 화면 양옆 가운데쯤에 있어 위 줄에 닿는다. 패널의 메모·편집·답글 칸에 초점이 가면 위 한 줄을 숨기고(`body.typing`) 초점이 빠지면 다시 보인다. 키보드가 남긴 약 200px를 패널이 받는다. 작성 패널은 휴대폰 시트와 같은 순서(위치 줄 → 메모 칸 → …)라, 고른 직후 스크롤 없이 메모 칸이 보인다. 터치에서는 다시 맞출 때마다 초점 받은 칸을 보이는 자리로 끌어오고(`keepFieldInView`), 작성 중 패널은 저장 줄 높이와 아래 안전 영역만큼 아래 여백을 두고 스크롤하므로(`scroll-padding-bottom`) 메모 칸 전체가 `[취소] [핀 저장]` 위에 보인다(`TouchLayoutBands`). 마우스 창은 이 여백과 끌어오기 없이 그대로 스크롤한다.

**목차 토글은 하나다.** 문서 탐색 줄 맨 왼쪽의 `#nav-toc-toggle`이 열릴 때도 닫힐 때도 같은 위치를 지킨다.

- aria-expanded와 동작 이름을 갱신하고 Enter/Space로 누를 수 있다.
- 목차 오버레이(`mid` 대역과 `tablet-sheet`)는 Escape 또는 장·절 선택으로 닫고, 초점을 토글로 돌린다.
- 목차를 여닫기 전의 쪽과 쪽 안 비율도 복원한다.
- 중간 폭에서 목차를 펴고 핀 패널을 접어도 데스크톱 목차 저장값은 바꾸지 않는다.
- `wide`의 목차는 `pinPrefs.outlineClosed`를 따른다. 저장값이 없으면 마우스는 펼친 채, 터치는 접은 채 시작한다. 한 번 여닫으면 저장값이 이긴다. `mid` 대역의 목차는 늘 접힌 채 시작한다.

**지금 절 표시.** 목차 항목은 쪽 번호와 함께 그 쪽 안의 세로 위치(`frac`, PDF XYZ 목적지의 위쪽 좌표를 쪽 높이로 나눈 값, 없으면 0)를 가진다(`destFrac`). 절 표시줄 `#section-current`와 목차 강조는 화면 위에서 조금 내려온 읽는 선(보이는 높이의 1/4, 최대 160px)보다 위에서 시작한 마지막 제목을 고른다(`outlineIndexAt`). 첫 제목보다 위(제목 쪽, 1쪽 맨 위)에서는 첫 절을 보인다. 쪽 번호만 보면 1·1.1·1.2가 모두 1쪽에서 시작할 때 1쪽 맨 위에서 `1.2`를 보이기 때문이다. 목차에서 고른 항목은 그 쪽을 벗어날 때까지 그대로 강조한다.

`mid`에는 절 표시줄이 없다. 그 줄의 `원고`가 탐색 줄의 `원고` 탭을 되풀이하고 38px를 차지했기 때문이다. 대신 쪽 표시(`1 / 2쪽`)를 탐색 줄 오른쪽 끝(`#nav-page`)에 작은 글자 버튼으로 둔다. 누르면 그 자리가 쪽 번호 칸이 되고 Enter로 간다. Esc나 초점이 빠지면 취소다. 절 이름은 목차 강조로 본다. `wide`는 절 표시줄을 그대로 둔다.

**번호와 인쇄 쪽 번호.** PDF outline에는 절 번호(`1.1`)와 인쇄 쪽 번호(`iv`)가 없다. 그래서 뷰어는 `GET /api/outline-labels`로 같은 빌드가 PDF와 함께 남긴 `.aux`의 목차 줄을 받아, 제목·계층·순서가 맞는 항목에만 붙인다(`mergeOutlineLabels`). 서버 쪽은 `.aux`를 읽는 일(`documents/reads.py`의 `outline_labels`)과 목차 줄을 해석하는 순수 파서(`documents/outline.py`)로 나뉜다. 응답 형식은 [api.md](api.md)에 있다.

**중간 폭의 패널 기억.** 중간 폭에서 사용자가 [핀]·손잡이·Esc·밀어 닫기·Ctrl+\로 직접 여닫으면 `pinPrefs.midClosed`에 기억하고, 폭이 바뀌어도 유지한다. 저장한 선택이 없으면 오버레이와 문서 옆 패널 사이를 오갈 때 위 표의 기본값을 적용한다. 작성·편집 중인 메모가 있으면 패널을 열어 둔다.

**상단 공간.** 문서 링크는 한 줄을 유지하며 필요하면 그 줄 안에서 가로로 스크롤된다. 중간 폭은 이름표를 [더보기]에 두고, 보기 전환과 목차 버튼은 줄어들지 않는다. 탐색 줄 높이는 마우스 44px, 터치 48px이다. 첫 안내는 `wide`에서는 탐색 줄 아래에, `mid`에서는 동작 줄 바로 위 왼쪽([선택] 위)에 뜬다. 안내 글은 클릭을 가로채지 않고 닫기 버튼만 입력을 받는다.

**compact에서 쪽 폭은 저장하지 않는다.** compact(`mid`·`narrow`)에서는 쪽 폭을 늘 화면에 맞추고 저장하지 않는다. −/＋를 누르면 그 레이아웃 동안만 유지한다. 접은 화면의 폭이 데스크톱 설정을 덮지 않게 하려는 것이다.

**쪽 좌우 여백은 같다.** compact에서 폭 맞춤한 쪽은 PDF 칸의 가운데에 있고, 좌우 여백은 `--edge`(휴대폰 12px, 그 밖 16px)다. 문서 옆 패널을 연 터치 화면은 오른쪽이 손잡이 히트를 비우는 40px라 왼쪽도 40px다(§패널 폭과 시트 높이). 마크 번호 배지는 마크 왼쪽 바깥에 그린다. 쪽 왼쪽 여백과 마크의 쪽 안 위치를 더한 자리가 배지가 바깥으로 나가는 폭(터치 28px, 마우스 24px)보다 좁을 때만 마크 안 왼쪽 위 모서리에 그린다(`.mark.in`, `markBadgeIn`). 그때만 바깥 배지가 PDF 칸 밖으로 나가 잘리고, 안에 그린 배지는 마크가 가리키는 글자를 덮기 때문이다. 실제 원고의 글은 쪽 폭의 6% 안팎에서 시작하므로 12px 여백에서도 배지가 바깥에 남고, 44px 여백의 데스크톱에서는 쪽 끝의 마크도 바깥이다. 쪽 폭이나 여백이 바뀌면(확대·다시 맞춤·대역 변경) 다시 정한다. 데스크톱(`wide`)의 여백은 그대로다(`EvenPageMargins`).

**아래 막대는 가운데가 화면 가운데다.** 휴대폰과 태블릿 시트의 도구 줄은 `minmax(0,1fr) 44px minmax(0,1fr)` 3칸 격자이고 가운데 칸이 손잡이다. 왼쪽 칸은 `[핀 N | 검토 M] [⬚]`, 오른쪽 칸은 휴대폰이 `[본문 3/25 ▾] [⋯]`, 태블릿 시트가 `[⋯]`다. 양쪽 칸 폭이 같으므로 손잡이는 언어·핀 수·문서 이름과 무관하게 화면(태블릿 시트는 640 칸) 정중앙에 온다. 펼친 화면의 아래 동작 줄은 `[⬚ 선택] ··· 상태 칸 ··· [⋯] [📍 N 👁 M ›]`다. 어느 막대에도 [PDF 재빌드]는 없다. 재빌드는 상태 줄의 [재빌드](원고가 PDF보다 새로울 때)와 [⋯]의 `PDF 재빌드` 행이 맡는다. 확대·테마·언어·알림·휴지통·도움말은 [⋯]에, 문서·보기 전환·쪽·목차는 휴대폰에서는 이동 시트에, 그 밖의 대역에서는 탐색 줄에 있다.

**상태는 한 줄이다.** compact 대역의 상태는 요소 하나(`#status`)가 대역의 자리에서 보인다(`placeStatus()`). 휴대폰·태블릿 시트에서는 시트 윗변 바로 위의 24px 줄(`#status-dock`, 태블릿 시트는 내용이 640 칸 안)이고, 상태가 있는 동안 시트는 위 모서리를 0으로 두어 둘이 한 면으로 보인다. 짧은 화면에서는 위 한 줄의 보기 전환과 쪽 표시 사이에 짧은 글로, 펼친 화면에서는 아래 동작 줄 가운데 칸(`#status-slot`, 최대 420px)에 있다. 데스크톱(`wide`)은 상태 칩 줄(`#bar2`)을 그대로 쓴다. 상태 줄은 시트 밖에 둔다. 시트는 스크롤 상자라 위로 나간 히트를 자르고, 아래는 도구 줄 버튼의 히트와 겹치기 때문이다. 그래서 줄의 동작은 24px로 그리고 44px 히트를 위로만, PDF 쪽으로 20px 넓힌다. 메모·편집·답글 칸에 초점이 있는 동안(`body.typing`)에는 상태 줄을 숨겨 키보드가 남긴 높이를 시트에 돌려준다.

- 한 번에 하나를 우선순위대로 보인다(`statusList()`, `STATUS_KIND`). 빌드 실패·LaTeX 오류 → 연결 끊김 → 빌드 중·쪽 그리는 중 → main 동기화 막힘 → 변경 없음 → 원고가 PDF보다 새로움 → main 동기화 중 → PNG로 보는 중이다. 빌드가 도는 동안은 낡음을 세지 않는다. 그 빌드가 곧 낡음을 푼다. 변경 없음은 이 탭이 누른 재빌드가 바뀐 것 없이 끝났다는 답이다([build-sync.md](build-sync.md) §따뜻한 LaTeX와 변경 없는 재빌드). 알림이 떠 있는 만큼(6초) 보이고 사라지며, 그동안은 낡음을 세지 않는다. 방금 그 재빌드가 새것이 없다고 답했기 때문이다.
- 둘 이상이면 첫 항목 끝에 `+N`이 붙는다. 누르면 모든 항목이 동작과 함께 44px 행으로 펼쳐진다. 바깥 누르기·Esc·뒤로 가기·행의 동작이 접는다.
- 동작은 항목마다 하나다. 원고가 더 새로우면 [재빌드](LaTeX 문서이고 `viewer` 역할이 아닐 때만, 그 줄의 강조 하나), 빌드가 실패했으면 [보기](시트를 펴고 오류 패널을 연다), main 동기화가 막혔으면 [이유], 변경 없음이면 [그래도 빌드](남겨 둔 LaTeX 부산물을 지우고 처음부터 빌드한다, `force=1`)다. compact 대역에서 재빌드는 이 줄과 [⋯]의 행에만 있으므로 변경 없음의 답과 그 동작도 알림이 아니라 이 줄에 둔다.
- 글은 먼저 긴 글을 넣고, 칸에 들어가지 않으면 짧은 글로 바꾼다. 그래도 넘치면 끝에서 말줄임한다. 글자는 12px 흐림이다.
- 빌드 중에는 줄의 아랫변에 2px 진행 막대가 있다. 빌드가 셀 수 있는 일의 진행(`progress`)을 주면 그 몫만큼 채우고, 아니면 끝을 모르는 막대(30% 띠가 1.2초에 한 번 지나간다)다. 지난번 걸린 시간은 예측이 아니라 참고값이라 막대를 채우는 데 쓰지 않고 글의 `(지난번 67초)`로만 보인다. 움직임 줄이기에서는 띠 없이 옅은 바탕만 남는다.
- 화면 낭독기는 항목의 종류가 바뀔 때만 읽는다. 초와 쪽 수는 `aria-hidden` 칸에 있고, 진행 막대는 `role="progressbar"`다.
- 상태 줄은 상태 칩 줄의 compact 얼굴이다. 칩이 바뀔 때마다 그 칩이 나온 상태(빌드 응답, 빌드 오류, 라이트 폴링 실패, meta의 `stale_build`·`sync`, 벡터 렌더 실패)로 다시 그린다.

**[더보기]는 아래 시트다.** 문서 목록이 들어간 이동 시트처럼 화면 아래 가장자리에 붙는다. 머리(이름표·[닫기])는 sticky이고 넘치면 그 아래가 스크롤된다. 이름표는 인스턴스 색 점과 이름이고 Limn 표시를 담지 않는다. Limn 워드마크와 버전은 바닥에 있다. 바닥의 세 덩어리, 워드마크·버전·[도움말 ›]은 잉크 바닥이 한 줄이다. 워드마크는 `--foot-word` 토큰(16px) 높이이고, x높이가 버전의 약 1.7배다. 셋은 먼저 한 기준선에 선다("limn"은 아래로 내려가는 획이 없어 SVG의 아랫변이 기준선이다). 그런데 한글은 라틴 기준선보다 조금 아래까지 내려와, 한 기준선에서는 '도움말'이 "limn"과 버전보다 1px 남짓 낮게 읽힌다. 그래서 [더보기]를 열 때 쓰고 있는 글꼴로 '도움말'의 한글 잉크가 기준선 아래로 내려가는 만큼과 버전의 잉크 하강량을 재고(`footInk`, 캔버스 글자 측정을 64배 크기로 읽는다. 캔버스가 정수 픽셀로 반올림하기 때문이다), 워드마크와 버전을 그만큼 내려 잉크 바닥을 '도움말'에 맞춘다(`inkDrops`). 글꼴이 바뀌면 값도 따라 바뀐다. 한글이 없는 영어 'Help'는 내리지 않는다('p'의 내림 획은 원래 기준선 아래에 있다). `›`는 '도움말' 잉크의 위아래 가운데에 온다. 가운데 맞춤도 견줬지만, 크기가 다른 두 글자를 가운데로 맞추면 작은 쪽이 떠 보여 한 덩어리로 읽히지 않는다. 전에는 20px 워드마크를 행 가운데에 두어 버전이 글자 발보다 6px 위에 떠 있었다(`MoreFoot`: DPR 2.63과 1, 밝게와 어둡게에서 화면 픽셀로 잰 세 잉크 바닥이 0.5px 안). 메타는 두 줄이고 조각 사이에서만 꺾으며 자르지 않는다. Git 밖의 원고라 서버가 커밋을 `-`로 보내면 그 조각을 구분점과 함께 뺀다(`commitShown`, `MetaWithoutCommit`). 전에는 `main.tex · 2쪽 · -`였고, 데스크톱 상태 칩 줄의 메타도 같다. 테마와 언어는 지금 값이 고른 칸인 분절이고, 누르면 바로 적용된다. 알림은 스위치이고, 켤 수 없으면 이유를 스위치 아래 한 줄에 쓴다. 높이는 최대 화면 − 48px다(`PhoneMoreAndHelp`).

**시트는 열리면 시트 자체가 초점을 받는다.** [더보기], 이동 시트, 도움말, 휴지통은 `tabindex="-1"`인 대화상자이고, 열 때 초점을 첫 컨트롤이 아니라 대화상자에 준다(`showSheet`). 테두리는 그리지 않는다. 주인의 휴대폰은 [더보기]를 탭으로 열 때마다 [닫기]에 파란 초점 테두리를 그렸다. 에뮬레이터의 `:focus-visible`은 키보드에만 켜지지만 실제 휴대폰 브라우저는 제 판단으로 그렸다. 키보드는 Tab 한 번으로 [닫기]에 간다. 이동 시트는 지금 문서의 행(문서가 하나면 고른 보기)을 초점 없이 보이게 두고, 목차의 지금 절을 그 행이 머리 밑에 가리지 않는 만큼만 끌어온다(`navSheetReveal`, `SheetFocus`).

**터치의 도움말.** 터치 기기에서는 도움말의 단축키 표(Ctrl·휠·Alt+1…9)를 숨기고(`.kbd-only`) 휴대폰·태블릿 표만 둔다. '한 바퀴'의 첫 단계도 드래그 대신 'PDF를 길게 누르거나 [선택]을 켜고 끌어서 고릅니다'이고(`.touch-only`), 저장 단계의 ⌘ Enter는 숨긴다. 범위 단계는 어느 레이아웃에서나 범위 발췌의 문장이다(스테퍼가 없다). compact에서 도움말과 휴지통은 [더보기]·이동 시트와 같은 아래 시트다. 머리도 넷이 같다. 맨 위 잡이 띠와 제목·[닫기] 줄이 시트 위에 붙어 있어 스크롤해도 남는다(`OneSheetHead`). 전에는 도움말과 휴지통에 띠가 없었고, 도움말의 [닫기]는 긴 안내와 함께 스크롤되어 사라졌다. 휴대폰에서는 전체 폭, 그 밖에서는 640px 칸이고, 바깥을 누르거나 아래로 끌거나(`sheetPull`) 뒤로 가기로 닫는다. 마우스 데스크톱은 그대로다(`SheetEdgeGrid`).

**대화상자는 바깥을 누르면 닫힌다.** [더보기]·이동 시트·도움말·휴지통이 모두 같다(바깥 = 대화상자 상자 밖의 배경).

**핀 카드는 아코디언이다.** 접힌 카드는 머리 한 줄(`#N · 줄 범위 · 쪽` 링크 ··· 담당·답글 수·접기)과 그 아래 메모 미리보기 두 줄(`.sum`)만 보인다. 링크와 칩이 아닌 곳을 누르면 어디든 태그·메모·버튼이 펼쳐진다(`openTappedCard`). 전에는 20px 높이의 미리보기와 꺾쇠만 펼쳤다.

- 미리보기는 머리 줄과 따로 두 줄을 받는다. 머리 줄의 남은 폭만 주면 '[C…'처럼 한 조각만 보인다.
- 검토 대기 카드는 미리보기 앞에 '내 확인 차례 · '를 붙이지 않는다. 보라 점이 이미 상태를 말한다.
- 마크 배지를 누르면 패널을 펴고 그 카드를 펼친다.
- `wide`의 카드는 접지 않고 늘 펼쳐 둔다(`.sum`과 접기 버튼이 없다).

**선택 입력은 Pointer Events 한 경로다.** 입력 장치마다 동작이 다르다.

- 마우스는 모드와 무관하게 끌어서 고른다.
- 터치·펜은 **선택 모드**를 켰을 때만 한 손가락 끌기가 사각형이 된다. 이때 쪽에 `touch-action:none`을 준다. 두 손가락은 §PDF 영역 전용 확대가 받는다. 선택 모드에서 탭은 **빠른 선택**이다.
- 선택 모드가 아니면 스크롤·확대가 평소대로 되고, **길게 누르기(450ms)** 가 빠른 선택이다.
- 빠른 선택은 누른 점 둘레의 작은 상자(쪽 폭 ±7%, 높이 ±0.6%)로 기존 `/api/pick`을 부른다. 서버의 기본 단계가 본문에서는 '문단', 그림·표에서는 '환경'이라 그대로 쓰고, 범위 사다리로 넓힌다([domain.md](domain.md) §범위 사다리). 그림 문서에서는 상자가 쪽 폭의 ±0.4%, 쪽 높이의 ±0.4%라, 가로세로비가 다른 쪽에서는 직사각형이다. 지도는 이 점을 품은 가장 깊은 요소를 고른다. 글 한 줄 모양의 긴 띠는 작은 요소 여럿에 걸쳐 바깥 요소로 올라가기 때문이다.
- 저장하거나 취소하면 선택 모드는 저절로 꺼진다. 다시 스크롤되게 하려는 것이다.
- 두 번째 손가락이 닿으면 그리던 상자를 버린다.

**좌표.** 좌표는 `clientX/Y`를 `getBoundingClientRect`로 나눈 쪽 안 비율이다. 둘은 같은 레이아웃 뷰포트 기준이라 브라우저 핀치 확대 중에도 맞는다. PDF 영역의 브라우저 핀치는 막고 앱 확대로 바꾼다(§PDF 영역 전용 확대).

**툴팁과 포커스.** 터치 직후의 흉내 `mouseover`·`focusin`으로는 툴팁을 띄우지 않는다. 설명은 버튼을 길게 누르면 뜨고, 그때 손을 뗀 click은 삼켜서 버튼이 눌리지 않게 한다. 터치로 고른 뒤에는 메모 칸에 자동 포커스하지 않는다. 가상 키보드가 범위 사다리를 덮기 때문이다.

**유령 클릭.** 터치를 뗀 뒤 브라우저가 보내는 click은 그 사이 손가락 밑으로 온 요소에 떨어진다. 손가락 밑의 화면을 바꾸는 동작 뒤에는 그 click 한 번을 삼킨다(`SWALLOW_CLICK`, 400ms). 그 사이 터치가 흉내 내는 `mousedown`도 막아 초점이 옮겨 가지 않는다. 대상은 손잡이 탭(폭 순환·시트 높이 순환), 길게 누르기와 [선택] 모드 탭의 빠른 선택(패널·시트가 손가락 밑에 펴진다), 손잡이 끌어 접기, 도구 줄을 끈 시트 드래그다. 삼키지 않으면 이 click이 편집을 열거나 종류를 바꾸거나 메모 칸에 초점을 줘 키보드를 띄운다.

**두 번 탭.** 선택 모드가 아닐 때 PDF를 두 번 탭하면(300ms·24px 안, `isDoubleTap`) 폭 맞춤 ↔ 2배를 오간다. 누른 자리를 기준으로 삼아 그 글자가 손가락 밑에 남는다(`doubleTapWidth`: 폭 맞춤의 ±5% 안이면 2배, 그 밖이면 폭 맞춤). 브라우저의 두 번 탭 확대는 PDF 영역에서 원래 꺼져 있다(`touch-action: pan-x pan-y`).

**가로 밀기.** `html`·`body`는 `overscroll-behavior-x: none`이다. 그러지 않으면 폴드·폰에서 오른쪽으로 밀 때 브라우저가 뒤로 가기로 받아 Limn을 떠나고 쓰던 메모가 사라지기 때문이다. 패널(`#right`)은 `touch-action: pan-y pinch-zoom`이다. 가로 끌기가 포인터 이벤트로 남아 겹친 패널을 밀어 닫을 수 있고(§펼친 화면 레이아웃), 패널 위 두 손가락 확대는 브라우저 확대다(§PDF 영역 전용 확대). `pan-y`만 두면 패널 위 핀치 확대까지 꺼지므로, 접근성을 위해 `pinch-zoom`을 남긴다.

**뒤로 가기 제스처.** 터치 기기에서 시트(`narrow`), 겹친 패널(`mid-overlay`, 900px 이하의 `short`), 목차 오버레이(`mid`·`tablet-sheet`)가 열려 있으면 시스템 뒤로 가기가 그 층을 먼저 닫는다(`backLayer`). `CloseWatcher`가 있으면(안드로이드 크롬) 그것 하나를, 없으면 history 항목 하나를 둔다. 다른 방법으로 닫으면 그 항목도 거둬, 뒤로 가기가 헛도는 일이 없다. 문서 전환은 해시를 바꿔 쓰므로(replaceState) 항목을 늘리지 않고, 뒤로 가기로 층을 닫아도 보던 문서의 해시를 지킨다. 모달 대화상자는 `CloseWatcher`가 있으면 브라우저가 스스로 닫는다. 없으면 열린 아래 시트 대화상자(이동 시트·[더보기]·도움말·휴지통)가 맨 위 층이고 history 항목 하나를 둔다. 시스템 뒤로 가기가 없는 마우스 기기에는 등록하지 않는다. 그래서 시트를 연 채 뒤로 가기를 눌러도 Limn을 떠나지 않는다.

**가상 키보드.** viewport meta의 `interactive-widget=resizes-content`(크롬 안드로이드)로 레이아웃 자체를 줄인다. 그 값을 모르는 브라우저에서는 `visualViewport`로 잰 높이(`--kb`)만큼 화면을 올린다. 핀치 확대로 줄어든 visualViewport는 `scale`을 곱해 되돌려, 키보드로 치지 않는다.

**배치는 모드가, 크기는 주 포인터가 정한다.** compact 모드(`narrow`·`mid`)의 배치 — 아코디언 카드와 그 동작 줄, `#N · 줄 · 쪽` 링크, [더보기] 시트, `mid`에 절 표시줄이 없는 것 — 는 모드를 따르므로, `mid-side` 대역인 1000px 마우스 창에도 같다. 그대로 두는 데스크톱은 마우스(`pointer:fine`)의 `wide`이고, 터치는 같은 배치에 아래의 크기만 더한다(`LayoutNotPointer`). 대역도 같은 주 포인터로 고르므로 배치와 크기가 어긋나지 않는다.

**터치 기기 크기.** 터치 기기(`pointer:coarse`)에서는 눌리는 영역이 모두 44×44px(`--hit`) 이상이고(글자 입력 칸도 높이 44px 이상이다. 이동 시트의 쪽 칸은 43px, 탐색 줄의 쪽 칸은 36px, 목차 오버레이의 찾기 칸은 37px였다. `TouchFieldsAnswer44`), 글자는 12px 이상, 입력 글자는 16px이다. 16px은 포커스 때 자동 확대를 막는다. 12px 하한은 토큰 하나로 둔다. 터치에서 `--text-xs`가 12px이 되어, 담당 칩·검토 대기 배지·처리 중 배지·답글 수·구획 수·아바타 머리글자·쪽 번호가 11px로 그려지지 않는다.

- 그린 크기가 44px보다 작은 컨트롤은 히트 유틸리티 하나로 넓힌다. `.hit`(그리고 누를 수 있는 배지 `button.badge`)의 `::after`가 가운데 맞춘 `--hit` 상자를 깔고, 그 요소의 `overflow`는 `visible`이다. 담당 칩의 `overflow:hidden`이 이 상자를 그린 높이 20px로 잘랐기 때문이다.
- 카드 머리의 글자 링크(`#N`·줄 범위·`N쪽`)는 4–8px 간격이라 가운데 맞춘 상자가 서로 겹치고, 뒤의 것이 앞의 것의 절반을 가져간다(`1쪽`이 16×38px로 눌렸다). 그래서 이 셋은 각각 실제 44×44px 상자로 그리고 글자를 가운데 둔다.
- 마우스(`pointer:fine`)는 그린 크기 그대로이고 히트는 24px이다(WCAG 2.5.8).
- 확인은 `PhoneTouchSizes`와 `DesktopMisc.test_desktop_hit_targets_are_at_least_24px`다. `PhoneTouchSizes`는 컨트롤마다 가운데에서 왼쪽·오른쪽·위·아래로 1px씩 밀어 나가며 `elementFromPoint`가 그 컨트롤을 돌려주는 거리를 재고(`MISSES_44`, 한쪽 60px까지), 실제로 눌리는 폭과 높이가 모두 44px 이상인지 본다. 히트가 한쪽으로 치우쳐도(시트 도구 줄은 아래로만, 상태 줄의 동작은 위로만 넓힌다) 잰다.

안전 영역(`env(safe-area-inset-*)`, `viewport-fit=cover`)은 모든 레이아웃에서 비운다. `wide`(아이패드 홈 화면 앱·전체 화면)도 탐색 줄과 펼친 패널이 위 안전 영역 아래에서 시작하고, 작성 패널의 `[취소] [핀 저장]`, 목록 끝, 접힌 패널의 상태 칩이 아래 안전 영역 위에 남는다(`WideSafeArea`). compact에서 알림은 탐색 줄 바로 아래 위쪽으로 옮긴다(`narrow`는 화면 위, `mid`는 본문 왼쪽 위). 아래 도구 줄·첫 안내와 겹치지 않게 하려는 것이다.

### 펼친 화면 레이아웃

`mid`는 화면을 세 층으로 고정한다. 패널을 접고 펴도 `[핀 N]`이 자리를 옮기지 않고, 문서 옆 패널(`mid-side`: 마우스 901–1099px, 터치 901–1366px)이 문서 탐색 줄을 자르지 않게 하려는 것이다. `wide`·`narrow`에는 이 층 구조가 없다. `short`에는 세 층이 없고 위 한 줄만 있다(§모바일 레이아웃 짧은 화면).

| 층 | 자리 | 담는 것 |
| --- | --- | --- |
| 위 | 탐색 줄 `#doc-nav`, 화면 전체 폭, `position:fixed` | 목차 토글 · 문서 링크 · `원고`/`변경사항` ··· 쪽 표시. 패널이 자르지 않는다 |
| 가운데 | 본문(`#main`)과 패널(`#right`) | 패널은 탐색 줄 아래에서 동작 줄 위까지만 편다(`mid-overlay`는 문서 위 오버레이, `mid-side`는 문서 옆) |
| 아래 | 동작 줄 `#bar1`, 화면 전체 폭, `position:fixed` | `[⬚ 선택]` ··· 상태 칸 ··· `[⋯] [핀 N | 검토 M]` |

**손의 흐름.** 편 폴드와 태블릿은 대개 두 손으로 쥐고, 엄지가 아래 양 끝에 닿는다. 그래서 자주 쓰는 동작을 아래로 모은다.

- `[선택]`은 왼쪽 아래 끝이다. PDF 위에서 쓰는 도구라 문서 쪽 엄지에 둔다.
- 패널 토글 칩 `[핀 N | 검토 M]`은 패널이 나오는 오른쪽 아래 끝이고, 그 옆이 `[⋯]`다. 가운데는 상태 칸이다.
- 작성 패널의 `[취소] [핀 저장]`(`#c-actions`)은 패널 바닥, 곧 동작 줄 바로 위라 오른손 엄지 거리다.
- 드문 동작(확대·테마·언어·도움말·재빌드)은 `[⋯]` 안이고, 쪽 이동은 탐색 줄의 쪽 표시다.

아래 고정은 `narrow`의 아래 시트와도 방향이 같다.

**자리가 움직이지 않는다.** 동작 줄은 패널을 따라다니지 않으므로 `[핀 N]`은 패널을 펴도 접어도 같은 자리다. 칩은 줄의 오른쪽 끝에 붙어 있어, 핀 수가 늘어 글자가 길어지면 왼쪽으로 자라고 오른쪽 끝은 그대로다. 휴대폰 시트의 칩처럼 펴짐 화살표도 바탕 변화도 없다. 펴진 상태는 패널 자체와 `aria-expanded="true"`로 보인다.

**구현.** 도구 줄은 DOM으로는 `#right` 안에 그대로 두고 `position:fixed`로 뺀다. `narrow` 시트가 같은 마크업을 손잡이 아래 sticky로 쓰기 때문이다.

> **주의**
>
> `mid`의 `#right`에는 `transform`·`filter`·`opacity`·`contain`을 주지 않는다. 이 속성이 붙으면 fixed 자식의 기준 상자가 바뀌어 동작 줄이 패널과 함께 움직인다.

버튼 순서는 CSS `order`로만 바꾼다. 키보드 초점 순서는 DOM 순서 `[핀]→[선택]→[⋯]` 그대로다. 휴대폰·태블릿 시트에서는 DOM 순서 `[핀]→[선택]→[손잡이]→[이동]→[⋯]`가 보이는 순서와 같다. 본문·패널은 `body`의 위아래 여백 사이에만 그린다. 위 여백 `--mid-top`은 탐색 줄 + 위 안전 영역이고, 아래 여백 `--mbar-h`는 도구 높이 + 위아래 여백(`--mbar-pad`) + 테두리 + 아래 안전 영역이다. 동작 줄 높이는 터치 49px(40px 버튼, 위아래 4px), 마우스 45px(28px 버튼, 위아래 8px)다. 터치 버튼의 44px 히트는 위아래 여백 안으로 넓힌다. `[⋯]`는 테두리 없는 아이콘이라 터치에서 44px 폭으로 그린다.

**오른쪽 안전 영역.** 펼친 패널은 오른쪽 안전 영역(가로 휴대폰의 노치)을 비운다. 전에는 `#c-copy`와 `[핀 저장]`이 노치 구역에 걸렸다(`MidChrome`).

**접힌 패널.** `#right`는 보이지 않는 틀로 남고 입력을 받지 않는다. 위치 다시 잡기 배너(`#banner`)만 동작 줄 바로 위 오른쪽에 카드로 띄운다. 상태는 동작 줄의 상태 칸에 있다.

**여닫는 움직임.** 오버레이(`mid-overlay`, 900px 이하의 `short`)는 패널이 오른쪽에서 0.18초 밀려 들어오고, 접을 때([핀]·Esc·손잡이·Ctrl+\) 같은 길로 0.18초 밀려 나간다. 위 주의 때문에 `right`만 움직인다. 밀려 나가는 동안에는 `body`에 `side-open`을 남겨 틀이 흔들리지 않게 한다. 문서 옆 패널은 폭이 바뀌면 PDF 쪽 폭을 다시 맞춰야 해서 움직임 없이 바로 바뀐다. `prefers-reduced-motion: reduce`이면 움직임이 없다(전역 규칙). 문턱과 미리 보기는 그대로다.

**밀어서 닫기(오버레이, 터치).** 겹친 패널은 오른쪽으로 밀어 닫는다. 10px 움직인 뒤 방향을 정한다(`swipeAxis`). `|dx| > 1.5|dy|`이고 오른쪽이면 가로 끌기이고, 아니면 스크롤이다. 패널은 손가락을 따라 `right: -dx`로 움직인다(`--swipe-x`, transform이 아니다 — 위 주의). 손을 떼면 `dismissOutcome`이 정한다. 패널 폭의 35% 이상 밀었거나, 24px 넘게 0.5px/ms 이상으로 튕기면 0.18초에 밀려 나가 닫히고 [핀]처럼 기억한다. 아니면 0.18초에 제자리로 돌아온다.

- 작성·편집·답글·위치 다시 잡기 중에는 닫지 않는다. 고무줄처럼 `dx × 0.25`(최대 24px)만 따라오고 돌아온다(`swipeFollow`).
- 분절 컨트롤(`.seg`), 가로로 스크롤하는 빌드 로그(`pre.nowrap`), 입력 칸, 손잡이, 도구 줄에서 시작한 끌기는 밀기가 아니다. 그 요소가 가로 스크롤을 쓴다. 450ms 넘게 가만히 누른 뒤의 끌기도 밀기가 아니다(글자 선택).
- 밀던 중에 두 번째 손가락이 닿으면 제자리로 돌아간다.
- 바깥을 눌러 닫지 않는다. 오버레이는 모달이 아니고, 패널을 연 채 PDF를 길게 눌러 다시 고르는 흐름과 부딪히기 때문이다.
- 문서 옆 패널은 밀어 닫지 않는다. 손잡이 규칙만 따른다.

**Esc.** 오버레이가 열려 있으면 Esc가 패널을 접는다. 고르는 중이면 첫 Esc는 선택을 취소한다.

**고르는 중 가리지 않기.** 오버레이에서 작성 중이면(`body.composing`) `#left`에 패널 폭만큼 `padding-right`를 준다. 변경사항 보기가 이미 쓰는 방식이다. 쪽 폭이 남은 자리에 다시 맞춰져, 오른쪽 단을 길게 눌러 고른 상자가 패널 밑에 숨지 않는다(`s10_fold_cover`). 확대해 둔 쪽은 그 자리까지 가로로 밀어 볼 수 있다.

**문서 링크가 넘칠 때.** 줄 안에서 가로로 밀리고, 스크롤바 대신 넘친 쪽 끝을 흐리게 한다(`.fade-l`·`.fade-r`, `docLinksFade`). 문서가 바뀌면 지금 문서 링크를 보이는 자리로 끌어온다. 폴링으로 다시 그릴 때는 사용자가 민 자리를 둔다.

**첫 안내.** 탐색 줄·패널을 가리지 않게 동작 줄 바로 위 왼쪽에 작은 칩으로 뜬다. 곧 안내가 가리키는 `[선택]` 위다. 알림은 탐색 줄 바로 아래 왼쪽 위라 첫 안내와 겹치지 않는다.

## 패널과 목록

### 패널 정리

작성 패널·도구 줄·카드는 한 간격 체계와 한 줄 배치를 따른다.

**가장자리 격자.** compact의 시트·패널은 x값 둘로 줄을 세운다. 상자(카드, 상태 칩, 작성 패널의 컨트롤, 저장 줄, 이동 시트의 행, 도움말의 표, 아래 시트의 [닫기])는 좌우 `--edge`(휴대폰 12px, 그 밖 16px)에서 시작하고 끝난다. 상자 없는 줄(구획 머리의 꺾쇠와 이름, 시트 제목, 보관함·휴지통 행, 도움말의 글)은 글자를 `--ink`(`--edge` + 12px)에서 시작한다. 카드 안 내용은 테두리와 12px 여백으로 `--ink`에 온다. 도구 줄도 `--edge`에서 시작하고 끝난다. 끝의 [⋯]는 44px 상자가 `--edge`에서 끝나고 잉크는 `--ink`에서 끝난다. 상태 줄과 변경 보기의 엄지 줄은 도구 줄 칸과 같은 가장자리에서 시작하고 끝난다(태블릿 시트는 640px 칸 안)(`SheetEdgeGrid`, `BarAndSheets`).

**한 간격 체계.** 8px 격자를 쓰고, 같은 줄의 버튼은 같은 높이다. 터치에서 그린 높이는 세 단계다. 주요 동작(`[취소] [핀 저장]`·`[보내기]`)은 44px, 도구 줄은 40px(`--ctl-touch`), 카드 동작·목록 머리 도구·작은 보조 버튼은 폰 시트 32px·태블릿 패널 36px(`--ctl-touch-sm`)이다. 아이콘 버튼은 36px로 그린다. 단 폰 시트 카드 동작 줄의 아이콘 버튼은 그 줄 높이에 맞춰 32px 정사각형이다. 그린 크기와 무관하게 눌리는 영역은 44×44px이다(§모바일 레이아웃 터치 기기 크기). 48px 단계는 없다. 강조 색(`--primary`, `.btn-default`)은 주요 동작 [핀 저장] 하나에만 칠한다. 카드의 [완료]는 옅은 파랑(`.btn-soft`)이고, [삭제]는 옅은 위험 색(`.btn-destructive`)이다. 나머지는 테두리만 있는 outline이다(§디자인 토큰과 컴포넌트).

**도구 줄(compact).** 휴대폰·태블릿 시트는 `[핀 N | 검토 M] [⬚] │ 손잡이 │ [본문 3/25 ▾] [⋯]`의 3칸 격자다(§모바일 레이아웃). 손잡이는 시트 높이를 바꾸는 칸이다(§패널 폭과 시트 높이 시트 머리). 말이 먼저다. 핀 아이콘이 수 옆에서 한쪽으로 기울어 보였고, 채운 버튼이 시트 가장자리에 붙어 두 모양으로 그려졌다.

- 왼쪽 묶음은 반쪽 둘로 나뉜 칩 하나다. 왼쪽 반 `[핀 N]`(`#btn-side`)은 열린 핀 수이고 시트를 펴고 접는다. 오른쪽 반 `[검토 M]`(`#btn-rv`)은 검토 대기 수를 보라(`--status-review`)로 쓰고, 누르면 목록의 검토 대기로 간다. 검토 대기가 없으면 오른쪽 반이 없고 `[핀 N]`이 온전한 칩이다. 두 반은 맞닿고, 그 사이는 테두리가 아닌 1px 안쪽 그림자(`--border`)다. 반쪽마다 최소 44px이고, 히트는 가운데로 옮겨 맞추지 않고 제 상자의 가장자리로 정한다. 그래서 글꼴이 그리는 폭과 무관하게 반쪽마다 44px이다. 가운데 맞춤은 소수 폭의 절반만큼 옮기는데, 브라우저가 옮긴 상자를 정수 픽셀로 넓혀 읽어 `[검토 M]`의 히트가 `[핀 N]`에 1px 들어갔다(CI 글꼴에서 `[핀 N]` 43px). `[핀 N]`의 히트는 이웃이 없는 바깥쪽 막대 가장자리로 4px 더 넓다. 키보드 초점의 테두리는 `[핀 N]`이 위에 그려 맞닿은 `[검토 M]`에 가리지 않는다. 작성 중 점은 칩의 모서리에 있다.
- 이름(aria-label)은 보이는 말로 시작한다. `[검토 M]`은 `검토 1 · 검토 대기 핀으로 가기`이고, `[핀 N]`은 `핀 3 · 패널 펴기`처럼 제 수만 말하고 검토 대기 수는 오른쪽 반에 맡긴다. 알약이 버튼 안에 있는 데스크톱 탐색 줄의 `[핀 N ‹]`(`#nav-side`)는 이름에 검토 대기 수를 넣는다.
- [⬚]는 네 모서리와 가운데 원의 `focus` 아이콘이다. 시트에서는 아이콘만 두고, 이름은 aria-label과 길게 누르기다.
- 막대의 버튼에는 테두리가 없다. 칩과 [⬚]는 같은 28px 채움(`--secondary`, `--radius-lg`)이고, 켜진 [⬚]는 그 칩을 `--primary`로 채운다. `[본문 3/25 ▾]`와 `[⋯]`는 ghost다. 말(핀·검토)은 14px 400, 수는 600에 고정폭 숫자다. 아이콘은 18px이다.
- 수·말·쪽 숫자는 대문자 높이로 다듬어(`text-box: trim-both cap alphabetic`) 줄의 모든 아이콘이 숫자의 대문자 높이 가운데에 온다.
- 컨트롤은 시트 윗변에서 12px 아래에서 시작하고, 손잡이 막대는 그 여백 안에 있다(§패널 폭과 시트 높이 시트 머리). 칸 안 틈은 8px다. 400px 미만에서는 칩 반쪽의 좌우 패딩이 12px에서 8px로 주고, 360px 미만에서는 오른쪽 칸의 틈이 4px로 준다. 왼쪽 칸의 틈은 늘 8px다. [⬚]의 44px 히트가 그 틈으로 8px 넓어지기 때문이다.
- 그래도 왼쪽 칸을 넘으면(영어, 세 자리 수, 접힌 폴드 겉화면) 단계를 밟아 줄인다(`fitBarWords`). 먼저 칩 반쪽의 좌우 패딩을 4px 한 단계 줄인다(`#bar1.bar-snug`). 그래도 넘치면 말(핀·검토) 대신 8px 점을 둔다(`#bar1.bar-tight`). 열린 핀은 초록(`--status-open`, 마크의 색), 검토 대기는 보라(`--status-review`)이고, 점은 수의 대문자 높이 가운데에 온다. 그래서 수만 홀로 남는 일은 없다. 영어 휴대폰의 `3 | 1`이 무엇의 수인지 알 수 없었다. 한국어는 360px에서 말을 지키고(344px 폴드 겉화면은 패딩을 줄여 지킨다), 영어는 411·430px에서 패딩을 줄여 말을 지키며 360·344px에서 점을 둔다. 수나 대역이 바뀔 때마다 다시 잰다.
- 칸을 넘으면 `[본문 3/25 ▾]`의 문서 이름만 줄어든다. 400px 미만이면 문서 이름이 없다.
- 펼친 화면·짧은 화면의 도구 줄도 같은 칩이다(교차 해상도 점검 2b). 예전 `[📍 N 👁 M ›]` 자리인 줄의 오른쪽 끝에 서고, `[⬚ 선택]`도 같은 채움이다. 컨트롤은 그 줄의 높이(터치 40px)로 그린다. 핀 아이콘과 보라 `👁 M` 알약은 데스크톱이 패널을 접었을 때의 `[핀 N ‹]`에만 남는다.
- 줄의 위아래 여백은 같다. 펼친 화면의 동작 줄은 채움 위아래가 4px씩이고, 시트의 도구 줄은 12px씩이다(§패널 폭과 시트 높이 시트 머리). 아래 안전 영역은 그 아래에 더한다. 칩 반쪽, [⬚], [⋯], 상태 줄의 아이콘·글·[재빌드]는 잉크 가운데가 줄 가운데에서 0.5px 안에 선다. 글자는 대문자 높이로 다듬어(`text-box`) 숫자의 대문자 높이 가운데가 아이콘 가운데와 맞는다. [재빌드]의 글이 1.9px 높게 서던 것을 그 다듬기로 맞췄다. 확인은 `CompactRowCentre`다.
- 데스크톱 도구 줄은 패널을 좁히면 두 줄로 접힌다.

compact에서는 이름표를 도구 줄에 두지 않고 [더보기] 머리(`#more-label`, 인스턴스 색 점 + 이름)에 둔다. 대화상자 이름은 `더보기 · <이름표>`다. 맨 위 이름표 색 띠가 인스턴스를 가른다.

**도구 줄 높이.** 버튼과 쪽 칸은 한 높이(`--tb-h`: 데스크톱 28px, 터치 44px, 폰 시트 40px)이고 아이콘 버튼은 정사각형이다.

- 쪽 칸은 54×28px·`--text-base`·왼쪽 정렬 자리표시 '쪽 이동'이다. 터치에서는 84×44px·`--text-xl` 16px이다(iOS 확대 방지).
- 폭 맞춤은 `move-horizontal` 아이콘 버튼이다. '폭' 한 글자 버튼은 뜻이 읽히지 않는다.
- 기본 348px 패널에서 마우스 도구 줄은 `[PDF 재빌드] [쪽 이동] [−] [＋] [↔] [알림] [테마] [?]`가 한 줄에 든다.
- 위계: 쪽·축소·확대·폭 맞춤은 테두리 있는 탐색 컨트롤, 알림·테마·도움말은 테두리 없는 유틸리티 아이콘, [PDF 재빌드]는 흐린 ghost 글자다. 원고가 PDF보다 새로우면 [PDF 재빌드]가 `.btn-default`로 올라온다.
- 터치 화면과 사용자가 좁힌 패널은 필요하면 줄을 접는다.
- [핀 다시 읽기]는 열린 핀 목록 머리의 [다시 읽기]에 있고, compact에서는 [더보기] 안에 있다.

**위치 한 줄.** `파일 L159` + 쪽 + (낮을 때만) '위치 불확실' 배지 + [복사]다. 범위 종류와 줄 수는 그 아래 범위 설명 줄이 말하므로 되풀이하지 않고, 드래그한 줄은 쪽 표시의 설명에 둔다.

**범위 설명 줄.** 범위 사다리 위 한 줄이 `범위 L5-L6 · 2줄`처럼 저장하면 넘길 줄과 그 줄 수를 말한다(`rangeCap`). 칸이든 범위 발췌든 무엇으로 바꿔도 같은 줄이 그대로 바뀐다. 칸이 하나라 사다리를 숨겼고 범위가 그 칸과 같으면 칸 이름이 붙는다(`범위 L5 · 1줄 · 문단`). 사다리가 있으면 눌린 칸이 이름을 보이므로 붙이지 않는다. 어느 칸과도 맞지 않는 범위에도 이름을 붙이지 않는다. 줄 번호와 줄 수가 그 범위를 그대로 말하기 때문이다. 전에는 위치 줄 쪽 옆에 '줄 직접 지정'이 붙었는데, 주인이 그 뜻을 읽지 못했다. 편집 카드의 설명 줄도 같고, 그 줄 범위를 누르면 `파일 L4-L5`가 복사된다(작성 패널은 위치 줄의 [복사]). 영역 핀의 편집 카드는 그 자리에 `쪽 2 · 영역`을 쓴다.

**범위 사다리.** 한 줄 분절 컨트롤이고, 이름(`aria-label`)은 '범위'이며 범위 설명 줄 바로 아래에 있다. 칸이 둘 이상일 때만 보인다. 칸이 하나면 고를 것이 없고, `문단 · 1줄` 한 칸만 있는 분절은 주인의 휴대폰에서 소음으로 읽혔다(`drawLadder`, `RangeLadderAndCaption`). 칸 이름은 짧게 쓴다(`드래그한 줄 · 1줄`, `문단 · 40줄`, `abstract · 19줄`, `7월 · 8줄`). 같은 환경 이름이 겹칠 때만 '(바깥)'을 남긴다. 줄 범위는 칸 설명과 aria-label에 둔다. 넘치면 가로 스크롤하고 고른 칸이 보이게 맞춘다. 줄 단위의 미세 조정은 어느 레이아웃에서나 범위 발췌가 맡는다. 넓은 화면(`wide`)에 남아 있던 스테퍼 `위 [+][−] 아래 [+][−]`는 해상도별 정리에서 주인이 고른 1b로 없앴다.

**범위 발췌.** 모든 레이아웃에서 원문 자체가 범위를 바꾸는 컨트롤이다(`excerpt.js`, `RangeExcerpt`). 원문 자리에, 고른 줄을 파란 띠로 칠하고 그 위아래 한 줄씩을 흐리게 둔 줄 목록이 온다. 줄마다 번호, 글(띠는 4줄까지, 흐린 줄은 2줄까지), 오른쪽 44px 칸이 있다. 흐린 줄은 그 자체가 버튼이라, 누르면 범위가 그 줄까지 넓어진다. 오른쪽 칸에는 옅은 파랑 `+`가 있다. 띠의 첫 줄과 끝 줄(두 줄 이상일 때) 오른쪽 칸에는 `−` 버튼('이 줄 빼기 (L5)')이 있어, 누르면 그 줄이 빠진다. `+`와 `−`는 같은 28px 원이고 그 줄의 첫 글줄 높이에 놓이며, `−`의 히트는 44px다. 1행 위와 마지막 행 아래에는 흐린 줄이 없다. 다섯 줄이 넘는 띠는 첫 두 줄과 끝 두 줄 사이를 `… N줄`로 접고, 작성 패널의 [원문 펼치기]가 편다. 위에 한 줄이 생기거나 빠져도 움직이지 않은 끝 줄의 행이 화면에서 제자리에 남도록 시트를 그만큼 스크롤한다. 그래서 누른 손가락 밑에서 띠가 튀지 않는다. 바꾼 범위는 범위 종류가 `lines`이고(`setLines`), 설명 줄과 사다리의 눌린 칸이 바로 따른다. 원문 글은 `/api/snippet`에서 끝 줄과 그 이웃만 두 창 이내로 가져와 선택마다 기억한다. 주인은 스테퍼 `위 + − 아래 + −`를 핀을 옮기는 단추로 읽었다. 편집 카드도 같은 발췌를 쓴다. 마우스와 키보드도 같다. 흐린 줄과 `−`는 버튼이라 누르거나 Enter·Space로 쓰고, 다시 그려도 초점이 다음 같은 동작으로 옮겨 가며(`excerptFocusTarget`), 범위 설명 줄은 바뀔 때만 읽히는 polite 라이브 영역이다(`setCap`).

발췌 위 안내 줄은 띠가 두 줄 이상일 때만 `−`를 말한다(한 줄 띠에는 `−`가 없다). 한국어는 낱말 사이에서만 줄을 바꿔(`word-break: keep-all`) 360px에서 한 음절이 홀로 줄에 남지 않는다. 키보드로 `+`나 `−`를 누르면 다시 그린 발췌가 초점을 이어받는다(`excerptFocusTarget`). 같은 줄의 같은 버튼이 남아 있으면 그것, 없으면 같은 쪽의 다음 흐린 줄이나 띠의 새 끝 줄 `−`라서 Enter를 거듭 누르면 같은 일이 이어진다. 그것도 없으면 그 줄에서 가장 가까운 버튼이다. 전에는 다시 그릴 때마다 초점이 문서로 빠졌다. 범위 설명 줄(`#c-cap`, 편집 카드의 `.e-cap`)은 polite 라이브 영역이라 화면 읽기 프로그램이 바뀐 범위를 읽는다. 바뀌었을 때만 다시 쓴다(`setCap`). 영역 선택에는 발췌가 없고 영역 글자가 그대로 보인다.

**그림 요소.** 그림 문서의 pick은 드래그 밑의 요소와 그 조상의 사다리를 돌려준다. 단계마다 그 요소(`levels[].el`: id, 뿌리부터의 경로, 이름, 쪽 위 상자 `frac`)가 붙어 있어, 작성 패널은 서버에 다시 묻지 않고 요소를 보인다.

- '새 핀' 상자가 고른 요소의 상자로 옮겨 붙는다. 저장하면 이 상자가 핀의 마크가 된다. 저장 전에 결과를 보이는 미리보기이고, 따로 확인하는 단계는 없다.
- 위치 줄은 요소 경로(`#c-path`)와 코드 줄(`#c-loc`)이다. 예: `B2 › 달력 › 7월 · B2_calendar.py L88-L95`. 경로의 이름은 그 요소를 실은 단계의 이름이고, 단계가 없는 조상(합쳐진 단계, 사다리 한도 밖, 다른 파일에서 그린 요소)은 id로 적는다. 경로의 설명은 요소 id다. 복사 형식은 줄 핀과 같은 `파일 L시작-L끝`이다.
- 범위 사다리의 칸 이름은 요소 이름(`label`, 없으면 `part`, 없으면 id)이고 줄 수가 붙는다. 사용자가 쓴 이름이라 환경 이름 틀(`levelLabel`)을 거치지 않는다. 칸을 바꾸면 상자·위치 줄·원문이 그 요소로 바뀐다. 줄이 같아 합쳐진 칸은 남은 칸의 요소를 쓴다.
- 범위 발췌로 줄을 직접 맞춰도 고른 요소와 상자는 그대로다.
- 저장과 위치 다시 잡기는 고른 요소를 쪽 위 상자(`frac`)까지 `el`로 보내고, 그 상자를 핀의 `frac`으로도 보낸다. 그래서 지금 빌드의 지도 없이 그리는 마크도 사람이 본 상자 자리에 온다. 요소 칸이면 범위 종류도 그 요소의 것(`el:<부품>`, 뿌리는 `figure`)이다. 이 이름 규칙은 서버의 `builds.figure_map.element_kind`와 같고, [`src/limn/viewer/tests/test_viewer.py`](../../src/limn/viewer/tests/test_viewer.py)가 같은 요소로 둘을 대조한다. 위치 다시 잡기 배너의 '새 위치' 상자도 새 요소에 맞춰진다.
- 위치 다시 잡기는 늘 새 위치 전체를 보낸다. 새 자리에 요소가 있으면 그 요소를, 없으면 `el` 없이 보내고, 그러면 서버가 핀의 `el`을 지운다(`el`은 위치 필드다). 서버는 줄 핀을 영역 핀으로, 영역 핀을 줄 핀으로 바꾸지 않는다. 그래서 모양이 다른 후보(줄 핀인데 지도를 못 읽었거나 코드 없는 요소가 답한 자리, 또는 그 반대)는 [이 위치로 바꾸기]를 내놓지 않고, 배너가 이유를 말하며 다시 고르기를 기다린다.
- 편집 카드의 범위 사다리는 원문 줄 단계 하나(`raw`, 화면에는 `지금 범위`)뿐이라 보이지 않고, 범위 설명 줄만 있다. 그림 문서 파일에는 `/api/snippet`이 요소 단계를 주지 않는다. 손대지 않고 저장하면 아무것도 보내지 않는다. 범위 발췌로 줄을 바꾸면 범위 종류가 `lines`가 되고, 핀의 `el`은 그대로 남는다(범위 고치기는 위치 바꾸기가 아니다). 위치 다시 잡기나 409로 핀이 바뀌면 편집 카드는 핀의 새 요소를 따른다.
- 요소 상자가 없는 답(`frac`이 없거나 유한한 네 수가 아니다)이면 상자는 드래그한 자리에 남는다.
- 코드 줄이 없는 요소(지도에 `src`가 없거나, 스크립트를 문서 폴더 안에서 읽지 못하거나, 줄이 지금 파일을 넘는다)는 영역 선택처럼 보이고, 쪽 옆에 '코드 없는 요소'가 붙는다. 지도를 읽지 못하면 영역으로 떨어지고 쪽 옆에 '영역'이 붙는다. 두 경우 모두 경고 줄이 이유를 말한다.
- 카드도 같은 이름표를 단다. 코드 줄이 없는 요소의 영역 핀은 '코드 없는 요소', 지도를 읽지 못한 때의 영역 핀은 '영역'이고, 보기 전용 PDF의 영역 핀만 '보기 전용'이다.

**원문.** (영역 선택) 기본 4줄로 접고, 넘치면 흐리게 끊는다. 원문 바로 밑 한 줄의 오른쪽 끝에 [원문 펼치기]가 있고, 그 버튼이 숨으면 줄도 없다. 원문은 늘 줄을 바꿔 보인다. 주인이 [줄바꿈] 토글이 무엇을 하느냐고 묻고 없애기로 했다. 문단 하나를 한 줄로 쓰는 원고가 흔해 끄고 쓸 일이 없었기 때문이다. URL·긴 명령처럼 끊을 곳 없는 낱말도 칸 안에서 끊는다(`overflow-wrap: anywhere`, 범위 발췌·편집 카드·소스 diff도 같다, `SourceAlwaysWraps`). 긴 한 줄이 여러 줄로 접히는 원고가 흔해, 넘침은 줄 수가 아니라 그린 높이로 잰다.

**동작 줄.** `[취소] [핀 저장]`을 1:2로 나눠 패널 바닥에 고정한다(`#c-actions`, 작성 패널 밖·목록 뒤). wide는 패널 flex 열의 바닥이다. compact에서는 보이는 화면의 바닥이다. 휴대폰·태블릿 시트에서는 화면 아래 가장자리, 펼친 화면에서는 패널 바닥(아래 동작 줄 바로 위)이다. 시트의 아랫변은 늘 화면 바닥(`bottom: var(--kb)`)이므로, 동작 줄은 스크롤 상자(`#right`)의 sticky 바닥이면서 목록이 짧을 때도 그 바닥까지 내려간다(`margin-top:auto`). 그래서 시트를 끝까지 올려도 목록 뒤를 따라 올라와 그 아래에 빈 시트를 남기지 않고, 시트를 끄는 동안에도 화면 바닥에 있으며, 키보드가 올라오면(레이아웃이 줄어듦 / `--kb`) 키보드 바로 위에 있다. 터치에서 이 줄은 56px(44px 버튼 + 12px)이다(`BottomActionRow`).

편집 카드의 `[위치 다시 잡기] [취소] [저장]`도 compact에서는 같은 바닥 줄이다. 카드 안의 sticky 줄은 카드 안에서만 붙으므로 이 줄은 화면에 고정한다(`position:fixed`). 휴대폰·태블릿 시트에서는 화면 바닥(태블릿은 640px 칸), 펼친 화면에서는 패널 폭으로 아래 동작 줄 바로 위다. 목록은 그 높이만큼 끝에 여백을 둬 마지막 카드가 줄 위로 올라온다. 바닥 줄은 하나다. 작성 패널이 함께 열려 있으면 `[취소] [핀 저장]`이 바닥 줄이고, 편집 카드의 줄은 카드 안에 남는다. 마우스 데스크톱(`wide`)에서는 두 줄 모두 그대로다.

**작성 패널의 순서.** 모든 레이아웃이 한 순서다. 위치 줄 → 메모 칸(@태그 미리보기·질문 제안·담당 줄이 따라온다) → 종류 → 겹침 안내 → 범위 묶음(`#c-range`: 범위 설명 줄 · 범위 사다리 · 범위 발췌 · 원문 밑 줄)이다. 마우스 데스크톱(`wide`)도 해상도별 정리의 1b로 같은 순서와 범위 발췌를 쓰고, 바탕도 패널 그대로다(전에는 `--card` 회색 상자, 위치 줄 → 범위 → 스테퍼 → 원문 → 종류 → 메모). 메모 칸이 넷째 블록이면 패널 위에서 328px 아래라 동작 줄 밑에 깔리고, 키보드를 올리면 위치 줄이 화면 밖으로 밀렸다. 이제 360×780에서도 메모 칸 전체가 동작 줄 위에 있고, 키보드를 올려도 위치 줄이 메모 칸 바로 위에 남는다(`PhoneComposer`). 종류는 메모의 성격이라 메모 곁에 두고, 범위를 바꾸는 것과 그 결과인 원문은 한 묶음으로 끝에 둔다. 펼친 화면은 전에 옛 순서였고 메모 칸이 범위 묶음과 원문 아래, 패널 바닥에 있었다(`MidComposerOrder`). 전에는 종류가 한 줄 버튼과 원문 사이에 끼어 범위 묶음을 갈랐다. 블록 사이와 범위 묶음 안은 모두 8px 한 간격이다. 전에는 0–20px가 섞였고 종류 분절이 원문에 붙어 있었다(`ComposerSamePass`). 마크업이 이 순서라 Tab도 화면 순서를 따른다. 전에는 마크업이 넓은 화면의 순서라 Tab이 위치 → 겹침 → 범위 → 종류 → 메모로 화면을 거슬러 갔다. 겹침 안내와 범위 묶음은 `#c-body`가 숨으면(pick 실패) 함께 숨는다.

compact에서 작성 패널은 시트·패널의 바탕 그대로이고, 아래 선으로 목록과 갈린다. `--card` 회색이던 때는 흰 시트 안에 회색 상자가 떴고, 태블릿 시트의 640px 칸에서는 따로 노는 상자였다. 위치 줄 끝의 [복사]는 줄 끝 ghost 아이콘이다(터치는 그린 36px, 히트 44px. 마우스 데스크톱도 같은 ghost를 28px로 그린다). 작성 패널의 테두리는 메모 칸 하나라, 저장 줄의 [취소]와 겹침 안내의 [덧붙이기]·[따로 저장]은 편집 카드의 [취소]와 같은 채운 secondary다. 전에는 같은 바닥 줄의 [취소]가 작성 패널에서는 테두리 상자, 편집 카드에서는 채운 칸이었다(`ComposerOneBorder`).

- 겹침 안내는 한 줄이다. 짧은 관계(`#4와 같은 범위`, 카드 배지와 같은 말)와 `[덧붙이기] [따로 저장]`을 한 줄에 두고, 줄 범위가 붙은 전체 문장은 짧은 관계의 설명에 둔다. 다른 레이아웃은 문장과 `[#4 메모에 덧붙이기] [별도 핀으로 저장]` 그대로다.
- 작성하는 동안 휴대폰 시트는 화면의 80%로 올라온다(`body.sheet-up`). 이 높이는 기억하지 않는다. 저장하거나 취소하면 저장된 높이로 돌아가고, 작성 중에 사용자가 높이를 정하면(끌기·탭·[더보기] 단계·키) 그 높이가 이긴다(`SHEET_KEPT`). 태블릿 시트는 작성 중에도 높이를 그대로 둔다. 메모 칸이 둘째라 45%에 위치 줄·메모 칸·저장 줄이 들어가고, 방금 끌어 고른 쪽이 시트 위에 보인다. 키보드가 올라와(메모 칸 같은 패널 입력 칸에 초점이 있을 때) 셋이 들어가지 않으면 들어갈 만큼만 올라오고, 60%를 넘지 않는다(`tabletLift`, `sheetLift`). 키보드가 내려가면 원래 높이로 돌아오고, 이 높이도 기억하지 않는다. 그때 위치 줄을 시트 위쪽으로 끌어와 메모 칸 위에 둔다(`keepFieldInView`).

**선택 버리기와 되돌리기.** 메모를 쓴 선택을 Esc나 [취소]로 버리면 선택은 바로 사라지고 `선택 취소됨 · [되돌리기]` 알림이 6초 뜬다. [되돌리기]는 선택(`COMPOSE.current`)·메모(@태그 힌트 포함)·종류·담당·점선 상자를 그대로 되살린다(`restoreSelection`). 확인 대화상자는 두지 않는다(결정 단계는 적게, 되돌리기로 받친다). 메모가 비었거나 위치를 아직 찾는 중이었으면 알림이 없다. 그사이 새 선택이나 메모 초안을 시작했으면 되살리지 않는다(새 것이 이긴다). 같은 문서·같은 빌드가 아니면 현재 메모가 비어 있을 때 메모만 돌아오고, 자리를 다시 골라야 한다고 알린다.

핀을 저장한 직후의 [되돌리기]도 같다. 핀을 지우면서 같은 선택과 메모로 작성 패널을 다시 연다. 저장 뒤에 고칠 곳이 보였을 때 처음부터 다시 고르지 않게 하려는 것이다.

**쓰던 초안은 탭에 남는다.** 작성 중인 초안(선택·점선 상자·메모·@태그 힌트·종류·담당, 또는 다음 선택을 기다리는 메모)은 고칠 때마다 `sessionStorage`에 적는다(300ms 모아서, 페이지가 숨겨지면 바로). 열쇠는 인스턴스 이름표와 문서마다 하나다(`draftKey`). 문서를 바꿀 때는 떠나는 문서의 초안을 먼저 확정하고, 도착한 문서의 초안만 화면에 되살린다. 새로고침하거나, 뒤로 가기로 시트를 닫은 뒤 한 번 더 눌러 Limn을 떠났다가 돌아오면, 이 탭의 다음 부팅이 그 문서의 초안을 되살리고 `작성 중이던 메모를 되살렸습니다 · [버리기]`를 띄운다. 확인 대화상자 없이 되살리고 되돌리기로 받친다.

- 같은 빌드에서 그린 상자면 선택·상자·메모를 모두 되살리고, 접힌 패널이나 시트를 편다(기억하지 않는다). 빌드가 바뀌었으면 상자의 좌표가 틀리므로 메모만 메모 칸에 되살려 다음 선택에 쓰게 하고, 알림이 그렇게 말한다(`draftRestore`).
- [버리기]는 보통의 버리기와 같다. 선택이 있던 초안이면 `선택 취소됨 · [되돌리기]`가 뜬다.
- 새 핀으로 저장하거나 기존 핀에 메모를 덧붙이면, 제출한 선택의 초안만 지운다. 다른 문서에서 응답이 오거나 원래 문서로 돌아온 뒤 응답이 와도, 새 선택과 고친 메모는 남기고 손대지 않은 원래 초안만 지운다. 버린 초안은 되돌리기 알림이 떠 있는 동안 남아 있다가(그사이 페이지를 떠나도 돌아오면 되살아난다) 알림이 사라질 때 지운다.
- 이 탭에서만 보인다. 다른 탭·기기와 나누지 않고, 탭을 닫으면 사라진다.

**드래그 직후 저장.** 드래그 → SyncTeX `/api/pick` 역변환은 약 1.1초 걸린다(`#c-spin`). 그 사이에도 [핀 저장]과 ⌘/Ctrl+Enter는 눌린다. 아직 `COMPOSE.current`가 없는 저장이 메모를 잃지 않게 이렇게 한다.

- pick이 끝나기 전에 저장을 누르면 요청을 큐에 담고(`COMPOSE.pendingSave`), 버튼이 "위치 찾는 중… 저장 대기"(스피너)로 바뀐다.
- 메모 글은 스냅샷하지 않는다. pick이 풀려 실제로 저장하는 그 순간 `#note`를 다시 읽는다. 대기하는 동안 고친 글자까지 반영하려는 선택이다.
- pick이 성공하면 저장을 자동으로 이어 실행한다. 실패하면(`d.error`·네트워크 오류) 큐를 비우고 저장하지 않은 채 기존 오류 패널만 보인다.
- 버튼을 다시 누르거나 [취소]를 누르면 대기를 취소한다(토글). Ctrl+Enter도 버튼과 같은 경로라 동작이 같다.

**고르는 중.** 고르는 중에는 첫 화면 안내 문단(`#empty`)을 숨긴다.

**핀 카드.** 머리 왼쪽에 번호·줄 범위·쪽, 오른쪽에 묶음 `.h-meta`(담당 칩·답글 수·작성자)와 접기가 있고, 배지는 그 아래 한 줄이다. 자리가 모자라면 `.h-meta`가 묶음째 다음 줄 오른쪽으로 내려간다. 한 줄에 우겨 넣으면 담당 칩이 있을 때 작성자 이름이 한 글자로 잘리기 때문이다. 묶음 안에서는 담당 칩 이름이 먼저 말줄임되고(`담당 @Sa…`), 작성자 이름이 그다음이다. `wide`의 동작은 같은 폭 격자 `[보기] [수정] [답글] [삭제] [완료]`이고, 처리 중이면 [풀기]가 붙는다.

compact(`narrow`·`mid`)는 한 번 더 줄인다. 279px 태블릿 패널에서 같은 폭 버튼 여섯이 40px 폭으로 눌렸기 때문이다.

- 머리의 `#N`·줄 범위·`N쪽`은 링크 하나 `#N · L4-L5 · 1쪽`이다. [보기]와 같은 `data-act="view"`라 한 번 눌러 같은 자리로 가고, 동작 줄의 [보기]는 빠진다. 높이 44px의 한 표적이다. 줄 범위 복사는 [수정] 카드의 줄 범위와 작성 패널의 [복사]에 있다.
- 동작 줄은 `[삭제] [수정] [풀기] ······ [답글] [완료]`다. 위험한 [삭제]는 왼쪽 끝, 주요 동작 [완료]는 오른쪽 엄지 끝이다. 마크업이 이 순서로 그려지므로(`cardActs`, 레이아웃이 바뀌면 카드를 다시 그린다) Tab도 왼쪽에서 오른쪽으로 간다. [삭제]·[수정]·[풀기]는 아이콘(`trash-2`·`pencil`·`lock-open`)만 보이고, 이름은 `aria-label`과 설명(길게 누르기)에 있다. 세 아이콘 버튼은 같은 중립 채움(`--secondary`)과 같은 크기이고, [삭제]의 그림만 위험 색이다. [삭제]는 [수정]과 한 간격 단계(8px) 더 떨어져 있어 [수정]을 누르려던 엄지가 [삭제]에 닿지 않는다. [답글]·[완료]는 이름을 쓴다. 검토 대기 카드는 `[변경 보기] ··· [답글] [확인]`이다.
- 터치에서 동작 버튼은 폰 시트 32px·태블릿 패널 36px로 그리고, 아이콘 버튼은 그 크기의 정사각형이다. 사이 틈은 12px라 44px 히트가 서로 겹치지 않는다. 동작 줄은 메모 바로 아래 한 간격 단계(8px)에 온다. 메모를 눌러 고치는 것은 [수정]과 같은 지름길이라 메모 칸에 최소 높이를 주지 않는다. 한 줄 메모에 44px를 주면 메모와 동작 줄 사이에 22–60px의 빈 띠가 생겼다.
- 버튼마다 `data-act`는 그대로다. 역할에 따라 숨기는 규칙과 에이전트·테스트가 그 값을 본다.
- 오버플로 메뉴나 확인 단계는 없다.

### 패널 폭과 시트 높이

| 항목 | 펼친 화면(`mid`) | 데스크톱(`wide`) |
| --- | --- | --- |
| 최소 | 300px — 터치 도구 줄이 한 줄에 들어가는 폭 | 280px |
| 최대 | 오버레이: 440px(화면 − 240px가 더 작으면 그 값). 문서 옆: 화면 − 488px(본문 480px + 손잡이 8px) | `min(80%, 화면 − 486px)` |
| 기본 | 330px | 348px |
| 단계(좁게·보통·넓게) | 300 · 330 · 50%(한계 안으로 제한) | 300 · 348 · 42%(한계 안으로 제한) |
| 기억 | `pinPrefs.sideMid`, 접힘은 `pinPrefs.midClosed` | `pinPrefs.side`, 접힘은 `pinPrefs.sideClosed` |
| 접는 문턱 T | 150px | 140px |

**손잡이.** 손잡이(`#grip`, `role=separator`)는 wide·mid 공통의 Pointer Events 구현 하나다.

- 보이는 막대는 6–8px이다. 잡는 영역은 `::after`로 넓힌다. 터치는 히트 유틸리티(`.hit`)로 44px, 마우스는 12px이다. 터치의 44px는 막대의 PDF 쪽에 둔다(패널 손잡이는 왼쪽, 목차 손잡이는 오른쪽). 패널 쪽으로 넓히면 카드의 왼쪽 가장자리를 눌렀을 때 카드가 펼쳐지지 않고 패널 폭이 바뀌었다. 그 대신 PDF 스크롤 상자(`#left`)가 오른쪽 여백을 넓혀 쪽이 히트 상자 밖에 놓인다. 문서 옆 패널 옆에서는 40px이고 왼쪽 여백도 같은 40px라 쪽이 칸 가운데에 온다. 작성 중인 오버레이 옆에서는 패널 폭 + 막대 8px + 40px, `wide`에서는 48px이다. 쪽 폭 맞춤은 터치에서 이 여백을 뺀 폭으로 계산하므로(`innerW`·`fitWidth`, [폭 맞춤] 포함) 쪽 오른쪽 틈이 이 여백과 같다. 확대한 쪽을 오른쪽 끝까지 밀어도 같은 틈이 남는다. 스크롤 상자의 오른쪽 여백은 스크롤 범위에 들지 않으므로, 쪽 묶음(`#doc`)이 같은 값(`--doc-end`)을 제 여백으로 지니고 음수 여백으로 되돌린다. 그래서 쪽 오른쪽 끝을 세로로 밀면 PDF가 스크롤되고, 길게 누르면 고른다. 손잡이 막대는 `touch-action:none`이라 히트가 쪽 위에 있으면 그 끌기가 패널 폭을 바꿨다. 목차 손잡이의 히트는 `#left`의 왼쪽 여백 44px 안에서 끝난다. 마우스의 여백과 쪽 폭은 그대로다. 마우스를 좁게 둔 것은 본문 스크롤바를 덮지 않기 위해서다. 넓은 화면의 목차 손잡이도 터치 44px, 마우스 24px이다(`TouchHandleHits`).
- 손잡이는 `touch-action:none`이라 끄는 동안 스크롤과 다투지 않는다. `setPointerCapture`로 손잡이 밖까지 따라간다.
- mid에서는 가운데에 잡는 막대를 그린다.

**끄는 동안.** 누르는 순간 손잡이의 설명(툴팁)을 닫아, 끄는 내내 PDF 위에 남지 않게 한다. 패널 폭만 바꾸고, `body.resizing` 동안에는 ResizeObserver가 다시 맞추지 않는다. 손을 떼면 한 번 `relayout`해 쪽 폭을 다시 맞춘다. 마크·선택 상자는 쪽 안 % 좌표라 저절로 제자리다. 보던 자리는 `topAnchor`로 지킨다.

**접기.** 손잡이를 오른쪽으로 끌어 패널을 접는다(`snapSide`). `wRaw`는 끌기 시작 폭 + (시작 x − 지금 x)이고 한계로 자르지 않는다. 문턱 T는 최소 폭의 절반(내림)이다.

| `wRaw` | 끄는 동안 | 손을 떼면 |
| --- | --- | --- |
| 최소 폭 이상 | 폭이 따라온다(최대까지) | 그 폭 |
| T 이상, 최소 폭 미만 | 폭은 최소에 멈추고 손잡이 막대가 주 색(`--primary`)이 된다 | 최소 폭 |
| T 미만 | 미리 보기: 패널 **내용**이 40% 불투명도(패널 상자가 아니다 — mid에서는 `#bar1`·`#sheet-grip`을 뺀 자식만), 커서 `w-resize`. T 위로 되돌리면 바로 풀린다 | 0.18초에 밀려 나가 접힌다. 저장 폭은 끌기 시작 폭 그대로라 다시 펴면 그 폭이다 |
| T 미만, 작성·편집·답글·위치 다시 잡기 중 | 접는 구역이 없다. 최소에 멈추고 커서 `not-allowed` | 최소 폭, 알림 없음 |

`pointercancel`이면 끌기 전 폭과 상태로 돌아간다. 끌어 접은 뒤에는 뒤따르는 click을 삼킨다(§모바일 레이아웃 유령 클릭). [핀]을 누르는 것은 분명한 뜻이라 작성 중에도 접힌다. 그때 [핀 N]에 작성 중 점(`.c-dot`, 주 색)이 붙고 이름에 '작성 중'이 붙는다. 메모는 숨었을 뿐 사라지지 않았다는 표시다(`draftOpen`).

**접힌 넓은 패널(`wide`).** 넓은 화면에서도 패널을 접을 수 있고, 접으면 이렇게 된다.

- 손잡이가 오른쪽 가장자리의 6px 레일로 남는다. `#left` 옆의 flex 항목이라 본문 스크롤바를 덮지 않는다. 레일을 왼쪽으로 T 넘게 끌면 최소 폭으로 펴지고 그 뒤로는 따라온다. 두 번 클릭(터치는 탭)하면 저장 폭으로 편다.
- 문서 탐색 줄 오른쪽 끝에 `[핀 N ‹]`(`#nav-side`)가 뜬다. 도구 줄의 [핀 N]과 같은 부품이다(열린 핀 수, 보라 검토 대기 알약, 작성 중 점, `aria-expanded`).
- 상태 칩 줄(`#bar2`)은 mid처럼 PDF 영역 오른쪽 아래에 카드로 뜨고, 알림도 그 위 PDF 영역 오른쪽 아래에 뜬다. 도구 줄(`#bar1`)은 패널과 함께 숨는다. 확대는 Ctrl+휠·Ctrl±·Ctrl+0으로 계속 된다. [PDF 재빌드]는 탐색 줄에 올리지 않는다.
- 새 선택, 마크 배지, 알림·`#pin=` 링크, 검토 대기, 글 속 `#N`은 접힌 패널을 편다. 이렇게 편 것은 기억하지 않는다.
- 처음 끌어 접으면 한 번만 안내가 뜬다: '핀 패널은 오른쪽 위 [핀 N] 또는 Ctrl+\ 로 다시 엽니다'.
- 접힘은 기기마다 `pinPrefs.sideClosed`에 기억하고, 폭 저장값(`pinPrefs.side`)은 건드리지 않는다. 부팅할 때 `#pin=` 링크나 쓰던 초안이 있으면 접힌 패널을 편다.

**버튼과 키보드.** 터치는 손잡이를 **탭**하면 좁게 → 보통 → 넓게로 순환한다. 마우스는 **두 번 클릭**해야 순환한다. 한 번 클릭으로 폭이 튀지 않게 하려는 것이다. [더보기] 안에도 '패널 폭' 분절 컨트롤이 있다.

키보드는 WAI-ARIA Window Splitter를 따른다(`gripKey`). 패널이 주 창이고 `aria-valuenow`가 그 폭이다.

| 키 | 펴져 있을 때 | 접혀 있을 때 |
| --- | --- | --- |
| Enter | 접는다 | 저장 폭으로 편다 |
| Space | 좁게 → 보통 → 넓게 순환 | 저장 폭으로 편다 |
| Home / End | 최소 / 최대 폭 | 최소 / 최대 폭으로 편다 |
| ← / → | 16px 넓히기 / 좁히기(최소 아래로는 접지 않는다) | ←는 최소 폭으로 편다 |

접히면 `aria-valuenow=0`, 이름은 '패널 폭 · 접힘'이다. **Ctrl/⌘+\**는 모든 폭에서 패널(`narrow`는 시트)을 펴고 접는다. 입력 칸 안에서는 받지 않는다. 초점이 패널 안에 있을 때 접으면 초점을 [핀 N]으로 옮긴다.

**화면 폭이 바뀔 때.** 접기·펴기로 화면 폭이 바뀌면 저장값은 두고 보이는 폭만 지금 한계 안으로 맞춘다. 다시 넓은 화면으로 가면 저장한 폭이 돌아온다.

**시트 머리.** 시트 위에 붙어 있는 것은 도구 줄 한 줄(52px)과 목록 머리(40px)뿐이다. 도구 줄은 28px 컨트롤을 시트 윗변에서 12px 아래에 두고, 그 아래에도 12px를 둔다(접힌 시트는 그 밑에 아래 안전 영역). 펴진 시트에서 아래 4px, 접힌 시트에서 아래 8px이던 것이 아래로 치우쳐 보여 교차 해상도 점검에서 위아래를 맞췄다. 손잡이(`#sheet-grip`)는 도구 줄 3칸 격자의 가운데 칸(44px)이고, 위 12px 여백 안, 윗변과 컨트롤에서 각각 4px 떨어진 자리에 32×4px 막대(시트 바탕 대비 3:1 이상)를 그린다. 손잡이가 따로 24px 줄을 차지하고 그 히트가 도구 줄 버튼 위 8px를 가로채던 것(머리 129px, 버튼이 36px 높이로만 눌림)을 없앤 배치다. 컨트롤의 히트는 컨트롤 가운데를 중심으로 44px 높이다. 위아래 모두 12px 여백 안에 머문다. 위로는 시트 가장자리 밖으로 나가지 않고(시트가 스크롤 상자라 위로 나간 히트는 잘린다), 아래로는 목록 머리에 닿지 않는다. 36px [⬚]의 히트는 왼쪽으로만 넓혀 손잡이 칸에 들어가지 않는다. 목록 머리 도구는 32px로 그리고 46px 히트가 머리 아래 12px 틈으로 내려간다. 44px에 2px를 더한 것은 시트가 소수 픽셀 자리에 놓일 때 가장자리 한 줄을 잃어도 44px가 남게 하려는 것이다. 도구 줄과 목록 머리 사이의 선은 목록 머리 윗선이다. 시트의 도구 줄 버튼은 늘이지 않는다. 확인은 `PhoneTouchSizes.test_the_sheet_header_is_84px_and_its_handle_and_section_tools_answer_44px`와 `BarChip`이다.

**시트 높이(narrow).** 도구 줄 안의 손잡이(`#sheet-grip`)나 도구 줄(`#bar1`) 전체를 끌면 높이가 바뀐다. 도구 줄의 버튼 위에서 세로로 8px 넘게 움직이면 시트 끌기가 되고 그 버튼의 click은 삼킨다(`#bar1`은 `touch-action: none`). 목록이 맨 위(`scrollTop` 0)일 때 내용을 아래로 끌면 시트가 내려간다(중첩 스크롤 넘기기, `pullDown`). 포인터 스트림은 브라우저가 스크롤을 시작하면 끊기므로 이 경로는 터치 이벤트로 받는다. 끄는 중에 두 번째 손가락이 닿으면 원래 높이로 돌아간다.

손을 떼면 `sheetRelease`가 정한다.

- 화면 25% 아래로 내려놓거나 아래로 튕기면(24px 넘게, 0.5px/ms 이상) 접힌다. 작성·편집·답글 중이면 접지 않고 30%(`SHEET_MIN_F`)에 멈춘다. 쓰던 메모가 시트와 함께 숨지 않게 하려는 것이다.
- 위로 튕기면 다음 높이 단계로 간다.
- 그 밖에는 놓은 높이에 머문다.
- 접힌 시트에서 위로 끌거나 탭하면 펴진다.
- 펴진 시트를 탭하면 낮게(45%) → 보통(64%) → 높게(휴대폰은 화면 − 48px, 태블릿 시트는 화면 − 탐색 줄)로 순환한다. [더보기]에서는 '시트 높이'로 고른다.
- 작성하는 동안 휴대폰 시트는 저장된 높이가 80%보다 낮으면 80%로 올라온다(§패널 정리 작성 패널의 순서). 태블릿 시트는 키보드가 올라와 위치 줄·메모 칸·저장 줄이 들어가지 않을 때만 들어갈 만큼, 60%까지 올라온다. 둘 다 기억하지 않는다.
- 기본 높이는 휴대폰 64%, 태블릿 시트 45%다. 높이는 화면 높이 비율로 휴대폰은 `pinPrefs.sheetF`, 태블릿 시트는 `pinPrefs.sheetFTab`에 따로 기억한다. 접은 폴드에서 고른 높이가 펼친 화면의 기본값을 덮지 않게 하려는 것이다. 휴대폰과 태블릿 시트 사이를 오가면 펴짐·접힘은 그대로이고 높이만 각자의 값으로 바뀐다. 키보드가 올라오면 CSS가 보이는 높이 안으로 줄인다.

### 목록 구획

목록은 구획(`section`) **열린 핀 · 검토 대기 · 완료** 셋으로 나뉜다. 어디서부터 닫힌 핀인지 경계가 보이게 하려는 것이다. 셋이 같은 머리 컴포넌트를 쓴다. 삭제한 핀은 목록에 없고 휴지통에 있다(§휴지통).

목록을 다시 읽을 때 `loadPins()`는 핀과 휴지통을 가져오고, `derivePinLists()`는 한 응답의 열린 핀·검토 대기·완료와 현재 문서의 행을 순수하게 가른다. `applyPinLists()`가 전환 알림, 작성 중인 입력, 화면 갱신을 맡는다. 이미 적용한 새 응답보다 늦게 도착한 옛 응답은 버린다. 핀이나 휴지통 읽기 중 하나라도 실패하면 화면을 부분 갱신하지 않는다. 기다리던 이전 성공 응답은 적용할 수 있고, 자동 동기화는 읽지 못한 `pins_rev`를 다음 폴링에서 다시 확인한다.

**구획 머리.** 폭 전체를 쓰는 한 줄(`.sec-head`)이다. 맨 앞이 접기 버튼(`button.sec-tg`)이고, 그 안에 꺾쇠(`chevron-down`/`chevron-right`) · 이름 · 수 배지가 있다. 예: `⌄ 열린 핀 3`, `› 완료 18`. 열린 핀 머리에는 버튼 뒤에 [다시 읽기]·[나를 부른 핀]·[모든 문서]가 붙는다.

- 접힌 구획 안의 카드로 가야 하면(PDF 표시 누르기, 알림, 글 속 `#N`, [검토 대기 N]) 그 구획을 먼저 펴고, 그 상태도 기억한다.
- `새 N`의 기준(`SEC_SEEN`)은 창마다의 기억이다. 새로고침하면 그때의 목록이 기준이 된다.
- 휴지통을 다른 문서의 핀 행으로 열면 휴지통만 모든 문서를 보인다. 목록의 문서 필터([모든 문서])는 건드리지 않는다.
- 네이티브 버튼이라 클릭·Enter·Space가 같고 `aria-expanded`·`aria-controls`(구획 몸통)를 가진다. 이름 요소(`#list-h`·`#review-h`·`#done-h`)는 이름과 수를 함께 담아, 구획의 `aria-labelledby`가 `열린 핀 3`처럼 읽힌다.
- 접힘 상태는 기기마다 `pinPrefs.sec`에 기억한다. 기본은 열린 핀·검토 대기가 펼침, 완료가 접힘이다.
- **접힌 구획의 `새 N`.** 구획마다 본 적 있는 핀 번호(`SEC_SEEN`)를 든다. 첫 목록을 읽을 때의 번호와, 펼쳐져 있는 동안 그 구획에 있던 번호(모든 문서)다. 접힌 동안 그 밖의 번호가 목록에 오면 머리에 `새 N`(주 색 옅은 배지)이 붙고, 펼치면 사라진다. 모든 문서의 번호를 보므로 문서를 바꿔도 `새`로 치지 않는다. 내가 방금 저장한 핀도 치지 않는다.
- 머리는 `position:sticky`라 스크롤해도 위에 붙어, 지금 어느 구획인지 늘 보인다. 다음 구획이 오면 앞 머리를 밀어낸다. 구획마다 `section`으로 감싼 덕이다.
- compact에서는 `#right`가 스크롤 상자이고 도구 줄이 먼저 위에 붙어 있다. 그래서 JS가 그 높이를 `--stick-top`으로 잰다. 머리와 접기 버튼의 `scroll-margin-top`도 같은 값이다.
- 검토 대기·완료 구획은 비면 머리째 숨긴다. 열린 핀 구획은 늘 있다.

### 보관함

**완료 행은 카드가 아니다.** 테두리·바탕·띠 없이 구분선 하나로 나뉘는 납작한 행이고 글자가 흐리다. 상태는 앞머리 아이콘으로 보인다. 휴지통의 행도 같은 모양이다.

- 첫 줄: 아이콘(완료 `check`, 삭제 `trash-2`) · `#번호` · 줄 범위 · 참조(`close_ref`, 예: PR 번호) · 시각(`MM-DD HH:MM`, 닫은 사람은 설명) · [답글] / [되살리기].
- 완료 행의 [답글]은 카드와 같은 답글 칸을 스레드 안에 연다(§스레드와 검토). 사람이 단 답글은 규칙에 따라 핀을 다시 연다. [다시 열기] 버튼은 없다.
- 둘째 줄(완료): 에이전트 답(`close_reply`) 한 줄이다. 넘치면 말줄임하고 누르면 펼친다. 답이 없으면 '설명 없이 닫힘'이다. 원래 요청 메모는 [원래 요청]을 눌러야 펼쳐진다.
- 둘째 줄(삭제): 그 핀의 메모 한 줄이다. 답이 없으니 그것이 알아볼 단서다.
- 펼친 줄은 자동 동기화로 다시 그려도 남는다.

문서 탭과 '모든 문서' 토글은 열린 목록과 같은 목록 함수(`listDone`·`listDropped`)를 쓴다. 모든 문서를 보면 행에 문서 칩이 붙는다.

### 휴지통

삭제한 핀은 목록이 아니라 휴지통 대화상자(`#trash`)에 있다. 되살릴 일이 드물어 목록을 늘리지 않으려는 것이다. compact에서는 [더보기]와 같은 아래 시트다(§모바일 레이아웃 터치의 도움말).

- **여는 곳.** compact는 [⋯] → `휴지통 N`(`#m-trash`), 데스크톱은 [⋯]가 없어 목록 맨 아래의 흐린 링크 `휴지통 N`(`#trash-link`, 비면 숨김)이다. 글 속 `#12`가 휴지통의 핀이면 그 행으로 연다. 브라우저 알림 `dropped`를 눌러도 연다.
- **행.** 보관함 행과 같다. 첫 줄에 시각 · 지운 사람(`Bob Park 삭제`) · 남은 날(`N일 뒤 지워짐`)이 `·`로 나뉘어 있고, [되살리기]가 있으며, 소유자에게만 [영구 삭제](위험 색)가 붙는다. 휴대폰에서는 두 버튼(`.arc-acts`)이 묶음째 메모 줄의 오른쪽 끝에 와서 행이 두 줄이다. 첫 줄에 우겨 넣으면 [영구 삭제]가 잘리고, 버튼만 한 줄을 차지하면 그 핀의 메모와 떨어진다.
- **삭제는 확인 없이 바로.** [삭제]를 누르면 카드가 그 자리에서 목록에서 빠지고(서버 응답을 기다리지 않는다), `핀 #N 삭제됨 · 휴지통에 30일 보관 · [되돌리기]` 알림이 뜬다. 요청이 실패하면 카드를 되돌린다.
- **영구 삭제는 알림 뒤로 미룬다.** 행이 바로 빠지고 `핀 #N 영구 삭제 · [되돌리기]`가 뜬다. 알림이 사라질 때 요청이 나간다(§알림(토스트)). 확인 대화상자는 없다.
- 휴지통은 모달 대화상자라 바깥이 비활성이 된다. 그래서 알림 상자(`#toasts`)가 열린 모달 대화상자 안으로 옮겨 가고, 닫히면 `<body>`로 돌아온다. 그러지 않으면 [되돌리기]를 누를 수 없다.

## 상태와 표시

### 알림(토스트)

알림은 방금 누른 자리 가까이 뜬다. 화면 구석에 띄우면 `핀 #N 저장됨 · 되돌리기`가 저장 버튼에서 너무 멀어 놓치기 때문이다.

| 레이아웃 | 자리(`placeToasts()`가 재서 `--toast-r`·`--toast-w`·`--toast-b`로 넣는다) |
| --- | --- |
| `wide` | 패널 열 안 오른쪽 아래(열 폭 − 24px, 최대 380px). 작성 중이면 저장·취소 줄(`#c-actions`) 윗변 바로 위. 패널을 접었으면 PDF 영역 오른쪽 아래(스크롤바 안쪽), 떠 있는 상태 칩 위 |
| `mid` | 패널 쪽 오른쪽, 아래 동작 줄(`#bar1`) 윗변 바로 위. 작성 중이면 저장·취소 줄 위, 패널을 접었으면 떠 있는 상태 칩(`#bar2`·`#banner`) 위 |
| `narrow` | 시트 윗변 바로 위(상태 줄이 있으면 그 동작의 히트 위, 변경 보기의 엄지 줄이 있으면 그 위), 화면 폭 − 16px. 시트가 화면의 70% 넘게 덮으면(시트 위에 자리가 없다) 시트 안 아래쪽 — 저장·취소 줄이 보이면 그 위. 화면 위로 올리면 시트의 도구 줄([더보기])을 가리기 때문이다 |

- 터치 기기에서는 알림 몸통이 누름을 뒤로 흘려보내고 버튼만 받는다. 시트 바로 위에 뜬 알림이 PDF 길게 누르기를 가로채지 않게 하려는 것이다.
- 떠 있는 동안 250ms마다 자리를 다시 잰다(`watchToasts`). 작성 패널이 뜨거나 패널을 여닫아도 저장·취소 버튼과 아래 도구 줄을 가리지 않는다.
- 새 알림이 맨 위에 쌓이고, 3개가 넘으면 나머지는 접힌다. 마우스를 올리거나 초점이 들어가면 펼친다. 쌓인 알림 밑에는 `알림 N건 더 보기` 버튼(`#toasts-more`)이 붙고, 누르면 펼친다. 터치에서는 알림 몸통이 탭을 흘려보내 hover가 없으므로 이 버튼이 펼치는 길이다. 3개 이하로 줄면 다시 접는다.
- 6초 뒤 사라지고, 마우스를 올린 동안은 멈춘다. 들어오는 움직임(0.16초)은 `prefers-reduced-motion`에서 꺼진다.

**보내기를 미루는 되돌리기.** 답글, 검토 대기 핀의 [확인], 휴지통의 영구 삭제는 눌러도 곧바로 서버로 가지 않는다(`deferred()`). 알림이 화면에서 사라질 때 보낸다. 6초가 지나거나, [x]를 누르거나, 새 알림에 밀려나거나(6개 초과), 페이지가 숨겨질 때(`visibilitychange`·`pagehide`, `fetch` `keepalive`)다. [되돌리기]를 누르면 아무것도 보내지 않고 글을 입력 칸에, 확인한 카드를 검토 대기 구획에 되돌린다. 알림이 떠 있는 동안에는 에이전트도 다른 사람도 그 변경을 보지 못하므로, 되돌리기가 "보낸 뒤 지우기"가 아니라 "보내지 않기"다. 페이지가 숨겨져 먼저 보낸 경우에는 알림도 함께 없앤다. 취소할 수 없게 된 [되돌리기]가 남아 있으면 취소된 줄 알기 때문이다. 구현은 알림의 `_gone` 고리다. 알림이 자기 동작 버튼이 아닌 이유로 사라지면 한 번 부른다.

모양은 sonner를 따른다.

- 떠 있는 면 하나: `--popover` 바탕, 가는 `--border` 테두리, `--radius-lg`, `--shadow`. 그림자는 떠 있는 면에만 쓴다.
- 앞머리 상태 아이콘: 완료 `circle-check` 초록 · 경고 `triangle-alert` 호박 · 오류 `circle-x` 빨강.
- 제목 한 줄(굵게)과 흐린 설명 한 줄. 글은 첫 ` — `(없으면 첫 ` · `)에서 제목과 설명으로 가른다(`toastSplit`). 예를 들어 알림의 제목은 `핀 #10 · 본문`이다.
- 작은 outline 동작 버튼([되돌리기]·[열기])과 닫기 `x`.
- 색 띠는 없다.

### 상태 표현

상태는 카드 왼쪽의 세로 색 띠가 아니라 점·아이콘과 글자로 가른다.

- 열린 카드: **머리 맨 앞의 작은 점(8px) 색**과 **같은 뜻의 배지**(글자·아이콘).
- 닫힌·삭제한 핀: 흐린 보관함 행의 **앞머리 아이콘**.

> **핵심**
>
> 어느 상태도 색만으로 가르지 않는다. 점도 `aria-label`과 설명 `상태: …`를 가진다.

배지 문구는 뜻이 드러나는 말로 쓴다. `⏳ 처리 중 · ~04:02`·`#20 안`·`일치 100%` 같은 기호와 줄임말은 뜻이 읽히지 않는다.

| 상태 | 점·아이콘 | 글자(배지) | 모양 |
| --- | --- | --- | --- |
| 열림 | 초록 점 `--status-open` | 없음(기본) | 카드 |
| 처리 중(claim) | 호박 점 `--status-claimed`(다크 `#f0b43c`, 라이트 `#b86e00`) | `clock` `처리 중 · …` | 카드 |
| 검토 대기 | 보라 점 `--status-review`(다크 `#b197fc`, 라이트 `#6d28d9`) | `eye` `<작성자>님 확인 필요` | 카드(§스레드와 검토), 검토 대기 구획 |
| 다시 열림 | 초록 점(열림) | `rotate-ccw` `다시 열림`(경고색, 설명에 누가·언제·이유) | 카드 — 스레드의 마지막 닫기·다시 열기 기록이 다시 열기일 때 |
| 위치 잃음 | 경고색 점 `--status-warning` | `triangle-alert` `위치 잃음` | 카드, 테두리도 경고색 |
| 요소 잃음 | 경고색 점 `--status-warning` | `triangle-alert` `요소 잃음` | 카드, 테두리도 경고색. 그림을 다시 그린 뒤 지도에 핀의 요소가 없다(`el_sync`가 `lost`). 마크는 찍은 때 자리에 경고색으로 남고, 목록이 바뀔 때 `#N 요소를 잃었습니다` 알림이 한 번 뜬다. 요소가 옮겨 간 것(`moved`)은 배지가 없다 |
| 질문 | (열림과 같은 점) | `circle-question-mark` `질문`(주 색) | 카드 — 상태가 아니라 종류다 |
| 완료 | `check` 초록 `--status-closed` | 닫은 시각·답 한 줄 | 보관함 행(§보관함) |
| 삭제 | `trash-2` 회색 `--status-dropped` | 메모 한 줄, 남은 날 | 휴지통의 행(§휴지통), 글자가 더 흐리다(`--subtle-foreground`). 글 속 `#N`은 흐린 `#N 삭제된 핀` |

점·아이콘 색은 두 테마 모두 카드·패널 바탕 대비 3:1(비텍스트) 이상이다(3.7–10.0). 흐린 글자는 4.5:1 이상이다(`--subtle-foreground` 다크 5.3 / 라이트 4.8).

배지:

| 배지 | 뜻 | 보일 때 |
| --- | --- | --- |
| `처리 중 · 약 15분 · 20:40쯤` | 에이전트가 견적(`eta_min`)을 넣고 잡았다. 남은 분·시각 모두 5분 단위로 올림 | 견적 안 |
| `예상보다 늦어짐 (+5분)` | 견적을 넘겼다(초과 분, 5분 단위). 경고 색 | 견적 초과 |
| `처리 중 · 20:02부터 (23분째)` | 견적 없이 잡은 claim | 견적 없는 claim |
| `#20 범위 안` · `#20과 같은 범위` · `#20과 일부 겹침` | 다른 열린 핀과 겹침. 같은 범위 > 범위 안(가장 좁은 바깥 핀) > 일부 겹침 순으로 하나. 조사는 숫자 읽기로 가린다(`#2와`, `#20과`) | 겹칠 때. pins.md 번호 칸도 같은 말 |
| `위치 불확실` | 드래그한 글자가 찾은 줄 범위에 90%보다 적게 있다. 그림 문서에서는 드래그가 고른 요소 안에 90%보다 적게 들어 있다. 30% 미만은 경고 색. 설명에 '좌표로 찾음/글자로 찾음/지도로 찾음 · 일치 N%'와 확인할 것 | 90% 미만일 때만(작성 패널의 위치 줄도 같다) |
| `줄 +3 이동` · `위치 잃음` · `수정됨` | 줄 맞춤이 옮김 · 앵커를 잃음 · 저장 뒤 고침 | 그대로 |

처리 중 배지의 시각은 보는 기기의 현지 시각이고 30초마다 다시 센다. 잠금 자동 해제 시각(`claim_until`)은 배지에 쓰지 않고 설명에만 둔다. 배지에 쓰면 그것이 예상 완료 시각으로 읽힌다. 잠금은 안전장치일 뿐이다([api.md](api.md) §처리 중 표시).

### 뜻과 모양

모든 시각적 구분은 뜻이 있어야 하고, 뜻 있는 것은 모두 눈에 갈려야 한다. 이 원칙에서 나온 규칙은 다음과 같다.

| 무엇 | 모양 |
| --- | --- |
| 누르는 참조(`#번호`·줄 범위·`N쪽`·글 속 `#12`·보관함 행의 줄 범위·[원래 요청]·[변경 보기]·[스레드 N]) | 링크 한 벌: 주 색 글자, 쉴 때 밑줄 없음, hover·초점에 실선 밑줄. 흐린 보관함 행에서도 누르는 말만 주 색이다. 회색 글자(작성자·시각·배지 속 `#20과 같은 범위`)는 누를 수 없다. 점선 밑줄은 풀리지 않은 '@말'(`.mention-bad`)만 쓴다 |
| 복사하는 글자(줄 범위 `.loc`) | 같은 링크 모양에 고정폭 글자 + `cursor:copy`, 설명 '누르면 복사' |
| 동작 | 맥락마다 강조 하나(작성 패널 [핀 저장] = default, 카드 [완료] = soft). 위험 동작은 가장 눈에 띄지 않는다(카드 [삭제] = 바탕 없는 위험 색 글자). 끈 버튼은 금지 커서(not-allowed), [핀 저장]의 '저장 대기'는 옅은 주 색 + 진행 커서 |
| 마우스로 누르는 넓이 | 작은 컨트롤(카드 머리의 `N쪽`·답글 수, 마크 배지, 카드 버튼, 구획 머리, 검토 대기 칩)은 그린 크기 그대로 `::after`로 24×24px 이상을 받는다(WCAG 2.5.8, `@media (pointer:fine)`). 터치는 44px다. 글 속 `#12`와 메모 줄 같은 글 안의 링크는 예외다 |
| PDF 쪽 위 마우스 커서 | 십자(`crosshair`) — 끌어서 영역을 고르는 곳이라는 표시. 첫 방문한 마우스 사용자에게는 한 번 'PDF를 끌어서 고칠 곳을 고르세요' 안내가 뜬다(`pinPrefs.coach.mouse`). 터치에는 길게 누르기 안내가 뜬다 |
| 사람 | 사진 또는 머리글자 원(주 색). 나는 이름 뒤 `(나)`(카드 작성자·스레드 글쓴이) |
| 에이전트 | `bot` 아이콘의 흐린 원 — 사람의 원과 가른다 |
| 시각 | 스레드·보관함은 상대 시각(`방금`·`N분 전`·`N시간 전`·`N일 전`, 일주일 넘으면 `M-D`), 절대 시각은 설명에. 60초마다 다시 센다(`tickRel`). 보관함의 시각은 말줄임으로 자르지 않는다 |
| 긴 글 | 스레드 글은 6줄에서 접고 [더 보기] 버튼을 둔다 — 접지 않으면 1,000자 답글 하나가 카드를 화면 몇 개 길이로 늘린다 |
| 검토 대기·완료 카드 | 겹침·위치 확실도 배지(`#N과 같은 범위`·`위치 불확실`)를 숨긴다 — 닫힌 핀은 줄 맞춤을 하지 않아 뜻이 없다 |
| 답글 수(`.th-n`) | 누르면 카드를 펴고 답글 칸을 한 번에 연다(접힌 compact 카드) |
| 검토 대기 수 | 상태 칩은 모든 문서를 센다 — 이 문서와 다르면 `검토 대기 2 (이 문서 1)` |
| 나를 부른 핀 거르기 | 목록 머리에서 `@` 아이콘 + 수(이름은 `aria-label`·설명) — 이름을 글자로 쓰면 좁은 패널에서 머리가 두 줄로 꺾인다 |
| 포커스 | 모든 조작 요소가 같은 `:focus-visible` 링(2px `--ring`). 링은 키보드에만 답한다. 누른 뒤(`html[data-input=pointer]`, `keyNavigates`)에는 스크립트가 옮긴 초점에도 링이 없고, 글자 입력 칸만 어디에 쓰는지 보이려고 링을 둔다. 시트는 열 때 스스로 초점을 받지만 닫을 때 초점을 스크립트로 돌려주고(이동 시트는 [본문 1/2 ▾]로, 도움말은 연 곳으로), 크롬은 마지막 입력을 키로 셌으면 그 초점에 링을 그리며 안드로이드에서는 탭이 그 셈을 풀지 않았다(`SheetCloseFocus`). 설명(툴팁)은 뜻이 글자로 다 드러나지 않는 곳에만 — 알림 닫기 `x`는 `aria-label`만 |

**hover 모양은 마우스에만 있다.** 모든 `:hover` 규칙은 `@media (hover:hover)` 안에 있다. 터치 화면은 누른 컨트롤에 `:hover`를 남기므로, 그러지 않으면 [더보기]에서 누른 행이 회색으로 남는다(`FrontendHoverForMouse`, `PhoneMoreAndHelp`). 접힌 알림 묶음도 터치에서는 hover로 펼치지 않고 초점과 `알림 N건 더 보기`로만 펼친다. 대신 터치에서 누르는 동안만 버튼 면에 글자색 8% 안쪽 그림자가 덮이고(`:active`), 손을 떼면 사라진다.

**같은 사건의 알림은 한 번만 뜬다.** 알림이 오는 길은 둘이다. 하나는 브라우저 알림 경로이고, 탭에 포커스가 있으면 토스트로 뜬다. 다른 하나는 목록 비교 알림(`검토 대기로 넘어왔습니다`·`다시 열림`)이다. 두 길이 같은 핀의 같은 전환을 8초 안에 알리면 브라우저 알림 쪽이 이긴다(`toastDup`, 열쇠 `<이벤트>:<핀>`).

**[변경 보기]의 안내 줄.** 글이 길면 글이 줄바꿈되고 [원고로]·[확인] 버튼은 잘리지 않는다. [확인]은 검토 대기 핀일 때만 있고 카드의 [확인]과 같은 동작이다. 휴대폰·태블릿 시트에서는 두 버튼이 변경 보기 아래쪽 sticky 줄에 붙는다. [변경 보기]를 누를 때 보던 문서를 기억해(`REV_BACK`) 그 문서로 돌아간다. 다른 문서면 버튼이 `<문서 이름>(으)로`라고 말한다. 소스 diff는 늘 줄을 바꿔 보인다. 문단 하나를 한 줄로 쓰는 원고가 흔해, 줄바꿈 없이는 폰에서 diff가 화면 여러 개 폭이 되기 때문이다. 전에 있던 [줄바꿈] 토글과 그 저장값(`pinPrefs.diffWrap`)은 없앴고, 옛 저장값은 부팅할 때 지운다.

## 협업 UI

### 스레드와 검토

핀마다 되묻고 답하는 스레드와, 에이전트가 닫은 핀을 사람이 확인하는 검토 대기를 보이는 화면이다. 데이터와 전환은 [api.md](api.md) §스레드와 §검토 대기가 맡는다.

**작성 패널.** 메모 위에 두 칸 분절 컨트롤 `[수정 요청 | 질문]`(`#c-kind`)이 있다. 기본은 수정 요청이고, 저장하거나 취소하면 되돌아간다. 편집 패널에도 같은 컨트롤이 있다. 질문 카드는 `질문` 배지(주 색 테두리)를 단다.

**종류 권하기.** 수정 요청인데 메모가 질문처럼 읽히면, 메모 칸 바로 밑에 `질문처럼 보입니다 — [질문으로 보내기]` 한 줄(`.q-hint`)이 뜬다. 판정은 `looksQuestion`이 한다.

- 질문으로 보는 끝: `?`·`？`, 또는 한국어 물음 어미 는가·나요·까요·인가·건가·니·냐·까.
- 끝의 마침표·말줄임·괄호와 끝에 붙은 @태그는 보지 않는다.
- 누르면 종류가 질문으로 바뀌고 줄이 사라진다. 스스로 바꾸지는 않는다.
- 누른 뒤 초점은 메모 칸 끝으로 돌아간다. 줄이 사라지며 초점이 `<body>`로 빠지면 Ctrl+Enter가 먹지 않기 때문이다. 작성 패널 안이면 초점이 [수정 요청 | 질문] 같은 버튼에 있어도 Ctrl+Enter로 저장한다.
- 질문이 되거나 글이 질문처럼 읽히지 않게 되면 사라진다.
- 작성·편집 패널 둘 다 적용된다.

분절 컨트롤을 못 보고 질문('…표현한 의도가 있는건가?')을 수정 요청으로 저장하는 일을 막으려는 것이다. 줄을 컨트롤 곁이 아니라 메모 칸 밑에 두는 까닭은 커서 때문이다. 쓰는 도중 `?`를 치는 순간 위쪽에 한 줄이 끼어들면 입력 칸이 밀려 커서가 움직인다. 버튼은 링크 한 벌 모양(주 색 글자, 가리키면 밑줄)이고 상자는 없다.

**스레드.** 메모 아래 점선 뒤에 답글과 전환 기록(닫음·다시 엶·확인)이 한 줄씩 붙는다.

- wide는 뒤 3건, compact는 마지막 1건만 보이고 [이전 N건 보기]로 펼친다.
- 접힌 compact 카드는 스레드를 숨기고 머리에 답글 수(말풍선 아이콘)만 둔다.
- [답글]을 누르면 카드 안에 입력 칸이 열린다. 입력 칸 DOM을 들고 있다가, 5초 자동 동기화가 목록을 다시 그리면 제자리에 다시 끼우고 커서를 돌려놓는다(`REPLY`). 편집 카드(`EDITOR`)도 같다. 자동 동기화나 레이아웃이 바뀌어 카드를 다시 그려도 메모 칸의 초점과 고른 글자가 남는다(`RedrawKeepsTheEditCard`).
- 닫아도 쓰던 글은 남긴다.

**검토 대기 구획(`#sec-review`).** 열린 핀과 완료 사이에 있다.

- 카드 모양은 열린 핀과 같고 머리의 점이 보라다(`--status-review`, 다크 `#b197fc`·라이트 `#6d28d9`, 카드 바탕 대비 7:1 안팎). PDF 마크도 보라다.
- 배지는 `<작성자>님 확인 필요`이고, 내가 작성자면 `내 확인 차례`다.
- 동작은 `[변경 보기] [답글] [확인]`이다. [확인]은 작성자가 볼 때만 강조(`.btn-soft`)한다. 누구나 누를 수 있지만 자연스러운 사람을 권하는 것이다(신뢰 모델). 누르면 카드가 바로 검토 대기 구획에서 빠지고 `핀 #N 확인 · 완료로 옮겼습니다 · [되돌리기]`가 뜬다. 요청은 알림이 사라질 때 나간다(§알림(토스트)). 그사이 누가 핀을 다시 열었으면 `핀 #N 은 이미 다시 열렸습니다`를 알린다.
- [다시 열기] 버튼은 없다. 흐름은 "결과를 본다 → [확인] 또는 [답글]에 틀린 점"이다.

**답글 하나와 결과 한 줄.** 닫힌 핀(검토 대기·완료)의 답글 칸 아래에 보내면 무엇이 되는지 한 줄(`.r-outcome`)이 뜬다. 서버의 순수 규칙(`reopens_on_reply`, [api.md](api.md) §답글이 핀을 다시 여는 규칙 (0.2.2))을 뷰어가 같은 함수(`replyReopens`)로 따라 그린다.

| 경우 | 한 줄 | [상태 유지] |
| --- | --- | --- |
| 사람, 사람을 @태그하지 않음 | 보내면 이 핀이 다시 열려 에이전트에게 갑니다(검토 대기 보라색) | [상태 유지] |
| 위에서 [상태 유지]를 켬 | 보내도 상태는 그대로입니다 | [상태 유지] 눌림 |
| 사람을 @태그함 | 보내면 Bob Park에게 알림이 가고 상태는 그대로입니다 | [다시 열기] |
| 질문 핀 | 답으로 남고 상태는 그대로입니다 | [다시 열기] |
| 신원 없는 화면(에이전트로 기록됨) | 이 화면은 에이전트로 보내므로 상태는 그대로입니다 | [다시 열기] |
| 위 셋에서 [다시 열기]를 켬 | 보내면 이 핀이 다시 열려 에이전트에게 갑니다 | [다시 열기] 눌림 |
| 열린 핀 | 없음(답글은 상태를 바꾸지 않는다) | 없음 |

- 결과를 뒤집는 토글은 하나(`data-act="reply-flip"`)이고 스위치다(`role="switch"`, `aria-checked`, 이름 앞의 작은 트랙과 손잡이, 켜지면 주 색). 이름은 기본값이 아닌 결과이고 터치 높이는 44px이다. 켜도 결과 한 줄은 알림 받을 사람을 함께 말한다(`보내면 이 핀이 다시 열려 에이전트에게 가고, Bob Park에게 알림이 갑니다`). 규칙이 다시 열면 [상태 유지] `reopen:false`, 규칙이 상태를 두면 [다시 열기] `reopen:true`로 이름이 바뀐다. 드물게 쓰므로 기본으로 꺼져 있다. 글에 태그를 더하거나 빼서 규칙의 방향이 바뀌면 다시 꺼진다. 칸을 닫거나 보내면 꺼진다. [다시 열기] 쪽이 있어야 질문 핀·사람을 부른 답글·신원 없는 화면에서도 뷰어로 닫힌 핀을 다시 열 수 있다.
- 자리표시 글은 결과 한 줄과 같은 계산(`replyPlaceholder`)에서 온다. 태그 없는 답글이 핀을 다시 열 때만 `무엇이 틀렸는지 적으면 다시 열려 에이전트에게 갑니다`이고, 그 밖에는 `답글`이다.
- **미리보기와 요청은 한 계산이다.** @태그는 요청이 실제로 싣는 힌트(`mentionHints`, 글에 이름 전체가 남은 자동 완성 선택)로 푼다. 미리보기가 다른 계산을 쓰면 `@Robin Lee`를 고른 뒤 `@Robin`으로 줄였을 때 미리보기는 'Robin Lee에게 알림'인데 서버는 겹치는 이름이라 아무도 부르지 않고 핀을 다시 연다. 메모·편집 칸의 알림 미리보기도 같은 힌트를 쓴다.
- 보낸 뒤 서버의 결정이 미리보기와 다르면(알림이 떠 있는 동안 다른 사람의 답글이 먼저 다시 열었을 때 등) 응답의 `reopened`·`state`로 한 줄 알린다(`replyServerNote`).
- 보내기가 실패하면(오프라인) 답글 칸이 글과 토글 상태 그대로 다시 열리고, 칸 안에 오류 한 줄(`.r-err`)이 뜬다.
- Ctrl+Enter로 보내면 초점이 알림의 [되돌리기]로 간다. Enter로 되돌릴 수 있다.
- 보내면 칸이 바로 닫히고 되돌리기 알림(`핀 #N 다시 열어 에이전트에게 보냄` 또는 `#N 에 답글을 남겼습니다`)이 뜬다. 요청은 알림이 사라질 때 나간다(§알림(토스트)). [되돌리기]는 글과 [상태 유지] 상태를 칸에 되돌린다.
- @태그 미리보기(`알림 Bob Park`)는 그 위 한 줄에 있다.

**수.** 휴대폰·태블릿 시트는 도구 줄 칩의 보라 반쪽 `[검토 M]`(`#btn-rv`, 누르면 구획으로), 펼친 화면·짧은 화면도 같은 칩의 `[검토 M]`, 데스크톱이 패널을 접었을 때는 `[핀 N ‹]` 옆의 보라 알약 `👁 M`(`#side-rv`), wide는 상태 칩 줄의 `검토 대기 N`(`#rv-chip`, 누르면 구획으로)이다. 문서를 가로질러 센다. 탭 제목에는 `· 검토 M`이 붙는다.

**신원이 없는 화면.** 로컬 `127.0.0.1`이나 SSH 포워딩처럼 이 화면에 신원이 없으면, [완료]도 에이전트 닫기로 쳐서 검토 대기가 된다. 알림에 그렇게 밝힌다.

### 변경 보기

검토 대기 카드와 완료 행의 [변경 보기]가 변경사항 탭을 그 핀에 맞춰 연다. 커밋은 최근 12개 안에서 아래 순서로 고른다.

| 단계 | 고르는 커밋(최근 12개 안) |
| --- | --- |
| 1 | 닫을 때 남긴 참조(`close_ref`)의 7–40자리 해시 앞부분(`PR #235 (f47c6bf)`) |
| 2 | 참조의 PR 번호가 제목에 든 커밋 — 스쿼시 `(#236)`, 머지 `Merge pull request #236` |
| 3 | 핀 파일의 핀 줄 ±5줄을 바꾼 가장 최근 커밋(커밋마다 소스 diff를 받아 hunk로 판정) |
| 4 | 가장 최근 커밋 |

- 줄 대응은 **소스 diff에만** 있다. 그래서 바로 [소스 diff]로 열고, 핀 파일(경로 끝 일치)을 고른다. 새 쪽 줄 번호가 핀 범위에 드는 줄을 보라로 강조해 가운데로 스크롤한다. 머리 아래 안내 줄(`#revision-pin`)이 어느 규칙으로 골랐는지와 [원고로]를 보인다. Esc도 [원고로]와 같다(겹친 패널이 열려 있으면 패널을 먼저 접는다).
- 비교 PDF(latexdiff)에는 SyncTeX 대응이 없다. 그 탭을 누를 때 만들고, 핀의 쪽 근처로만 옮기며 '대략'이라고 적는다.
- 휴대폰에서는 `[본문 3/25 ▾]` → 이동 시트의 `[원고 | 변경사항]`으로 열고 닫는다. 핀에서 열었으면 안내 줄의 [원고로]도 돌아가는 길이다. 휴대폰·태블릿 시트에서는 안내 줄의 [원고로]·[확인]이 아래 엄지 줄에 붙는다.

**핀의 변경만.** 한 커밋이 핀 여럿을 고쳤으면 [변경 보기]는 그 핀의 hunk만 보인다. 어느 hunk가 그 핀의 것인지는 서버가 정한다([api.md](api.md) §핀 단위 변경 보기). 결정 단계를 늘리지 않는다. 새 대화상자는 없고, 컨트롤은 아래 두 개뿐이다.

- **소스 diff.** 핀의 hunk만 보이고 그 아래에 `이 커밋의 다른 변경 N곳 ▸`(`#revision-other-toggle`, `aria-expanded`)가 접혀 있다. 누르면 같은 자리에서 나머지 hunk(`#revision-other`)가 펼쳐지고, 다시 누르면 접힌다. 다른 핀으로 [변경 보기]를 다시 열면 접힌 채 시작한다. 펼친 diff도 같은 줄바꿈·색 규칙을 따른다. 줄 번호는 커밋의 실제 번호라 핀 범위 강조가 그대로 맞는다. 안내 줄에 `이 핀의 변경 N곳만 보입니다(에이전트가 기록한 줄 | 핀 자리로 추정)` 가 붙는다.
- **비교 PDF.** 옛 판에 핀의 hunk만 넣은 합성 판과 비교한다. 상태 줄이 `핀 #N의 변경만 · 첫 부모 …` 로 시작하고, 컨트롤 줄에 토글 `[커밋 전체 비교]`(`#revision-whole`, `aria-pressed`)가 생긴다. 켜면 커밋 전체 비교, 끄면 다시 핀의 것만이다. 두 비교는 각각 캐시되어 다시 누를 때는 빌드하지 않는다. 쪽 근처로만 옮긴다는 '대략' 안내는 그대로다.
- 핀의 hunk만으로 컴파일이 안 되면 커밋 전체 비교로 넘어가고 상태 줄에 `이 핀의 변경만으로는 비교 PDF를 만들지 못해 커밋 전체를 비교합니다` 를 붙인다. 이때 토글은 숨긴다.
- 핀 단위 보기는 [변경 보기]가 그 핀에 골라 준 커밋에서만이다. 목록(`#revision-select`)에서 다른 커밋을 고르면 그 커밋을 통째로 보이고(`pin` 없이 요청), 두 컨트롤도 없다. 핀의 커밋으로 돌아오면 다시 핀 단위다(`revisionPinFor`).
- 커밋 전체가 그 핀의 것이거나(핀별 커밋), 핀의 것을 하나도 고르지 못했으면 커밋 전체를 보이고 두 컨트롤도 없다.
- 터치에서 두 컨트롤은 다른 버튼처럼 44px다. 폰 폭에서는 [커밋 전체 비교]가 들어오면 컨트롤 줄이 두 줄로 꺾인다.

**검토는 여기서 끝난다.** 검토 대기 핀에서 열었으면 안내 줄에 [확인]이 있다. 카드와 같은 `data-act="confirm"`이고 같은 알림·되돌리기다. 누르면 확인하고 [원고로]와 같은 문서로 돌아간다.

할 수 없는 것도 있다.

- 닫힌 핀은 줄 맞춤을 하지 않는다. 그래서 닫은 뒤 원고가 크게 바뀌면 강조가 빗나갈 수 있다. 못 찾으면 그렇게 적는다.
- 최근 12개 밖의 커밋, 아직 머지 안 된 PR 브랜치의 커밋, 미커밋 수정은 볼 수 없다.
- 보기 전용 PDF 문서와 Git 저장소가 아닌 문서는 탭을 열고 그 이유를 한 줄 적는다. 쓸 수 없는 `[변경 PDF] [소스 diff]`와 비교 안내 줄은 숨긴다. 최근 변경이 없을 때도 같다.

좁은 화면과 터치에서는 다음을 지킨다.

- 핀 패널이 본문 위에 겹쳐 뜨는 대역(`mid-overlay`, 900px 이하의 `short`)에서는 변경사항 보기가 패널 폭(`--side-w`)만큼 오른쪽을 비운다. 본문 PDF와 달리 diff는 옆으로 밀어 볼 수 없어, 줄바꿈한 글의 오른쪽과 안내 줄의 [원고로]가 패널 밑에 가려지기 때문이다.
- 터치에서 커밋 고르기(`#revision-list select`)·파일 고르기와 [빌드 경고 보기]는 44px다.
- 핀 범위 줄이 diff에 없고 곁(±5줄)만 바뀌었으면 안내 줄이 그렇게 말한다(`tg.near`). 강조한 줄이 없는데 '강조한 줄이 핀 범위입니다'라고 하지 않으려는 것이다.
- 안내 줄의 `참조 PR #240`은 누를 수 없는 회색 글이고(링크 한 벌 규칙), 누르는 것은 [원고로] 하나다.

### @태그

**사람 목록.** 메모·편집·답글 칸에서 `@`를 치면 사람 목록(`#mention-pop`)이 뜬다. 최대 6명이고 나는 뺀다. 자리는 그 칸의 동작 줄을 가리지 않게 고른다(`mentionTop`). 동작 줄은 답글·다시 열기의 [취소][보내기], 편집의 [저장], 작성 패널의 [핀 저장]이다. 고르는 순서는 다음과 같다.

1. 입력 칸 바로 아래에 동작 줄 전까지 들어가면 아래.
2. 아니면 입력 칸 위.
3. 위에도 자리가 없으면 동작 줄 아래.
4. 어디에도 안 들어가면 입력 칸 아래를 화면 안으로 당긴다.

답글 칸은 두 버튼이 입력 칸 바로 밑이라 위로 뜬다. 아래로 뜨면 고르는 동안 [취소][보내기]를 덮기 때문이다.

- 고른 줄은 목록 폭 전체의 납작한 띠(`--accent`, 모서리 없음 — shadcn Command 모양)다. 틀 안에 또 둥근 상자를 두지 않는다(§한 겹 담기).
- ↑/↓로 움직이고 Enter/Tab으로 고르고 Esc로 닫는다. Esc는 선택 취소보다 먼저 받는다(window capture).
- 목록을 눌러도 입력 칸 포커스를 뺏지 않는다. 고르면 `@이름 `을 넣는다.

**태그 토큰.** 글 속의 풀린 `@이름`(그 글의 `mentions`에 든 사람)은 **태그 토큰**이다. Slack·GitHub처럼 주 색 글자에 옅은 주 색 틴트 알약(`.mention`)을 입히고, 설명은 `@태그 — <이름>에게 알림이 갑니다`다. 지금 신원을 부른 태그는 한 단계 진한 틴트(`.mention.me`, 설명 `나를 부름`)다. 메모, 스레드 글, 접힌 카드 요약(`.sum`), 보관함의 답 한 줄, 원래 요청, 삭제한 핀 메모에 똑같이 적용한다. 풀리지 않은 `@말`은 평문 그대로다. 부른 것처럼 보이면 안 되기 때문이다.

**찾는 규칙.** 서버 `resolve_mentions()`가 정본이고 뷰어는 그것을 한 단계씩 따라 한다. 미리 보기 줄·답글 결과·담당 고르기가 쓰는 `mentionScan()`과 후보 목록 `mentionTokens()`는 서버의 `mention_hits()`·`mention_tokens()`와 같은 순서로 판단한다. 같은 말뭉치를 양쪽에 돌려 결과가 같은지 [`src/limn/viewer/tests/test_mentions_parity.py`](../../src/limn/viewer/tests/test_mentions_parity.py)가 확인한다.

- 이름 전체, 로그인, 로그인의 `@` 앞, 이름 첫 단어(이름이 두 단어 이상일 때)를 본다. 두 글자(코드 포인트) 미만은 후보가 아니다.
- 긴 것부터, 대소문자 없이 찾는다.
- 한 사람의 후보가 소문자로 겹치면(이름 `Bob`, 로그인 `bob@example.com`) 한 후보다. 여러 사람이 나눠 가진 후보만 힌트(자동 완성으로 고른 사람)가 있어야 풀린다.
- `@` 앞이 어느 문자든 글자·숫자이거나 `._-`면(메일 주소, 단어 속) 건너뛴다(`mentionAfterWord`). 서버의 `str.isalnum()`과 같게 유니코드 글자·숫자를 모두 보고(`é@`, `김@`), astral 글자는 UTF-16 두 단위를 한 글자로 읽는다. 자동 완성(`mentionQuery`)과 태그 토큰(`fmtText`)도 같은 판단을 쓴다.
- 영문으로 끝나는 이름 뒤에 영문·숫자·밑줄이 이어지면 다른 말로 본다.

글은 먼저 `esc()`를 거치고, 토큰은 이스케이프된 글에서 감싼다. 자리표로 바꿔 겹쳐 감싸지 않는다. 그래서 사람이 쓴 글이 HTML로 새지 않는다.

**입력 중 미리 보기.** textarea 안은 색을 칠할 수 없다. 그래서 메모·편집·답글 칸 바로 아래 한 줄(`.m-preview`, `#note-mentions`)에 두 가지를 보인다. 저장하면 알림이 갈 사람(`@ 알림  Bob Park`)과, 풀리지 않을 `@말`(점선 밑줄, `등록된 사람이 아님`)이다. 저장 전에 부른 것이 실제로 알림이 되는지 알 수 있다.

- 미리 보기는 저장·보내기가 실어 보내는 힌트(`mentionHints`)로 푼다. 그래서 줄에 뜬 사람이 곧 서버가 적을 사람이다.
- 쓰는 중인 `@말`(커서가 그 끝에 있다)은 아직 알리지 않는다. 커서가 떠나거나(방향키·누르기) 칸을 벗어나면 알린다(`mentionBadSettled`). `@Sa`를 치며 목록에서 고르는 동안 경고가 먼저 뜨지 않게 하려는 것이다. JS 조각의 주석 끝에 코드 문장이 붙지 않았는지 [`src/limn/viewer/tests/test_viewer_source.py`](../../src/limn/viewer/tests/test_viewer_source.py)가 확인한다.
- 나를 쓴 태그는 `(나 — 알림 없음)`이다.

**`#번호` 링크.** 글 속 `#12`는 그 핀이 있으면(열림·검토 대기·완료·삭제) 링크(`.pin-ref`, 링크 한 벌)다. 누르면 그 카드나 보관함 행을 펴고 스크롤해 반짝인다. 다른 문서면 '모든 문서'를 켠다. 없는 번호와 `&#39;` 같은 이스케이프는 건드리지 않는다.

**부름 배지.** 사람을 부른 카드에는 `나를 부름`·`@이름` 배지가 붙는다. 담당이 적히지 않은 옛 핀에 쓴다.

### 담당

'누가 처리하나'를 글에서 짐작하지 않고 명시 값 `assignee`로 둔다([api.md](api.md) §@태그·사람·이벤트). 글만 보면 사람에게 맡긴 수정 요청(`… @Bob Park 확인 부탁합니다`)도 `참고 @Bob Park`로 떠, 에이전트가 자기 일로 읽기 때문이다.

**작성 패널.** 메모에 풀린 @태그가 하나라도 있으면 알림 줄 아래에 `담당  [에이전트 | @Bob Park | …]` 분절 컨트롤(`#c-assign`)이 뜬다. 태그된 사람마다 한 칸이고, 나는 빠진다. @태그가 없으면 컨트롤이 없다(에이전트).

- 기본값(`defaultAssignee`): 메모가 풀린 @태그로 **시작**하면 그 사람, 아니면 질문 핀의 첫 @태그, 아니면 에이전트.
- 컨트롤의 사람과 기본값은 저장이 실어 보내는 힌트(`mentionHints`)로 푼 @태그에서 고른다(작성 패널·편집 모두).
- 고르기 전에는 메모가 바뀔 때마다 기본값을 다시 고른다.
- 고른 뒤에는 그 사람이 메모에서 빠질 때만 기본값으로 돌아간다.

**카드.** 담당이 사람이면 머리에 `담당 @이름` 칩이 붙는다. 나면 `담당 나`이고 한 단계 진한 틴트다. 에이전트는 기본이라 칩이 없다. 작성자(또는 신원 없는 로컬 화면)는 칩을 눌러 [수정]을 열고 같은 컨트롤로 바꾼다. 바뀌면 스레드에 `담당 바꿈` 한 줄이 남는다.

**에이전트와 알림.** 담당이 사람이면 에이전트가 건너뛰고(`→ @이름`) 그 사람에게 `assigned` 알림이 간다. 알림 순위는 담당 > 부름 > 다시 엶 > 검토 대기 > 답글이다. 담당이 에이전트면 @태그는 참고(`참고 @이름`)다. 어느 쪽이든 태그된 사람에게 부름 알림은 간다.

**나를 부른 핀.** 목록 머리의 [나를 부른 핀 N] 토글(`#mention-filter`)은 지금 신원을 부른 열린·검토 대기 핀만 모든 문서에서 보인다. 없으면 숨는다. 로컬 신원에는 뜨지 않는다.

### 브라우저 알림

탭이 살아 있는 동안만 쓰는 1단계 알림이다. 웹 푸시, 바깥 서비스, 새 의존성은 없다.

**켜기(기기마다).** 데스크톱 도구 줄의 벨(`#btn-notify`)과 [더보기]의 `브라우저 알림` 스위치(`#m-notify`, `role=switch`)로 켠다. `Notification.requestPermission()`은 이 클릭에서만 부른다. 켠 여부는 `pinPrefs.notify`(localStorage)에 둔다. 상태 표시는 다섯 가지다.

- `켜짐`
- `꺼짐`
- `브라우저에서 차단됨`: 주소창 자물쇠 → 알림 → 허용을 안내한다.
- `이 주소에서는 안 됨`
- `테일넷 주소에서만`: 로컬 신원일 때다(아래).

**로컬 신원은 켤 수 없다.** 테일넷 로그인 없이(`127.0.0.1` 직접 접속 등) 연 탭에는 서버가 이벤트를 아예 싣지 않는다([api.md](api.md) §@태그·사람·이벤트, `events_since`). 그래서 알림이 영영 오지 않는다. 벨과 스위치를 비활성(`disabled`)으로 두고, 스위치 아래 흐린 한 줄과 벨의 설명이 '테일넷 주소로 열면 켤 수 있습니다'라고 말한다. 차단됨·지원 안 됨도 같은 자리에 이유를 쓴다. 브라우저 권한을 얻어도 소용없는 상태를 숨기지 않으려는 것이다.

**보안 컨텍스트.** 서비스 워커와 알림은 https(테일넷 `*.ts.net` 주소)와 `http://127.0.0.1`·`localhost`에서만 된다. 다른 호스트의 plain http(예: LAN IP)는 브라우저가 막는다.

**흐름.** 5초 폴링(`pollLight`)이 `ev=<커서>`를 붙여 나에게 온 이벤트를 받는다([api.md](api.md) §브라우저 알림 커서). 커서(`pinNotifyCursor`)는 브라우저의 localStorage에 있다. 그래서 새로고침하거나 탭을 두 개 열어도 같은 이벤트를 다시 알리지 않는다. 처음 켜면 지금 `ev_seq`부터 센다. 지난 일을 몰아 알리지 않기 위해서다.

**무엇을 알리나.**

- 나를 부름(`mention`)
- 내 핀이 검토 대기로 옴(`review_requested`)
- 내가 쓰거나 불린 핀의 답글(`replied`)
- 내 핀이 다시 열림(`reopened`)
- 누가 내 핀을 지움(`dropped`). 탭이 보이면 [되살리기]를 단 경고 알림이다. 브라우저 알림에도 [되살리기] 동작이 붙어(서비스 워커가 탭에 넘긴다), 본문을 누르면 휴지통의 그 행이 열린다. `viewer` 역할이면 [되살리기] 대신 [열기]다

내가 한 일은 알리지 않는다. 서버의 `to`와 뷰어가 둘 다 거른다. 한 번 받은 묶음 안에서는 핀마다 하나만 알린다(삭제 > 담당 > 부름 > 다시 엶 > 검토 대기 > 답글).

**보이기.** 늘 서비스 워커의 `registration.showNotification()`을 쓴다. 안드로이드 크롬은 페이지의 `new Notification()`을 막기 때문이다. 서비스 워커는 [`src/limn/viewer/sw.js`](../../src/limn/viewer/sw.js) 한 파일이고, 서버가 시작할 때 `service_worker()`로 읽어 `GET /sw.js`로 따로 내준다. 페이지 조각이 아니라 `parts.txt`에 없다. `fetch` 처리기가 없어 앱 데이터와 쪽 그림을 캐시하지 않는다.

- `tag` = `pin-<번호>`라 같은 핀의 알림은 한 칸으로 겹친다. 에이전트가 답글과 닫기를 5초 틈을 두고 하면 두 번 오지만, 화면에는 나중 것(`검토 대기`)만 남는다.
- 제목은 `핀 #N · <문서 이름>`이다.
- 본문은 `Bob Park님이 불렀습니다: <80자>`(부른 사람의 `name` 그대로 + '님') 또는 `검토 대기: <답 첫 줄>`이다.
- 아이콘은 180px 앱 아이콘 PNG(`apple-touch-icon`, 뼈종이)다. 없으면 첫 파비콘이다. 안드로이드 알림은 SVG 아이콘을 그리지 않는다.
- 탭이 보이고 포커스가 있으면 알림 대신 토스트([열기])를 띄운다.
- 탭이 **숨어** 있어도 알림이 켜져 있으면 느린(20초) 이벤트 전용 폴링이 계속 돈다. 이 폴링은 목록을 다시 그리지 않는다.

**누르면.** 서비스 워커가 열린 뷰어 탭을 앞으로 가져와 `postMessage`로 그 핀을 연다. 탭이 없으면 `/#doc=<키>&pin=<번호>`로 새로 연다. `dropped` 알림의 [되살리기]를 눌렀는데 탭이 없으면 `&act=restore`가 붙는다. 부팅은 해시의 `doc=`·`pin=`·`act=`를 **맨 먼저** 읽는다. 해시를 먼저 `#doc=<키>`로 고쳐 쓰면 `pin=`을 잃기 때문이다. 읽은 뒤 곧바로 주소에서 `pin=`·`act=`를 지운다. 새로고침한 `act=restore` 링크가 그사이 다시 지운 핀을 또 되살리지 않게 하려는 것이다. 그다음 그 문서로 바꿔 핀을 되살린 뒤(`act=restore`, `viewer` 역할 제외) 카드를 펴서 보인다. 해시는 그다음 `#doc=<키>`로 줄어든다.

**검증.** 브라우저 테스트는 Playwright 새 헤드리스(`channel="chromium"`)로 돈다. 헤드리스 셸은 권한을 주어도 `Notification.permission`이 `denied`이기 때문이다. 실기기 안드로이드·iOS에서는 확인하지 않는다. iOS는 홈 화면에 추가한 웹앱에서만 알림을 준다.

## 여러 문서 전환

논문 저장소 하나에는 본문·답변서·커버레터·하이라이트처럼 문서가 여럿 있다. **논문 저장소마다 뷰어 하나·주소 하나**를 두고 그 안에서 문서를 전환한다. 이 결정의 근거와 서버 쪽 규칙(핀 저장소, 문서별 빌드 폴더, 보기 전용 PDF)은 [domain.md](domain.md) §여러 문서가 맡는다. 여기서는 뷰어가 문서를 어떻게 전환해 보이는지만 다룬다.

| 화면 | 전환 수단 |
| --- | --- |
| 데스크톱·펼친 폴드(`wide`·`mid`) | PDF 영역 위의 낮은 줄에서 인라인 문서 링크와 `원고`/`변경사항` 보기를 고른다. `목차`는 PDF.js에 실제 outline이 있을 때 왼쪽에 펼쳐 쪽으로 이동한다. 쪽·확대·재빌드 도구는 기존 오른쪽 패널에 둔다 |
| 휴대폰(`phone`) | 도구 줄의 `[본문 3/25 ▾]` → 이동 시트의 문서 목록(이름·경로·핀 수·보기 전용 `PDF`·그림 문서 `그림`). 고르면 그 문서로 바꾸고 시트가 닫힌다. 바깥 누르기, 아래로 시트 높이의 35% 넘게 끌기나 튕기기, 뒤로 가기·Esc·[닫기]로 닫힌다. 탐색 줄은 없다 |
| 문서 하나 | 문서 선택기·문서 버튼·'모든 문서' 토글이 숨는다. 데스크톱의 보기 전환과 목차는 쓸 수 있다 |

**전환이 즉각적이어야 한다.** meta를 문서별로 캐시해, 기다리지 않고 바로 그린다. 뒤에서 최신 meta를 받아 빌드가 바뀌었으면 그 응답으로 쪽만 바꾼다. 이전 전환에서 시작한 새로고침·상태 폴링·재빌드 응답은 같은 문서로 다시 돌아왔더라도 현재 화면과 버전 기준을 덮지 않는다. 다른 문서 핀의 [보기]·[수정]이나 [변경 보기]도 시작한 전환이 끝나기 전 떠났다가 돌아오면 옛 동작을 이어서 실행하지 않는다. 선택·초안·위치 다시 잡기 배너·작성 패널의 원문 조각·변경 보기 PDF의 비동기 응답은 요청을 시작한 문서 방문과 그때의 화면 객체가 여전히 현재 것일 때만 해당 화면을 바꾼다. 저장·수정·삭제 요청의 서버 결과는 현재 문서와 관계없이 알리고 핀 목록을 다시 읽는다. 문서를 바꿔도 남는 같은 편집 카드에는 수정·위치 변경 응답의 새 개정 번호와 위치, 요청한 범위의 원문 조각을 반영해 다음 저장이 낡은 개정 번호를 보내지 않게 한다. PDF.js 문서 객체는 `문서|빌드`로 최근 3개만 들고 있다. 넘치면 오래 안 쓴 것부터 닫는다(워커 메모리). 되돌아올 때는 PDF를 다시 받지 않고, 보이는 쪽만 벡터로 다시 그린다.

**화면 상태의 소유자.** `DOC`와 `SWITCHSEQ`가 현재 문서 방문을 나타내고, 비동기 화면 작업은 그 둘을 직접 비교하거나 `captureVisit()`·`currentVisit()`으로 방문을 확인한다. `composer.js`의 `COMPOSE`는 작성 패널의 선택·PDF 상자·위치 찾기·저장 대기·저장 중·겹침 안내 선택을 함께 맡는다. 저장 응답은 `composeOwns()`로 요청 당시 문서 방문과 선택·상자가 여전히 현재 것인지 확인한 뒤 작성 패널을 비운다. 그림 pick이 고른 요소(`COMPOSE.current.elSel`)는 선택의 일부라 선택과 함께 거둬지고, `renderComposer()`가 대기 상자를 그 요소 자리에 맞춘다. 그래서 새 소유자나 요청 번호가 없다. 다른 문서로 옮긴 뒤 도착한 그림 pick 응답은 `PICKSEQ`로 버린다. 선택과 핀 위치 다시 잡기는 PDF 드래그를 한 번에 하나만 맡는다. 위치 다시 잡기를 시작할 때 아직 위치를 찾는 선택·저장 대기·상자와 실패한 위치 찾기 패널은 거두고 메모 글은 초안으로 남긴다. 이미 완료된 작성 패널의 선택은 위치 다시 잡기를 취소해도 남는다. 작성 패널을 취소하면 진행 중인 위치 다시 잡기도 거둔다. 두 작업의 요청 번호 `PICKSEQ`는 이 전환에서 이전 응답을 함께 무효화한다. 편집 카드와 저장 중 여부는 `edit.js`의 `EDITOR`가 맡는다. 저장하지 않은 편집 카드는 문서를 바꿔도 남으므로, 저장 응답은 `editorOwns()`로 원래 카드가 현재 카드인지 확인해 반영한다. 새 카드를 열거나 취소해 소유자가 바뀌었으면 그 응답은 카드를 건드리지 않는다. 초안의 문서별 저장 열쇠·쓰기 타이머·문서별 되돌리기 보류는 `draft.js`의 `DRAFT`가 맡는다. 빌드 칩의 폴링 타이머·진행 중 요청·현재 문서의 완료 번호와 오류는 `build-chip.js`의 `BUILD`가 맡고, 문서가 바뀌면 `resetBuildForDoc()`이 그 문서의 기준으로 재설정한다. 변경 보기의 선택 커밋·소스·요청 번호는 `revisions.js`의 `REV`가 맡으며, 비교 PDF의 로딩 작업과 범위 토글은 각각 `REV_PDF`와 `REV_SCOPE`가 맡는다. 이 객체들은 탭 안의 화면 상태만 담고 저장 형식이나 API 본문에 들어가지 않는다.

**문서마다 보던 자리와 확대를 기억한다.** 기억하는 것은 위쪽 기준 쪽·비율, 쪽 폭, compact의 손 확대 여부, 가로 스크롤이다. 같은 레이아웃에서 본 폭만 되살린다. 접은 화면에서 맞춘 폭이 데스크톱에 가지 않게 하려는 것이다. 새로고침에도 남게 `sessionStorage`에 둔다.

**주소.** `#doc=<키>`로 링크를 공유하고 새로고침한다. 처음 볼 문서는 해시 → 이 기기의 마지막 문서(localStorage) → 첫 문서 순으로 정한다.

**키보드.** Ctrl+PgUp/PgDn은 이전·다음 문서, Alt+1…9는 번호로 고르기다. Alt+숫자는 `e.code`로 읽는다. 맥의 Option+숫자는 다른 글자를 내기 때문이다. 문서 선택기는 기본 키보드 조작을 쓴다. 입력 칸에서는 전역 단축키가 동작하지 않는다.

**사이드바.** 기본은 지금 문서의 핀이다. '모든 문서' 토글을 켜면 전부 보이고 카드에 문서 칩이 붙는다. 다른 문서 카드의 `#번호`·[보기]·[수정]은 그 문서로 바꾼 뒤 그 자리로 간다. `jumpPin`·`openEdit`이 맨 앞에서 `viaDoc`을 거친다. 마크·겹침 배너·편집은 지금 문서의 핀(`PINS`)만 본다. 쪽 좌표는 그 문서의 PDF에서만 뜻이 있기 때문이다.

**빌드.** [PDF 재빌드]는 지금 문서만 빌드한다. LaTeX 문서가 아니면(보기 전용 PDF, 그림 문서) 숨긴다. 숨김은 `/api/meta`의 문서 종류(`kind`)로 정하고 `body.no-rebuild`가 맡는다. compact에서는 상태 줄의 [재빌드]와 [⋯]의 `PDF 재빌드` 행이 같은 규칙으로 숨는다. 두 문서는 파일이 바뀌면 저절로 다시 그리고, 알림은 'PDF가 바뀌어 쪽을 새로 그렸습니다'다. 다른 문서가 낡았거나 빌드 중이면 선택기에 표시한다. 뒤에서 빌드가 끝나면 알림에 [열기]를 붙인다(`build_seq`를 문서별로 센다).

**변경사항.** 선택한 메인 `.tex`가 있는 폴더 아래의 `.tex`·`.bib`·`.sty`·`.cls`·`.bst` 파일에 손댄 최근 Git 커밋 12개를 보여 준다.

- 빌드 루트가 같은 문서라도 메인 파일 폴더가 다르면 이력이 섞이지 않는다.
- 첫 화면은 가장 최근 커밋의 실제 patch다. 커밋과 파일을 고를 수 있다.
- API는 현재 목록에 나온 40자리 커밋 ID만 받고, diff는 256 KiB에서 자른다.
- 별도 작업 트리의 미커밋 수정과 보기 전용 PDF의 바이너리 변경은 표시하지 않는다.

**전환할 때 거두는 것.** 쓰던 선택과 위치 다시 잡기는 거둔다. 떠나는 문서의 메모와 선택은 그 문서의 초안에 남기고, 화면에는 도착한 문서의 초안만 놓는다. 저장 안 한 편집은 닫지 않고 그 카드를 목록에 남긴다. 이전 전환을 기다리던 검토 핀 이동·알림 링크·위치 다시 잡기는 같은 문서로 돌아왔어도 실행하지 않는다. 알림 링크의 핀 읽기나 되살리기를 기다리는 사이 다른 문서로 옮겼을 때도 남은 화면 이동은 실행하지 않는다. 핀이나 휴지통 읽기가 실패해 이전 목록만 남았으면 링크를 열거나 되살리지 않는다.

## 디자인 토큰과 컴포넌트

색·radius·글자·간격은 [shadcn/ui](https://ui.shadcn.com)의 **체계(토큰 이름·역할·변형 이름)만** 빌린 한 벌의 토큰으로 쓴다. 같은 역할의 버튼과 배지가 곳마다 조금씩 달라지지 않게 하려는 것이다. React·Tailwind·빌드 단계·CDN은 없다. CSS는 `src/limn/viewer/css/` 조각을 이은 인라인 `<style>` 하나이고(§뷰어 규칙을 바꿀 때), 배포는 패키지 설치뿐이다.

### 토큰

테마 색 리터럴은 **두 테마 블록**(`:root` = 다크, `:root[data-theme=light]` = 라이트) 안의 변수 정의에만 있다. 테마와 무관한 색 — 브랜드 색 `--limn-*`과 이름표 위 글자 `--brand-foreground` — 은 세 번째 척도 블록에만 있다. 가드가 블록을 가려 본다(`FrontendDesignTokens.test_a_colour_in_the_wrong_block_is_caught`). 규칙은 모두 `var(--…)`를 쓴다. 옅은 채움(선택 상자·마크·위험 버튼 바탕 등)은 `color-mix(in srgb, var(--토큰) N%, transparent)`로 만든다. 중립색은 zinc 계열이다.

**분절 컨트롤은 하나다.** 채운 트랙(`--muted`, `--radius-lg`) 하나가 칸들을 모든 가장자리에서 4px 안쪽에 둔다. 고른 칸은 떠 있는 면(`--popover`)이고, 반지름은 트랙 반지름에서 그 안쪽 여백을 뺀 값(`--radius`)이며, 그림자(`--shadow-xs`, 3px)는 안쪽 여백 안에 머물러 어느 가장자리에도 잘리지 않는다. 트랙은 어느 포인터에서나 36px(칸은 컨트롤 높이 28px)이고, 터치에서는 칸마다 44px 히트를 `::after`로 넓힌다. 전에는 마우스의 칸이 글자 크기로 정해져 데스크톱 작성 패널·편집 카드와 마우스 창의 시트에서 트랙이 34.8px였다(`SegmentedControlMouse`). 그래서 44px 행에 놓인 분절들은 서로 8px 떨어지고 히트는 맞닿는다. 8px은 한 줄 안 컨트롤 사이의 간격 단계와 같고, 12px이면 행이 52px가 되어 [더보기]가 길어지면서 히트 사이에 빈 띠가 생긴다. 안쪽 여백을 2–3px로 줄이면 반지름이 토큰 밖(7–8px)으로 나가고 3px은 4px 격자 밖이라 4px로 둔다. 범위 사다리는 가로로 스크롤하므로 스크롤 상자(`.seg.lad`)와 그린 트랙(`.lad-t`)을 나눈다. 스크롤 상자는 넘친 것을 자르므로, 터치에서는 상자에 위아래 4px를 더해 히트를 담고, 작성 패널에서는 그만큼 음수 여백을 줘 트랙이 이웃과 8px로 남는다. 주인이 본 것은 두 가지였다. [더보기]의 트랙이 44px 행을 꽉 채워 위아래로 붙어 있었고, 이동 시트의 시트 여백 규칙이 트랙의 좌우 안쪽 여백을 0으로 덮어 [변경사항] 칸이 트랙 끝에 닿았다.

모양만 정하는 표시 전용 클래스(`.p`·`.x`·`.ghost`·`.ib`·`.ico`·`.tag`·`.t`, `.tag.claim`)는 쓰지 않는다. `.b-close`·`.b-drop`·`.arc-b` 같은 이름은 역할 표시로 남고, 모양은 변형 클래스가 정한다. 버튼처럼 눌리지만 모양이 다른 것도 있다. 분절 컨트롤(`.seg`), 범위 발췌의 줄(`.xp-row`), 구획 머리(`.arc-head`), [원래 요청] 글자 버튼(`.arc-orig-t`, 밑줄)이다. 이들은 같은 토큰을 쓰는 별도 모양이다.

### 한 겹 담기

담는 층은 하나만 둔다. 테두리 상자 안에 또 테두리 상자를 그리지 않는다. 카드 안의 테두리 배지·버튼, 테두리 분절 컨트롤 안의 테두리 칸, 테두리 원문 상자, 테두리 겹침 안내, 보관함 행 안의 테두리 스레드 상자가 그런 예다.

| 층 | 모양 |
| --- | --- |
| 패널·구획 | 테두리 없음. 구획 머리 + 구분선(`.arc-head` 윗줄) |
| 카드(`.card`) | 가는 `--border` 테두리 하나. 그림자 없음 |
| 카드 안 | 배지 = 옅은 채움(뜻 있는 배지는 그 색 14% 틴트) · 버튼 = 채운 secondary(완료 soft, 삭제 바탕 없는 위험 색) · 스레드 = 구분선 하나 뒤 목록 · 편집 = 간격만 |
| 작성 패널 | 상자 없음. 범위 사다리·종류 = shadcn Tabs(채운 틀 + 떠 있는 고른 칸) · 범위 발췌·원문 = `--code` 채움(테두리 없음) · 겹침 안내 = 글 + 버튼 · 테두리는 메모 입력 칸 하나 |
| 보관함 행 | 상자 없음. 행 사이 구분선 하나, 스레드·원래 요청은 들여쓰기만 |

### 아이콘

이모지와 기본 문자 아이콘(⏳ ▾ ▸ ☾ ◐ ✓ ✎ ⚠ ⧉ ⋯ ＋ ×)은 기기·글꼴마다 모양이 달라 쓰지 않는다. 꼭 필요한 곳에만 [Lucide](https://github.com/lucide-icons/lucide)(ISC) 아이콘을 쓴다. 출처·버전·아이콘 목록은 [`src/limn/vendor/lucide/README.md`](../../src/limn/vendor/lucide/README.md)에 있다.

- `lucide-static` npm 원본의 `<svg>` 안 요소만 `src/limn/viewer/assemble.py`의 `LUCIDE`에 인라인으로 넣는다. 외부 CDN은 없다.
- `stroke="currentColor"`·`stroke-width="2"`(24 격자)·16px이라 글자색을 따른다. 배지·행 안에서는 12–14px이다.
- 서버가 `{{ic:이름}}` 자리를 채우고, JS는 `ic(이름)`으로 같은 모양을 그린다.
- 아이콘 없이 뜻이 분명한 버튼은 글자만 둔다. 카드의 [보기]·[수정]·[풀기]·[삭제]·[완료], 보관함 [답글]·[되살리기], 휴지통 [영구 삭제], [원문 펼치기] 등이다. [더보기]의 핀 묶음 행은 앞머리 아이콘(16px) + 이름이다.
- 아이콘만 두는 버튼(축소·확대·테마·도움말·더보기·위치 복사·알림 닫기, 시트의 [⬚])은 `aria-label`로 이름을 준다.
- 산문 속 화살표(→)와 키 이름(⌘ Enter)은 글자로 남긴다. 아이콘이 아니다.

### 마크와 파비콘

뷰어의 브랜드는 확정된 Limn 로고 하나다. 로고는 앱 아이콘과 워드마크로 되어 있다. 그림은 모두 브랜드 원본 저장소 [dartworklabs/limn-sans](https://github.com/dartworklabs/limn-sans)가 그린다(`site/limn-brand.js`, `make icons`). 이 저장소는 결과 파일을 바이트 그대로 [`src/limn/viewer/brand/`](../../src/limn/viewer/brand/README.md)에 담고 다시 그리지 않는다. 표준 라이브러리만 쓴다는 불변식([architecture.md](architecture.md) §불변식 2)에 맞게, 서버는 시작할 때 이 파일을 읽어 그대로 내보낸다.

**모양.** 앱 아이콘은 연속 곡률 사각형(squircle) 타일 위의 글자 i다. i는 획 하나와 그 위의 점(핀)으로 되어 있다. 워드마크는 Limn 서체로 쓴 소문자 `limn`이다. 그라데이션·그림자·효과는 없다.

| 요소 | 라이트 | 다크 |
| --- | --- | --- |
| 타일 | 뼈종이 `#fbf1e6` | 먹 `#15161a` |
| 획(아이콘의 i, 워드마크 글자) | 먹 | 미색 `#f4ede1` |
| 점(핀) | 주 `#e8452c` | 주 |

주는 점에만 쓴다. 다른 색의 점, 주색 획, 늘이기, 다른 서체나 대문자 L, 그림자·효과는 BI가 막는 사용이다. 주 바탕 아이콘은 홍보물용이라 앱에서 쓰지 않는다.

**쓰는 곳.** 뷰어 안의 로고는 인라인 SVG다.

| 자리 | 그림 | 크기 |
| --- | --- | --- |
| 탐색 줄의 이름표 앞(`#paper-identity-mark`, 데스크톱·펼친 폴드) | 아이콘 | 16px |
| 도움말 머리(`#help-h`) | 워드마크 + `— 사용법` | 높이 20px |
| [더보기] 바닥(`#more-foot`, compact) | 워드마크 + 버전 | 높이 16px(`--foot-word`) |

- 아이콘 SVG는 그 크기의 광학 보정을 한 벡터 그림이다. 20px 이하에서는 획이 1.45s로 굵고 핀 아래 틈이 0.75(획 기준)로 넓다. 화면 배율과 무관하게 같은 그림을 쓴다.
- 도움말 머리는 워드마크를 쓴다. 제목 줄 상자가 24.8px라 BI의 광학 보정 없는 최소 높이(19px)를 넘는 20px이 들어간다. 워드마크와 `— 사용법`은 [더보기] 바닥과 같은 규칙으로 잉크 바닥이 한 줄이다. 워드마크가 제목의 기준선에 서고, 제목의 한글 잉크가 기준선 아래로 내려가는 만큼 내려온다(`headInk`). 전에는 20px 상자를 줄 가운데에 두어 "limn"의 발이 제목보다 3.3px 낮았다(`HelpHeadInk`: DPR 2.63과 2, 밝게와 어둡게에서 0.5px 안. 1배 화면은 글자를 정수 픽셀로 힌팅해, 대체 한글 글꼴에 따라 1px 남짓 어긋날 수 있다). 보호 여백(x높이의 절반, 이 크기에서 약 7px)도 옆 글자와의 8px 간격과 대화상자 여백 안에 든다. 탐색 줄 이름표 앞 자리는 정사각 16px라 아이콘을 쓴다. 프로젝트 이름표에는 Limn 표시를 담지 않는다. 브랜드와 작업 공간을 한 그릇에 같은 무게로 두지 않기 위해서다.
- 워드마크는 제목의 `Limn` 자리에 서므로 `role="img"`·`aria-label="Limn"`이다. 대화상자 이름은 `Limn — 사용법`으로 읽힌다. 아이콘은 장식이라 `aria-hidden`이고, 이름은 옆 이름표가 말한다. 두 워드마크(도움말 머리, [더보기] 바닥)는 `role="img"`·`aria-label="Limn"`이다.

**색은 토큰이 칠한다.** [`src/limn/viewer/mark.py`](../../src/limn/viewer/mark.py)의 `parse_svg`가 SVG를 닫힌 어휘로 읽는다. `svg`·`g`·`path`·`circle`과 그 기하 속성만 받고, 브랜드 색을 역할로 바꾼다(뼈종이 → 타일, 먹 → 획, 주 → 점). 그 밖의 요소·속성·색·DOCTYPE이 있으면 거절하고, 그러면 서버가 시작하지 않는다. `inline_svg`는 클래스만 달고 색을 넣지 않는다.

- 전체: `limn-mark`(아이콘), `limn-mark-word`(워드마크)
- 부분: `limn-mark-tile`·`limn-mark-stroke`·`limn-mark-pin`
- 칠하는 토큰: 타일 `--mark-tile`, 획 `--mark-stroke`, 점 `--limn-ver`(§토큰)

그냥 `.mark` 는 PDF 위 핀 상자라 `marks()` 가 지우고 다시 그린다. 같은 이름을 쓰면 핀을 그리는 순간 로고가 모두 사라진다(가드 `InlineMarkup.test_mark_classes_are_its_own`, 브라우저 `EnglishChrome.test_the_limn_mark_survives_boot_and_pin_marks`).

**파비콘.** 탭 파비콘은 앱 아이콘과 다른 그림이다. 정사각을 모서리까지 채운 먹 둥근 사각형에 미색 획과 주 핀을 둔 16·32px 픽셀 그림 하나이고, 밝은 탭과 어두운 탭에 똑같이 쓴다. i는 16 중 10(32 중 20) px이다. Chrome의 밝은 탭은 뼈종이와 색이 거의 같아(ΔE 8) 뼈종이 타일은 16px 탭에서 사라지고 2 × 9 px의 i만 남기 때문이다. 홈 화면 아이콘(`apple-touch-icon`)은 180px 뼈종이이고 모서리까지 꽉 찬 네모다. iOS가 모서리를 깎고, 투명한 모서리는 검게 보이기 때문이다. 경로와 파일은 [api.md](api.md) §화면·PDF·정적 파일에 있다.

- `<head>`는 한 묶음(`/favicon.ico`·`/favicon-16.png`·`/favicon-32.png`, `apple-touch-icon`)만 잇는다. `media`도 색 구성 스크립트도 없다. 탭은 16 CSS px라서 1× 화면은 16 그림을, 2× 화면은 32 그림을 고른다.
- 뷰어의 테마 설정(`pinPrefs.theme`)은 인라인 로고의 색만 바꾸고 탭 파비콘은 바꾸지 않는다. 탭 막대는 브라우저가 그린다.
- `/favicon-dark.ico`·`/favicon-dark-16.png`·`/favicon-dark-32.png`는 없다. 폐지를 알린 릴리스(0.3.8)의 다음 릴리스(0.4.0)부터 서버가 이 주소를 내지 않는다. 이 주소는 없는 경로처럼 404이고, 0.3.6–0.3.7 페이지의 어두운 탭은 파비콘 없이 열린다. HTTP API는 경로를 알린 릴리스 뒤에만 뺀다([architecture.md](architecture.md) §불변식 3).
- 주소의 `?v=<내용 키>`는 아이콘 파일 바이트에서 낸 sha256의 앞 12자리다(`limn.viewer.mark.content_key`). 그림이 바뀌면 주소도 바뀌어 옛 그림이 캐시에서 나오지 않는다.
- 파비콘은 인스턴스와 무관하다. 여러 인스턴스의 탭은 제목의 이름표(`Limn · <이름표>`)로 가른다. 인스턴스 색(`--brand`)은 화면 맨 위 띠(`#brand-stripe`)와 [더보기] 이름표의 점에만 쓴다.

**바꿀 때.** 그림은 브랜드 저장소에서 `make icons`로 다시 만들고, [`src/limn/viewer/brand/README.md`](../../src/limn/viewer/brand/README.md)의 절차대로 파일과 `SHA256SUMS` 줄을 옮긴다. 손으로 고치지 않는다. 가드는 셋이다.

- `VendoredFiles.test_every_file_is_listed_in_sha256sums_with_its_hash`: 모든 파일이 `SHA256SUMS`와 맞는지
- `VendoredFiles.test_the_tab_favicon_is_the_ink_pixel_drawing`: 탭 파비콘이 정사각을 채운 먹 픽셀 그림인지
- `LogoInTheBrowser`: 실제 Chromium에서 크기·테마 색이 맞는지, 파비콘 링크가 색 구성과 무관한지

## 렌더링과 확대

### 벡터 렌더링

뷰어는 같은 빌드의 PDF를 PDF.js로 캔버스에 직접 그린다. 서버가 그린 `pdftoppm -r 150` PNG(A4 한 쪽 1241×1754px)는 데스크톱 폭 맞춤·DPR 2에서 이미 화면 픽셀보다 거칠고, 확대할수록 더 흐려지기 때문이다. PNG는 첫 화면과 폴백으로 남는다. 벡터 렌더링이 쓰는 서버 경로는 `GET /pdf`·`GET /vendor/pdfjs/…` 둘이다([api.md](api.md)). `vendor` 경로는 `.mjs` 이름 하나만 받고 폴더 밖(심볼릭 링크 포함)을 가리키지 않는다(`limn.files.vendor_file`).

| 항목 | 규칙 |
| --- | --- |
| 라이브러리 | `pdfjs-dist` 6.3.289 `legacy` 빌드를 `src/limn/vendor/pdfjs/`에 담는다(외부 CDN 없음). 출처·sha256·뺀 파일의 근거는 [`src/limn/vendor/pdfjs/README.md`](../../src/limn/vendor/pdfjs/README.md) |
| 문서 | `GET /pdf?build=<META.pages_build>` — 쪽 이미지와 같은 빌드의 PDF. 쪽 수가 화면과 다르면 쓰지 않는다 |
| 백킹 크기 | 쪽 CSS 크기 × `devicePixelRatio` × (브라우저 핀치 배율, 1 이상). 앱 확대는 쪽 CSS 폭(`W`)에 이미 들어 있다 |
| 가로·세로 | 따로 맞춘다(렌더 `transform`의 세로 배율). 쪽 상자 비율은 PNG 픽셀 수에서 왔고 PDF 쪽 비율과 0.1% 안쪽으로 다르다. PNG도 쪽을 그 상자에 꽉 채워 그렸으므로, 이렇게 해야 글자가 PNG 때와 같은 % 자리에 온다 |
| 가시 영역 | `IntersectionObserver`(root `#left`, 위아래 150%) 안의 쪽만 그린다. 밖으로 나간 쪽의 캔버스는 크기를 0으로 줄여 떼어 낸다(사파리도 메모리를 바로 돌려준다) |
| 순서 | 화면 안의 쪽을 가운데에서 가까운 순으로, 한 번에 한 장. 쪽 캔버스 → 상세 캔버스 순 |
| 픽셀 상한 | 캔버스 한 장 16,777,216 픽셀(iOS 캔버스 한계, 모바일 메모리). 넘으면 쪽 캔버스를 상한까지 낮추고, 화면에 보이는 부분(+화면 크기의 25% 여유)만 원래 해상도로 그린 **상세 캔버스**(`.dt`)를 쪽 안 % 좌표로 겹친다. 스크롤해 상세 영역을 벗어나면 다시 그린다 |
| 다시 그리기 | 확대·창 크기·DPR이 바뀌면 그리던 것을 취소하고 150ms 뒤 다시 그린다. 그동안에는 옛 캔버스가 CSS로 늘어나 보인다(깜빡임 없음). 끝나면 새 캔버스로 바꿔 끼운다 |
| 재빌드 | 캔버스를 걷어 새 PNG를 먼저 보이고(옛 PDF 그림이 새 좌표 위에 남지 않게), 새 빌드의 PDF를 열어 다시 그린다. 옛 문서는 `loadingTask.destroy()`로 닫는다 |
| 폴백 | pdf.js를 못 불러오거나(`vendor` 404·네트워크), PDF를 못 열거나, 쪽 수가 다르거나, 그리다 실패하면 캔버스를 모두 걷는다. 밑에 늘 있는 PNG `<img>`가 그대로 보이고, 상태 칩 'PNG 보기'(`#vec-chip`)가 사유를 설명에 싣는다. 서버의 `pdftoppm` 렌더는 그대로 둔다(첫 화면·폴백) |
| 텍스트 레이어 | 넣지 않는다. 드래그가 글자 선택이 아니라 영역 선택이라, 글자 선택 레이어가 있으면 끌기와 다툰다. 복사는 원문 스니펫(작성 패널)으로 한다 |

**좌표 체계는 PNG와 같다.** 캔버스는 `pointer-events:none`이라 드래그와 길게 누르기는 쪽 상자(`.pg`)가 받는다. `frac`은 쪽 상자 대비 비율이다. 쪽 상자의 크기·비율은 PNG에서 정한다. `pt_w`·`pt_h`도 PNG에서 온다(서버의 `limn.builds.artifacts.page_list`가 PNG 머리의 픽셀 크기와 dpi로 계산한다).

### PDF 영역 전용 확대

PDF 영역의 확대 입력을 가로채 쪽 폭(`W`)만 바꾼다. 가로채지 않으면 브라우저 페이지 확대가 되어 사이드바와 도구 줄까지 커지기 때문이다.

| 입력 | 처리 |
| --- | --- |
| Ctrl(⌘)+휠(`#left` 위) | `wheel`을 `passive:false`로 받아 `preventDefault`. 마우스 휠 한 칸(\|dy\|≥50 또는 줄 단위)은 버튼 한 번과 같은 1.2배, 트랙패드 핀치(크롬·파이어폭스는 ctrlKey가 붙은 잘게 나뉜 wheel)는 `exp(−dy/100)`(크롬이 핀치 배율을 휠로 바꾸는 식의 역, 한 이벤트 ±18로 자름). 한 프레임에 모아 한 번 적용한다 |
| 사파리 트랙패드 핀치 | `gesturestart`/`gesturechange`의 `e.scale`(시작 폭 × scale) |
| Ctrl(⌘) + `=`·`+` / `−` / `0` | 확대 / 축소 / 폭 맞춤. 입력 칸에 포커스가 있으면 가로채지 않는다 |
| 두 손가락(터치) | `#left`에 `touch-action: pan-x pan-y` — 브라우저 핀치·두 번 탭 확대를 막고 스크롤만 넘긴다. `touchstart`/`touchmove`(`passive:false`)에서 두 손가락 거리 비율로 `W`를 바꾸고, 두 손가락 가운데 점 밑의 자리가 손가락을 따라가게 스크롤한다. 선택 모드의 쪽은 `touch-action:none`(한 손가락 = 선택, 두 손가락 = 같은 앱 확대). 두 번째 손가락이 닿으면 그리던 선택 상자와 길게 누르기를 버린다 |
| 버튼 [＋]·[−]·[↔ 폭 맞춤] | 같은 1.2배 단계와 폭 맞춤(PDF 영역 가운데 기준) |

**기준점을 지킨다.** 확대할 때 포인터 밑의 쪽과 그 쪽 안 비율을 잡아 둔다. 키보드·버튼이면 PDF 영역 가운데가 기준이다. 폭을 바꾼 뒤, 그 비율 자리가 같은 화면 좌표에 오게 `#left`를 스크롤한다. 폭 맞춤은 보던 쪽의 위쪽 자리를 지키고 가로 스크롤을 처음으로 되돌린다.

**한계.** 폭 맞춤 폭의 0.5–5배이고 최소 160px이다. 쪽이 넘치면 `#left` 안에서만 가로로 스크롤되고 `body`는 넘치지 않는다.

**패널은 영향이 없다.** 사이드바·시트·도구 줄은 `#left` 밖이라 영향을 받지 않는다. 패널 위의 Ctrl+휠은 PDF 영역이 아니므로 가로채지 않는다.

**뷰포트 메타는 확대를 막지 않는다.** `maximum-scale`·`user-scalable=no`를 넣지 않는다. 패널 쪽 핀치는 브라우저 확대라, 접근성 확대를 빼앗지 않는다.

## 역할에 따른 화면

서버는 `/api/meta`의 `me.role`로 역할을 알려 준다. `viewer` 역할이면 `body.role-viewer`가 붙고, 서버가 어차피 `403`으로 거절할 상태 변경 컨트롤을 숨긴다. 카드의 수정·답글·삭제·완료·확인·되살리기·영구 삭제·처리 중 풀기, 재빌드(상태 줄의 [재빌드]와 [⋯]의 행 포함), 변경 보기 안내 줄의 [확인], 작성 패널의 메모·종류·담당·[핀 저장]이 그 대상이다. 읽기는 그대로다. 보기·쪽 이동, 스레드, 닫힌 핀, 그리고 작성 패널의 위치와 원문 줄은 보인다. 작성 패널에는 `#c-viewer` 안내(`보기 권한만 있습니다 — …`)가 뜨고, Ctrl+Enter 같은 키 입력으로 저장·답글·수정을 보내려 하면 요청을 보내지 않고 토스트로 알린다(`viewerBlocked`). 휴지통의 [되살리기]는 viewer에게 아예 그리지 않고(`droppedCard`), [영구 삭제]는 소유자에게만 그린다. 숨김 규칙만 쓰면 보이지 않는 버튼이 문서에 남기 때문이다(테스트 `test_viewer_browser.ViewerTrashControls`).

**거부된 첫 화면.** 뷰어를 여는 `GET /`가 거부되면(`--members-only` 밖의 사람, `--allow` 밖의 사람, 테일넷의 헤더 없는 요청) 브라우저(`Accept: text/html`)는 JSON 대신 짧은 HTML 안내를 받는다(`limn/web/errors.py`의 `error_page_html`). 언어는 서버가 `?lang=` → 인스턴스 기본값(`--ui-lang`) → `Accept-Language`의 첫 태그(`ko*`면 한국어, 아니면 영어) 순으로 정한다. `?lang=`이 없고 이 기기에 저장한 선택(`limnLang`)이 쪽의 언어와 다르면 쪽 안의 한 줄 스크립트가 그 언어로 다시 연다. 그래서 순서가 뷰어와 같다. 문구는 뷰어와 같은 메시지 표(`viewer/ui_en.json`)를 거친다. API 경로와 브라우저가 아닌 요청은 그대로 JSON이다.

## 알려진 제약

뷰어 화면·입력·렌더링·측정의 한계만 적는다. 좌표 역변환, 앵커, 여러 문서 서버 쪽 한계는 [domain.md](domain.md)가 맡는다.

**실기기에서 확인하지 않는 것.**

- 밀어서 닫기, 시트 끌기, 두 번 탭, 유령 클릭 삼키기는 헤드리스 크롬의 CDP 터치로만 확인한다. CDP 이동은 약 30ms 간격으로 오므로 튕김 판정(0.5px/ms)도 그 간격에서만 확인된다. 실기기는 입력 빈도가 더 높다.
- 안드로이드의 시스템 뒤로 가기는 흉내 낼 수 없다. `CloseWatcher` 경로는 데스크톱의 닫기 요청(Esc)으로, history 경로는 `CloseWatcher`를 지운 채 `go_back()`으로 확인한다.
- 벡터 렌더링과 PDF 영역 전용 확대는 헤드리스 크롬(Playwright)으로만 확인한다. 사파리의 `gesturechange` 경로, 실기기 핀치(가속·관성), 실제 GPU의 렌더 시간은 재지 않는다.
- 그림 요소 상자·마크와 PDF.js가 그린 요소의 겹침, 그리고 다시 렌더한 뒤 마크가 요소를 따라가는지는 손으로 쓴 표본 그림 세트로 헤드리스 크롬(데스크톱·펼친 폴드·휴대폰, 폭 맞춤·300%, DPR 1·2·3)에서만 잰다. 지도를 내는 그림 도구가 없어, 실제 도구가 낸 요소 상자의 정확도와 pick 임계값([ADR-0011](../adr/0011-figure-documents.md) D6)은 재지 않는다. 사파리와 실기기에서도 재지 않는다.
- 모바일 레이아웃과 패널 폭·시트 높이 손잡이는 헤드리스 크롬 에뮬레이션(Playwright, `isMobile`·`hasTouch`)으로만 확인한다. 끌기는 CDP 터치 이벤트로, 가상 키보드는 visualViewport 높이를 줄이는 흉내로, 핀치 확대는 두 손가락 CDP 터치로 대신한다. 실제 갤럭시 Z 폴드 7에서는 확인하지 않는다. 주 포인터 판정(트랙패드를 붙인 iPad 포함), 회전 중 크기 이벤트의 순서, 흔들림 막기의 값(96px·200ms)도 흉내로만 확인한다.
- 여러 문서의 탭 전환은 헤드리스 크롬(데스크톱·펼친 폴드·접은 폴드 터치 에뮬레이션)으로만 확인한다. Ctrl+PgUp/PgDn은 실제 크롬에서 브라우저 탭 전환이 먼저 가져갈 수 있다.

**일부러 가로채지 않는 입력.** 입력 칸에 포커스가 있을 때의 Ctrl/⌘ + `=`·`−`·`0`, 그리고 패널 위의 Ctrl+휠·핀치는 가로채지 않는다. 그래서 이때는 브라우저 확대가 된다. 입력 칸의 브라우저 단축키를 빼앗지 않으려는 것이고, 사이드바는 PDF 영역이 아니기 때문이다. 이미 브라우저로 확대해 둔 페이지는 입력 칸 밖에서 Ctrl+0으로 되돌릴 수 없다. 그 키는 PDF 폭 맞춤이 된다. 브라우저 메뉴나 입력 칸 안에서 되돌린다.

**`GET /pdf`는 `Range`를 받지 않는다.** 그래서 PDF를 통째로 받은 뒤 연다. 원고 PDF는 보통 쪽 PNG를 모두 합친 것보다 작지만, 아주 큰 원고에서는 첫 캔버스가 늦을 수 있고, 그동안은 PNG가 보인다.

**빠른 선택의 마크는 작다.** 빠른 선택의 상자가 작아서, 저장된 핀의 마크도 작은 상자로 그려진다. 문단 전체를 칠하지 않는다. 서버가 문단의 PDF 좌표를 돌려주지 않기 때문이다.
