# 목적과 진실 소스

이 topic은 Limn이 왜 있는지, 누구의 어떤 비용을 줄이는지, 그리고 영역마다 "지금의 정답"이 어디에 있는지를 설명한다. 처음 이 저장소에 들어온 사람은 여기부터 읽는다. 무언가의 현재값이 헷갈릴 때도 §진실 소스 표에서 어디를 봐야 하는지 먼저 찾는다. 제품의 범위나 정본의 위치가 바뀌면 이 파일을 고친다.

## Limn이 줄이는 비용

LaTeX 원고를 퇴고할 때 사람은 PDF를 보고, 에이전트는 `.tex` 소스를 고친다. 둘 사이에 "여기를 이렇게 고쳐 줘"를 전하려면 보통 스크린샷을 붙인다. 스크린샷 한 장은 1,000~1,600 토큰이 들고, 그 안에는 위치 정보가 없다. 에이전트는 사진 속 문장이 어느 파일 몇째 줄인지 다시 찾아야 한다.

Limn은 이 왕복을 없앤다. 사람이 PDF에서 영역을 드래그하면 Limn이 SyncTeX 역변환과 본문 글자 대조로 `.tex` 파일과 줄 범위를 되찾는다. 여기에 메모를 붙인 것이 **핀**이다. 에이전트는 `sections/method.tex L493-L501` 같은 한 줄(약 35 토큰)을 받아 곧바로 읽고 고친다. 고친 뒤에는 무엇을 바꿨는지 남기며 핀을 닫고, 사람이 확인하면 끝난다.

> **핵심**
>
> Limn의 가치는 "위치가 정확한 작업 목록"이다. 그래서 위치를 잘못 찾는 것, 원고가 고쳐진 뒤 핀이 엉뚱한 줄을 가리키는 것, 에이전트가 읽는 형식이 예고 없이 바뀌는 것이 가장 큰 실패다. 구조와 검증 규칙의 대부분이 이 세 실패를 막으려고 있다.

## 누가 쓰나

| 사용자 | 하는 일 | 주로 보는 곳 |
| --- | --- | --- |
| 원고 저자 | PDF에서 고칠 곳을 핀으로 남기고, 에이전트가 닫은 핀을 확인한다 | 브라우저 뷰어 |
| 공저자 | 같은 사설망(테일넷) 주소로 들어와 핀과 답글을 남긴다. 누가 남겼는지 기록된다 | 브라우저 뷰어 |
| 에이전트 | API 토큰으로 인증하고, 열린 핀을 읽고, 고치기 직전에 claim하고, 고친 뒤 사유와 함께 닫는다 | `pins.md`, HTTP API, [SKILL.ko.md](../../skill/SKILL.ko.md) |
| 운영자 | 원고마다 인스턴스를 띄우고 업데이트하며, 에이전트 토큰과 멤버 역할을 관리한다 | `limn` 명령, [instances.md](instances.md) |

## 쓸 때와 쓰지 않을 때

Limn이 필요한 순간은 다음과 같다.

- 사용자가 원고의 특정 문단·표·그림·수식을 화면으로 보면서 "여기를 이렇게 고쳐 줘"라고 지목하고 싶을 때. 스크린샷을 붙이려는 순간이 대표적이다.
- 리뷰어 코멘트나 공저자 피드백을 원고 PDF 위에 표시하듯 쌓아 두고 싶을 때. 핀은 위치가 붙은 TODO다.
- 에이전트가 세션을 시작할 때, 또는 사용자가 "핀 확인해 줘"라고 할 때 열린 핀을 한꺼번에 처리한다.

쓰지 않는 경우도 분명하다.

- 원고가 아직 SyncTeX 빌드가 안 되는 상태(구조적 컴파일 오류)라면 빌드부터 고친다.
- 사용자가 이미 파일과 줄 번호를 알고 있다면 서버를 띄우는 비용이 낭비다. 바로 고친다.
- Typst 원고는 범위 밖이다. SyncTeX은 LaTeX 전용이다.

## 하지 않는 일

- **공개 인터넷에 직접 열지 않는다.** 0.2.0부터 신원 방식·에이전트 토큰·멤버 역할이 있지만, 로그인 화면(OIDC)이나 초대 링크는 아직 없다. 사설망(`tailscale serve`)이나 인증 프록시(`--auth trusted-proxy`) 뒤에서만 노출한다. 이후 단계는 [ADR-0002](../adr/0002-access-control.md)에 있다.
- **원고를 서버가 직접 고치지 않는다.** 고치는 것은 에이전트나 사람이고, 서버는 위치와 요청을 기록한다.
- **VPN이나 조정 서버를 제품으로 운영하지 않는다.** 테일넷은 지원하는 자체 호스팅 방법 중 하나일 뿐이다.

## 진실 소스

"지금 값이 무엇인가"를 물을 때 어디가 정답인지 영역별로 정리한다. Handbook이 모든 영역의 정본은 아니다. 직접 절차를 소유하는 영역과, 다른 정본을 가리키는 안내판 역할만 하는 영역을 구분한다.

| 영역 | 현재 정답이 있는 곳 | Handbook의 역할 |
| --- | --- | --- |
| 서버 동작·비즈니스 규칙 | 코드 [`src/limn/server.py`](../../src/limn/server.py)와 그것을 고정하는 테스트 | 안내판. 규칙의 이유와 중요한 값(한도·시간·임계치)을 [domain.md](domain.md), [build-sync.md](build-sync.md)에 설명한다 |
| 뷰어 화면 규칙 | `src/limn/viewer/`의 파일과 `tests/test_server.py`의 `Frontend*` 가드 | 안내판. 규칙과 근거는 [viewer.md](viewer.md) |
| 에이전트 계약 (`pins.md`, HTTP API) | [api.md](api.md)가 계약 문서이고, 코드가 그 계약을 구현한다. 둘이 어긋나면 결함이다 | **정본.** 계약을 바꾸려면 이 문서부터 바꾼다 |
| 에이전트 작업 절차 | [SKILL.ko.md](../../skill/SKILL.ko.md) / [SKILL.md](../../skill/SKILL.md) | 안내판 |
| 핀·빌드·사람·권한 데이터 | 인스턴스의 상태 디렉터리 (`pins.jsonl`, `pins.seq`, `builds.json`, `people.json`의 멤버와 역할, `tokens.json`의 토큰 해시, `events.jsonl` 등) | 안내판. 파일 배치는 [operations.md](operations.md) §상태 파일 배치 |

> **주의**
>
> 코드와 Handbook 설명이 어긋나면 어느 쪽이 옳은지 추측해서 고르지 않는다. 동작 영역이면 코드와 테스트를 확인하고, 계약 영역이면 [api.md](api.md)를 기준으로 코드가 결함인지 판단한다. 판단이 서지 않으면 멈추고 사람에게 묻는다.
