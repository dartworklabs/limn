# 접근 제어, 협업 범위, 동기화

상태: v0.2 는 Limn 0.2.0 에 구현됨(2026-09-25) — 신원 방식, 에이전트 토큰, 멤버 역할, 바인딩 규칙
([api.md](../api.md) §Authentication, [instances.ko.md](../instances.ko.md) §접근). 이후 단계는 아직 초안입니다.
영어 정본: [access-and-sync.md](access-and-sync.md). "문제" 절은 v0.1 기준 설명입니다.

## 문제

지금 Limn에는 자체 인증이 없습니다. 사설망(Tailscale 테일넷)이 문지기이고, 서버는 루프백에서 Tailscale이 붙여 준 신원 헤더를 믿습니다. 포트에 닿는 사람은 누구나 공동 작업자이고, 헤더 없는 루프백 요청은 에이전트로 취급됩니다.

한 연구실이 테일넷 하나에서 쓸 때는 충분합니다. 그러나 다음은 할 수 없습니다.

- 테일넷 밖의 공저자 초대
- 프로젝트를 지정한 사람으로만 제한
- 직접 관리하는 사설망 머신 밖에서 실행
- 에이전트에게 전부가 아닌 필요한 권한만 부여

## 결정 (초안)

접근은 **네트워크가 아니라 앱이 막습니다.** Limn은 VPN을 만들거나 운영하지 않습니다. 테일넷은 자체 호스팅의 한 방법으로 계속 지원하지만 필수는 아닙니다.

세 층으로 나누고, 각 층을 따로 갈아 끼울 수 있게 합니다.

### 1. 신원: 이 요청은 누구인가

인터페이스 하나에 방식 여러 개를 두고, 인스턴스마다 고릅니다.

| 방식 | 용도 | 신원 확인 |
|---|---|---|
| `local` | 내 컴퓨터에서 혼자 | 루프백 요청은 전부 소유자 |
| `tailscale` | 지금의 연구실 구성 | `Tailscale-User-*` 헤더, 루프백에서만 신뢰 |
| `trusted-proxy` | oauth2-proxy·Cloudflare Access 등 뒤에 자체 호스팅 | 설정한 헤더 이름, 설정한 프록시 주소에서 올 때만 신뢰 |
| `oidc` | VPN 없는 자체 호스팅·호스팅 서비스 | GitHub·Google 등 OIDC 로그인, 서버 쪽 세션 쿠키 |

**에이전트**는 "루프백에서 헤더 없이 오면 에이전트"가 아니라 **프로젝트별 API 토큰**으로 인증합니다. 토큰은 범위가 있고, 취소할 수 있고, 해시로 저장합니다. Limn을 루프백 밖에서 닿게 하기 전에 가장 먼저 고칠 부분입니다.

### 2. 권한: 이 프로젝트에서 이 일을 해도 되는가

- `people.json`을 역할이 있는 **프로젝트 멤버 목록**으로 키웁니다.
  - `owner`: 설정·멤버·토큰 관리
  - `editor`: 핀·답글·확인·다시 열기
  - `viewer`: 읽기 전용
  - `agent`: 토큰 주체. 에이전트 계약의 권한만 가짐(claim, 답글, 닫아서 검토 대기로. 확인은 불가)
- 합류는 이메일 허용 목록이나 만료되는 초대 링크로 합니다.
- "허용된 사용자만 공동 작업"은 네트워크와 무관하게 이 층에서 해결됩니다.

### 3. 동기화: 정본은 어디에 있는가

- **기본: 프로젝트마다 기준 서버 하나.** 브라우저와 에이전트가 모두 그 서버에 붙습니다. 실시간 반영은 폴링을 SSE·WebSocket 푸시로 바꿔 해결합니다.
- **나중, 선택: git 기반 핀.** 핀과 스레드를 원고 리포의 `.limn/`에 두고, 추가만 하는 사건 기록 하나를 ID와 버전으로 병합합니다. 공저자가 이미 리포를 공유하므로 별도 동기화 서비스가 필요 없습니다. 대신 실시간은 아닙니다. 지금의 `events.jsonl`이 이미 추가 전용이라 한 걸음이면 됩니다.
- **나중: 인스턴스 사이 복제.** 실제로 필요해지면 같은 사건 기록으로 합니다.

## 호스팅 제품 (Limn Cloud), 나중에

- 워크스페이스, 멤버, SSO, 알림, 실시간 동기화를 Dartwork가 호스팅합니다.
- 빌드는 사용자 컴퓨터에 남길 수 있습니다. `limn connect`가 클라우드로 나가는 연결을 하나 열고, 클라우드는 그 연결로 PDF와 핀을 중계합니다(ngrok·Cloudflare Tunnel과 같은 원리). 들어오는 포트도 VPN도 필요 없고, 원고 소스가 연구실 밖으로 나가지 않아도 됩니다.
- AGPL-3.0 + 상용 라이선스 모델과 맞습니다. 자체 호스팅은 무료로 두고, 호스팅 서비스와 상용 라이선스를 판매합니다.

## 로드맵

| 단계 | 범위 |
|---|---|
| v0.2 (**구현됨**, 0.2.0) | 신원 방식 인터페이스(`local`, `tailscale`, `trusted-proxy`), 에이전트 API 토큰, `people.json` 멤버 역할, 서버 시작 메시지와 README에 "인증 방식 없이 밖에 열지 말 것" 경고. 함께 들어간 것: `trusted-proxy` 가 아니면 loopback 밖 `--bind` 거부, `--members-only`, `--public-host`. 헤더 없는 loopback 에이전트는 남기되 폐지 예정. 초대 링크는 v1.0, 소유자 전용 작업은 당분간 CLI 수준 |
| v0.3 | SSE 실시간 반영, 상태를 바꾸는 엔드포인트를 역할 기준으로 점검 |
| v1.0 | `oidc` 방식, 세션, 초대 링크, HTTPS 자체 호스팅 안내(Caddy, Cloudflare Tunnel) |
| 이후 | `.limn/` git 기반 핀, `limn connect`와 Limn Cloud |

## 하지 않는 것

- VPN이나 조정 서버(Headscale, 내장 tsnet)를 제품의 일부로 운영하기
- 오픈소스 서버 안에서 여러 조직을 호스팅하기. 이는 호스팅 서비스의 몫입니다.

## 호환성

v0.2에서 에이전트 계약(`pins.md`, HTTP API 필드, 핀 상태)은 바뀌지 않습니다. 토큰은 에이전트가 인증하는 방법만 바꾸고, 읽고 쓰는 내용은 바꾸지 않습니다. 논문 리포 안내에는 "토큰을 어디서 받는가" 한 줄이 추가됩니다.
