# ADR-0013: [확인]은 사람이 본 닫기에만 묶인다

| | |
|---|---|
| **번호** | ADR-0013 |
| **제목** | [확인]은 사람이 본 닫기에만 묶인다 |
| **상태** | 승인됨 |
| **결정일** | 2026-10-03 |
| **결정자** | 프로젝트 소유자 |
| **출처** | [설계](../superpowers/specs/2026-10-03-confirm-binds-shown-close-design.md) |

## 맥락

검토 대기는 에이전트가 닫은 결과를 사람이 봤다는 기록이다. `POST /api/pins/{id}/confirm`은 무엇을 봤는지 받지 않아, 요청이 닿는 순간 핀에 있는 닫기를 완료로 바꿨다. 사람이 카드를 보는 사이 에이전트가 핀을 다시 열고 다른 `reply`·`changes`로 다시 닫으면, 사람이 보지 않은 결과가 그 사람의 이름으로 확인됐다. 뷰어의 [확인]은 되돌리기 알림이 끝난 뒤 보내는 지연 전송이라 이 창은 몇 초 더 열린다. 에이전트는 [확인]을 부를 수 없지만 다시 닫기는 할 수 있고, 고쳐서 다시 닫는 일은 흔하다.

이 변경은 HTTP API에 선택 필드와 오류 코드를 더하므로 에이전트 계약의 HARD-GATE 대상이다.

## 결정

`POST /api/pins/{id}/confirm`이 선택 본문 `{"done_at"}`을 받는다. 값은 사람이 본 닫기의 `done_at`이다.

- 핀이 검토 대기나 완료이고 지금 닫기의 `done_at`이 그 값과 다르면 `409 {"error":"conflict","reason":"conflict","pin":<최신>}`로 답하고 아무것도 쓰지 않는다. 모양은 `edit`의 `base_rev` 충돌과 같다.
- 같으면 본문이 없을 때와 같다. 열린 핀은 지금처럼 `409 open`이다.
- 문자열이 아니거나 비었거나 64자를 넘으면 `400 bad_done_at`이다.
- 필드가 없으면 지금 닫기를 확인한다. 필수로 만들지 않는다.
- 뷰어의 [확인]은 카드가 보인 닫기의 `done_at`을 보내고, `conflict`면 다시 닫혔다고 알린 뒤 새 결과를 검토 대기에 다시 보인다.

## Trade-off

**장점:**
- 사람의 확인이 본 결과에만 남는다. 에이전트의 다시 닫기가 사람의 승인을 가져가지 못한다.
- 저장 형식이 그대로다. `done_at`은 이미 저장·응답에 있다.
- 원고 줄 맞춤처럼 사람이 본 결과를 바꾸지 않는 변경은 확인을 막지 않는다.

**단점·포기한 것:**
- `done_at`은 초 단위라 같은 초 안에 다시 열고 다시 닫은 닫기는 구별하지 못한다.
- 필드를 보내지 않는 옛 뷰어 탭과 스크립트는 지금처럼 묶이지 않는다.

## 대안

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| `rev`에 묶는다(`base_rev`처럼) | `rev`는 원고를 고쳐 줄 번호를 자동으로 맞출 때도 오른다. 사람이 본 결과가 그대로여도 확인이 자주 거절된다 |
| 닫기 회차 번호를 새로 저장한다 | 정확하지만 저장 형식 변경이다. 옛 레코드 해석과 되돌리기 호환을 따로 설계해야 하는데, 같은 초 안의 재닫기라는 좁은 경우만 더 막는다 |
| `done_at`을 필수로 만든다 | 옛 뷰어 탭과 사람이 직접 부르는 스크립트가 깨진다. 필수화는 버전이 붙은 이전 계획이 있을 때만 한다 |

## 결과

- 판단은 `pins/lifecycle/rules.py`의 `confirm()`이 `ShownCloseChanged` 거절 값으로 내리고, HTTP 층이 `409 conflict`로 바꾼다.
- [api.md](../handbook/api.md) §검토 대기·§엔드포인트·§오류 응답, [domain.md](../handbook/domain.md) §전이와 할 수 있는 쪽, [code-style-roadmap.md](../handbook/code-style-roadmap.md) §R10이 현재 규칙을 적는다.
- SKILL은 바뀌지 않는다. 에이전트는 [확인]을 부르지 않는다.
