# ADR-0044: 뷰어의 약어 이름과 이력 주석을 줄기만 하는 기준선으로 막는다

| | |
| --- | --- |
| **번호** | ADR-0044 |
| **제목** | 뷰어의 약어 이름과 이력 주석을 줄기만 하는 기준선으로 막는다 |
| **상태** | 제안 |
| **결정일** | 2026-11-16 |
| **결정자** | Limn 소유자가 작업 지시로 정함(두 검사의 대상, 줄기만 하는 기준선, 정리는 기능별로 나중에). 낱말 목록의 내용과 이력 판별 패턴은 지시가 이 변경에 맡겼다 |
| **출처** | 이 변경이 `src/limn/viewer/js` 57개 모듈에 돌려 센 값, 실제 주석 hit을 읽고 정한 면제, `tools/tests/viewer_naming.test.mjs`가 넣어 본 위반의 검출 결과 |
| **부분 대체** | 없음. [ADR-0043](0043-viewer-typescript.md) D4의 ESLint 규칙 목록과 [ADR-0042](0042-viewer-es-modules.md) D7의 줄기만 하는 기준선에 규칙 둘을 더하며, 두 결정의 어느 조항도 바꾸지 않는다 |

## 맥락

[ADR-0043](0043-viewer-typescript.md)으로 뷰어 모듈 57개(약 3만 7천 줄)가 Prettier로 서식이 정해진 TypeScript가 되었지만, 읽기를 어렵게 하는 두 가지가 코드에 남아 있었다.

- **약어 이름.** 최상위 이름이 접두사로 영역을 말한다(`pv`·`md`·`PV`·`mdc`·`off`·`vec`·`rd`·`rv`·`tx`·`ime`·`cc` …). 지역 변수와 매개변수는 한두 글자다(`c`·`f`·`p`·`d`·`el`). 읽는 사람은 이름을 풀려고 선언을 찾아가야 한다.
- **이력 주석.** 릴리스 번호(`0.4.34`), 이슈 번호(`#418`), QA 날짜(`2026-09-24`)가 주석에 들어 있다. 주석은 지금 코드가 무엇을 왜 하는지를 말해야 하고, 고친 경위는 PR과 CHANGELOG가 소유한다.

정리 자체는 기능을 하나씩 만지며 나중에 한다. 이 기록은 그 전에 걸어 둘 검사, 곧 이미 있는 위반을 줄이는 동안 새 위반이 들어오지 못하게 하는 검사만 정한다.

## 결정

| | | |
| --- | --- | --- |
| D1 | **`limn/plain-names`(ESLint 지역 규칙)가 선언한 이름의 낱말을 본다.** 이름을 camelCase·PascalCase·UPPER_SNAKE·숫자로 낱말에 나눠, 세 글자 미만이면서 허용 목록에 없거나 약어 목록에 있는 낱말이 있으면 그 선언을 한 번 센다. 세는 것은 변수·함수·매개변수·클래스·타입 별칭·인터페이스·타입 매개변수·`catch` 매개변수와 import가 새로 짓는 이름이다. 사용처, 속성 이름, 객체 키, 별칭 없는 import, `.d.ts`는 세지 않는다. `i`·`j`·`k`는 `for` 머리의 선언 이름 전체일 때만 통과한다 | 제안 |
| D2 | **두 목록은 `tools/viewer-names.json` 하나에 둔다.** 일반 영어 두 글자 낱말(`english`), 영어 낱말이 아닌 짧은 말과 단위(`allow`, 항목마다 이유 한 줄), 풀어 쓸 약어(`deny`, 항목마다 풀어 쓴 낱말)다. 항목을 더하는 것은 diff에 보이는 리뷰 대상이다 | 제안 |
| D3 | **`limn/no-history-comment`가 주석의 이력을 본다.** 릴리스 번호(`d.d.d`), 이슈·PR 번호(`#dd` 이상, 또는 `issue`·`PR`·`pull request`·`review` 뒤의 `#d`), ISO 날짜를 주석 하나에 한 번 센다. Handbook 절과 ADR 번호는 지금 규칙을 가리키므로 세지 않는다. 따옴표 안의 예, IPv4 주소, `WCAG`·`RFC`·`§` 뒤의 번호, URL과 `@version` 뒤의 번호도 세지 않는다 | 제안 |
| D4 | **두 규칙은 기존 ESLint 규칙처럼 줄기만 하는 기준선에 든다.** 같은 타입 정보 ESLint 실행에서 돌고, `tools/strict_ratchet.py`가 파일마다·규칙마다 수를 `tools/strict-baseline.json`과 비교한다. 기준보다 많으면 새 위반이라 실패하고, 적으면 기준을 낮출 때까지 실패한다. 기존 규칙의 수는 바뀌지 않는다 | 제안 |

## 낱말 목록을 고른 방법

57개 모듈의 선언 11,170개에서 낱말을 뽑아 빈도순으로 읽었다.

- **두 글자 이하.** 대부분은 약어와 한 글자 변수라 규칙이 센다. 낱말이거나 단위인 것만 목록에 넣는다. `english`는 `as at by go if in is me my no of ok on or to up`이다. `allow`는 `id ui px ms db en ko io x y i18n`이고, 코드가 좌표(`x`·`y`)와 단위(`px`·`ms`)와 DOM·서버의 필드 이름(`id`)으로 쓰는 말이다. `io`는 `IntersectionObserver`를 줄여 쓴 자리가 있어 풀어 쓸 수 있지만, 지시가 허용 목록의 시작으로 정해 둔다. `lo`·`hi`·`dx`·`dy`처럼 흔하지만 약어인 것은 목록에 넣지 않는다.
- **약어.** 세 글자 이상인데 풀어 쓴 낱말이 코드 다른 곳에 있고 한 가지로만 읽히는 것을 `deny`에 넣는다(`sel`·`seg`·`upd`·`rev`·`sec`·`msg`·`btn`·`vec`·`mdc` 등). 실제 두문자어(`IME`·`PDF`·`URL`·`DOM`·`CSS`·`HTML`·`FYI`)는 넣지 않는다. `err`는 관례라서, `off`는 접두사 `off`(offline)와 낱말 `off`를 구별할 수 없어서, `doc`은 도메인 용어와 겹쳐서 넣지 않는다. `ref`·`rel`·`src`·`pre`는 HTML 속성·태그 이름이라 넣지 않는다.
- **이력 판별.** 실제 hit을 먼저 읽고 정했다. 릴리스 번호 모양의 hit 14개 가운데 4개는 IPv4 주소(`127.0.0.1`, `0.0.0.0/8`), 1개는 `WCAG 3.2.2`라서 면제한다. `#` 번호 hit 가운데 `'#12 deleted pin'`·`'핀 #10 · 본문'`처럼 뷰어가 쓰는 핀 번호를 보인 예는 따옴표 안이라 면제하고, 따옴표는 소유격 `'s`와 줄을 넘는 따옴표를 가려 읽는다.

## 결과 (이 변경이 센 값)

- `limn/plain-names` 5,926(57개 파일 전부, 가장 많은 파일은 `verdict.ts` 681, `md-surface.ts` 566, `verdict-reason.ts` 450).
- `limn/no-history-comment` 89(25개 파일, `verdict.ts` 24, `verdict-reason.ts` 13, `layout.ts` 9).
- 기준선 파일은 두 규칙의 항목만 더했고 기존 항목은 그대로다. `src/limn/viewer/js`와 `dist/viewer.js`는 바뀌지 않는다.
- 현재 규칙은 Handbook에 있다: [viewer.md](../handbook/viewer.md) §이름과 주석, §타입 검사, [code-style-roadmap.md](../handbook/code-style-roadmap.md) §R12, [verification.md](../handbook/verification.md) §9.

## Trade-off

- **얻는 것.** 이미 있는 위반을 줄이는 동안 새 약어와 새 이력 주석이 들어오지 못한다. 정리는 한 기능의 파일마다 기준선을 낮추는 작은 변경으로 나뉜다.
- **감수하는 것.**
  - 글자 모양만 보는 검사라 번호 없는 이력 서술("예전에는 …")과 목록에 없는 약어는 잡지 못한다. 번호가 아닌데 모양이 같은 글(`#333` 색 코드)은 오탐이라 따옴표에 넣어 쓴다.
  - 낱말 목록이 약어의 전부는 아니다. 목록은 코드에서 한 가지로만 읽히는 약어만 담고 늘릴 때 리뷰를 거친다.
  - 줄기만 하는 기준선이 5,926개를 세므로 기준선 파일이 커진다.

## 대안

- **이름 규칙을 정규식 한 줄(`id-length` 등)로 건다.** `id-length`는 길이만 보고 접두사 약어(`pvPress`)와 낱말 단위의 허용 목록을 모른다. 채택하지 않는다.
- **이력 주석을 리뷰에만 맡긴다.** 지금 89개가 있다는 것이 리뷰가 놓쳤다는 증거다. 채택하지 않는다.
- **정리를 먼저 하고 규칙을 나중에 건다.** 정리하는 동안 새 위반이 들어와 끝나지 않는다. 채택하지 않는다.

## 되돌릴 조건

규칙이 정당한 코드를 막아 정리를 방해하면 목록에 한 줄을 더하거나(허용), 규칙을 `eslint.config.mjs`에서 빼고 기준선의 두 규칙 항목을 지운다. 브라우저가 받는 코드·저장 형식·API는 바뀌지 않는다.
