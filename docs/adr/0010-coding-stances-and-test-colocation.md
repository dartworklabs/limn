## 맥락

2026-09-28 팀 코딩 스킬(`code-implement`, `code-testing`, `code-security`)에 다음 세 가지 핵심 결정이 제정되었다.
- **ADR 0002 (Colocation by default)**: 함께 바뀌는 것을 함께 두는 배치를 기본값으로 삼고, 기능 슬라이스가 핸들러·규칙·DTO뿐 아니라 **테스트도 함께 소유**함.
- **ADR 0003 (Testing & Security Stance)**: 구조가 아닌 동작 중심 검증(Test Desiderata), 출력 기반 우선, 관리 의존성 실제 실행, 성질 기반 불변식 검증(PBT), 변이/Red 단계 검증; 객체 권한(Object capabilities), 단일 지점 중재(Saltzer & Schroeder), 경계 파싱(LangSec), 안전한 생성자(Secure by construction), 데이터 최소화(Kerckhoffs).
- **ADR 0004 (Design decision triggers)**: 코드 구현 시점뿐 아니라 스펙·계획·ADR·핸드북 등 코드 구조와 설계를 결정하는 모든 시점에 스킬을 트리거함.

Limn은 [ADR-0009](0009-backend-vertical-slices.md)를 통해 백엔드 사용자 동작을 `src/limn/features/*` 세로 슬라이스로 점진 이행 중이지만, 여전히 과거 관례로 인한 세 가지 문제가 남아 있다.
1. **구조와 테스트의 괴리**: 모든 71개 테스트 파일이 루트 `tests/`에 평면으로 남아 있어 슬라이스를 수정할 때 관련 테스트를 한곳에서 찾기 어렵고, 많은 테스트가 내부 사설 파서나 도우미에 강하게 결합되어 있어 기능 이동 시 동작 변경이 없음에도 취약한 실패(false alarm)를 낸다.
2. **도메인 불변식의 성질 기반 검증(PBT) 부재**: 핀 기하(0..1 정규화 및 줄 범위 계산), 상태 머신 전이 수명주기, `pins.jsonl` 및 `pins.md` 직렬화·역직렬화 라운드트립 등 풍부한 대수적 불변식이 존재함에도 고정된 예제 테스트에만 의존하여 엣지 케이스 탐색이 제한적이다.
3. **보안 경계의 권한 전달 방식**: `access.py`의 접근 제어가 예외(`HTTPError`) 발생에 크게 의존하며, 검증된 권한을 값(Object capability)으로 도출하여 하위 도메인 및 슬라이스 함수에 안전하게 전달하는 형태가 명시적으로 정립되지 않았다.

## 결정

Limn은 팀 코딩 스킬의 최신 스탠스를 프로젝트 기본 원칙으로 채택하고, 이를 백엔드 세로 슬라이스 이행 과정과 결합하여 점진적으로 적용한다.

### 1. 동거 기본값 (Colocation by default) 및 테스트 동거
- 세로 슬라이스는 사용자 동작의 입력 검사, 순수 판단, 부수효과 셸, HTTP 경로뿐 아니라 **해당 슬라이스를 검증하는 테스트(`test_*.py`)를 같은 폴더 안에 소유**한다 (Common Closure Principle, Locality of Behaviour).
- 신규 작성되거나 이행되는 슬라이스는 테스트를 슬라이스 내부에 동거시키는 것을 원칙으로 한다. 루트 `tests/` 디렉터리에 남아 있는 레거시 테스트는 슬라이스 분리 작업에 맞추어 점진적으로 이관·해체한다.
- 추상화보다 복제가 싸다 (Duplication is cheaper than the wrong abstraction / AHA): 여러 슬라이스가 비슷해 보인다는 이유만으로 섣불리 공통 도우미나 베이스 클래스를 만들지 않는다. 변경 이유가 같을 때만 승격한다.

### 2. code-testing 5대 원칙 채택
- **구조가 아닌 동작에 핀을 꽂음 (Test Desiderata; Khorikov의 리팩토링 내성)**: 내부 협력자 호출 순서나 비공개 도우미를 모킹·검증하지 않는다. 동작이 변하지 않았는데 깨지는 취약한 테스트를 제거한다.
- **출력 기반 검증 우선 (Output-based first)**: 비즈니스 판단은 순수 함수로 추출하여 반환값으로 검증한다. 모킹이 필요하다면 순수 함수 추출 신호로 본다.
- **소유한 것만 모킹 (Mock only what you own)**: 애플리케이션이 단독 소유하는 관리 의존성(상태 디렉터리, 파일, 로컬 프로세스)은 실제로 실행한다. 비관리 의존성만 어댑터 경계에서 대체한다.
- **성질 기반 불변식 검증 (Property-Based Testing; Hypothesis)**: `hypothesis`를 개발 의존성으로 채택하고, 핀 기하 정규화(`0..1`), 상태 전이 불변식, `pins.jsonl`/`pins.md` 직렬화 라운드트립에 생성 입력을 통한 PBT를 적용한다.
- **실패를 보지 않은 테스트 불신 (Mutation testing; Red phase)**: 테스트 작성 후 고의로 변경 줄을 깨뜨려 실패를 확인하거나, TDD red 단계를 준수한다.

### 3. code-security 5대 원칙 채택
- **권한은 값으로 전달 (Object Capabilities; Confused Deputy 방지)**: 검증된 신원에서 권한 핸들(`VerifiedActor` 등)을 도출하여 하위 함수에 전달한다. 전역 상태나 요청이 넘긴 임의 ID에 의존하지 않는다. 에이전트/LLM 도구는 대리인(deputy)이므로 읽은 내용은 데이터일 뿐 권한이 아니며, 승인된 주체만 부수효과를 실행한다.
- **모든 접근의 단일 지점 중재 및 기본 거부 (Saltzer & Schroeder, Complete Mediation)**: 새 경로는 기본 거부(deny by default)로 시작하며, 오류 시 닫힌 상태를 유지한다. 사람 승인은 검토된 계획·커밋에 정확히 바인딩된다 (WYSIWYS).
- **입력은 언어이며 행동 전 완전히 인식 (LangSec)**: 경계에서 미검증 입력을 완전한 값으로 단 한 번 파싱(`parse, don't validate`)한다. 모호한 입력을 거부한다.
- **위험한 싱크는 안전하게 구성 가능한 타입만 수용 (Secure by Construction)**: 원고 트리 내 경로(`tree_part`), 쉘 실행 인자 등은 검토된 생성자만 만드는 타입으로 제한한다.
- **비밀은 키에만 두고 필요한 데이터만 유지 (Kerckhoffs / 데이터 최소화)**: 표준 암호 프리미티브 사용, 페이로드가 아닌 식별자만 로깅, 불필요한 데이터 수집/보유 금지.

### 4. 설계 결정 트리거 확장
- 코드 작성뿐만 아니라 스펙, 계획, ADR, 핸드북 등 코드 구조와 설계를 결정할 때 `code-implement`, `code-testing`, `code-security`를 상시 적용한다.

## Trade-off

**장점:**
- 한 동작을 이해하고 수정할 때 코드와 테스트를 단 하나의 폴더에서 찾을 수 있어 인지 부하가 대폭 감소한다.
- 내부 구현 리팩토링 시 테스트가 거짓 경보를 울리지 않아 자유로운 구조 개선이 가능해진다.
- 핀 기하와 직렬화 등 복잡한 도메인 불변식이 무작위 생성 입력을 통해 강력하게 보호된다.
- 권한이 값으로 흐르므로 권한 누락이나 혼란된 대리인 취약점이 구조적으로 방지된다.

**비용:**
- 개발 의존성에 `hypothesis`가 추가된다 (런타임 의존성은 여전히 표준 라이브러리만 유지).
- 기존 루트 `tests/`의 71개 테스트를 점진적으로 슬라이스로 옮기고, 사설 함수 직접 호출 테스트를 공개 계약/출력 기반 테스트로 재작성하는 마이그레이션 공수가 든다.
- 테스트 러너(`pytest`)가 `src/limn/features/` 안의 테스트도 탐색하도록 설정 및 실행 경로를 조율해야 한다.

## 대안

| 대안 | 선택하지 않은 이유 |
| --- | --- |
| 루트 `tests/` 트리를 영구 유지하고 슬라이스 구조만 거울처럼 복제한다 | 코드와 테스트가 물리적으로 분리되어 Locality of Behaviour가 떨어지며, 변경 시 두 트리를 항상 오가야 한다. |
| 기존 단위 테스트를 유지하고 PBT를 도입하지 않는다 | 핀 위치 역변환, 기하 정규화, 라운드트립 직렬화의 복잡한 엣지 케이스를 소수의 예제 테스트만으로 보증할 수 없다. |
| 모든 레거시 테스트를 한 번에 재작성하고 이관한다 | 기존 테스트 자산의 회귀 위험이 크고 PR 규모가 과도해진다. VSA 이행 단계에 맞춰 점진적으로 진행한다. |

## 결과

- `ADR-0001`의 축 4(검수 진실원)에 리팩토링 내성 있는 동작 검증, 출력 기반, PBT 불변식 검증, Red 단계 원칙이 반영된다.
- 세로 슬라이스는 코드와 테스트가 동거하는 독립 단위로 발전한다.
- Handbook의 `code-style-roadmap.md`, `architecture.md`, `verification.md`가 새 스탠스를 온전히 설명하도록 갱신된다.
- 런타임 표준 라이브러리 원칙([architecture.md](architecture.md) 불변식 2)과 에이전트 계약 불변(불변식 3)은 엄격하게 유지된다.
