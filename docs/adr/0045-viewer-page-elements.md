# ADR-0045: 뷰어 페이지의 요소 타입을 index.html에서 지은 선언으로 정하고, 그 참은 시험이 지킨다

| | |
| --- | --- |
| **번호** | ADR-0045 |
| **제목** | 뷰어 페이지의 요소 타입을 index.html에서 지은 선언으로 정하고, 그 참은 시험이 지킨다 |
| **상태** | 승인됨 |
| **결정일** | 2026-11-17 |
| **결정자** | Limn 소유자의 위임자가 작업 지시로 정함(대안 (c), 실행 중 검사 없음, 생성기 언어, HTML에 새 id를 두지 않음, 도우미 셋과 그 실패 방식, 타입 인자 게이트, 다시 그려지는 두 id의 처리). 생성기의 세부(SVG·MathML·`<template>`·`<noscript>`의 처리, 시험의 형태)는 지시가 이 변경에 맡겼다 |
| **출처** | 이 변경 전에 `origin/main`의 사본에서 잰 계획(`$`·`$$`의 호출 921개와 그 null 처리, 세 대안의 시제품과 그 수), 이 변경의 브랜치에서 다시 잰 값(아래 결과) |
| **부분 대체** | 없음. [ADR-0043](0043-viewer-typescript.md) D4의 검사 목록에 ESLint 규칙 하나를 더하며, 그 결정의 어느 조항도 바꾸지 않는다 |

## 맥락

뷰어는 요소를 `$('#id')`(`js/platform/dom.ts`)로 찾는다. `$`의 매개변수에 타입이 없어 `document.querySelector(any)`가 `any`를 돌려주고, 뷰어 코드의 `any` 값 경고(`no-unsafe-*`)의 절반 가까이가 여기서 나온다. `$`에 정직한 타입 `(selector: string) => Element | null`을 주면 `tsc` 오류가 2천 개 가까이 생긴다. 호출 대부분은 요소가 있다고 보고 그 클래스의 멤버(`value`·`open`·`showModal()`)를 읽기 때문이다.

그런데 그 가정은 대체로 참이다. 페이지는 정적 HTML 한 장이고, 스크립트는 `<body>`의 마지막 자식이라 모듈의 최상위 코드가 돌 때 페이지의 모든 요소가 이미 있다. 정적 id를 지우거나 다른 태그로 바꾸는 코드는 없다. 정적 id 가운데 둘(`#c-verdict-l`, `#queue-h`)은 부모를 다시 그릴 때 같은 id·같은 태그로 동기에 다시 만들어진다. 그래서 "`$('#note')`는 있는 `HTMLTextAreaElement`다"는 사실이고, 문제는 그것을 무엇이 보증하느냐다.

## 결정

| | | |
| --- | --- | --- |
| D1 | **요소의 타입은 페이지에서 짓는다.** `tools/page_elements.py`(파이썬 표준 라이브러리)가 `src/limn/viewer/index.html`을 읽어 `src/limn/viewer/types/page.d.ts`를 쓴다. `PageElements`는 페이지가 요소에 주는 id마다 그 태그의 DOM 클래스, `LiveElements`는 뷰어 마크업이 실행 중에 만드는 id(생성기의 `LIVE_ELEMENTS` 표)와 그 클래스, `PageLookup`은 `$`가 받을 타입이다. 페이지 id는 그 클래스, 실행 중 id는 그 클래스나 `null`, 그 밖의 선택자는 `Element \| null`이다. 같은 id를 두 요소에 주거나 `#id`로 그대로 쓸 수 없는 id를 주면 생성기가 거절한다. `<template>`·`<noscript>` 안은 스크립트가 보는 문서에 없으므로 빼고, `<svg>`·`<math>` 안은 SVG·MathML 요소로 적는다. 출력은 정렬되어 같은 페이지에 늘 같은 바이트이고, 지은 파일은 커밋한다. 다시 그려지는 두 정적 id도 `PageElements`에 둔다 | 승인됨 |
| D2 | **`$`의 실행 코드는 그대로다.** `$`에 `PageLookup`을 다는 것은 타입 주석뿐이라 지은 `dist/viewer.js`의 바이트가 같다. 실행 중에 클래스나 존재를 검사하지 않으므로, 요소가 없을 때 페이지가 실패하는 모양(첫 사용에서의 `TypeError`)도 그대로다 | 승인됨 |
| D3 | **선언의 참은 시험이 지킨다(D4).** `tsc`는 `$`의 본문을 `PageLookup`과 대조하지 않는다. 그래서 선언이 거짓이 되는 길, 곧 페이지를 바꾸고 선언을 다시 짓지 않음, 없는 id를 찾음, 실행 중 id의 태그가 선언과 다름, 정적 요소를 지우거나 다른 태그로 다시 그림을 시험 하나씩이 막는다 | 승인됨 |
| D4 | **시험 의무.** (1) 커밋한 선언이 지금 페이지로 지은 것과 같다(`test_viewer_page_elements.GeneratedDeclaration`, CI의 `uv run python tools/page_elements.py --check`). (2) 모듈의 `$('#id')` 리터럴은 모두 두 표 가운데 하나에 있다. (3) `LiveElements`의 id는 모두 어떤 모듈의 마크업이 만들고, 만드는 모든 자리의 태그가 선언한 클래스에 든다. 모듈이 만드는 리터럴 id는 모두 선언에 있고, 정적 id를 다시 그리는 마크업은 `index.html`과 같은 태그를 쓴다. (4) 브라우저에서 `PageElements`의 모든 id가 부팅 뒤, LaTeX·Markdown·텍스트·그림·보기 전용 PDF 문서마다, 문서 전환과 다시 짓기 뒤, `#c-verdict-l`·`#queue-h`를 다시 그린 뒤 그 클래스의 요소다. (5) 생성기의 단위 시험이 같은 id 두 번 거절, 태그와 클래스의 대응(모르는 태그와 사용자 정의 요소 포함), SVG·MathML, 중첩된 `<template>`, 정렬, `--check`를 본다. 페이지에 정적 요소를 더하거나 실행 중 id를 더하는 변경은 이 시험을 함께 지나야 한다 | 승인됨 |
| D5 | **id 하나가 아닌 질의는 찾은 것을 검사한다.** `platform/dom.ts`의 `findElement(scope, selector, Class)`는 코드가 요소가 있다고 보는 자리에서 쓰고, 그 클래스의 요소가 없으면 선택자와 클래스를 말하는 `Error`를 던진다. `findMaybe`는 없음을 견디는 자리에서 쓰고 `null`을 준다. `findAll`은 그 클래스의 요소만 문서 순서로 준다. 이름이 `find`가 아닌 것은, 지은 스크립트가 고전 스크립트라 최상위 `function find`가 브라우저의 `window.find`(페이지 찾기)를 덮기 때문이다. 정적 요소를 이 표에 넣으려고 HTML에 새 id를 더하지 않는다. id는 CSS·시험·에이전트 문서가 부르는 이름이라서다 | 승인됨 |
| D6 | **DOM 질의의 타입 인자를 막는다.** `querySelector<T>()`·`querySelectorAll<T>()`·`closest<T>()`는 찾은 것의 클래스를 검사 없이 말하는 단언인데 `consistent-type-assertions`가 보지 못한다. `eslint.config.mjs`의 `no-restricted-syntax`(`UNCHECKED_QUERIES`)가 이를 거절한다. 지금 코드에는 하나도 없어 기준선 항목 없이 0을 지킨다 | 승인됨 |
| D7 | **`$`는 이 변경에서 잇지 않는다.** 이으면 `npm run typecheck`가 오류를 낸다. 대부분은 정직해진 `null`(복합 선택자, 실행 중 id), 타입이 생긴 리스너 매개변수, 글자 속성에 넣는 숫자다. 그 고침이 먼저 들어가고, 잇는 변경은 그 한 줄과 기준선 낮추기뿐이며 지은 파일의 바이트가 같은 것으로 같은 프로그램임을 보인다 | 승인됨 |

## 대안

| | (a) 키로 찾는 표, 적재 때 한 번 검사 | (b) 호출마다 `must(selector, Class)` | (c) 지은 선언(채택) |
| --- | --- | --- | --- |
| 모양 | `PAGE.note`, `PAGE.searchField` … 256개 이름의 객체를 스크립트 적재 때 `getElementById`와 `instanceof`로 채운다 | `must('#note', HTMLTextAreaElement).value` | `$('#note').value` 그대로 |
| 실행 중 검사 | 적재 때 256번. 없는 id는 이름을 말하며 부팅을 멈춘다 | 호출마다 `instanceof` | 없음 |
| 바뀌는 호출 | `#id` 호출 860여 곳 전부 | 860여 곳 전부, 클래스를 자리마다 되풀이 | 0(정직해진 `null`의 고침만) |
| 읽기 | CSS·HTML·시험이 쓰는 `#id`가 코드에서 사라지고 이름 256개를 새로 짓는다 | 가장 길다 | HTML과 같은 글로 읽힌다 |
| 시험 | 원본 글을 찾는 시험과 node에서 `$`를 흉내 내는 시험이 깨진다 | 같다. node에는 `HTMLTextAreaElement`가 없다 | 그대로 |
| 다시 그려지는 두 id | 적재 때 잡은 참조가 다시 그린 뒤 낡는다. 표에서 빼야 한다 | 문제없다 | 문제없다(같은 태그를 D4가 지킨다) |

(a)와 (b)는 (c)와 같은 타입을 860여 곳을 고쳐 얻고, 페이지가 실패하는 모양을 바꾸며, 기존 시험을 깨뜨린다. 그 실행 중 검사가 더 증명하는 것은 정적 페이지에서는 D4의 브라우저 시험이 이미 증명한다. 키를 받아 클래스를 돌려주는 일반 함수 `page<K>(key)`는 단언 없이는 타입 검사를 지나지 않아 (a)는 객체 하나로만 쓸 수 있다. 실행 중 검사를 두는 것은 결정 D2·D3을 되돌리는 일이라 기각한다.

## 결과 (이 변경이 센 값)

- `index.html`의 id 256개(중복 없음, `<template>` 없음)가 `PageElements`, 실행 중 id 7개가 `LiveElements`다. 모듈의 `$('#id')` 리터럴은 862번, 206개 id이고 모두 두 표에 있다.
- `findElement`가 가정하는 자리 셋(`#composer .c-loc-row`), `findMaybe`가 견디는 자리 둘(`#pins .edit-slot`, `#doc .pg`), `findAll`로 쪽 번호의 자리를 정하는 쪽 목록 하나(`#doc .pg`, `pageNoSides`)를 바꿨다. 선택자와 범위가 `$`가 쓰던 그대로라 같은 요소를 찾는다. ESLint 경고는 6,603에서 6,590으로 줄었고 늘어난 파일·규칙은 없다.
- `$`를 이으면(이 변경에 넣지 않음) `npm run typecheck` 오류는 46개다(composer 2, documents 11, layout 15, pdf 5, pins 6, revisions 7). 지은 파일의 바이트는 같고, ESLint 경고는 3,679가 된다.
- 현재 규칙은 Handbook에 있다: [viewer.md](../handbook/viewer.md) §타입 검사, §뷰어 규칙을 바꿀 때, [verification.md](../handbook/verification.md) §9.

## Trade-off

- **얻는 것.** 호출을 고치지 않고 `$('#id')`가 그 클래스가 된다. 잇는 변경이 같은 프로그램임을 지은 파일의 바이트로 보인다. 정적 페이지의 사실을 실행 중이 아니라 시험에서 한 번 증명한다.
- **감수하는 것.**
  - 선언은 실행 중에 검사하지 않는다. 시험이 지나지 않는 상태에서 정적 요소를 지우는 코드가 들어오면 타입이 거짓이 된다. 그 길은 D4의 (3)·(4)가 덮는 만큼만 막힌다.
  - 지은 파일이 하나 는다. 페이지를 고치면 생성기를 돌려 함께 커밋한다. 잊으면 pytest와 CI가 실패한다.
  - 실행 중 id의 표는 생성기 안에 사람이 적는다. 표가 마크업과 어긋나면 D4의 (3)이 실패한다.
  - `findElement`는 클래스가 다른 요소에서도 던진다. 지금은 일어나지 않는 일이지만, 일어나면 예전의 `TypeError` 대신 선택자를 말하는 `Error`가 같은 순간에 난다.

## 되돌릴 조건

선언이 정적 페이지의 사실과 맞지 않는 일이 잦아지면(페이지가 실행 중에 정적 요소를 바꾸기 시작하면) 실행 중 검사 (a)나 (b)로 옮기는 새 ADR을 쓴다. `$`를 잇기 전이라면 선언과 생성기, 시험을 지우는 것으로 되돌아간다. 브라우저가 받는 코드는 `findElement`·`findMaybe`·`findAll`과 그 여섯 자리 밖에서는 바뀌지 않았고, 저장 형식·API·화면은 바뀌지 않는다.
