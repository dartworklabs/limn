# ADR-0001: Limn 청사진 결정

- 상태: 확정 (2026-09-26, 소유자 결정)
- 날짜: 2026-09-25
- 범위: 1차 구조, 도메인 정체, 함수형 설계 범위, 검수 진실원·시점, HARD-GATE, 정본 매체, Handbook 책임 구성, 시간축 호환

## 맥락

Limn은 LaTeX 원고 PDF에서 드래그한 영역을 `.tex` 파일과 줄 범위로 되돌려 주고, 그것을 사람과 에이전트가 함께 처리하는 **핀**으로 관리하는 서버다. 2026-09-21 한 스킬의 스크립트로 시작해, 2026-09-25 독립 저장소로 옮겨졌다. 설계 문서는 영어 레퍼런스와 한국어 가이드로 흩어져 있었고, System Handbook이나 ADR은 없었다.

이 ADR은 기존 코드에서 역추론한 사실을 바탕으로 쓴 초기 청사진이다. 근거는 2026-09-25 Limn 0.1.0(커밋 `946a92d`)에서 잰 값이다. 같은 날 0.2.0이 접근 제어를 더하면서 수치가 조금 늘었고, 현재값은 [architecture.md](../handbook/architecture.md) §현재 구조에 있다.

| 관찰 | 근거 |
| --- | --- |
| 배포 단위는 하나 | `pyproject.toml`의 `dartwork-limn` 패키지, 입구 `limn = "limn.cli:main"` |
| 런타임 의존성 없음 | `dependencies = []`, `requires-python = ">=3.10"` |
| 서버 로직이 모듈 하나에 모임 | `src/limn/server.py` 8,660행, 최상위 함수 236개, `# ------` 배너로 23개 구역 |
| 뷰어가 파이썬 문자열 안에 있음 | `HTML = r"""..."""` 4,760–8,110행 (약 3,350행) |
| 전역 상태로 문맥 전달 | 모듈 전역 `C = Cfg()` 참조 131곳, 스레드 지역 `cur_doc()` 호출 46곳 |
| 핀은 사전으로 다님 | 상태는 `done`·`review` 필드 조합에서 `pin_state()`가 계산 |
| 검증과 HTTP 표현이 섞임 | `HTTPError`를 던지는 함수 43개 (입력 검사와 핀 조작 모두) |
| 저장은 한 경로 | `transact()`가 잠금·재동기화·원자적 쓰기·`pins.md` 재생성을 강제 |
| 품질 도구 | 포매터·린터·타입 검사기 없음. CI는 pytest(3.10·3.12)와 셸 테스트, 설치 스모크 |
| docstring | `server.py` 함수 287개 중 175개, 테스트 519개 중 2개 |

사용자(프로젝트 책임자)는 2026-09-25 다음을 지시했다. 설계 방향은 **실용적 함수형 구현**과 팀 공통 코딩 규칙을 따른다. 지금 코드의 관례가 잘 짜여 있다고 가정하지 않고, 팀 코딩 규칙을 우선한다.

## 결정 — 축별 채택과 이탈

| 축 | 채택값 | 기본 청사진과의 관계 |
| --- | --- | --- |
| 1차 구조 | 작은 단일 배포 안의 **책임별 모듈**. 현재의 단일 모듈에서 [code-style-roadmap.md](../handbook/code-style-roadmap.md)의 단계대로 옮긴다 | 이탈. 웹 SaaS용 VSA(기능 슬라이스)는 쓰지 않는다. 기능이 아니라 책임(핀 도메인·역변환·저장·빌드·HTTP·뷰어 자산)이 변경 이유를 가른다 |
| 도메인 정체 | 핀의 수명 주기(상태 전이)와 위치 규칙(역변환·범위 사다리·anchor 재동기화) | 비즈니스 엔티티 대신 상태 기계와 위치 계산 |
| 함수형 DDD 범위 | **실용적 함수형.** 판단은 순수 함수, 부수효과는 가장자리. 의미 있는 수명 주기(핀)에만 상태별 타입과 전이 함수를 쓰고, 계산·파싱은 평범한 함수로 둔다. 명령·이벤트 값은 실제 필요가 있을 때만 쓴다 | 부분 채택. 전면 DDD 대신 팀 스킬 `code-implement`의 기본값 |
| 코딩 규칙 권위 | 제품 불변식 > 팀 코딩 스킬(`code-implement`, `code-testing`, `code-security`) > 기존 코드 관례 | 새 결정 |
| 예상된 실패 표현 | **반환 타입에 드러낸다.** 도메인 판단과 경계 파서는 성공 값이나 이유가 닫힌 거절 값(`Pin \| ConfirmRejected`)을 돌려주고, 업무상 거절로 `raise`하지 않는다. 예외는 결함과 인프라 장애에만 쓴다. 일반 Result 라이브러리는 들이지 않는다 (2026-09-26 추가) | 새 결정. 호출자가 서명만 보고 거절을 알고, `match`와 타입 검사기가 빠뜨린 경우를 드러낸다 |
| 구조 이동과 기능 작업의 순서 | **구조 이동이 우선.** 충돌하면 열린 기능 PR이 새 구조를 따라온다. 구조 이동 PR은 동작을 바꾸지 않고 테스트로 증명한다 (2026-09-26 추가) | 새 결정 |
| 검수 진실원 | 자동 테스트 녹색 + 에이전트 계약 호환 + 화면 변경 시 실측 | green test 단독이 아니다 |
| 검수 시점 | 머지 전 게이트 (CI) | 기본 |
| HARD-GATE | 행동 계약 변경 전: 에이전트 계약·보안 경계·저장 형식 | 코드 작성 전 일반 게이트보다 좁고 구체적 |
| 정본 매체 | 동작은 코드, 에이전트 계약은 `api.md`·`SKILL`, 데이터는 인스턴스 상태 디렉터리. Handbook은 설계 교과서이자 안내판이고, 구조·검증·변경 흐름에서는 정본 | 기본 |
| Handbook 책임 구성 | 목적, 구조, 도메인, 뷰어, 빌드·동기화, API 계약, 운영(서버·인스턴스 두 편), 검증, 변경 흐름, 코딩 로드맵. 한국어 단일본. 흩어진 기존 문서를 모두 흡수한다 | 새 결정 |

| 경제·비용, 외부 검수 권위 | 해당 없음 | — |

## Trade-off

- **책임별 모듈로 옮기는 비용.** 8,660행을 나누는 동안 import 경로와 테스트 위치가 바뀐다. 한 번에 옮기지 않고, 단계마다 동작 불변을 증명하는 테스트(바이트 동일 HTML, 계약 스냅숏, 레코드 왕복)를 먼저 세운다. 얻는 것은 판단을 파일 없이 테스트할 수 있고, 뷰어를 JS 도구로 다룰 수 있고, 의존 방향을 도구로 확인할 수 있다는 점이다.
- **실용적 함수형의 비용.** 핀 상태를 타입으로 나누면 저장 형식과 내부 모델 사이의 변환 코드가 생긴다. 저장 형식을 바꾸지 않기 위해 치르는 값이다. 계산·파싱까지 타입과 명령으로 감싸지는 않아서 과한 추상화는 피한다.
- **한국어 단일 Handbook.** 개발팀이 읽기 쉽고 유지 비용이 한 벌이다. 대신 영어 사용자를 위한 상세 레퍼런스가 사라진다. 영어 사용자는 [README.md](../../README.md)와 [SKILL.md](../../skill/SKILL.md)로 시작한다.
- **팀 스킬 우선.** 기존 관례를 근거로 삼지 않으므로 초기에는 리뷰에서 지적이 늘 수 있다. 로드맵이 순서를 정해 한꺼번에 몰리지 않게 한다.

## 대안

- **현재 구조 유지(단일 모듈).** 배포와 테스트가 단순하다는 장점이 있지만, 뷰어와 서버가 다른 이유로 바뀌는 압력, JS를 문자열에서 잘라 내는 테스트, 전역 문맥 의존이 이미 비용을 만들고 있다. 채택하지 않는다.
- **여러 배포 단위(워크스페이스) 분리.** 런타임이 하나고 소비자가 하나라서 빌드·버전 관리 비용만 늘어난다. 채택하지 않는다.
- **전면 함수형 DDD (명령·이벤트·결과 타입 전면 도입).** 핀 수명 주기 외의 대부분이 계산과 입출력이라 얻는 것보다 의례가 크다. 채택하지 않는다.
- **프론트엔드 빌드 도구 도입(번들러, 프레임워크).** 표준 라이브러리 단일 설치라는 제품 불변식과 부딪힌다. 뷰어는 빌드 없는 정적 파일로 분리하는 데서 멈춘다.
