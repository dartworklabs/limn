## 맥락

Limn은 LaTeX 원고에만 줄 핀을 준다. 보기 전용 PDF에는 쪽과 영역 핀만 있고, 그림 문서는 요소 지도로 코드 줄을 가리킨다. 그런데 사람과 에이전트가 함께 고치는 작업 문서는 Markdown인 경우가 많다. 지금은 Markdown을 줄 1:1로 LaTeX로 바꾼 생성 파일을 커밋해 띄우는 임시 방법을 쓴다. 이 방법은 생성 파일을 원본과 계속 맞춰야 하고, 제안 수정 편집 칸에 이스케이프된 글이 보이며, 휴대폰에서 종이 쪽을 확대해 읽어야 한다.

Limn 안에서 Markdown을 LaTeX로 바꾸는 길도 검토했다. 그러나 TeX와 글꼴이 필요하고, `.md` 만 고치면 화면이 옛 쪽에 머물며, 형식마다 변환기가 필요해 기각했다(설계 §진단). 이 길로 돌아가야 했던 까닭은 뷰어가 PDF밖에 그리지 못하기 때문이다.

소유자는 2026-10-24에 지금은 LaTeX만 유지하기로 하고 이 계획을 검토에 넘겼다. 이 ADR은 그 계획을 현재 코드(0.4.45, 인용한 줄은 0.4.46에서도 같다)와 다시 대조하고 PoC로 확인한 결정이다. 이 변경은 문서 종류·사다리 값·제안 관문 등 에이전트 계약과, `page` 없는 줄 핀이라는 저장 모양, 런타임 번들(멈춤 신호), 그리고 같은 출처에서 남이 쓴 글을 그리는 보안 경계를 건드려 소유자 승인을 받았다. 소유자는 2026-11-04에 PoC(테일넷 시안)와 설계 개정 1을 보고 진행을 승인했고, 열려 있던 세 결정을 추천안대로 정했다. `page`·`frac`·`pdf_build` 를 저장하지 않고 `pins.md` 쪽 칸에 `—` 를 쓴다(D2). markdown-it을 번들한다(D5). 원시 HTML은 자리표시, 링크는 허용 목록, 그림은 불러오지 않으며 뷰어 페이지 CSP는 먼저 따로 승인받는다(D6).

## 결정

| # | 결정 | 상태 |
| --- | --- | --- |
| D1 | 문서를 그리는 화면을 둘로 나눈다. PDF 화면은 지금 그대로다. HTML 화면에서는 브라우저가 원문을 그리고, 그린 블록마다 원문 줄 범위를 붙인다. 첫 종류는 `.md` 로 등록하는 `markdown` 이다. 빌드·생성 파일·감시 스레드가 없다 | 승인됨 |
| D2 | Markdown 줄 핀은 `file`·`lo`·`hi`·`kind`·`scope`·`quote`·`raw_lo`·`raw_hi` 만 가진다. `page`·`frac`·`pdf_build` 는 저장하지 않는다. 보내도 버리고, 레코드에 남아 있던 값도 그 핀을 쓸 때 지운다. `pins.md` 의 쪽 칸은 `page` 가 없는 줄 핀에 `—` 를 쓴다 | 승인됨 |
| D3 | 값 목록을 늘린다(ADR-0011 D5 선례). 문서 `kind` 에 `markdown`, `scope`·`levels[].level` 에 `block`·`section`, 핀 `kind` 에 `md:<블록>`(`md:paragraph`·`md:item`·`md:table`·`md:code`·`md:quote`·`md:html`)과 `md:section` 을 더한다 | 승인됨 |
| D4 | 행동은 능력으로 가른다. `Doc` 에 `renders_in_browser`·`takes_suggestions` 를 더한다. 제안 관문, 판정 대상 계산, 시작 빌드에 남은 종류 비교를 능력으로 바꾼다. API에 능력 필드는 더하지 않는다 | 승인됨 |
| D5 | 파서는 markdown-it을 뷰어에 번들한다(`src/limn/vendor/markdown-it/`, ESM 브라우저 빌드, MIT). 번들에 함께 든 의존성(`entities` BSD-2-Clause, `mdurl` 등 MIT, 번들러 도우미가 베낀 `@babel/runtime` MIT)의 판과 고지를 모두 싣는다. Markdown 문서를 열 때만 불러오고, 토큰을 따라 DOM을 짓는다. 서버는 Markdown을 파싱하지 않는다 | 승인됨 (멈춤 신호) |
| D6 | 그린 문서는 아무것도 실행하거나 불러오지 않는다. DOM API로만 짓고, 원시 HTML은 줄 범위를 가진 자리표시로 보이며 그리지 않는다. 모든 링크 토큰은 렌더러의 허용 목록을 지난다. 다른 출처의 `http(s)`, `mailto`, 문서 안 `#제목` 만 열고, 뷰어 자신의 출처·루프백 주소·자격 증명이 든 주소는 열지 않는다. 호스트는 목적지와 뷰어 모두 Limn의 Host 검사와 같은 철자(소문자, 끝의 점 없음)로 비교한다. markdown-it의 `validateLink`(거부 목록)에는 기대지 않는다. 그림은 불러오지 않는다. 뷰어 페이지의 `script-src` CSP는 앞선 조건이고 따로 결정한다 | 승인됨 |
| D7 | 줄 번호의 권위는 서버다. 원문 경로는 `str.splitlines()` 로 나눈 줄 목록을 1 MiB 한도로 읽어 보낸다. 뷰어는 그것을 이어 파싱할 뿐 원문 바이트를 다시 나누지 않는다. 블록 안에서는 인라인의 줄바꿈 토큰 수가 원문의 줄 끝 수와 같을 때만 줄 단위로 가리키고, 다르면 그 범위 전체로 물러선다. 파싱은 Worker에서 중첩·토큰·요소·시간 한도 안에서 하고, 넘으면 원문 줄 보기로 물러선다 | 승인됨 |
| D8 | 제안 수정은 Markdown 줄 핀에도 둔다. 편집 칸과 차이는 Markdown 원문이다. 원문 대조·`suggest_state`·`## 제안 문안` 은 그대로 쓴다 | 승인됨 |

### D2를 고른 근거

레코드 검사는 `page` 가 있을 때만 정수인지 보고, 모델에서도 `page` 는 선택 필드다. 그래서 `page` 없는 줄 핀은 지금 서버도, 옛 서버도 읽는다. 막는 곳은 만드는 길과 고치는 길이다. 만드는 길에서는 추가 파서가 `page` 기본값 1을 넣고, 새 줄 핀 규칙이 `pdf_build` 를 늘 넣는다. 고치는 길에서는 줄 위치가 `page` 를 요구하고, 위치를 바꿀 때 `frac` 이 오면 `pdf_build` 를 되살리며, 이름이 불리지 않은 `page`·`frac` 은 저장된 값을 남긴다. 그래서 쪽 없는 문서라는 사실을 두 길 끝까지 싣는다. 입력 파서는 문서 사실(`DocumentFacts`, 요소 지도와 같은 길)에서 읽고, 순수 규칙은 인자로 받는다. 보낸 값이든 물려받은 값이든 쪽 필드가 Markdown 저장을 지나 남지 않는 것을 시험으로 지킨다.

PoC는 기본값 때문에 `page: 1` 을 저장했다. 그러자 `pins.md` 쪽 칸에 `1` 이 찍혔다. 뜻 없는 값이 에이전트 계약에 남고 퍼지면 거두기 어렵기 때문에 그 길을 고르지 않는다.

### D5를 고른 근거

블록 토큰의 `map` 이 원문 줄 범위를 준다. PoC로 문단·제목·목록 항목·표 행·코드 블록·인용·원시 HTML 블록에서 이를 확인했다. 문단 안에서는 줄바꿈 토큰이 원문 줄의 경계지만, 여러 줄에 걸친 코드 표시·원시 HTML 태그·링크 주소 같은 구성은 줄 끝을 삼킨다. markdown-it은 인라인 자식에 원문 위치를 주지 않으므로, 줄바꿈 토큰 수가 원문의 줄 끝 수와 맞는 인라인만 줄 단위로 가리키고 나머지는 블록 범위로 물러선다(D7, 설계 §결정 6). 그래서 문단 안의 한 줄도 대개 핀이 되고, 줄을 틀리게 매기는 일은 없다. 번들은 124,681바이트이고, 이미 번들한 PDF.js의 약 7%다.

서버에서 표준 라이브러리로 렌더하는 안은 번들이 없다. 대신 CommonMark 블록 규칙을 Limn이 소유하고, GitHub 렌더와 경계 사례에서 어긋나며, 서버가 만든 HTML을 넣는 두 번째 sink가 생긴다.

## Trade-off

- 런타임 번들이 하나 는다. 판을 고정하고 sha256을 적으며, 고칠 때는 PDF.js와 같은 절차로 갈아 끼운다. 번들에 든 의존성의 판과 고지도 판을 올릴 때마다 다시 맞춘다.
- 1 MiB를 넘는 Markdown 문서는 그리지 않고, 한도에 걸린 문서는 원문 줄로 보인다. 지금 쓰는 가장 큰 Markdown(612 KB)은 한도 안이다.
- README류 문서의 머리 HTML(가운데 맞춘 로고, 배지)이 그려지지 않는다. 자리표시와 원문 첫 줄만 보인다. 허용 목록 소독기를 들이면 그릴 수 있지만, 번들과 정책이 하나 더 는다.
- 원격 그림과 문서 밖 상대 링크가 열리지 않는다. 읽는 사람이 원문 저장소에서 따로 봐야 한다.
- 뷰어에 문서 영역이 둘이 된다. 쪽을 전제한 기능(쪽 판정 줄과 패널, 비교 PDF, 쪽 목록, PDF 확대, Limn 찾기)은 Markdown 문서에서 꺼진다. 1단계의 찾기는 브라우저의 찾기다.
- 옛 서버로 되돌리려면 먼저 Markdown 문서를 인스턴스 설정에서 빼야 한다. 옛 서버는 `.md` 문서가 있는 설정으로 시작하지 않는다. 상태 폴더의 핀은 그대로 읽힌다.

## 대안

- **Limn 안에서 Markdown을 LaTeX로 바꾼다.** 외부 도구, 조용한 옛 쪽, 형식마다 변환기 문제로 기각했다.
- **저장소가 생성 LaTeX를 커밋하는 지금 방법을 유지한다.** 이 ADR이 승인되기 전까지의 임시 방법이다.
- **`page: 1` 을 저장한다.** 코드는 가장 적지만 거짓 사실이 계약에 남아 기각했다(D2).
- **블록 번호로 핀을 저장한다.** 편집에 살아남지 못해 기각했다.
- **서버 렌더러(표준 라이브러리).** D5 근거대로 기각했다.
- **원시 HTML을 소독해 그린다.** 1단계에서는 기각한다. 필요해지면 별도 ADR로 다룬다.

## 결과

- 구현은 [계획](../superpowers/plans/2026-10-24-html-document-surface.md) 순서로 한다. 서버 쪽 단계(Task 1–4)는 이 ADR의 승인으로 시작한다. 뷰어 화면(Task 5)은 뷰어 페이지 CSP를 따로 결정한 뒤에 넣고, 머지 전에 네 기기군 PoC를 보인다. `.md` 등록은 화면이 갖춰진 판에서 연다.
- 에이전트 계약에 값 넷(문서 `kind`, `scope`, 핀 `kind`, 원문 경로)과 `pins.md` 표시 둘(쪽 칸 `—`, Markdown 문서 절 꼬리말)이 더해진다. 기존 경로·필드·상태의 뜻은 그대로다.
- 저장 형식에 새 필드는 없다. Markdown 핀은 `page` 없는 줄 핀이다.

### 현재 상태 투영

- **영향받는 현재 권위**
  - `runtime/documents.py` 의 문서 종류와 능력
  - 시작 빌드(`builds/run.py`, `builds/service.py`)
  - 핀 만들기·편집(`pins/editing/`)과 `pins.md`(`pins/listing/render.py`)
  - 판정 대상(`pins/verdict.py`, `pins/runtime.py`)
  - 변경 보기의 이력 파일 선택(`builds/queries.py` `history_files`, `revisions/core.py` 의 파일 목록 길. LaTeX pathspec은 그대로)
  - 읽기 권한(`security/access.py`)과 보안 헤더(`web/handler.py`)
  - 뷰어와 번들
  - 에이전트 계약(`api.md`, SKILL)
- **갱신할 Handbook role/path:** purpose `docs/handbook/purpose.md`(지원 범위), architecture `docs/handbook/architecture.md`(채택값, 번들), `docs/handbook/domain.md`(능력 표, 여러 문서), `docs/handbook/api.md`(값 목록, `page` 없는 줄 핀, 제안 관문, 판정 대상, 원문 경로), `docs/handbook/viewer.md`, `docs/handbook/build-sync.md`, `docs/handbook/instances.md`, `docs/handbook/operations.md`, `docs/handbook/index.md` 파일 지도
- **효력 형태:** 단계적 이행(계획의 Task 1–6)
- **완료 증거**
  - 계약 스냅숏에 Markdown 문서와 `page` 없는 줄 핀이 있다.
  - 직전 릴리스가 그 레코드를 지우지 않는다.
  - 보안 시험 문서가 무력하게 그려진다.
  - 서버와 뷰어의 줄 번호가 모든 구분자에서 같다.
  - 네 기기군 실측이 있다.
