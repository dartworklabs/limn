## 맥락

Markdown 문서의 변경 보기는 소스 diff 하나다. 표·목록·그림이 바뀐 커밋도 원문 기호로만 보이고, 낱말 몇 개를 고친 문단은 줄 전체가 지운 줄과 더한 줄로, 옮긴 절은 지운 줄 수십 개와 더한 줄 수십 개로 보인다. LaTeX 문서에는 latexdiff 비교 PDF가 있다.

서버는 그 커밋의 diff만 주고(256 KiB까지) 원문 전체를 주는 경로가 없다. 뷰어가 지금 원문에 diff를 거꾸로 적용하면 고른 커밋이 HEAD가 아니거나 미커밋 수정이 있을 때 틀린 판이 나온다. 그래서 두 판을 그리려면 에이전트 계약에 읽기 경로가 하나 더해지고, 소유자 승인을 받는다([workflow.md](../handbook/workflow.md) §기본 경로).

## 결정

| # | 결정 | 상태 |
| --- | --- | --- |
| D1 | 새 읽기 경로 `GET /api/revision-source?doc=&commit=[&base=]` 가 브라우저가 그리는 문서(Markdown·텍스트)의 파일 하나를 소스 diff와 같은 두 쪽(첫 부모 → 커밋, 범위는 옛 쪽 → 커밋, 곁가지는 병합 기준)에서 `{id, base, merge_base?, path, old, new}` 로 준다. 쪽은 `{lines}`(`GET /api/source` 와 같은 줄 규칙), 파일이 없으면 `null`, 그릴 수 없으면 `{reason}`(`source_too_large`·`source_not_utf8`·`not_a_file`·`source_unreadable`)다. 경로 매개변수는 없고 이력 창 안의 커밋만 읽는다. 다른 문서는 `404 commit_not_recent`, 범위의 거절은 [api.md](../handbook/api.md) §두 커밋 사이 그대로다 | 제안 |
| D2 | 한 쪽은 1 MiB까지(git이 알려 준 크기로 먼저 거른다), git 호출마다 30초. 아무것도 쓰지 않고 캐시도 없다([ADR-0027](0027-get-write-guard.md) 결정 1) | 제안 |
| D3 | 뷰어가 두 판을 Markdown 화면의 렌더러로 그려 블록(문단·제목·목록 항목의 제 글·표 행·코드 블록·구분선·HTML 자리표시) 단위로 맞댄다. 같은 틈의 같은 종류·같은 그림·낱말 40% 넘게 겹치는 쌍은 고친 블록(낱말 단위 표시), 다른 곳의 똑같은 블록은 옮긴 블록이다. 그림은 두 쪽 모두 지금 트리의 파일이고 그렇다고 적는다 | 제안 |
| D4 | Markdown 문서의 변경 보기와 핀의 [변경 보기]는 [그린 비교] 탭으로 열고, [소스 diff]는 옆 탭에 남는다. 배치는 한 단(뺀 블록을 제자리에 줄 그어 넣는다)이고 옆으로 넘기지 않는다. 핀은 그 핀의 커밋에서만 그 핀의 hunk에 걸친 블록을 표시한다 | 제안 |
| D5 | 핀 레코드·`pins.md`·SKILL·저장 형식은 바꾸지 않는다. 에이전트 계약에는 읽기 경로 하나와 쪽의 오류 이름 넷이 더해진다 | 제안 |

## Trade-off

- 읽기 경로가 하나 는다. 이력 창·범위 규칙·크기 한도·쓰기 없음을 시험이 지켜야 한다. 이미 소스 diff가 같은 커밋의 같은 파일을 줄 단위로 내놓으므로 새로 닿는 정보는 없다.
- 렌더러를 두 번 더 돌린다. 700 KB 문서의 두 판이 Chromium에서 약 0.2초다(설계 §결정 2의 잰 값). 1 MiB를 넘는 쪽은 그리지 않고 소스 diff로 보낸다.
- 옛 판의 그림은 지금 트리의 파일이다. 같은 경로의 그림 파일이 그사이 바뀌었으면 옛 판에도 새 그림이 보인다. 비교 머리의 문장이 그렇다고 말한다.
- 블록 대응은 짐작이다. 문단을 둘로 나누면 고친 블록 하나와 더한 블록 하나로 보일 수 있다. 정확한 줄은 [소스 diff]에 남는다.

## 대안

- **`/api/revision-diff` 에 두 쪽 필드를 더한다.** 경로를 아끼지만 소스 diff만 볼 때도 1 MiB 두 쪽을 읽는다. 기각한다.
- **뷰어가 diff를 거꾸로 적용한다.** 경로가 없지만 HEAD가 아닌 커밋·미커밋 수정·잘린 diff·git과 다른 줄 끝에서 틀린다. 기각한다.
- **원문 줄 diff를 그린 블록에 비춘다.** 낱말 표시도 옮김도 없다. 기각한다.
- **두 단.** 패널을 편 1440 데스크톱에서 비교 칸이 536px라 서지 못한다. PoC의 후보 B(`?cmp=split`)로 보였다.
- **옛 판의 그림을 그 커밋에서 읽는 경로.** 정확하지만 경로가 하나 더 늘고 이력 전체의 트리 그림을 읽게 된다. 다음 단계로 둔다.

## 결과

- 승인되면 PoC를 구현으로 이어 쓰고, 렌더러가 문맥 객체를 받게 고친 뒤(형제 작업 머지 뒤) Handbook([viewer.md](../handbook/viewer.md) §변경 보기, [api.md](../handbook/api.md) §변경 보기와 비교 PDF·§두 커밋 사이, [verification.md](../handbook/verification.md))·CHANGELOG를 같은 변경에서 고친다. 머지 전에 네 기기군 PoC를 보인다.
- 되돌리기는 이전 태그로의 업데이트다. 상태 폴더에 남는 것이 없다.

### 현재 상태 투영

- **영향받는 현재 권위:** 변경 보기(뷰어), 읽기 경로 목록(`security/access.py`), revision 기능(`revisions/`), 에이전트 계약(`api.md`)
- **갱신할 Handbook role/path:** `docs/handbook/viewer.md`(§변경 보기), `docs/handbook/api.md`(§변경 보기와 비교 PDF, §두 커밋 사이), `docs/handbook/verification.md`, `docs/handbook/index.md` 파일 지도
- **효력 형태:** 한 번에 이행
- **완료 증거:** 경로 시험(두 쪽·범위·창 밖·크기·쓰기 없음), 순수 시험(대응·고침·옮김), 브라우저 시험(표시·핀·옆 넘김 없음), 네 기기군 전후 캡처
