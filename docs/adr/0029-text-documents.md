## 맥락

[ADR-0025](0025-html-document-surface.md)로 뷰어가 원문을 직접 그리는 화면이 생겼다. 그러나 일반 텍스트와 소스 코드 파일(그림 스크립트, 참고문헌, 설정, 메모)은 여전히 등록할 수 없다. 사람이 그 줄을 골라 핀을 남길 길이 없다. Markdown 화면은 서버가 센 줄 목록, 쪽 없는 줄 핀, 능력으로 가르는 제안 관문·판정 대상·이력 파일을 이미 갖추었다. 텍스트 문서는 여기서 파싱만 빼면 된다.

이 변경은 에이전트 계약(문서 `kind` 값, `scope` 값, `pins.md` 표시)과 등록 규칙을 넓히고, 남이 쓴 글을 뷰어의 출처에서 보이는 보안 면(글 순서를 바꾸는 문자)을 다룬다. 그래서 소유자 승인이 필요하다.

## 결정

| # | 결정 | 상태 |
| --- | --- | --- |
| D1 | 문서 종류 `text` 를 더한다. 뷰어가 서버의 줄을 하나씩 고정폭으로 보이고, 파싱하지 않는다. 능력은 Markdown과 같다(`takes_line_pins`·`shows_revisions`·`renders_in_browser`·`takes_suggestions`). 뷰어만 그리는 법을 가른다. `pins.md` 의 문서 절 꼬리말은 `— 텍스트(쪽 없음)` 다 | 제안 |
| D2 | `--doc` 경로의 확장자가 닫힌 목록 `TEXT_SUFFIXES` 에 있으면 텍스트 문서다. 대소문자는 가리지 않는다. 목록은 더하기만 한다. 화면이 따로 생길 수 있는 확장자(`.typ`·`.ipynb`)와 흔히 비밀을 담는 확장자(`.env`·`.pem`·`.key`)는 넣지 않는다. 대소문자만 틀린 그림 지도 접미사는 거절한다. 셸과 서버는 같은 목록을 쓰고 시험이 둘을 묶는다 | 제안 |
| D3 | 사다리는 고른 줄(`raw`) → 문단(`para`, 빈 줄 사이) → 들여쓰기 블록(새 `scope` 값 `indent`, 핀 `kind` `indent`)이다. 문단과 블록은 짧은 쪽이 먼저다. 둘 이상의 문단에 걸친 선택은 줄로 저장한다 | 제안 |
| D4 | 텍스트 문서의 줄 핀은 제안 수정을 받고, 판정 핀의 대상은 그 줄이다. 판정 낱말 파일은 지금 자리 규칙(메인 파일의 `stem` + `.limnverdicts.json`)을 따른다 | 제안 |
| D5 | 그린 텍스트는 글자뿐이다. 파서·구문 강조·링크·그림이 없다. 글 순서를 바꾸거나 보이지 않는 문자(양방향 제어, 영폭 공백, 제어 문자)는 원문 문자를 격리된 span 안에 남긴 채 이름으로 보이고, 문서 머리에 개수를 알린다. 긴 줄은 늘 접는다 | 제안 |
| D6 | 바이트 한도(1 MiB, 서버)와 줄 한도(50,000줄, 뷰어)는 Markdown과 같다 | 제안 |

### D3을 고른 근거

들여쓰기 블록은 언어를 가리지 않고 파이썬 함수, YAML 항목, 함수 호출의 인자 목록, `.bib` 항목을 한 번에 잡는다. 파일 전체 단은 한 핀이 문서 전체를 칠하고 80줄을 넘으면 제안 수정을 둘 수 없다. 문단에는 LaTeX 문서의 `para` 를 그대로 쓴다. 빈 줄로 나뉜 덩어리라는 뜻이 같다.

### D5를 고른 근거

리뷰하는 화면이 원문과 다른 순서로 보이면, 사람은 실제와 다른 코드를 승인한다(Trojan Source, CVE-2021-42574). 원문 문자를 지우면 복사한 글이 원문과 달라진다. 격리 span 안에 남기면 둘 다 피한다. 구문 강조는 번들(멈춤 신호)과 토큰을 DOM으로 짓는 보안 면을 늘리는데, 줄 핀에는 필요 없다.

## Trade-off

- 코드에 색이 없다. 긴 코드를 읽기는 편집기보다 불편하다.
- 확장자 없는 파일(`Makefile`, `LICENSE`)과 목록에 없는 확장자는 아직 받지 않는다.
- 같은 폴더에서 `stem` 이 같은 두 문서(`plan.md`, `plan.txt`)는 판정 낱말 파일 하나를 함께 쓴다.
- 들여쓰기 블록은 들여쓰기만 본다. 들여쓰기가 어긋난 파일에서는 블록이 기대와 다를 수 있다. 그때도 고른 줄과 문단 단은 맞다.
- 제안 편집 칸(`textarea`)은 양방향 문자를 브라우저 순서대로 보인다. 알림 줄로 덮는다.
- 옛 서버로 되돌리려면 먼저 텍스트 문서를 인스턴스 설정에서 빼야 한다. 상태 폴더의 핀은 그대로 읽힌다.

## 대안

- **다른 종류가 차지하지 않은 확장자를 모두 텍스트로.** 오타·바이너리·나중의 종류를 삼켜 기각했다.
- **`--doc` 문법에 종류를 적는다.** 등록 문법을 바꿔 기각했다.
- **`text`·`code` 두 종류.** 행동 차이가 없어 기각했다.
- **구문 강조 번들.** 1단계에서는 기각한다. 필요해지면 별도 ADR로 다룬다.
- **긴 줄을 상자 안에서 옆으로 넘긴다.** 휴대폰에서 끌기가 글 고르기와 부딪혀 기각했다.

## 결과

- 에이전트 계약에 값 셋(문서 `kind` `text`, `scope` `indent`, 핀 `kind` `indent`)과 `pins.md` 표시 하나(문서 절 꼬리말)가 더해진다. 새 경로·필드는 없다.
- 저장 형식에 새 필드는 없다. 텍스트 핀은 `page` 없는 줄 핀이다.

### 현재 상태 투영

- **영향받는 현재 권위:** `runtime/documents.py` 의 종류·능력·확장자 목록, 등록(`administration/serve_documents.py`, `instance_documents.sh`), `scope` 값(`pins/editing/values.py`), `pins.md`(`pins/listing/render.py`), 뷰어의 텍스트 화면, 에이전트 계약(`api.md`, SKILL).
- **갱신할 Handbook role/path:** purpose `docs/handbook/purpose.md`(지원 범위), `docs/handbook/domain.md`(능력 표, 사다리, 텍스트 문서), `docs/handbook/viewer.md`(텍스트 화면), `docs/handbook/api.md`(값 목록, 낱말 파일 자리), `docs/handbook/instances.md`·`docs/handbook/operations.md`(받는 확장자), `skill/SKILL.md`·`skill/SKILL.ko.md`.
- **효력 형태:** 승인 뒤 한 번에(PoC에 시험과 문서를 더한다).
- **완료 증거:** 계약 스냅숏에 텍스트 문서와 `indent` 가 있다. 직전 릴리스가 텍스트 핀 레코드를 지우지 않는다. 숨은 문자 시험 문서가 원문 순서대로 보인다. 네 기기군 실측이 있다.
