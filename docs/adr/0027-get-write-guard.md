## 맥락

Limn 0.4.48의 GET 경로 중 9개가 조건에 따라 방문·핀 재동기화·휴지통 정리·비교 루트 생성으로 디스크를 바꾼다. 기능 캐시·Git 프로세스까지 포함하면 12개이며, 인증 캐시는 등록된 29개 GET 경로·경로군 모두에 조건부로 걸린다. HEAD는 구현되어 있지 않아 501이다. 전수 목록과 파일:줄은 설계의 §현재 코드 대조 — 쓰기 목록에 있다.

다른 사이트가 하위 자원 GET을 보내도 방문 기록이 생겼다. Chromium·Firefox의 외부 이동 뒤 뷰어는 전체 meta·pins를 `same-origin`으로 요청했다. 그래서 처음 요청의 `cross-site`·`same-site`만 막아서는 기동 쓰기가 남는다. 측정은 빈 임시 상태의 로컬 인증으로 했으며 실제 Serve·신뢰 프록시와 조건부 핀/휴지통 쓰기는 미측정이다. 공격자가 고른 핀 편집·권한 상승·응답 유출은 확인되지 않았다. 비교 GET이 컴파일을 시작한다는 증거도 없다. 비교 컴파일은 POST다.

## 결정

다음은 2026-11-05 소유자가 승인한 결정이다. 구현 전까지 현재 동작은 0.4.48 그대로다.

1. GET과 향후 HEAD는 영속 파일·폴더를 바꾸지 않고 쓰는 작업을 예약하지 않는다. 한도 있는 조회용 메모리 캐시와 Git 읽기 프로세스만 예외로 한다. HTTP 경계에서 나눈 읽기 권한이 기능 협력자의 저장 가능성까지 제한해야 한다.
2. `/`·전체 meta에서 방문 기록을 빼고 뷰어 기동·폴링은 GET만 유지한다. 사람 파일은 권한을 검사한 실제 변경 POST에서 갱신한다. 열기만 한 사람의 자동 등록·방문 기록을 포기한다. 기록도 핀 참여도 없는 새 독자는 사람 목록·멘션 후보에 없고 `@`로 적어도 알림이 가지 않는다. 편집자는 첫 변경 뒤에, `viewer`는 소유자의 `limn member add` 뒤에 나타난다. 기존 멤버·역할은 보존한다.
3. 핀 조회는 현재 anchor를 메모리에서 계산한다. 재동기화 저장·파생 Markdown·휴지통 정리는 시작과 요청과 무관한 60초 주기로 옮긴다. 실행은 하나만 겹침 없이 진행하고 변경이 없으면 쓰지 않는다. 실패하면 원본을 보존한다. HTTP pins.md는 즉시 계산하고 디스크 파일은 정상 가동 중 한 주기 늦을 수 있다. 긴 실행·실패에는 더 늦을 수 있다.
4. 비교 GET은 기존 루트만 읽고, 루트가 없으면 idle/not-ready로 답한다. 폴더 생성·정리·컴파일은 권한을 받은 POST에 둔다.
5. 순수 GET은 Fetch Metadata가 없거나 외부 출처여도 기존 인증·입장 검사 뒤 허용한다. curl·agent의 헤더 계약을 늘리지 않는다. Referer·Origin 부재를 사람 승인으로 삼지 않는다. 읽기 자원 남용은 남는 위험이다. 서버 로그는 '영속 쓰기 없음'에 들지 않는다. 반복 오류(아주 긴 핀 번호의 500 traceback, 손상 레코드 경고)가 journal을 늘리지 않게 경로 인자 길이 제한과 반복 로그의 상한·중복 억제를 둔다.

## Trade-off

- 채팅·메일·북마크로 곧장 뷰어를 열 수 있고 탭별 입장 상태가 필요 없다. 반면 열기만 한 참가자는 자동 발견되지 않아 방문·참가자 표시의 의미를 바꿔야 한다.
- HTTP pins.md의 필드와 즉시 계산은 유지하지만 디스크 파일 독자는 갱신 지연을 감수한다. 요청과 독립된 유지 실행의 권한·수명·실패 복구를 구현해야 한다.
- 상한 있는 메모리 캐시·Git 조회는 남긴다. GET을 무비용으로 만들거나 읽기 DoS까지 막는 결정은 아니다.
- 순수 조회와 저장 경로 분리는 헤더 조건 하나보다 변경 범위가 넓다. 새 경로가 쓰기를 우회하지 못하게 등록 전수 검사와 기능 경계 검증이 필요하다.

## 대안

- **외부 이동 이어 가기 화면.** 하위 요청 차단과 이동 뒤 기동을 함께 막지만 메일·채팅 링크마다 추가 클릭과 새 입장 상태가 생긴다. 헤더 없는 사람 요청도 처리해야 한다. 추천하지 않는다.
- **외부 이동에 쓰기 없는 뷰어.** 즉시 읽을 수 있지만 모든 기동·폴링·직접 API를 탭별 읽기 능력에 묶어야 한다. 쿠키 하나로 정상 탭과 외부 탭을 함께 허용하면 우회된다. 추천하지 않는다.
- **Fetch Metadata 차단만 또는 멱등·상한 강화만.** 전자는 이동 뒤 같은 출처 기동을 놓치고 후자는 의도 없는 한 번의 쓰기를 남기므로 단독 해결로 삼지 않는다.

## 결과

소유자는 기본 방어 B, 읽기만 한 사람의 기록 포기, 60초 유지와 파생 파일 지연, 헤더 없는 순수 조회 허용, 캐시·Git 조회 예외를 모두 추천대로 정했다(설계 §소유자 결정). 이어서 구현 계획을 쓰며 제품 코드·테스트는 이번 변경에서 고치지 않는다. Handbook의 현재 구현·채택값도 아직 바꾸지 않는다.

구현은 모든 경로의 정상·오류·304와 외부 이동→기동→폴링에서 파일·폴더·쓰기 작업 예약이 없음을 검증한다. 조건부 쓰기를 유발할 상태도 따로 둔다. 화면·문구·조작이 바뀌면 [workflow.md](../handbook/workflow.md) §화면 변경은 PoC를 먼저 보인다의 네 기기군 PoC를 머지 전에 보인다. 마지막 구현 커밋은 별도 Codex 리뷰를 거친다. 새 영속 형식은 제안하지 않으며 이전 판으로 되돌리면 기존 GET 쓰기가 다시 생긴다는 한계를 안내한다. 이 ADR은 HTML 화면 설계의 유보를 구체화하며 승인된 ADR을 대체하지 않는다.
