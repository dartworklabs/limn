# ADR-0050: 번호 배지를 끌어 핀의 위치를 다시 잡는다 — 끄는 것은 한 글줄 짚개이고, 확정은 조각으로 스냅한 배너가 받는다

| | |
| --- | --- |
| **번호** | ADR-0050 |
| **제목** | 번호 배지를 끌어 핀의 위치를 다시 잡는다 — 끄는 것은 한 글줄 짚개이고, 확정은 조각으로 스냅한 배너가 받는다 |
| **상태** | 제안 |
| **결정일** | 2026-11-19 |
| **결정자** | Limn 소유자. 제스처의 기기별 조건, 확정 모양, 끌 수 없는 핀, 쪽 안으로의 한정, "놓는 즉시 저장" 기각, 문턱 값을 2026-11-15 에 PR #487 의 PoC 를 보고 골랐다(D1·D2·D4·D6). ADR-0049 가 마크를 조각 여러 개로 바꾼 뒤 새로 열린 둘 — 끄는 사각형과 조각 스냅의 범위 — 을 2026-11-19 에 골랐다(D3·D5) |
| **출처** | 설계는 [spec](../superpowers/specs/2026-11-19-pin-badge-drag-reposition-design.md). 2026-11-15 PR #487(닫힘, 브랜치 `t3/pin-drag-reposition-and-tracking`)의 PoC 와 그 설계 문서 §결정 7·§소유자가 정한 것. 끄는 사각형의 비교는 `limn.pins.location.source.by_synctex` 의 격자 표본 규칙과 [ADR-0049](0049-pin-marks-follow-the-range.md) §명료화의 쪽 높이 비율 측정 |
| **부분 대체** | 없음. [ADR-0049](0049-pin-marks-follow-the-range.md)가 LaTeX 줄 핀의 마크와 '새 핀' 상자에 정한 조각 규칙을 '새 위치' 상자까지 넓히며, 그 결정의 어느 조항도 바꾸지 않는다 |

## 맥락

저장된 핀의 위치를 고치는 길은 하나다. 카드 → [수정] → [위치 다시 잡기] → 선택 모드 → PDF 에 새 사각형 끌기 → 배너의 [이 위치로 바꾸기]. 쪽 위의 마크와 번호 배지는 이미 거기 있고 배지는 이미 이름 있는 버튼인데, 그 배지에서 바로 끌 길이 없다.

ADR-0049 가 그사이 두 가지를 바꿨다. 첫째, 마크가 상자 하나에서 **조각 여러 개**가 되고 번호 배지는 첫 조각에만 붙는다. 둘째, 작성 중인 '새 핀' 상자가 드래그한 사각형이 아니라 **고른 줄 범위가 차지하는 영역**을 그린다. 그래서 2026-11-15 에 승인된 "핀의 지금 상자를 그 자리로 옮긴 사각형을 보낸다, 크기는 바꾸지 않는다"가 더는 성립하지 않는다 — 그때 그 상자는 사람이 끈 **낱말 크기** 사각형이었고, 지금은 **문단 전체 또는 그림 전체**다.

그리고 ADR-0049 D1 이 '새 핀' 상자만 말하고 '새 위치' 상자를 말하지 않아 공백이 남았다. 지금 줄 핀의 위치 다시 잡기는 끈 사각형을 보이며 [이 위치로 바꾸기]를 묻는데, 저장되면 마크는 그 범위의 조각으로 선다. 사람이 긁은 몇 낱말을 보고 확정하지만 핀이 쥐는 것은 문단 전체다 — ADR-0049 가 '새 핀' 상자에서 없앤 바로 그 어긋남이다.

## 결정

| | | |
| --- | --- | --- |
| D1 | **손잡이는 번호 배지 하나다.** `.mark button.mark-jump` 에서 시작한 누름만 위치를 다시 잡는다. `.mark` 상자는 `pointer-events: none` 을 유지하고, 그 위를 끄는 것은 지금처럼 새 선택이다([viewer.md](../handbook/viewer.md) §조작 한눈에의 마크 배지 행이 이미 선언한 동작). 문턱은 `TAP_SLOP`(8px)이고, 넘지 않은 누름은 전과 같이 배지의 클릭이다. **마우스는 모드 없이 바로 끌고, 터치는 그 핀의 [위치 다시 잡기] 모드가 켜져 있을 때만 끈다** — 모드 밖의 배지는 길게 누르기 설명을, `[선택]` 모드의 다른 핀 배지는 새 상자를 시작하는 지금 동작을 지킨다 | 제안 |
| D2 | **끌 수 있는 핀은 판정이 없는 열린 핀이다.** 편집 카드가 [위치 다시 잡기] 버튼을 숨기는 판정과 같다. 판정 핀은 `400 verdict_fixed`, 닫힌·검토 대기 핀은 `409` 로 거절되므로 끌리기 전에 막는다. 거절로 알리지 않는다 | 제안 |
| D3 | **끄는 것은 한 글줄 짚개다.** 손에 붙는 사각형과 서버에 보내는 사각형은 쪽 폭 ±7%·쪽 높이 ±0.6% 의 한 글줄 띠이고, 탭과 길게 누르기가 문단을 집을 때 이미 보내는 `quickBox` 와 같은 모양이다. 핀의 첫 조각 상자를 그대로 옮기지 않는다 — 그 상자는 문단 높이라 조금만 옮겨도 옛 문단과 새 문단에 반씩 걸리고, 어느 쪽이 집히는지는 `by_synctex` 의 격자 표본(가로 2~5 × 세로 2~6) 밀도가 정해 사람이 예측할 수 없다. 쪽 높이의 최대 26%인 float 상자는 쪽 안에서 옮길 자리도 거의 없다. 짚개는 표본을 4~10 점으로 줄여 드래그의 임계 경로도 짧다 | 제안 |
| D4 | **쪽 안에서만 끈다.** 짚개의 중심은 배지를 누른 쪽 요소 안으로 자른다. 쪽을 넘기려면 [위치 다시 잡기]로 새 상자를 그린다. 짚은 자리가 만든 **범위**가 쪽을 넘어 조각이 두 쪽에 서는 것은 막지 않는다 — ADR-0049 가 이미 그리는 모양이다 | 제안 |
| D5 | **'새 위치' 상자는 조각으로 스냅한다. 배지 드래그만이 아니라 모든 위치 다시 잡기에서 그렇다.** 작성 중인 '새 핀' 상자와 같은 기구를 쓴다 — 첫 조각에 상자가 서고 조각마다 상자를 하나 더 그리며, 답이 "조각 없음"이면 끈 사각형으로 돌아간다. 같은 상자·같은 배너인데 시작 제스처에 따라 보이는 것의 뜻이 달라지면, 사각형을 그려 들어온 사람은 긁은 자리를 보고 확정한 뒤 마크가 다른 크기로 서는 것을 보게 된다 | 제안 |
| D6 | **확정은 기존 배너가 받는다.** `지금 L5-L6 · 새 L20-L24` 와 `[이 위치로 바꾸기] [취소]` 그대로다. 새 버튼도 새 흐름도 없다. **놓는 즉시 저장하지 않는다** — 저장될 마크가 짚은 띠와 크기·자리·쪽까지 다르므로, 즉시 저장은 사람이 비교를 보기 전에 커밋하게 만든다. 확정할 자리가 PDF 영역 밖이면(쪽을 넘는 범위) 그 조각을 영역 안으로 데려온다. 배지에서 시작한 위치 다시 잡기는 읽을 편집 카드가 없으므로 **그 핀 자신의 `rev`** 를 기준으로 저장한다 | 제안 |
| D7 | **영역 핀(보기 전용 PDF)만 핀의 상자를 그대로 옮긴다.** 영역 핀에는 줄 범위가 없어 조각이 없고, 사람이 고른 넓이 자체가 핀의 대상이다(그래서 `/edit` 가 핀의 모양을 바꾸지 않는다). 옮기는 일이 곧 크기를 지키는 일이므로 D3 의 짚개를 쓰지 않는다 | 제안 |

## Trade-off

- **'핀을 집어 옮긴다'는 느낌이 약해진다.** 손에 붙는 것은 핀의 상자가 아니라 한 글줄 띠이고, 떠난 자리의 마크는 핀 목록이 계속 그려 남아 있다. 그래서 끄는 동안 쪽 위에 상자가 둘 보인다. 그 대신 집히는 범위가 또렷하다.
- **배지의 누름에 두 뜻이 생긴다.** 8px 안이면 클릭, 넘으면 드래그다. 손이 떨리는 사람에게는 카드로 가려던 누름이 위치 다시 잡기를 시작할 수 있다. 되돌리기는 Esc 나 배너의 [취소] 한 번이고 저장된 것은 없다.
- **기존 길의 화면이 바뀐다**(D5). 사각형을 그려 들어오던 사람은 지금까지 보던 끈 사각형 대신 조각들을 본다. 그 길의 회귀 위험을 지며, 네 기기군 여덟 크기 PoC 의 전후 비교에 이 길도 들어간다.
- **짚개가 집는 것은 기본 단계다.** 핀이 쓰던 사다리 단계(문단·환경)와 다를 수 있다. 배너가 새 범위를 글로 말하고 상자가 그 범위를 그리므로 확정 전에 보이지만, 단계를 맞춰 주지는 않는다.
- **터치는 두 단계다.** 카드 → 모드 → 끌기. 소유자가 2026-11-15 에 기존 두 제스처(배지의 길게 누르기 설명, `[선택]` 모드의 배지 드래그)를 하나도 포기하지 않는 쪽으로 이 대가를 골랐다.

## 대안

- **핀의 첫 조각 상자를 그대로 옮긴다** (닫힌 PR #487 의 문장). 느낌은 가장 또렷하지만 D3 의 이유로 집히는 범위가 표본 밀도에 맡겨진다.
- **짚개 + 떠난 자리를 흐리게.** D3 에 원래 마크의 투명도를 더하는 것이다. 원래 마크는 어차피 남아 있어 '떠난 자리'가 이미 보이므로, 더 세게 말하는 것뿐이다. 마크의 상태색과 흐림이 겹쳐 보이는 문제가 생겨 PoC 에서 볼 후보로 남긴다.
- **놓는 즉시 저장 + 되돌리기 칩.** 누름이 가장 적다. 저장될 마크가 짚은 띠와 다르므로 사람이 비교를 보기 전에 커밋하게 되어 소유자가 기각했다.
- **마크 상자 전체를 손잡이로.** `pointer-events` 를 켜면 마크 위의 새 선택을 잃는다. [viewer.md](../handbook/viewer.md) 가 그 동작을 이미 선언했다.
- **'새 위치' 상자의 스냅을 배지 드래그에만.** PoC 범위와 회귀 위험이 가장 작다. 같은 배너가 시작 제스처에 따라 다른 것을 보이게 되어 기각했다.

## 결과

- 마우스 사용자는 배지를 끌어 한 번에 위치를 다시 잡는다. 네 번 누르고 한 번 끌던 일이 한 번 끄는 일이 된다.
- 확정하기 전에 보이는 상자가 저장되면 설 자리다. 사각형을 그려 들어오는 기존 길에서도 그렇다.
- 저장 형식·HTTP API·상태 이름은 하나도 바뀌지 않는다. 서버 코드를 고치지 않으므로 옛 서버와도 같은 요청을 주고받는다.
- 뷰어의 조각 그리기 기구가 작성 중인 선택과 '새 위치' 상자 둘의 소유자를 가린다. 전에는 `.sel-part` 를 전역에서 찾아 지워, 두 상자가 동시에 있으면 한쪽이 다른 쪽의 조각을 지웠다.
