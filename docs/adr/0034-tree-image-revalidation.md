## 맥락

ADR-0030은 두 비용을 받아들였다. 탭을 연 채 그림 파일만 바뀌면 페이지를 다시 열 때까지 옛 그림이 보인다. 바뀌지 않은 그림의 `304` 도 파일을 한도까지 읽고 해시를 잰다. 앞의 것을 고치려면 그림마다 폴링해야 하고, 뒤의 것을 고치려면 메타데이터로 답해야 해서 둘 다 하지 않았다.

그림을 다시 그리는 스크립트를 돌리며 문서를 보는 것이 이 화면의 흔한 쓰임이다. 다시 열면 읽던 자리를 잃는다. 폴링을 하면 `304` 의 비용이 묻는 횟수만큼 곱해진다. 8 MiB 그림 하나를 읽고 해시를 재는 데 약 12 ms가 든다. 그래서 두 결정은 함께 간다.

## 결정

| # | 결정 | 상태 |
| --- | --- | --- |
| D1 | Markdown 문서가 열려 있으면 가벼운 폴링이(원문이 바뀌지 않은 차례에) 불러오기를 마친 트리 그림을 `GET /api/asset` 의 재검증(`cache:'no-cache'`)으로 다시 묻는다. 화면에 있거나 문서 영역 높이 하나 안에 있는 그림 가운데 가까운 것부터 많아야 6개이고, 4초에 한 번, 요청은 한 번에 하나다. 태그가 달라진 그림은 주소에 `&v=<새 태그>` 를 붙여 다시 받는다(서버는 `doc`·`path` 만 읽는다). 보이는 그림의 태그는 그 그림이 불러와질 때 브라우저 캐시에 남긴 응답에서 읽는다(`cache:'only-if-cached'`, 서버에 묻지 않음). 캐시에 없으면 태그를 모르는 것으로 보고 첫 묻기에서 지금 태그의 주소로 한 번 옮긴다. 경로·필드는 더하지 않는다 | 승인됨 |
| D2 | 서버는 실행마다 메모리에만, 보낸 그림의 내용 태그를 그 파일의 정체(해석한 경로, `st_dev`·`st_ino`·크기·`st_mtime_ns`·`st_ctime_ns`)와 묻는 접미사로 기억한다(많아야 1,024개, 가장 오래 묻지 않은 것부터 버림). `If-None-Match` 가 같은 정체의 기억한 태그와 맞으면 파일을 열지 않는 no-follow stat 하나로 `304` 다. 바뀐 지 2초가 안 된 파일은 기억하지 않는다. `200` 은 늘 읽고 해시를 잰다. 태그는 늘 내용 해시다 | 승인됨 |

## Trade-off

- 열린 Markdown 탭 하나가 많아야 4초에 6개, 초당 1.5개의 조건부 요청을 보낸다. 바뀌지 않았으면 서버에서는 stat 하나다(8 MiB 그림 약 0.06 ms).
- 문서 영역에서 먼 그림, 늦게 불러오기가 아직 시작하지 않은 그림, 불러오지 못해 대체 글이 된 그림은 묻지 않는다. 이런 그림은 다시 그리거나 다시 열 때 보인다. 그림만 바꾼 커밋은 여전히 변경 보기에 나오지 않는다.
- 캐시를 지웠거나 끈 브라우저는 그림마다 한 번 더 받는다. 모르는 태그를 서버의 지금 태그로 메우면 옛 그림이 끝내 남기 때문이다.
- `304` 는 파일 메타데이터를 믿는다. 같은 크기로 다시 쓰고 mtime을 되돌려도 ctime이 달라 다시 읽는다. ctime을 믿을 수 없는 파일 시스템(일부 네트워크·FUSE 마운트)에서는 그런 재작성이 다음 변경 때까지 `304` 로 남을 수 있다. 태그 자체는 내용 해시라, 메타데이터만 바뀐 파일(`touch`)은 다시 읽어도 같은 태그다.
- 메모리 기억은 많아야 1,024개다. 아무것도 쓰지 않으므로 [ADR-0027](0027-get-write-guard.md)의 읽기 예외(한도 있는 메모리 캐시) 안이다.

## 대안

- **ADR-0030 그대로.** 바뀐 그림을 보려면 다시 열어야 하고 읽던 자리를 잃는다. 기각한다.
- **서버가 파일 변경을 밀어 준다(SSE·WebSocket, 감시자).** 새 통로와 감시 상태가 생긴다. 기각한다.
- **그림 정체를 돌려주는 새 경로.** 에이전트 계약에 경로가 늘고, 결국 그림을 다시 받아야 한다. 기각한다.
- **태그를 메타데이터로 짓는다.** ADR-0030 D6의 내용 태그를 버리게 되고, 내용이 같아도 태그가 달라진다. 기각한다.
- **문서의 모든 그림을 묻는다.** 비용이 문서 크기를 따른다. 보는 자리 가까이로 좁힌다.
- **`304` 마다 읽고 해시를 잰다(ADR-0030).** 폴링과 함께면 탭 하나가 4초마다 8 MiB 그림 6개, 약 72 ms의 서버 일을 시킨다. 기각한다.

## 결과

- 브랜치 `fix/md-surface-followups` 가 D1·D2를 구현했고, 소유자 승인 뒤 머지한다. Handbook([viewer.md](../handbook/viewer.md) §그림, [api.md](../handbook/api.md) §화면·PDF·정적 파일)이 이것을 현재 규칙으로 적는다.
- 에이전트 계약은 바뀌지 않는다. 경로·필드·이유 코드가 그대로이고, `&v=` 는 서버가 읽지 않는 쿼리다.
- 소유자는 D1의 범위(6개·4초·영역 높이 하나)와 D2가 메타데이터를 믿는 정도를 그대로 받아들였다. ctime을 믿을 수 없는 마운트에서 같은 정체로 다시 쓴 그림이 다음 변경까지 `304` 로 남을 수 있는 비용을 감수한다. "기억한 태그도 N분마다 다시 읽는다"로 좁히는 안은 쓰지 않는다.
