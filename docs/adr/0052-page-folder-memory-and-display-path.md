# ADR-0052: 화면 빌드의 쪽은 빌드 이름으로 기억하고, 문서의 표시 경로는 기동 때 푼 경로다

| | |
| --- | --- |
| **번호** | ADR-0052 |
| **제목** | 화면 빌드의 쪽은 빌드 이름으로 기억하고, 문서의 표시 경로는 기동 때 푼 경로다 |
| **상태** | 승인됨 |
| **결정일** | 2026-11-19 |
| **결정자** | Limn 소유자. v0.4.63 성능 진단의 다음 작업으로 "가벼운 폴링의 파일 읽기 줄이기"를 골랐고, 설계 문서의 B안(중복 읽기 없애기와 쪽 폴더 기억, 열쇠는 빌드 이름)과 "표시 경로는 기동 때 푼 경로로"를 승인했다. 구현과 검증이 끝난 뒤 그 결과(측정, `main`과의 응답 대조, 독립 리뷰)를 보고, 구현 중에 바뀐 둘(D5의 한도 규칙, D6의 늦게 읽는 meta)을 받아들이고 이 결정을 ADR로 남기기로 했다 |
| **출처** | 2026-11-19 측정(macOS, 문서 셋·LaTeX 29쪽인 시험 원고, 합성 핀 1,002개): 폴링 한 번의 파일 시스템 호출 프로파일, 단계별 측정용 실행 래퍼, `main`과 번갈아 잰 폴링 지연, `main`과의 차등 비교 23단계 184건, 변이 34개, 독립 리뷰. 설계는 [spec](../superpowers/specs/2026-11-19-light-poll-file-reads-design.md), 시공은 [plan](../superpowers/plans/2026-11-19-light-poll-file-reads.md) |
| **부분 대체** | 없음. [ADR-0027](0027-get-write-guard.md)의 "한도 있는 메모리 캐시" 예외 안에 있고, [ADR-0050](0050-kept-pin-lines.md) D6의 "파일 위치 판정은 요청 사이에 기억하지 않는다"를 바꾸지 않는다. 표시 경로는 위치 판정이 아니다 |

## 맥락

뷰어는 탭이 보이는 동안 5초마다 가벼운 폴링(`GET /api/meta?light=1`)을 보낸다. 시험 원고에서 이 요청 하나가 파일 시스템 호출을 290번 했다. 호출마다 요청 스레드가 인터프리터를 내놓고, 그사이 다른 스레드가 계산을 시작하면 되찾는 데 전환 간격(5 ms)까지 걸린다. 그래서 다른 읽기가 계산 중일 때 폴링의 지연은 폴링이 하는 호출 수를 따랐다. 계산만 하는 스레드 하나 뒤에서 호출 하나가 약 5 ms였다.

290번의 대부분은 같은 요청이 이미 읽은 것을 다시 읽거나, 발행된 뒤 바뀌지 않는 것을 다시 읽는 일이었다. 고른 문서의 요약을 두 번 만들고, 요약마다 쪽 포인터를 두세 번 읽고, 화면 빌드의 쪽 그림 29장을 요청마다 두 번씩 열고, 문서의 표시 경로를 만들려고 요청마다 링크를 풀었다.

요청 사이에 무엇을 남기는 일은 이 저장소에서 조심해 온 일이다. 그래서 무엇이 바뀌지 않는 값인지, 무엇으로 "지난번과 같다"를 아는지, 무엇은 남기지 않는지를 정해야 했다.

## 결정

| | | |
| --- | --- | --- |
| D1 | **실행은 화면 빌드의 쪽 폴더가 가진 쪽 이름의 수와 쪽마다의 픽셀 크기를 한 번 읽어 기억하고, 열쇠는 문서 상태 폴더와 빌드 이름이다.** 시각 이름의 쪽 폴더는 숨긴 이름으로 다 쓴 뒤 한 번의 rename으로 발행하고, 화면에 있는 동안 아무도 쓰지 않으며, 그 이름은 다른 빌드에 다시 주지 않는다. 같은 전제로 그 이름의 쪽 그림 주소를 브라우저가 1년 동안 캐시한다. 묻는 것은 문서 요약뿐이고, 이름으로 부른 빌드(pick, 핀의 쪽 검사)는 전처럼 디스크에서 읽는다. 포인트 크기는 요청마다 지금 dpi로 계산한다 | 승인됨 |
| D2 | **폴더의 stat과 시계를 열쇠나 조건에 넣지 않는다.** 폴더의 inode와 mtime을 더하면 손으로 그림을 지우거나 더한 경우를 잡지만, 그림을 제자리에서 고친 경우와 굵은 시계의 한 눈금 안에 일어난 두 변화는 잡지 못한다. 반쯤만 막는 확인을 위해 정착 시간과 주입한 시계, 드물게 깨지는 시험을 들이지 않는다 | 승인됨 |
| D3 | **읽은 것은 셋이 모두 맞을 때만 담는다.** 이름이 시각 이름이다(옛 배치의 `pages` 는 담지 않는다). 읽기가 온전했다(이름이 하나 이상이고 모든 그림의 크기를 읽었다). 읽은 뒤에도 쪽 포인터가 그 이름을 가리킨다(쪽 교체와 겹친 읽기는 지워지는 중인 폴더의 반쯤 남은 목록일 수 있다). 담지 않은 폴더는 요청마다 읽고 답은 같다 | 승인됨 |
| D4 | **바뀌는 것은 기억하지 않는다.** 쪽 포인터, 빌드 표식 세 파일, 빌드 이력, 빌드 상태, 원고 수정 시각은 요청마다 읽는다. 대신 요청 하나가 문서마다 한 번만 읽는다. 표식을 기억하려면 파일의 판을 stat으로 가려야 하고, 그것은 ADR-0050 D2가 기각한 조건들을 다시 들인다 | 승인됨 |
| D5 | **기억은 문서마다 빌드 하나, 쪽 수의 합 4,096까지다.** 문서의 새 빌드를 담을 때 그 문서의 앞 빌드를 버린다. 남은 자리에 들어가지 않는 폴더는 담지 않고 이미 담은 폴더는 둔다. 자리를 내려고 앞서 담은 폴더를 버리면, 화면의 쪽이 한도를 넘는 인스턴스에서 폴링마다 문서들이 서로를 밀어내 아무것도 남지 않는다. `RuntimeResources`가 실행마다 하나를 소유하고 디스크에 쓰지 않는다 | 승인됨 |
| D6 | **빌드가 답하는 문서 요약은 요약을 답할 때 완성하고, meta 조각(쪽 크기, 빌드 표식)은 소비자가 처음 물을 때 읽는다.** 요약만 쓰는 조회(`GET /api/docs`, meta의 다른 문서)는 그 읽기를 치르지 않는다. 문서 조회와 빌드 사이의 선언에 조회를 더하지 않는다. 선언 모듈의 공개 서명에 `dict`를 새로 싣지 못하기 때문이다 | 승인됨 |
| D7 | **문서의 표시 경로는 문서를 만들 때 한 번 푼 경로에서 나온다.** 응답의 `path`, `pins.md` 머리말의 문서 경로, 보기 전용 PDF의 pick 응답 `pdf` 가 이 값이다. 요청마다 링크를 풀지 않는다. 변경 보기가 문서의 파일을 이름 붙이는 규칙과 같다. 표시 값일 뿐이고, 읽을 권한과 핀의 파일 위치 판정은 전처럼 읽는 자리에서 한다 | 승인됨 |

## Trade-off

- **얻은 것.** 폴링 한 번의 파일 시스템 호출이 시험 원고에서 290번에서 22번이 됐고 쪽 수와 무관해졌다. `main`과 번갈아 잰 폴링의 중앙값은 무거운 읽기 하나 뒤 100 → 6 ms, 둘 뒤 240 → 28 ms, 넷 뒤 562 → 123 ms, 계산만 하는 스레드 하나 뒤 1,884 → 162 ms다. 한 요청이 쪽 포인터를 한 번만 읽으므로 한 응답에 두 빌드가 섞이지 않는다.
- **감수한 것.** 발행된 쪽 폴더 안의 그림을 손으로 지우거나 바꾸면 그 실행은 처음 읽은 쪽을 다음 빌드나 재시작까지 답한다. 서버가 도는 동안 주 파일이나 그 위 폴더를 다른 곳을 가리키는 링크로 바꾸면 표시 경로는 재시작까지 기동 때의 값이다. 두 경우 말고는 `main`과 응답이 같다. meta 조각을 읽는 순간에 파일 읽기가 일어난다. 실행마다 쪽마다 약 200바이트를 쓴다.
- **새로 생긴 의무.** D1의 전제는 코드가 스스로 지키지 못한다. 발행된 쪽 폴더에 다시 쓰는 코드를 더하면 기억이 낡는다. 지금 그런 코드는 없고(쪽 교체는 화면 빌드와 바로 앞 빌드를 건드리지 않는다), 구현 뒤의 전체 시험에서 발행된 폴더를 뷰어가 읽은 뒤 손으로 고치던 시험 하나가 이 전제에 걸려 준비 단계를 옮겼다. 구현 직후의 독립 리뷰는 처음의 한도 규칙("먼저 담은 폴더부터 버린다")에서 D5가 적은 절벽을 재현했다.
- **주지 않는 것.** 무거운 읽기가 계산 슬롯 수(4)보다 많을 때의 슬롯 대기는 그대로다(여덟 뒤 594 ms 가운데 527 ms). 원고 수정 시각의 기억은 2초이고 뷰어의 폴링은 5초 간격이라, 뷰어 하나의 폴링은 올 때마다 LaTeX 문서의 빌드 루트를 훑는다. 원고 파일이 300개면 이 결정 뒤에도 폴링 한 번이 약 980번 호출하고 그 대부분이 훑기다.

## 대안

- **기억 없이 중복 읽기만 없앤다.** 새 상태가 없어 틀릴 조건이 없지만 호출이 쪽 수에 비례해 남는다. 29쪽에서 135번이고, 측정한 지연은 절반까지만 줄었다.
- **폴더의 stat을 열쇠에 더한다.** D2에서 기각했다.
- **표식 파일도 stat이 같으면 다시 읽지 않는다.** D4에서 기각했다. 얻는 것은 호출 열 번 남짓이다.
- **쪽 크기를 발행할 때 파일 하나에 적어 둔다.** 상태 폴더에 새 파일이 생기고, 이전에 발행된 폴더에는 그 파일이 없어 옛 길이 함께 남는다.
- **요약만 답하는 조회를 문서 조회와 빌드 사이에 하나 더한다.** 승인 때의 문안이었다. `dict`를 돌려주는 새 선언은 원시 타입 규칙과 타입 기준선을 올리고, 요약을 타입 있는 값으로 바꾸는 일은 이 변경의 범위를 넘는다. D6으로 바꿨다.
- **한도를 넘으면 먼저 담은 폴더부터 버린다.** 승인 때의 문안이었다. D5가 적은 절벽 때문에 바꿨다.
- **표시 경로를 요청마다 푼 채로 둔다.** 응답은 어떤 경우에도 전과 같지만, 그러면 폴링 한 번에 남는 호출 55번 가운데 33번이 그 `lstat`이다.

## 결과

- 규칙의 본문은 [build-sync.md](../handbook/build-sync.md) §쪽 교체와 §폴링 한 번이 읽는 것에, 실행 자원과 표시 경로는 [architecture.md](../handbook/architecture.md) §의존 방향에, 메모리 캐시 예외와 `path` 의 수명은 [api.md](../handbook/api.md) §GET의 영속 무효과와 §버전·상태·사람에, 호출 수를 세는 검사는 [verification.md](../handbook/verification.md) §불안정한 테스트에 있다.
- 발행된 쪽 폴더에 쓰는 새 코드는 D1의 전제를 다시 다뤄야 한다. 화면 빌드의 쪽을 바꾸는 길은 새 폴더를 발행하고 포인터를 옮기는 것이다.
- 원고 폴더 훑기를 줄이는 일과 계산 슬롯 대기를 줄이는 일은 이 결정의 범위 밖이고, 따로 설계한다.
