# ADR-0007: 서버 머신의 에이전트는 인스턴스별 토큰 파일로 인증한다

- 상태: 확정 (2026-09-26, 소유자 결정)
- 날짜: 2026-09-26
- 범위: 보안 경계(서버 머신 에이전트의 신원, 헤더 없는 루프백 에이전트를 끄는 순서), 토큰 원문을 두는 곳, CLI(`limn token create --save`·`limn token path`·`limn token revoke`), 인스턴스 관리자가 돌고 있는 인스턴스에 묻는 HTTP 요청, 에이전트 계약(`pins.md` 인증 안내 줄에 더하는 구절, 헤더 없는 루프백 요청이 받는 `401` 메시지에 더하는 구절, `limn snippet`)
- 관련: [ADR-0002](0002-access-control.md)의 v0.2 결정(에이전트는 토큰, 헤더 없는 루프백 에이전트는 폐지 예정)을 실제 운영으로 옮기는 단계다. [ADR-0003](0003-tailnet-headerless-and-owner-clear.md) §남는 한계(헤더를 더하지 않는 전달은 로컬 요청과 구별되지 않는다)를 이 머신에서 닫는 길이기도 하다. ADR-0002·0003 본문은 고치지 않는다

## 맥락

0.2.0부터 에이전트 API 토큰이 있었고, 헤더 없는 루프백 요청을 에이전트로 받는 0.1 동작은 폐지 예정으로 표시돼 있다. 그런데 운영 중인 인스턴스에서 토큰을 쓰는 에이전트가 없다. 서버 로그에는 폐지 예정 경고(`a request from loopback without an identity header or token is treated as the agent - this is deprecated ...`)가 계속 찍힌다.

토큰이 안 쓰인 이유는 두 가지였다.

1. **토큰을 둘 곳이 정해져 있지 않았다.** `limn token create`는 토큰을 한 번 찍고 `export LIMN_TOKEN=…`을 권했다. 에이전트 세션은 새로 뜰 때마다 사람이 그 값을 다시 넣어야 했다. 셸 설정 파일에 넣으면 모든 프로세스 환경에 퍼지고, 논문 저장소의 `AGENTS.md`에는 넣을 수 없다. 그래서 같은 머신의 에이전트는 헤더 없는 루프백에 계속 기댔다.
2. **헤더 없는 루프백 에이전트를 끌 수 없었다.** 인스턴스 관리자(`limn status`·`list`, `limn start`·`update`·`doc … --restart`의 기동 대기)는 `/api/meta?light=1`을 헤더 없이 불러 `200`을 기다린다. `AGENT_LOOPBACK=0`을 두면 이 요청이 `401`이 된다. 상태 표시는 `401`로 바뀌고, 기동 대기는 `LIMN_WAIT`(기본 240초)를 다 쓴 뒤 "아직 200이 아니다"라고 경고한다.

헤더 없는 루프백 에이전트는 루프백에 닿는 모든 것을 에이전트로 받는다. 같은 머신의 다른 계정, 그리고 헤더를 더하지 않는 포트 전달(`ssh -L`, `tailscale serve --tcp`)로 들어온 요청도 여기에 든다(ADR-0003 §남는 한계).

## 결정

**서버 머신의 에이전트는 인스턴스마다 토큰 하나를 `~/.config/limn/<인스턴스>.token`에서 읽는다.** 파일 권한은 `0600`이다. 토큰 원문은 어느 저장소에도 두지 않는다. 에이전트가 이 파일을 쓰기 시작하면 그 인스턴스는 `AGENT_LOOPBACK=0`으로 헤더 없는 루프백 에이전트를 끈다.

### 1. 파일

- 경로는 `<설정 폴더>/<인스턴스>.token`이다. 설정 폴더는 인스턴스 설정 `<인스턴스>.env`가 있는 곳과 같다(`LIMN_CONFIG_DIR`, 없으면 `$XDG_CONFIG_HOME/limn`, 없으면 `~/.config/limn`). `LIMN_SOURCE_DIR`(설정 원본을 두는 dotfiles 저장소 등)에는 절대 쓰지 않는다.
- 내용은 토큰 원문 한 줄(`limn_…`)이다. 서버의 `tokens.json`에는 지금처럼 해시만 있다.
- 폴더가 없으면 `0700`으로 만든다. 파일은 `0600`으로 만든다. 폴더가 git 작업 트리 안이고 그 파일이 git에서 무시되지 않으면 쓰지 않는다. 판단은 심링크를 푼 실제 폴더로, 호출한 셸의 `GIT_*` 변수 없이 한다. git이 판단하지 못하면(소유권 경고 등) 쓰지 않는다.

### 2. CLI

- `limn token create <인스턴스> --save`가 토큰을 만들고 그 파일에 쓴다. 파일이 이미 있으면 덮어쓰지 않고 멈춘다. `--force`를 주면 원자적으로 바꾼다. `--save`일 때는 토큰을 화면에 찍지 않는다. `--print`를 함께 줄 때만 찍는다.
- 파일을 쓰기 전에 검사를 모두 마친다. 토큰을 만든 뒤 쓰기가 실패하면 만든 토큰을 곧바로 폐기해 쓸 사람이 없는 토큰을 남기지 않는다.
- `limn token path <인스턴스>`는 경로만 찍는다. 파일을 읽지 않는다.
- `limn token revoke`가 폐기한 토큰이 그 파일에 든 토큰이면(원문의 해시가 폐기한 항목의 해시와 같으면) 파일도 지운다. 다른 토큰이 든 파일은 두고, 그 사실을 알린다. 폐기한 토큰이 든 파일을 남겨 두면 에이전트가 조용히 `401`을 받기 때문이다.

### 3. 인스턴스 관리자

- 돌고 있는 인스턴스에 HTTP로 묻는 곳(`limn status`·`list`의 응답 코드, `start`·`update`·`doc … --restart`의 기동 대기)은 토큰 파일이 있으면 그것을 붙인다. 헤더는 표준 입력으로 `curl`에 넘겨 명령줄(`ps`)에 토큰이 보이지 않게 한다.
- 토큰은 그 포트에서 듣는 프로세스가 모두 이 계정의 것일 때만 붙인다(Linux는 `/proc/net/tcp`의 uid, macOS는 `lsof`). 포트 번호는 장부에 있어 예측할 수 있으므로, 인스턴스가 꺼진 사이 다른 계정이 그 포트를 잡으면 토큰을 받아 갈 수 있기 때문이다(PR 검토에서 발견).
- 파일이 심링크이거나, 다른 계정의 것이거나, 그룹·다른 사람 권한 비트가 있거나, 한 줄 토큰 형식이 아니면 쓰지 않고 이유와 고칠 명령을 경고한다.
- 토큰 없이 받은 `401`은 "서버는 떠 있고 토큰이 필요하다"는 뜻으로 보고한다. 기동 대기는 그 자리에서 끝내고 `limn token create <인스턴스> --save`를 안내한다.
- 열린 핀 수는 지금처럼 상태 폴더의 `pins.md`에서 읽는다. HTTP를 거치지 않는다.

### 4. 서버와 에이전트 계약 (더하기만)

- 서버는 새 인자 `--agent-token-file <경로>`로 그 경로를 안다. 기본값은 환경 변수 `LIMN_AGENT_TOKEN_FILE`이고, `limn run`이 인스턴스의 경로를 이 변수로 넘긴다. 인자 목록에 더하지 않는 것은 "접근 키가 없는 v0.1 설정은 v0.1과 똑같은 argv를 낸다"는 인스턴스 관리자의 약속을 지키기 위해서다. 서버는 이 파일을 **읽지 않는다.** 있는지만 본다. 그래서 토큰 파일을 나중에 만들어도 재시작 없이 다음 렌더부터 안내가 붙는다.
- 파일이 있으면 `pins.md`의 인증 안내 줄 끝에 이 머신 에이전트가 쓸 형식 한 구절을 더한다: `curl -H "Authorization: Bearer $(cat ~/.config/limn/<인스턴스>.token)" …`. 토큰 원문은 어디에도 찍지 않는다. 원격 base로 렌더하는 `GET /pins.md`에는 더하지 않는다. 원격 에이전트는 그 파일에 닿을 수 없기 때문이다.
- 헤더 없는 루프백 에이전트가 꺼진 인스턴스에서 헤더 없는 루프백 요청이 받는 `401` 메시지 끝에 같은 안내를 더한다. 기존 메시지 문구는 그대로 앞에 둔다.
- `limn snippet`이 논문 저장소 `AGENTS.md`에 붙일 조각을 토큰 파일 형식으로 쓴다. 원격 에이전트에게는 지금처럼 소유자가 건넨 토큰(`$LIMN_TOKEN`)을 쓰라고 한다.

### 5. 배포 순서

1. 이 변경이 든 판을 설치한다(`limn update`). 헤더 없는 루프백 에이전트는 아직 켜져 있다.
2. 인스턴스마다 `limn token create <인스턴스> --name <이름> --save`로 토큰 파일을 만든다. 돌고 있는 서버는 재시작 없이 새 토큰을 받는다. 다음 `pins.md` 렌더부터 토큰 파일 안내가 붙는다.
3. 에이전트가 토큰 파일을 쓰게 한다. 논문 저장소 `AGENTS.md`의 Limn 절을 `limn snippet <인스턴스>` 출력으로 바꾼다. 토큰으로 온 요청은 `agent:<이름>`으로 기록되므로(`closed_by`·`claimed_by`) 바뀐 것을 확인할 수 있다.
4. 설정에 `AGENT_LOOPBACK=0`을 넣고 재시작한다(`limn stop <인스턴스> && limn start <인스턴스>`). 기동 로그의 `auth` 줄이 `loopback agent off`이고, `limn status <인스턴스>`의 로컬 응답이 `200`이면 끝이다.

### 6. 되돌리기

- 헤더 없는 루프백 에이전트로 돌아가려면 설정에서 `AGENT_LOOPBACK=0` 줄을 지우고 재시작한다. 토큰 파일은 남아 있어도 해가 없다. 토큰을 쓰는 에이전트는 그대로 된다.
- 토큰을 거두려면 `limn token revoke <인스턴스> <이름>`을 쓴다. 파일도 함께 지워진다. 이때 `AGENT_LOOPBACK=0`이 켜져 있으면 이 머신의 에이전트는 `401`을 받으므로, 먼저 위 줄로 되돌리거나 새 토큰을 `--save`한다.
- 판을 되돌리면(`limn update --ref v<이전 판>`) 옛 서버와 옛 인스턴스 관리자가 함께 설치된다. 옛 판은 `LIMN_AGENT_TOKEN_FILE`을 넘기지도 읽지도 않으므로 인자 불일치는 없다. 옛 인스턴스 관리자는 토큰 파일을 모르므로, `AGENT_LOOPBACK=0`인 인스턴스의 `limn status`는 다시 `401`을 보이고 기동 대기는 시간이 다 될 때까지 기다린다. 서버와 에이전트의 동작은 그대로다.

## 버린 대안

- **상태 폴더에 두기(`<STATE_DIR>/agent.token`).** 서버가 쓰고 백업·복사하는 폴더에 평문을 두면, `tokens.json`에 해시만 두는 이유가 약해진다. 상태 폴더를 옮기거나 되살릴 때 토큰도 함께 퍼진다. 경로가 설정마다 달라 에이전트 안내도 복잡해진다.
- **환경 변수(`LIMN_TOKEN`)만.** 에이전트 세션마다 사람이 넣어야 한다. 셸 설정에 넣으면 그 사용자의 모든 자식 프로세스 환경에 퍼진다. 원격 에이전트에게는 여전히 이 방법을 쓴다. 토큰 파일은 서버 머신 에이전트의 표준 경로일 뿐, 환경 변수를 막지 않는다.
- **OS 키링(Secret Service, macOS 키체인).** 표준 라이브러리만으로는 쓸 수 없어 런타임 의존성 규칙([architecture.md](../handbook/architecture.md) §불변식 2)과 부딪힌다. 화면 없는 SSH 세션에서는 키링을 열 수 없는 경우가 많다. 에이전트가 `curl` 한 줄로 쓰기도 어렵다.
- **헤더 없는 루프백 에이전트를 지금 없애기.** 토큰 파일로 옮기지 않은 에이전트가 모두 `401`을 받는다. 인스턴스마다 위 순서대로 끄는 쪽이 되돌리기 쉽다. 기본값을 끄는 일은 다음 판에서 따로 정한다.

## 결과

- 같은 머신이라도 다른 계정은 에이전트가 될 수 없다. `0600` 파일을 읽을 수 있는 이 계정의 프로세스만 에이전트다. 헤더를 더하지 않는 포트 전달로 들어온 요청도 `AGENT_LOOPBACK=0`인 인스턴스에서는 `401`이다.
- `$(cat …)`로 펼친 토큰은 그 `curl`이 도는 동안 명령줄에 보인다. 여러 계정이 쓰는 머신에서는 `printf 'Authorization: Bearer %s\n' "$(cat <파일>)" | curl -H @- …`처럼 표준 입력으로 넘긴다(`printf`는 셸 내장이라 명령줄에 남지 않는다). [SECURITY.md](../../SECURITY.md)와 [api.md](../handbook/api.md) §인증에 적는다.
- 토큰 파일을 쓰는 로컬 에이전트의 기록은 `local`(`로컬/에이전트`)이 아니라 `agent:<토큰 이름>`이다. 이 차이는 이미 에이전트 계약에 있다([api.md](../handbook/api.md) §신원을 정하는 순서).
- 인스턴스 관리자의 확인 요청도 토큰 에이전트로 온다. `/api/meta?light=1`은 읽기만 하고 에이전트는 `people.json`에 기록되지 않으므로 상태를 바꾸지 않는다.
- 새 서버 인자 `--agent-token-file`(환경 변수 `LIMN_AGENT_TOKEN_FILE`)과 새 CLI 옵션·명령이 더해지고, 없어지거나 뜻이 바뀌는 것은 없다. `pins.md`와 `401` 메시지는 기존 문구 뒤에 더하기만 한다.
