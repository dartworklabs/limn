## 맥락

HTML 문서 화면 설계의 이후 단계 3은 원문 위치를 지키는 렌더러가 있는 다른 줄 단위 형식이다. 이 머신의 저장소 11개를 세어 보니 후보 형식(`.qmd`·`.Rmd`·`.ipynb`·`.adoc`·`.org`·`.rst`·`.mdx`)의 파일은 하나도 없었다. Typst는 53개 있지만 제안서 보관본·CV·서식이고, 2026-08 뒤에 바뀐 제안서 Typst는 없다. 연구실은 Markdown(1,281개)과 LaTeX로 쓴다(설계 §이 연구실이 쓰는 문서).

수요는 Markdown 안에 있다. 71개 파일이 YAML 머리 정보로 시작한다(논문 노트, 에이전트 규칙과 스킬 등). 지금 뷰어는 그 첫 줄 `---` 를 구분선으로, YAML을 문단이나 setext 제목으로 그린다. 스킬 파일의 `name:`·`description:` 은 h2 제목이 되어 목차와 절 사다리에 든다. 줄 번호는 맞지만 보이는 글과 문서 구조가 원문과 다르다.

TeX 수식은 170개 파일에 있다(인라인 1,762, 따로 선 블록 19). 지금 뷰어는 `$t^*$ 는 … $t^*=\infty$` 의 두 `*` 를 기울임으로 짝지어 지우고, `$L_{b,t}$` 의 `_` 도, `\(y_{i,t}\)` 의 백슬래시도 지운다. 44개 파일에서 기울임·굵게 94짝이 수식 글자를 먹는다. 줄 번호는 맞지만 보이는 글자가 원문과 다르다(설계 §수식).

이 변경은 핀 `kind` 값을 둘 더하므로 에이전트 계약을 넓힌다([architecture.md](../handbook/architecture.md) §멈춤 신호의 에이전트 계약 변경). 그래서 소유자 승인이 필요하다. 번들·저장 형식·페이지 정책·서버 코드는 바꾸지 않는다.

## 결정

| # | 결정 | 상태 |
| --- | --- | --- |
| D1 | Markdown 종류 안에서 문서 맨 앞의 YAML 머리 정보를 제 블록으로 그린다. 새 문서 종류와 새 접미사는 없다 | 승인됨 |
| D2 | 머리 정보는 첫 줄이 `---`(바이트 순서 표시와 끝 공백은 허용, 들여쓰기와 `----` 는 아님)이고, 둘째 줄이 비지 않고 YAML 매핑을 열며(키와 쌍점, 또는 `#` 주석), 뒤의 한 줄이 `---` 나 `...` 일 때만이다. 문서 자체의 첫 줄이어야 하고, 인용이나 목록 항목의 첫 줄은 아니다. Pandoc `yaml_metadata_block` 의 시작·끝 규칙에 둘째 줄 검사를 더했다. 문서 중간의 블록은 받지 않는다. 어긋나면 다른 규칙이 지금처럼 읽는다 | 승인됨 |
| D3 | 상자 하나가 두 `---` 줄까지 블록 범위를 가지고, 머리 줄(화면 언어로 `머리 정보 · YAML N줄`) 아래 안쪽 줄을 서버의 줄 그대로 줄마다 하나씩 보인다. YAML은 파싱하지 않으므로 링크·그림·마크업이 없다. 긴 값은 상자 안에서 접는다. 블록을 누른 핀의 `quote` 는 안쪽 줄의 글만이다. 펼쳐 둔다. 제목이 아니므로 목차·절 표시줄·절 단계에 들지 않는다 | 승인됨 |
| D4 | 블록 종류 `front` 를 더한다. 핀 `kind` 는 `md:front`, `scope` 는 `block` 이다. 사다리는 `고른 줄` → `머리 정보` 이고, 누르면 블록이 기본이다. 서버는 바꾸지 않는다 | 승인됨 |
| D5 | 규칙은 파싱 worker 안의 Limn 자체 규칙(`mdFrontMatter`, `mdMathBlock`, `mdMathInline`)이다. 라이브러리를 번들하지 않는다 | 승인됨 |
| D6 | TeX 수식을 알아본다. `$…$`·`$$…$$` 는 Pandoc `tex_math_dollars` 규칙(여는 `$` 뒤와 닫는 `$` 앞이 공백이 아니고 닫는 `$` 뒤가 숫자가 아님)이고, `\(…\)` 는 줄 안의 수식, `\[…\]` 는 제 줄에 선 블록일 때만 수식이다. 수식 안에서 백슬래시는 다음 글자를 넘기고(`\$`), 코드 스팬 안의 기호는 수식을 닫지 못한다(줄을 넘는 코드 스팬도). 빈 줄을 넘지 않는다. 어긋나면 지금처럼 읽는다 | 승인됨 |
| D7 | 수식을 그리지 않는다. 구분 기호까지 원문 글자 그대로 고정폭으로 보인다. 인라인은 바탕색 없는 `code.md-math` 하나, 따로 선 수식은 줄마다 한 줄인 코드 상자다(긴 줄은 접음). 따로 표시·툴팁·`aria-label` 은 두지 않는다 | 승인됨 |
| D8 | 인라인 수식은 worker가 원문 줄 끝마다 조각으로 끊고 사이에 줄바꿈 토큰을 둔다. 그래서 [ADR-0025](0025-html-document-surface.md) D7의 줄 단위 대응이 그대로 정확하다. 따로 선 수식은 `$$`·`\[` 로 시작하는 줄에서 닫는 기호로 끝나는 줄까지의 블록이고, 펜스처럼 문단을 끊는다 | 승인됨 |
| D9 | 블록 종류 `math` 를 더한다. 따로 선 수식 핀의 `kind` 는 `md:math`, `scope` 는 `block` 이다. 사다리는 `고른 줄` → `수식` → `절` 이고, 누르면 블록이 기본이다. 인라인 수식은 새 사다리 칸이 없다. 서버는 바꾸지 않는다 | 승인됨 |

### D2를 고른 근거

Pandoc의 규칙("The initial line `---` must not be followed by a blank line", 끝은 `---` 나 `...`)은 Quarto·R Markdown·Jekyll류 머리 정보가 따르는 공통분모다. 둘째 줄 검사는 `---` 로 시작하는 평범한 Markdown(구분선 뒤 문단과 또 하나의 구분선)을 머리 정보로 잘못 읽지 않으려는 것이다. YAML을 파싱하지 않고도 고를 수 있는 가장 좁은 조건이다. 연구실의 머리 정보 71개는 모두 이 규칙에 든다. 규칙이 받지 않은 문서는 지금과 똑같이 그려지므로, 규칙이 틀려도 줄을 잘못 매기지는 않는다.

### D3을 고른 근거

줄 핀에는 원문 줄이 가장 정확하다. GitHub처럼 표로 그리면 칸에서 어느 줄을 골랐는지 말할 수 없고, YAML 파서(번들, 앵커 폭탄 같은 한도)가 필요하다. 머리 정보는 짧고(중앙값 4줄, 최대 38줄) 핀이 바로 그 줄(제목, 날짜, 태그)에 붙으므로 접지 않는다.

### D4를 고른 근거

머리 정보는 문단도 코드 블록도 아니다. `md:code` 를 받은 에이전트는 코드 블록을 찾는다. `md:front` 는 문서의 메타데이터를 고친다는 것을 값만으로 알린다. 레코드 검사는 `kind` 가 문자열인지만 보고, `pins.md` 범위 칸은 `md:` 로 시작하는 값을 그대로 적는다. 그래서 직전 릴리스도 이 핀을 지우지 않고 `md:front` 로 적는다. D9의 `md:math` 도 같은 까닭으로 고른다. `md:code` 를 받은 에이전트는 코드를 찾고, `md:math` 를 받으면 TeX를 고친다.

### D6을 고른 근거

Pandoc의 `$` 규칙은 통화(`$5 and $10`, `$5,$10`)를 글자로 남기는 검증된 규칙이고, 연구실 문서의 `$숫자` 29곳이 모두 글자로 남는다. `\(…\)`·`\[…\]` 는 연구실의 에이전트 노트가 쓴다(6개 파일 15곳, 3개 파일 6블록). 줄 안의 `\[` 는 대괄호를 이스케이프하는 흔한 쓰임이라 제 줄의 블록만 받는다. 코드 스팬 우선은 CommonMark의 우선순위를 따른다. Pandoc은 `$10 …` 다음 줄의 `` `$x$` `` 까지 수식으로 읽지만, 여기서는 코드가 이긴다. 수식으로 잘못 읽어도 원문 글자가 그대로 보일 뿐이고, 놓치면 글자가 사라진다. 그래서 규칙은 Pandoc과 같거나 조금 넓다.

### D7을 고른 근거

글자만 지키면 번들이 필요 없고, 고르기·복사·핀의 `quote` 가 원문 글자를 그대로 가진다. 에이전트는 그 글로 원문을 찾는다. "그대로"는 구분 기호와 백슬래시가 남는다는 뜻이다. `quote` 계약은 지금처럼 공백을 하나로 접고 160자에서 자르므로, 바이트까지 같은 인용은 아니다. `$` 가 이미 수식이라고 말하므로 표시를 더하지 않는다. 툴팁은 휴대폰의 길게 눌러 고르기와 부딪힌다. 인라인에 바탕색을 두지 않는 것은 코드 스팬과 구별하고, 수식이 많은 표가 얼룩지지 않게 하려는 것이다.

### D8을 고른 근거

markdown-it은 인라인 자식에 원문 위치를 주지 않는다. 수식 하나가 줄 끝을 삼키면 그 뒤 글이 한 줄 일찍 매겨지므로 문단 전체 범위로 물러서야 한다. 줄마다 조각으로 끊으면 물러설 일이 없다. 연구실 문서에서 수식 규칙이 줄 대응의 정확 여부를 바꾼 인라인 토큰은 0개다.

## Trade-off

- 문서 중간의 메타데이터 블록, TOML 머리 정보(`+++`)는 받지 않는다. 연구실 파일에는 둘 다 없다.
- 머리 정보는 표가 아니라 원문 줄로 보인다. 키와 값이 길면 읽기가 GitHub보다 덜 편하다.
- 옛 뷰어는 같은 문서를 지금처럼(구분선과 문단) 그린다. 핀의 줄은 같아 되돌리기에 설정을 바꿀 일은 없다.
- `---` 로 시작하고 둘째 줄이 키처럼 생긴 평범한 문서는 머리 정보로 보인다. Pandoc·GitHub도 그렇게 읽는다.
- 수식은 그려지지 않는다. 읽는 사람은 TeX 원문을 읽는다.
- `\(…\)` 는 GitHub에서 `(…)` 로, Limn에서 `\(…\)` 로 보인다.
- 문단 중간의 `$$` 줄은 블록이 되어 문단을 끊는다. Pandoc은 한 문단 안의 수식으로 둔다. 줄은 어느 쪽이든 맞다.
- 표에서는 `|` 가 칸을 먼저 나누므로 수식 안의 `|` 는 `\|` 로 써야 한다. GitHub와 같다.

## 대안

- **markdown-it-front-matter(MIT)를 번들한다.** 3.6 KB를 위해 판 고정·sha256·고지 절차가 하나 늘고, Pandoc 규칙과 둘째 줄 검사를 위해 결국 고쳐야 해서 기각했다.
- **YAML을 파싱해 표로 그린다.** 번들과 한도가 늘고 줄 핀이 흐려져 기각했다.
- **머리 정보를 숨기거나 접는다.** 핀이 붙을 줄을 감추므로 기각했다.
- **수식을 지금 그린다(KaTeX).** 번들이 약 560 KB로 markdown-it의 4.5배이고, HTML 출력의 `style` 속성이 [ADR-0026](0026-viewer-csp.md)의 `style-src` 와 부딪힌다. 글자를 지키는 것만으로 원문과 다른 글이 사라지므로 미뤘다(설계 §결정 5).
- **수식 플러그인(markdown-it-texmath 등)을 번들한다.** 렌더러를 함께 부르고, 줄을 넘는 수식을 한 토큰으로 만들어 D7의 줄 대응을 깨므로 기각했다.
- **구분 기호를 빼고 TeX만 보인다.** 고르기·복사·`quote` 가 원문과 달라져 기각했다.
- **새 형식부터 받는다(Quarto·R Markdown 접미사, AsciiDoc, Org, reStructuredText, Jupyter, Typst).** 연구실에 검토할 파일이 없어 지금은 열지 않는다. 여는 조건은 설계 §결정 5에 있다. Org의 uniorg는 GPL-3.0-or-later라 [CLA](../../CLA.md)의 재허락 조항과도 맞지 않는다.

## 결과

- 에이전트 계약에 값 둘(핀 `kind` `md:front`·`md:math`)이 더해진다. 새 경로·필드·저장 형식은 없다.
- 수식 그리기는 별도 결정으로 남는다(설계 §결정 5).

### 현재 상태 투영

- **영향받는 현재 권위:** 파싱 worker(`viewer/md-parse.mjs`), Markdown 화면(`viewer/js/md-surface.js`, `viewer/css/md-surface.css`), 에이전트 계약(`api.md`, SKILL). 그린 본문의 숨은 문자 표시와 합치면 수식 조각과 수식 줄, 머리 정보 상자(`mdFront`)의 줄도 코드 스팬·코드 줄과 같은 길로 표시한다(설계 §결정 10, 구현 후속).
