# 구조 리팩토링 직후 코딩 스킬 준수 점검

## 후속 조치

아래 항목은 PR #107 직후의 조사 기록이다. 사용자의 후속 요청으로 입력 모호성 거부, 등록 경로 기본 거부, 작업·대상·자원에 묶인 변경 권한, 검사된 원고 읽기 핸들을 구현했다. 현재 구조는 Handbook, 변경 설계와 검증 기록은 [후속 작업 계획](../plans/2026-09-29-trust-boundary-completion.md)이 정한다. 아래 발견 항목을 아직 미구현인 현재 상태로 읽지 않는다.

미수정 테스트의 설명 누락과 모든 입력·스케줄의 완전 탐색 부재는 일괄 구현해야 할 결함 목록이 아니다. 스킬은 새로 쓰거나 고친 코드의 설명과 의미 있는 성질 테스트를 요구한다. 후속 작업은 변경 함수의 설명 누락을 확인하고 생성한 전이 시퀀스를 추가하되, 저장소 전체의 무결점 증명으로 확대하지 않는다.

## 당시 판정

남겨 둔 구조 정리와 함수 분리를 수행해도 **저장소 전체의 스킬 완전 준수를 증명한 것은 아니다.** 이 점검은 코드·테스트·설정의 확인 범위와 아직 강제되지 않는 규칙을 구분한다. 자동 검사는 설정된 규칙을, 코드 리뷰는 검토한 경로를 보장한다.

대상은 `code-implement`, `code-testing`, `code-security`와 Handbook의 R1–R10이다. 구현·검증 기록은 [남은 로드맵 작업 계획](../plans/2026-09-29-remaining-roadmap-cleanup.md)에 있다.

## 정책 변경이 필요한 차이

1. `web/handler.py`의 JSON 본문 파서는 중복 키를 거부하지 않는다. `web/parse.py::query_first`는 반복된 쿼리의 첫 값을 사용한다. 실제로 `{"doc":"a","doc":"b"}`와 반복 doc 입력을 확인했다. 거부 정책을 새로 적용하면 수용하던 요청의 동작이 바뀐다.
2. `access.py::check_role`에서 agent/editor/owner는 거부 목록으로 제약된다. 새 POST를 등록할 때 명시적인 허용 선언이 필수인 구조는 아니다. **현재 미등록 경로는 dispatch에서 404다.** 이 점검은 미등록 경로가 실행되는 취약점을 발견했다는 뜻이 아니다.
3. 서비스는 일반 actor mapping을, 경로 검증은 일반 `Path`를 사용한다. 생성 경로가 강제되는 별도 권한·검증 타입만 위험한 실행 경계에 전달하는 구조는 아니다. 현재 보호는 요청 가드와 실행 경계의 검사에 의존한다.

이 세 가지는 기존 동작을 유지하는 파일 이동만으로 해결되지 않는다. API 입력 계약과 권한 정책을 먼저 확정해야 하며, `docs/handbook/architecture.md`의 멈춤 신호가 적용된다. 이번 작업에서 기존 권한을 임의로 바꾸지 않았다.

## 검증 해석

고의 위반을 넣어 순수 import, 빌드 로그·오류 한도, 실제 claim 저장 검사가 실패함을 확인하고 복구했다. 이것은 해당 검사의 탐지 능력에 대한 근거이며 저장소 전체의 결함 부재 증명은 아니다. TeX·bwrap·실제 상태 복사본이 필요한 검사와 실제 지원 최저 Python 버전 실행은 로컬 환경 한계로 구분해 보고한다.
