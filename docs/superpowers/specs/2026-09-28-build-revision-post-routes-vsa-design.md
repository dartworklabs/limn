# 빌드·이력 POST 경로 VSA 설계

> **상태: 확정.** 전체 경계와 불변식은 [백엔드 VSA 점진 이행 설계](2026-09-28-backend-vsa-migration-design.md)와 ADR-0009가 정한다.

## 대상과 현재 구조

`POST /api/rebuild`와 `POST /api/revision-build`는 각각 빌드·이력 기능의 `http.py`가 입력과 결과를 처리한다. 그러나 공통 처리기가 문서 대상 경로 목록에 두 이름을 쓰고, `_post_doc`에서 다시 분기해 호출한다. 경로의 소유권이 둘로 갈라져 있다.

## 선택

공통 `PostDocRoute`는 경로 이름과 문서·쿼리·본문을 받는 함수만 담는다. 빌드·이력 기능의 `routes.py`가 각 이름과 응답 조립을 소유하고, 조립 지점이 실행별 서비스를 묶어 등록한다. 처리기는 공통 본문 읽기 → Host/Origin → 신원 → 입장 → 역할 검사 → 사람 기록 → JSON 파싱을 마친 뒤 경로를 고른다. 등록된 경로와 아직 옮기지 않은 PDF 선택·새 핀 경로만 문서를 고른다. 알 수 없는 POST는 문서를 고르지 않고 404를 낸다.

`POST /api/pick`과 `POST /api/pin`, 핀 ID 동작, 전체 비우기는 이후 슬라이스에서 옮긴다. 공통 처리기의 역할 검사와 문서 선택 순서는 바꾸지 않는다.

## 합격 기준

- 두 POST 경로 이름과 호출 분기가 공통 처리기에서 사라지고 각 기능 경로가 하나씩 소유한다.
- 동기·비동기 재빌드와 비교 작업 시작의 성공·거절 상태, 본문, 상태 파일은 기준 커밋과 같다.
- 요청 검사와 문서 선택 순서, 실행별 서비스 격리, 전체 게이트가 유지된다.
