# 핀 편집 요청 문맥과 서버 전달 메서드 정리 설계

> **상태: 확정.** [백엔드 VSA 점진 이행 설계](2026-09-28-backend-vsa-migration-design.md)와 ADR-0009의 조립 지점 정리 단계다.

## 대상과 선택

핀 만들기·편집의 HTTP 입구는 `ServerApplication`의 `assignee_people()`·`edit_scope()`를 호출한다. 둘 다 편집 기능만을 위한 요청 문맥이다. 편집 기능에 실행별 `EditingRequests`를 두고 사람 목록·문서 사실·저장소 읽기·공개 응답 협력자를 조립 지점에서 전달한다. 사람 목록은 본문에 담당자가 있을 때만 읽고, 편집할 핀의 문서·PDF 영역은 기존과 같은 순서로 저장소에서 읽는다.

`ServerApplication.reply_reopens()`와 `claim_active()`는 제품 흐름이 쓰지 않고 테스트가 순수 규칙에 도달하려고 거치는 전달 메서드다. 테스트가 상태 파싱과 시계를 명시해 도메인 규칙을 직접 검증하도록 바꾸고 두 메서드를 지운다. 이는 규칙 복제가 아니다.

## 합격 기준

- 편집 전용 문맥의 소유자가 편집 기능이고 서버 조립 지점에는 협력자 연결만 남는다.
- 성공·거절의 HTTP 상태·본문과 저장 파일·알림 결과가 기준 커밋과 같다.
- 테스트 전용 서버 전달 메서드가 사라지고 전체 게이트가 통과한다.
