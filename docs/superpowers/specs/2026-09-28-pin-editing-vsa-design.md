# 핀 만들기·편집 VSA 이행 설계

> **상태: 구현·검증 완료.** [백엔드 VSA 점진 이행](2026-09-28-backend-vsa-migration-design.md)의 핀 편집 묶음이다.

## 범위

`POST /api/pin`과 `POST /api/pins/{id}/edit`의 위치·본문 검사, 응답, 저장·알림을 `features/pins/editing/`에 모은다. 만들기와 편집이 함께 쓰는 줄 핀·PDF 영역 위치 검사는 같은 기능의 `location.py`에 둔다. `ServerApplication`은 실행별 협력자를 묶고 문서·사람·파일 사실을 제공하되 두 동작의 평면 전달 메서드는 지운다. 남은 `service/add_edit.py`도 제거한다.

요청의 공통 본문 읽기·신원·입장·역할 검사, 문서 선택의 순서, 저장 잠금과 원자적 쓰기, 순수 편집 규칙은 기존 소유자를 유지한다. 여러 경로가 실제로 쓰는 기본 숫자·메모·멘션 파서와 `DocumentFacts`는 공통 경계에 둔다.

## 행동과 검증

새 핀의 위치 → 메모 → 종류 → 멘션 → 담당 순서, 편집의 필드 검사 → 핀의 문서 확인 → 위치 재검사 순서, 줄 핀과 PDF 영역 핀의 거절 문구를 보존한다. 새 번호 발급, anchor·파일 상대 경로, 닫힌 핀의 편집 제한과 낡은 rev 거절, @멘션·담당 알림의 저장 뒤 순서를 유지한다. 기준 커밋과 별도 프로세스에서 HTTP 응답·상태 파일을 비교하고, 집중·전체 게이트를 실행한다.
