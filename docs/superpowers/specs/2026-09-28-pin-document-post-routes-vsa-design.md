# PDF 선택·핀 만들기 POST 경로 VSA 설계

> **상태: 확정.** 전체 이행의 경계와 불변식은 [백엔드 VSA 점진 이행 설계](2026-09-28-backend-vsa-migration-design.md)와 ADR-0009가 정한다.

## 대상

`POST /api/pick`과 `/api/pin`은 문서가 선택된 뒤 각각 `features/pins/location/http.py`와 `features/pins/editing/http.py`가 동작한다. 공통 처리기에는 두 경로의 이름, 새 핀 본문의 `doc` 우선 규칙, 기능별 호출 분기가 남아 있다. 빌드·이력의 문서 대상 POST 경로는 이미 등록 함수다.

## 선택

등록 문서 POST 함수에 `PostDocRequest`를 넘긴다. 값에는 검사 뒤 파싱한 쿼리·본문, 선택된 문서, actor와 principal만 담는다. 등록 정보의 `new_pin` 표시는 기존 `parse_doc_choice`가 새 핀 본문의 `doc`으로도 문서를 선택하게 한다. 본문과 쿼리의 불일치는 기존 편집 입력 검사에서 계속 거절한다. 위치 기능은 PDF 선택 경로, 편집 기능은 새 핀 경로의 이름과 응답을 소유한다. 빌드·이력 등록 함수도 같은 요청 값으로 연결한다.

공통 처리기는 요청 가드, POST 역할 검사, 사람 기록, JSON 파싱, 문서 선택을 유지한다. 알 수 없는 경로는 문서 선택 없이 404다. 핀 ID 동작과 전체 비우기는 이후 이행한다.

## 합격 기준

- 처리기에서 두 경로의 이름·분기와 새 핀 전용 경로 비교가 사라진다.
- PDF 선택의 성공·거절, 새 핀 저장과 문서 우선 순위, 기존 빌드·이력 POST의 응답·상태 파일이 기준 커밋과 같다.
- 보안 검사·저장 잠금·실행별 격리와 전체 게이트가 유지된다.
