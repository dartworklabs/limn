# 뷰어 셸 GET 경로 VSA 설계

> **상태: 확정.** 목표와 불변식은 [백엔드 VSA 점진 이행 설계](2026-09-28-backend-vsa-migration-design.md)와 ADR-0009가 정한다.

## 대상

공통 HTTP 처리기에 남은 뷰어 첫 화면, 파비콘, 버전, 서비스 워커, 번들 PDF.js의 GET 경로 분기다. 이 경로들은 문서별 업무 요청이 아니지만 현재 처리기는 공통 가드와 전송까지 맡으면서 뷰어 파일·이미지·캐시 정책도 알고 있다.

## 선택

`features/viewer_shell/routes.py`가 이 경로의 매칭·응답·캐시 정책을 소유한다. 기존 `GetRequest`의 `record_person` 콜백을 첫 화면에서 같은 순서로 호출한다. 실행별 뷰어 페이지·강조색·버전·vendor 파일 검사는 좁은 `ViewerShellApp` 계약으로 조립 지점에서 주입한다. 공통 처리기는 기존 순서대로 문서를 찾고 GET 등록 함수를 돌려 응답을 전송한다. 알 수 없는 vendor 이름의 기존 404 문구와 전체 요청 가드 순서는 유지한다.

정적 화면 조각과 번들 파일 자체는 `viewer/`·`vendor/`에 남는다. 이 변경은 HTTP 제공 경로의 소유권만 옮긴다.

## 합격 기준

- 공통 처리기에서 뷰어·vendor 경로 분기와 파일·이미지 읽기 코드가 사라진다.
- 성공·거절 상태, 헤더, 본문과 사람 기록이 기준 커밋과 같다.
- 전체 테스트와 정적·Handbook 검사가 통과한다.
