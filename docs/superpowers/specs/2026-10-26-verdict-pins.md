# 판정 핀 — 문서마다 정한 판정 낱말을 버튼 하나로 (설계 초안)

> **상태: 초안, 소유자 승인 대기.** 소유자는 "판정을 메모 첫 낱말이 아니라 버튼으로, 특정 그림·논문이 아니라 어느 문서에나"라는 방향을 원칙으로 승인했다. 이 문서의 결정(D1–D14)과 계약 문자열은 아직 승인되지 않았다. 에이전트 계약(`pins.md`·HTTP API)·저장 형식·권한 규칙을 더하므로 HARD-GATE다([workflow.md](../../handbook/workflow.md) §기본 경로). 승인 전에는 생산 코드·계약·저장 형식을 바꾸지 않는다. 뷰어 부분은 승인 뒤에도 네 기기군 PoC(전후 비교)를 소유자에게 보인 다음에만 `main`에 들어간다(§뷰어 §PoC 게이트).
>
> superpowers brainstorming 위임은 이 세션에서 쓸 수 없어, 지금의 Handbook과 코드(`main` `7ee9047`)를 직접 읽고 썼다.

## 요청과 지금의 관례

한 논문 저장소는 그림 탭 둘(개념도 그림 문서, 쪽마다 그림 한 장인 LaTeX 카탈로그)에서 **판정 핀**을 쓴다. 메모 첫 낱말이 `채택`·`보류`·`삭제`인 핀이고, 그 저장소의 에이전트가 첫 낱말을 읽어 그림을 카탈로그의 다른 절로 옮기거나 지운다. Limn에 버튼이 없어도 쓸 수 있게 만든 관례다. 불편은 셋이다.

- 낱말을 손으로 친다. 휴대폰에서 특히 느리고, 오타(`채텍`)는 판정이 아니게 된다.
- 판정인지 아닌지를 서버도 화면도 모른다. `채택한 이유는…`으로 시작하는 메모도 판정처럼 읽힌다.
- 한 그림의 지금 판정이 무엇인지 화면에 보이지 않는다. 같은 그림에 판정을 두 번 찍으면 어느 것이 앞서는지 규칙이 없다.

소유자는 이것을 그림이나 그 논문에 묶지 않고 **문서마다 선언한 판정 낱말을 한 번 누르는 버튼**으로 일반화하기를 원한다.

## 현재 권위와 지켜야 할 불변식

- **purpose / `docs/handbook/purpose.md`**: 핀은 위치가 붙은 요청이다. 서버는 원고를 고치지 않는다. 판정을 실행하는 것도 에이전트다.
- **architecture / `docs/handbook/architecture.md`**: 불변식 3(계약은 더하기만), 4(핀 쓰기는 `transact()`), 6(옛 레코드는 쓰기 이관 없이 읽는다), 7(개인정보·논문 이름 없음), 8(계약 문자열은 번역하지 않음). 기능은 서로 import하지 않고 조립 지점이 주입한다. 이 설계가 걸리는 멈춤 신호: 에이전트 계약 변경, 레코드 필드 추가, 권한 규칙 추가.
- **`docs/handbook/api.md`**: `POST /api/pin`은 화이트리스트 필드만 저장한다. 유효한 모르는 필드는 읽은 그대로 되쓴다. `pins.md`의 한국어 문자열은 계약이다.
- **`docs/handbook/domain.md`**: 확인(confirm)은 사람만 한다(에이전트는 `403`). `viewer` 역할은 아무것도 바꾸지 못한다.
- **`docs/handbook/viewer.md`**: 상태는 세로 색 띠가 아니라 점·아이콘·글자로 가른다. 색만으로 가르지 않는다. 삭제는 확인 대화상자 대신 6초 [되돌리기]다. 작성 패널 순서는 위치 줄 → 드래그 글자 → 메모 → 종류 줄 → 제안 칸 → 겹침 → 범위 묶음이다.
- **진행 중인 다른 작업**: PR #257(`fix/suggest-editor-fit`)이 작성 패널의 종류 줄·제안 칸과 시트 높이(`composer.js`·`layout.js`·`panel-size.js`·`suggest.js`, viewer.md §패널 정리)를 고치고 있다. 이 설계는 문서만 더하므로 겹치지 않는다. 뷰어 구현은 #257이 머지된 뒤의 `main`을 PoC의 "전" 화면으로 삼는다.

## 계약

### 판정 낱말 파일 (`limn-verdicts/1`)

등록한 문서 경로에서 종류 접미사(`.tex`·`.pdf`·`.limnmap.json`)를 떼고 `.limnverdicts.json`을 붙인 파일이다. `::`가 있으면 그 뒤 경로를 쓴다.

| `--doc` 경로 | 낱말 파일 |
| --- | --- |
| `paper::sub/main.tex` | `paper/sub/main.limnverdicts.json` |
| `figures/out/figures.limnmap.json` | `figures/out/figures.limnverdicts.json` |
| `submission/manuscript.pdf` | `submission/manuscript.limnverdicts.json` |

```json
{
  "format": "limn-verdicts/1",
  "page": true,
  "verdicts": [
    {"key": "채택"},
    {"key": "보류"},
    {"key": "삭제", "confirm": true}
  ]
}
```

| 필드 | 규칙 |
| --- | --- |
| `format` | 필수. 정확히 `limn-verdicts/1` |
| `page` | 선택 불리언, 기본 `false`. `true`면 쪽 판정 줄을 보인다(D5) |
| `verdicts` | 필수. 1–5개, 이 순서로 버튼이 선다 |
| `verdicts[].key` | 필수. 1–16자, 유니코드 글자·숫자·`-`·`_`만(파이썬 `[\w-]`). 목록 안에서 유일하다. 레코드·API·`pins.md`에 이 글자 그대로 간다 |
| `verdicts[].label` | 선택. 버튼 이름, 1–12자, 제어 문자 없음. 없으면 `key` |
| `verdicts[].confirm` | 선택 불리언, 기본 `false`. `true`면 두 번 눌러 저장하고 위험 색 글자로 그린다(D7) |
| 그 밖의 키 | 무시한다. 다음 판을 위한 자리다 |
| 파일 | UTF-8 JSON, 4,096바이트 이하 |

읽기는 원고 읽기 규칙 그대로다. 검사된 `ManuscriptFile`로 열고(원고 트리 안, 점 이름 아래 아님, 심볼릭 링크 거절) 4,097바이트까지만 읽는다. 파일 서명(`mtime_ns`·크기·inode)이 바뀔 때만 다시 파싱한다. 파일이 없으면 그 문서에는 판정이 없다. 있는데 쓸 수 없으면 판정이 없는 것으로 다루고, `/api/docs`에 이유 코드를 싣고 서버 로그에 그 판마다 한 번 경고한다. 이 파일은 `.tex` 계열이 아니므로 빌드 지문·`src_mtime`에 들지 않는다(`SRC_TEX_EXTS`).

### HTTP API (더하기만)

| 경로 | 더하는 것 |
| --- | --- |
| `GET /api/docs`의 문서 항목, `GET /api/meta`(전체) | 낱말이 있으면 `verdicts: {"page": <bool>, "choices": [{"key", "label", "confirm"}]}`. 파일이 있으나 쓸 수 없으면 대신 `verdicts_error: "unreadable" \| "too_large" \| "invalid"`. 파일이 없으면 둘 다 없다. `?light=1`과 그 안의 `docs` 사본에는 싣지 않는다(폴링 응답을 늘리지 않는다) |
| `POST /api/pin` | 저장 화이트리스트에 `verdict`(문자열)를 더한다. 검사는 아래 표 |
| `POST /api/pins/{id}/edit` | 본문에 `verdict` 키가 있으면 값과 무관하게 `400 {"error": "판정은 바꾸지 않습니다 — 새 판정 핀을 찍거나 이 핀을 지웁니다.", "reason": "verdict_fixed"}`이고 아무것도 쓰지 않는다 |
| `GET /api/pins`, `GET /api/pins/{id}`, 변경 응답의 `pin` | 저장된 `verdict`를 그대로 싣는다. 계산 필드는 없다 |
| 닫기·다시 열기·답글·claim·삭제·되살리기 | 바뀌지 않는다. 판정 핀도 평소처럼 `changes`·`ref`를 붙여 닫는다 |

`POST /api/pin`에 `verdict`가 있을 때의 거절. 역할 검사(`viewer`는 `403`) 뒤에 이 순서로 본다.

| 경우 | 응답 |
| --- | --- |
| 에이전트(토큰, 헤더 없는 루프백, `agent` 역할) | `403 {"error": "판정은 사람이 정합니다 — 에이전트는 판정 핀을 만들지 않습니다.", "reason": "verdict_human"}` |
| 그 문서에 쓸 수 있는 낱말 파일이 없다 | `400 {"error": "이 문서에는 판정 낱말이 없습니다.", "reason": "verdict_unsupported"}` |
| 문자열이 아니거나 낱말에 없다 | `400 {"error": "이 문서의 판정 낱말이 아닙니다.", "reason": "verdict_unknown", "choices": ["채택", "보류", "삭제"]}` |
| `kind_req: "question"` 또는 `suggest`와 함께 | `400 {"error": "판정 핀은 질문·제안 수정과 함께 쓰지 않습니다.", "reason": "verdict_conflict"}` |

검사는 저장 트랜잭션 안에서 그때의 낱말로 한다. 그래서 낱말 파일이 바뀐 직후 옛 화면이 보낸 낱말은 `verdict_unknown`이고, 뷰어는 낱말을 다시 읽고 알린다. 뷰어의 영어 화면은 네 `reason`의 영어 문장을 `ui_en.json`에 둔다.

### 핀 레코드

```json
{"id": 41, "doc": "fig", "file": "<절대경로>/src/B2.py", "lo": 12, "hi": 140, "scope": "fig",
 "frac": [0, 0, 1, 1], "el": {"id": "B2", "...": "..."}, "note": "", "verdict": "채택", "...": "..."}
```

- `verdict`는 선택 문자열이다. 만든 때의 낱말 `key`를 그대로 둔다. 표시 이름(`label`)은 저장하지 않는다.
- 읽을 때 문자열이 아니거나 `key` 규칙에 맞지 않으면 판정으로 올리지 않고 저장된 그대로 둔다. 깨진 줄로 치지 않는다(값이 틀린 선택 필드의 기존 규칙).
- 낱말 파일에서 그 `key`가 빠져도 핀의 판정은 그대로다. 표시는 저장된 글자다.
- 이 필드를 모르는 0.4.x 서버는 모르는 필드로 읽고 응답에 싣고 되쓸 때 그대로 둔다(`suggest`와 같은 경로). `tests/contracts/test_figure_rollback.py`와 같은 방식으로 확인한다.

**쪽 전체.** 저장된 `frac`의 네 값이 `[0, 0, 1, 1]`과 각각 `1e-6` 안이면 "쪽 전체" 핀이다. 새 필드 없이 위치에서 계산한다. 손으로 쪽 전체를 끈 판정도 같은 뜻이므로 같게 본다.

### `pins.md` (더하기만)

- **번호 칸.** `판정 <key>`를 번호 바로 뒤, 다른 표시보다 앞에 놓는다. 쪽 전체면 `판정 <key>(쪽 전체)`다. 예: `41 · 판정 채택(쪽 전체) · 처리 중(에이전트 B, 약 10분)`. `key`에는 `|`·줄바꿈이 없으므로 이스케이프할 것이 없다.
- **메모 칸.** 메모가 비면 `(판정만)`이다.
- **범례.** 열린 핀에 판정이 있을 때만 끝에 더한다: `'판정 X' = 작성자가 버튼으로 고른 판정이다(메모 첫 낱말보다 앞선다) · '(쪽 전체)' = 그 쪽 전체에 대한 판정`
- **안내 줄.** 열린 판정 핀이 있을 때만 안내 문단에 더한다: `판정 핀(번호 칸 '판정 X')은 그 문서 저장소의 규칙대로 처리한다 · 같은 대상으로 풀리는 열린 판정 핀이 여럿이면 번호가 가장 큰 핀만 따르고, 나머지에는 '#N 판정이 앞섭니다' 답글을 남기고 닫는다 · '(쪽 전체)' 판정의 대상은 쪽 칸의 쪽에 보이는 항목이다`

### 에이전트 절차 (`skill/SKILL.md`·`SKILL.ko.md`에 더할 절)

1. 판정 핀은 JSON `verdict`가 있는 핀이다(`pins.md` 번호 칸 `판정 X`). `verdict`가 메모 첫 낱말과 다르면 `verdict`를 따르고 답글에 그 사실을 적는다.
2. 무엇을 실행할지는 그 문서 저장소의 규칙(AGENTS.md)이다. Limn은 낱말의 뜻을 모른다.
3. 대상은 평소처럼 위치에서 푼다. 쪽 전체 판정은 그 쪽의 항목 전체이고, 그림 문서에서는 `el.id`가 그림 id다.
4. 같은 대상의 열린 판정 핀이 여럿이면 번호가 가장 큰 핀만 실행한다(D4).
5. 처리는 평소대로 claim → 실행 → PR → `changes`·`ref`로 닫기다. 판정 핀을 만들지 않는다(`403`).

## 뷰어

이 절은 무엇을 어디에 둘지까지만 정한다. 크기·간격·줄바꿈·터치 동작은 PoC가 정한다.

### 작성 패널

- 낱말이 있는 문서의 작성 패널에 **판정 줄**(`#c-verdict-row`)을 메모 칸 바로 다음, 종류 줄 앞에 둔다. 앞머리 글 `판정으로 저장` 뒤에 낱말 버튼이 파일 순서로 선다. 버튼은 outline이고 `confirm` 낱말은 위험 색 글자다. 강조 색은 여전히 [핀 저장] 하나다.
- 누르면 지금 선택·메모로 `verdict`를 붙여 저장한다(`savePin()`과 같은 길: 저장 대기, `저장됨 [되돌리기]` 6초, 실패 배너). 종류가 `질문`이거나 [제안 수정]이 켜져 있으면 버튼을 끄고 설명에 까닭을 적는다.
- 선택 상자 곁 메모 팝오버(`#sel-pop`)에는 1단계에서 넣지 않는다. 동작 줄이 이미 차 있고, 한 번에 끝내는 길은 쪽 판정 줄이 맡는다.

### 쪽 판정의 위치

`"page": true`인 문서에서 쪽 판정 버튼을 누르면, 뷰어는 그 쪽 전체 상자(`frac` `[0, 0, 1, 1]`)와 화면 빌드로 `POST /api/pick`을 부르고 아래 단계로 저장한다.

| 문서 종류 | 저장하는 위치 |
| --- | --- |
| `figure` | 사다리의 `fig` 단계(뿌리 요소 = 그 그림). 뿌리에 코드 줄이 없으면 pick이 주는 영역 답(`el` 포함) |
| `tex` | `raw` 단계(합쳐졌으면 그것을 품은 단계). 문단·환경 단계는 드래그 기준이라 이웃 float로 샐 수 있어 쓰지 않는다 |
| `pdf` | 영역 답 그대로 |

pick이 거절하면(생성 파일, 원고 밖, 되짚을 곳 없음) 저장하지 않고 그 이유를 알린다. LaTeX의 `raw`가 쪽 하나에 항목 하나인 문서에서 그 항목 안에 드는지는 PoC 단계에서 실제 카탈로그로 잰다(§검증). 들지 않으면 소유자에게 대안(그 쪽에서 시작하는 0단 책갈피의 목적지 한 점으로 pick)을 묻는다.

### 쪽 판정 줄과 지금 판정

- **쪽의 지금 판정**은 그 문서의 열린 쪽 전체 판정 핀 가운데, 지금 그 쪽에 놓인 것의 번호가 가장 큰 핀이다. 놓인 쪽은 그림 핀이면 `mark_page`, 아니면 `page`다. 요소를 잃은 그림 핀(`el_sync` `lost`)과, 그림 핀이 아니면서 `est`가 참인 핀(빌드가 바뀌어 쪽을 장담할 수 없다)은 쪽 판정 줄에서 세지 않고 목록 카드로만 보인다.
- **쪽 판정 줄**에는 지금 판정(없으면 `판정 없음`, 있으면 `#41 채택`과 다른 사람이면 그 이름·상대 시각, 처리 중이면 `처리 중`)과 낱말 버튼이 선다. 지금 판정의 버튼은 눌린 상태(`aria-pressed="true"`)다. 같은 낱말을 다시 누르면 아무것도 만들지 않고 그 핀을 잠깐 반짝인다(같은 판정 두 번은 하나다). 다른 낱말을 누르면 새 핀을 만든다(D3·D4). 앞선 열린 판정이 남아 있으면 `앞선 판정 N건`을 링크로 붙인다.
- **자리 후보(PoC에서 고른다).** A: 쪽마다 쪽 바로 아래의 줄(권장. 판정이 어느 쪽 것인지 눈으로 묶이고, 쪽 둘이 함께 보여도 헷갈리지 않는다). B: PDF 영역 바닥에 떠 있는 "지금 쪽" 막대(쪽 사이 배치를 건드리지 않는다). A는 PDF 영역 전용 확대에서 줄이 쪽과 함께 커지지 않아야 한다.
- **마크.** 쪽 전체 판정 핀은 쪽 크기 상자를 그리지 않는다. 번호는 쪽 판정 줄에 있다. 카드의 [보기]는 그 쪽 판정 줄로 간다.
- **쪽 목록.** 그 쪽에 지금 판정이 있으면 줄 끝(체크 앞)에 낱말을 붙인다(`3쪽 · 채택`). 그림 문서와 보기 전용 PDF도 쪽 번호 뒤에 붙는다. 판정 전체를 한눈에 훑는 자리다.
- **카드.** 머리에 종류 배지 `판정 채택`(질문 배지와 같은 모양, 글자가 뜻을 진다). 상태 점은 평소 그대로다. 검토 대기·완료 행에도 같은 글자를 둔다.
- **되돌리기와 확인.** 저장 뒤 그 자리에 `#42 저장됨 [되돌리기]` 6초다. 쪽 판정 줄의 되돌리기는 핀을 지우기만 하고 작성 패널을 열지 않는다. `confirm` 낱말은 첫 누름에 버튼이 4초 동안 `<낱말> 확정`이 되고 화면 낭독기에 알린다. Esc·바깥 누르기·시간 초과로 풀린다.
- **역할과 언어.** `viewer` 역할에는 판정 줄과 버튼이 없고 지금 판정 글자만 보인다(§역할에 따른 화면). 낱말은 원고의 말이라 `translate="no"`이고, 둘레의 말은 `ui_en.json`으로 옮긴다. 버튼 이름은 `채택 판정으로 저장 — 3쪽`처럼 쪽을 말한다.

### PoC 게이트

뷰어 변경은 `main`에 넣기 전에 [workflow.md](../../handbook/workflow.md) §화면 변경은 PoC를 먼저 보인다의 네 기기군 표(데스크톱 1440×900, 휴대폰 390×844·320×720, 태블릿 768×1024·1024×768, 폴더블 344×882·673×841·841×673)로 전후를 나란히 보인다. 보일 것은 다음이다.

- 작성 패널의 판정 줄(낱말 셋·다섯, 한국어·영어, `confirm` 첫 누름 상태), 쪽 판정 줄의 후보 A·B, 쪽 목록, 카드 배지
- 잰 값: 누름 영역(터치 44px), 같은 줄 잉크 가운데, 넘침과 줄바꿈(320px에서 다섯 낱말), PDF 확대 중의 줄 위치
- 낱말 파일이 없는 문서가 바이트 단위로 그대로인지(변경이 닿지 않는 대역)
- 에뮬레이션과 실기기를 구별해 적는다

## 보안과 기록

- **누가.** 판정 핀은 `editor`·`owner`인 사람만 만든다(D8). 판단은 `security/access.py`의 `Principal`이 답한다. 확인과 같은 질문을 쓰고, 역할 비교를 그 모듈 밖에 두지 않는다. 입장(`--allow`·`--members-only`)은 그대로다.
- **낱말 파일은 믿지 않는 입력이다.** 저장소에 커밋할 수 있는 누구나 고칠 수 있다. 크기·개수·글자 규칙으로 닫고, 뷰어는 낱말과 이름을 글자(`textContent`)로만 넣는다. 파일에 경로나 URL 필드가 없으므로 다른 파일로 이어지는 길이 없다. 낱말 파일을 고쳐도 이미 저장된 판정은 바뀌지 않는다.
- **기록.** 새 상태 파일과 `audit.jsonl` 항목은 없다. 판정 핀은 되돌릴 수 있는 요청이기 때문이다. 누가 언제 어떤 판정을 냈는지는 핀의 `author`·`at`·`verdict`, 처리는 스레드의 `close` 기록과 `ref`, 거둔 판정은 휴지통의 `dropped_by`에 남는다. 되돌릴 수 없는 일(그림 삭제)은 에이전트의 PR이 git에 남긴다.

## 첫 낱말 관례와의 호환·이행

- **옛 핀은 그대로다.** `verdict`를 채우려고 레코드를 다시 쓰지 않는다. 메모 첫 낱말 판정 핀은 그 프로젝트의 관례대로 계속 처리된다.
- **에이전트는 둘 다 읽는다.** `verdict`가 있으면 그것, 없으면 프로젝트 관례(첫 낱말). 둘이 다르면 `verdict`가 앞선다.
- **들이는 프로젝트가 할 일.** 낱말 파일의 `key`를 지금 첫 낱말(`채택`·`보류`·`삭제`)과 같게 두면 에이전트 규칙의 실행표를 그대로 쓴다. 같은 PR에서 그 저장소의 판정 핀 규칙에 "번호 칸 `판정 X` 또는 메모 첫 낱말", "`(쪽 전체)`는 그 쪽의 항목", "같은 대상이면 번호가 큰 핀"을 더한다. LaTeX 카탈로그는 쪽 전체 판정의 줄 범위가 절 머리 줄을 함께 잡을 수 있으므로 "범위 안의 항목 머리 줄이 하나면 그 항목"처럼 푸는 규칙을 둔다.
- **되돌리기.** 이전 Limn으로 되돌리면 버튼과 `pins.md` 표시가 사라지지만 `verdict`는 레코드와 JSON 응답에 남는다. 그동안 새 판정은 첫 낱말로 찍는다.
- **뒤에 할 다리(3단계).** 메모 첫 낱말이 그 문서의 `key`와 같으면 작성 패널이 `판정 '채택'으로 저장할까요? [판정으로]`를 제안한다(질문 제안과 같은 자리).

## 검증

- **순수.** 낱말 파일: 형식·개수·`key` 규칙·중복·크기·모르는 키 무시·쓸 수 없는 이유 코드. 만들기 검사: 낱말 없음·모르는 낱말·질문·제안과의 충돌·에이전트 거절. 편집의 `verdict_fixed`. 쪽 전체 판정(`1e-6`). 성질 검사: 어떤 낱말 파일 바이트도 예외 없이 "낱말" 또는 "이유 코드"가 된다.
- **저장.** `transact()` 왕복, 판정 없는 옛 레코드, 틀린 `verdict`가 깨진 줄이 되지 않음, 이전 릴리스가 `verdict` 레코드를 바이트 그대로 되쓰는지(롤백 계약 테스트).
- **계약.** `/api/docs`·`/api/meta`의 `verdicts`·`verdicts_error`와 라이트 응답의 부재, 네 거절, `pins.md`의 표시 순서·`(쪽 전체)`·`(판정만)`·범례·안내 줄이 판정 핀이 있을 때만, 여러 문서 소절. `tests/contracts/test_contract_snapshot.py`에 판정 흐름을 더하고 판정이 없는 흐름의 바이트가 그대로인지 본다.
- **보안.** 원고 밖을 가리키는 심볼릭 링크 낱말 파일 거절, 큰 파일, `<script>`가 든 이름이 글자로 보이는지, `viewer`·토큰·`agent` 역할의 거절.
- **뷰어.** 낱말이 있을 때만 판정 줄, 누르면 `verdict`를 보낸 요청과 저장된 레코드, `confirm` 두 번 누르기, 되돌리기, 쪽 판정의 단계 선택(그림 `fig`·LaTeX `raw`·PDF 영역), 같은 낱말 다시 누르기, 처리 중·앞선 판정 표시, 쪽 목록, 카드, `viewer` 역할. 네 기기군 기하(`SuggestGeometry`와 같은 방식)와 PoC.
- **실측(PoC 단계).** 쪽 하나에 항목 하나인 LaTeX 카탈로그에서 모든 항목 쪽의 쪽 전체 pick `raw`가 그 항목의 줄에 드는 몫. 그림 문서에서 모든 쪽의 쪽 전체 pick이 뿌리 요소를 주는지.

## 소유자에게 묻는 것

1. **낱말의 자리(D2).** 문서 옆 파일 `<이름>.limnverdicts.json`(권장)과 인스턴스 설정 키 중 무엇인가.
2. **사람만(D8).** 에이전트가 판정 핀을 만들지 못하게 막는가(권장), 아니면 여느 핀처럼 둘 것인가.
3. **바꾸지 않는 판정(D3·D4).** 판정을 바꾸면 새 핀이 생기고 에이전트가 번호 큰 핀을 따르는 규칙으로 충분한가.
4. **쪽 판정 줄의 자리.** A(쪽마다 아래 줄)와 B(떠 있는 지금 쪽 막대) 가운데 PoC에서 고른다. 한국어 앞머리 글 `판정으로 저장`이 맞는가.
5. **LaTeX 쪽 판정의 단계.** `raw`로 두고 실측에서 어긋나면 책갈피 목적지 pick으로 바꾸는 순서가 맞는가.
6. **계약 문자열과 한도.** `판정 X`·`(쪽 전체)`·`(판정만)`·범례·안내 줄의 글, 낱말 5개·`key` 16자·이름 12자·파일 4 KiB.
