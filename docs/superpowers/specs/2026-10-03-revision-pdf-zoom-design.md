# 변경 PDF 확대·축소 — 이슈 #161

상태: 승인됨. 사용자가 “ㅇㅇ ㄱㄱ 구현까지 고고고”로 설계와 구현을 승인했다.

## 목적과 범위

[이슈 #161](https://github.com/dartworklabs/limn/issues/161)의 목적은 변경 PDF를 읽기 좋은 크기로 확대·축소하고, 확대된 문서 안을 이동하며, 화면 폭에 맞는 크기로 돌아오는 것이다. 기존 변경 보기 안의 화면 기능을 추가하는 한정된 변경이다. 서버의 비교 PDF 생성·캐시·HTTP API·핀 상태·저장 형식을 바꾸지 않는다.

## 현재 권위와 상태

- 질문 종류: 현재 실재와 변경 의도.
- role: purpose. path: `docs/handbook/purpose.md`. 실제 정본: `src/limn/viewer/`의 화면 코드와 브라우저 테스트. 대상 사용자는 핀의 변경 내용을 읽고 검토하는 사람이다.
- role: architecture. path: `docs/handbook/architecture.md`. 현재 불변식: 런타임 의존성·저장 형식·에이전트 계약을 유지한다. 이번 변경은 기존 viewer 기능 안에 둔다.
- role: 일반 주제. path: `docs/handbook/viewer.md`의 변경 보기·벡터 렌더링·PDF 영역 전용 확대. 실제 정본: `js/revisions.js`, `css/revisions.css`, `js/pages.js`, `js/zoom.js`. 변경 PDF는 최대 780px로 한 번 그려지고 조절할 배율이 없다. 원고 PDF의 기존 배율은 폭 맞춤을 기준으로 50–500%, 버튼 단계는 1.2배다.
- role: verification. path: `docs/handbook/verification.md`. 현재 불변식: 브라우저 테스트는 임의 시간을 기다리지 않고 관찰할 상태를 기다린다. 실제 렌더링과 계약·타입·정적 검사로 확인한다.

## 제안 동작

1. 변경 PDF 탭의 도구 줄에 `[−] [100%] [+] [폭 맞춤]`을 둔다. 소스 diff에서는 이 컨트롤을 숨긴다. PDF가 준비되기 전에는 조절 버튼을 비활성화한다.
2. 100%는 변경 PDF 스크롤 영역의 가용 폭에 맞춘 상태다. 기존 원고 뷰어와 같은 50–500% 범위와 1.2배 단계를 사용한다. 한도에서 해당 버튼을 비활성화한다. 최초 진입과 다른 커밋 선택은 폭 맞춤으로 시작한다.
3. 변경 PDF 위 Ctrl/⌘+휠과 입력 칸 밖 Ctrl/⌘ `+`·`−`·`0`은 변경 PDF에 적용한다. 원고 모드에서는 원고의 기존 동작을 따른다. 휴대폰은 44px 이상의 버튼과 가로·세로 스크롤로 조절·이동한다. 두 손가락 핀치도 해당 PDF 영역에만 적용한다.
4. 확대 시 포인터 또는 화면 중심 아래의 쪽과 그 안의 상대 위치를 유지한다. 좌우 끝과 마지막 쪽까지 스크롤할 수 있어야 한다. 화면·패널 크기가 바뀌면 폭 맞춤 모드는 새 폭에 맞추고, 수동 배율은 비율과 읽던 위치를 유지한다.
5. 소스 diff로 갔다가 같은 변경 PDF로 돌아오거나 같은 커밋의 비교 범위를 바꿔도 배율을 유지한다. 새 커밋·다른 문서·변경 보기 재진입에서는 초기화한다. 원고 배율과 브라우저에 저장하는 원고 설정은 건드리지 않는다.
6. PDF.js로 현재 배율에 맞게 다시 그린다. 빠른 연속 조작에서는 오래된 렌더 작업을 취소하고 뒤늦은 완료가 최신 화면을 덮지 못하게 한다. 기존 벡터 렌더링의 캔버스 픽셀·메모리 제한 원칙과 화면 근처 쪽의 지연 렌더링을 따른다. 확대할 때 서버에서 비교 PDF를 다시 빌드하지 않는다.

## 설계 이유와 제약

주 기준은 Limn의 기존 디자인 시스템이다(`viewer.md`, `css/tokens.css`, `js/pages.js`). 중립 탐색 버튼, Lucide 아이콘, 기존 글꼴·여백·명암과 터치 영역을 유지한다. Refero의 Dropbox 문서 미리보기(`fb8f75a3-d17e-46dc-8328-04d9fe43f934`)와 Missive 문서 뷰어(`b14045d0-6f3d-4e2e-8a9d-ca581cf66a61`)에서 문서 옆 도구 줄의 배율 표시와 조작 묶음을 참고한다. 두 스타일 검색은 결과가 없으므로 기존 제품을 화면 기준으로 잠그고 Refero의 icons·craft-details 접근성 지침을 보조로 쓴다. 색이나 레이아웃을 새로 디자인하지 않는다.

기존 원고 도구 줄을 공용으로 돌리는 안은 배율 상태와 원고 저장 설정을 연결해 잘못된 문서를 확대하기 쉽다. 변경 PDF의 별도 컨트롤을 권한다. CSS로 캔버스만 늘리는 안은 글자가 흐려지므로 PDF.js 재렌더링을 권한다. 상단 도구 줄은 스크롤 영역 밖에 둬 확대 후에도 바로 폭 맞춤으로 돌아올 수 있게 한다.

## 검증

- 데스크톱과 좁은 터치 화면에서 버튼·배율 표시·폭 맞춤, 한도, 가로·세로 이동을 브라우저로 확인한다.
- 포인터·중심 위치 유지, 화면 크기 변경, 소스 diff 왕복, 커밋·문서 변경 시 초기화를 확인한다.
- Ctrl/⌘ 입력과 핀치를 확인하고 입력 칸·원고 배율·브라우저 UI에 영향을 주지 않는지 확인한다.
- 연속 확대와 비교 전환 중 느린 렌더 결과의 폐기, 지연 렌더링, 캔버스 제한을 확인한다.
- 기존 핀 변경 보기와 소스 diff의 회귀 테스트, JS 타입 검사·strict ratchet·정적 검사·전체 관련 게이트를 실행한다. 밝은/어두운 화면과 좁은/넓은 화면을 실측한다. `viewer.md`를 같은 변경에서 갱신한다.

## 충돌·미확인

사용자가 위 조작 방식과 배율 범위, 구현 진행을 승인했다. 이 설계를 기준으로 구현·검증하며 추가 승인이 필요한 충돌·미확인은 없다.
