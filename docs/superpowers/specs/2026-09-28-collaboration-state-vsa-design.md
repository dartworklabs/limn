# 사람·알림 실행 문맥 VSA 이행

`GET /api/people`은 기능 입구가 있지만 `people.json`·`events.jsonl`의 실행별 문맥과 사람·알림 판단은 `ServerApplication`의 전달 메서드에 남아 있다. `features/collaboration/`에 실행별 사람 디렉터리와 알림 서비스를 두고, 읽기·기록·후보·멘션·이벤트 생성·기록·폴링을 그곳에서 연결한다. 여러 핀 기능이 공유하는 `people.py`·`events.py`·`mentions.py`의 저장 형식과 순수 규칙은 공통 핵심으로 유지한다.

공통 HTTP 가드 뒤 사람 기록 여부와 `/api/people`의 역할 조회 → 핀 스냅숏 → 후보 조회 순서를 유지한다. 메모 멘션은 새 태그가 없으면 이벤트 파일을 읽지 않고, 있으면 같은 트랜잭션 안에서 읽는다. 이벤트 쓰기는 핀 쓰기 이후이고 실패해도 핀 변경을 되돌리지 않는다. `/api/meta`의 이벤트 선택·필드·키 순서와 `people.json`·`events.jsonl` 바이트·권한을 유지한다. 실행별 잠금·캐시·시계는 같은 런타임의 것을 받고 설정 교체와 테스트의 시계 주입은 호출 시점에 반영한다.

해당 기능을 옮긴 뒤 앱의 사람·이벤트 전달 메서드와 평면 `App` 항목을 제거한다. HTTP 입구는 보안 검사나 핀 저장 순서를 새로 구현하지 않는다.
