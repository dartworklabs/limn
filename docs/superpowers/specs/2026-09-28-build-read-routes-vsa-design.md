# 빌드 읽기 경로 VSA 설계

> **상태: 확정.** 전체 이행의 범위와 불변식은 [백엔드 VSA 점진 이행 설계](2026-09-28-backend-vsa-migration-design.md)와 ADR-0009가 정한다.

## 대상과 현재 경로

`GET /api/build`, `GET /pages/<name>`, `GET /pdf`는 빌드 기능의 상태와 산출물을 읽는다. 현재 기능별 입력과 거절은 `features/builds/http.py`가 처리하지만, 경로 매칭과 최종 HTTP 응답은 `web/handler.py`의 `_get_document`와 `_get_files`에 흩어져 있다. 요청마다 문서를 고르는 단계와 공통 가드는 처리기에 있다.

## 선택

세 경로의 매칭과 응답 조립을 `features/builds/routes.py` 한 곳으로 옮긴다. 기능 경로는 문서와 쿼리, 텍스트 정리 함수를 받으며 실행별 전역 상태를 찾지 않는다. 조립 지점은 등록한 GET 함수들을 `App` 계약에 제공하고 처리기는 기존 경로 뒤에서 등록 순서대로 호출한다. 이 단계에서 다른 경로의 매칭 순서와 `/pages/`의 이미지가 없을 때 다음 경로로 넘어가는 동작을 유지한다.

공통 응답 타입과 JSON 직렬화는 `web/reply.py`로 분리해 처리기와 기능 경로가 같이 쓴다. 처리기는 본문 읽기, Host/Origin, 신원, 입장, 문서 선택, 응답 전송을 계속 한 번만 수행한다. 경로가 없는 경우의 404도 처리기가 낸다.

## 합격 기준

- 처리기에서 세 GET 경로의 분기를 지운다. 재빌드 POST가 쓰는 빌드 HTTP 함수는 후속 이행까지 남는다. 새 GET 경로는 다른 곳에 같은 매칭 권위를 남기지 않는다.
- `/api/build`, `/pages/<name>`의 존재·부재, `/pdf`의 현재 빌드·사라진 빌드·빌드 없음이 기준 커밋과 상태·헤더·본문이 같다.
- 공통 가드 순서와 문서 선택, 두 실행의 격리, 정적 검사와 전체 게이트가 유지된다.
