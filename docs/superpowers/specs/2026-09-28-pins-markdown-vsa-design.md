# pins.md 조립 VSA 이행 설계

> **상태: 구현·검증 완료.** [백엔드 VSA 점진 이행](2026-09-28-backend-vsa-migration-design.md)의 핀 조회 묶음 두 번째 단계다.

## 범위

`GET /pins.md`와 핀 저장 때 공통으로 쓰는 `pins.md` 입력 조립·순수 렌더 호출을 `features/pins/listing/markdown.py`가 소유한다. 서버는 실행별 문서·경로·겹침·사람 사실을 좁은 협력자 계약으로 제공하고, `PinStore`에 이 기능의 렌더 함수를 직접 건다. 기존 `ServerApplication.pins_md_input`·`pins_md_text`와 평면 `App.pins_md_text`를 제거한다.

HTTP의 본문 읽기·신원·입장·역할 가드, 주기적 휴지통 정리, 원격 base 계산은 기존 순서를 유지한다. `pins.md`의 바이트·키 순서와 순수 렌더 규칙은 바꾸지 않는다.

## 행동과 검증

열린 핀의 위치·겹침·인용 길이·스레드·@태그, 문서 머리말과 빌드 도장, 토큰 파일 안내, 갱신 시각을 같은 시점에 같은 순서로 모은다. 같은 파일의 인용을 한 번만 읽고, 원고 밖 파일은 읽지 않는다. 기준 커밋과 별도 프로세스에서 GET 본문과 쓰기 후 `pins.md` 바이트를 비교하고, 저장 렌더 실패 주입 및 전체 게이트를 통과시킨다.
