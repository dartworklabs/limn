# 검증된 저장 핀의 타입 경계

상태: 제안 — 설계 검토 전. 구현 계획과 코드 변경은 별도 승인 뒤 진행한다.

## 목적과 성공 조건

`parse_pin()`은 어떤 JSON 객체도 상태 타입으로 무손실 파싱한다. 반면 `pins.jsonl`에서 `PinStore`가 돌려준 핀은 `fits_record()`를 통과했으므로 정수 `id`와 완전한 위치를 갖는다. 지금은 두 경로가 모두 `Pin = OpenPin | ReviewPin | DonePin`을 반환하고, `PinCore.id`·`place`가 선택 타입이다. 서비스·위치 계산·저장소의 호출자는 저장 경계가 보증한 사실을 타입에서 다시 얻지 못한다.

검토할 목표는 **무손실 파싱 결과와 검증된 저장 핀을 내부 Python 타입에서 분리**하는 것이다. 다만 타입을 하나 더 만드는 비용이 실제 위험 감소보다 크면 채택하지 않는다. 성공 조건은 구체적인 잘못된 기본값/방어 분기를 제거하면서 어댑터 증가를 제한하고, 파서의 키·값·순서 보존, 손상 줄 처리, 저장소의 기존 직렬화 결과, HTTP와 `pins.md` 계약을 유지하는 것이다. 새 저장 필드, 파일, 런타임 의존성은 없다.

### 지켜야 할 현재 불변식

1. `parse_pin(record).record`와 `TrashedPin.from_record(record).record`는 키·값·순서가 같은 레코드로 돌아간다. 형식이 잘못된 선택 필드와 현재 검사에서 허용하는 모르는 필드도 보존한다. 저장소는 읽은 원본 줄의 공백을 보존하지 않고 기존 `dump_jsonl()` 방식으로 다시 직렬화한다.
2. `fits_record()`가 거부한 줄은 서비스에 전달되지 않는다. 다음 재작성 전에 원래 파일을 백업한다.
3. 저장소 읽기 자체는 쓰기 마이그레이션을 하지 않는다. `doc` 없는 핀과 `done:true`이지만 `review` 없는 핀은 현재 의미로 읽는다.
4. 저장 파일은 **동일한 입력에 대한 기존 저장소의 재직렬화 결과**와 같아야 한다. HTTP·`pins.md`의 바이트 및 필드 계약도 바꾸지 않는다.

### 결정 맥락

- ADR-0006 (`docs/adr/0006-relative-pin-paths.md`, 2026-09-26, 확정·구현): `file_rel`이 없는 옛 레코드는 읽을 때 위치를 해석하고 이관 쓰기를 하지 않는다. 새 검증 타입이 `file_rel`을 필수로 만들면 이 결정과 충돌한다.
- ADR-0005 (`docs/adr/0005-pin-scoped-changes.md`, 2026-09-25, 확정·구현): 선택 필드 `changes`의 모양이 틀리면 저장 레코드를 깨진 줄로 다룬다. 타입 승격이 이 기존 검사 범위를 약화하면 안 된다.

### 충돌·미확인

- `pins.jsonl`의 실제 운영 데이터는 테스트 말뭉치와 다를 수 있다. 현재 `fits_record()`의 허용 범위를 넓히거나 줄일 근거는 이 작업에 없다.
- `tests/data/pin_records.jsonl`의 147개 레코드 중 129개만 현재 `fits_record()`의 테스트 대역 문서 키·행위자 검사에 합격하고, 18개는 거부된다. 이 수치는 저장소 입력 허용 범위를 정하는 정책이 아니라 무손실 파서와 저장 경계가 다르다는 증거다.

## 설계 선택지

| 선택지 | 장점 | 비용·위험 |
| --- | --- | --- |
| A. `PinCore.id`·`place`를 필수로 바꾸고 `parse_pin()`이 거부 | 호출부 타입이 즉시 단순해진다 | `{}`, 잘못된 선택 필드, 미완성 레코드의 무손실 파싱과 말뭉치 왕복이 깨진다. 채택하지 않는다. |
| B. `VerifiedPin` 내부 래퍼를 `fits_record()` 뒤에 만든다 | 검증의 출처가 타입으로 보이고 기존 상태 객체·레코드 순서를 보존한다. 저장소 경계에서만 타입이 승격된다 | 저장소 목록과 거래 콜백, 서비스·위치 계산 호출부의 타입을 명시적으로 옮겨야 한다. **좁은 수직 증명 후에만 채택 후보.** |
| C. `cast()` 또는 `assert`만 더한다 | 변경량이 적다 | 호출자가 `Pin`만 받는 계약이 그대로여서 유효하지 않은 파서 결과도 검증된 것처럼 흐를 수 있다. 채택하지 않는다. |
| D. 저장 경계의 기존 검사와 리프트 일치성만 테스트하고, 필요한 호출부에서 `PinCore.pid`를 쓴다 | 현재의 실질적인 잘못된 기본값을 적은 변경으로 제거한다 | 명목상 분리된 검증 타입은 얻지 못한다. B의 수직 증명이 이득을 보이지 못하면 **이 범위로 마친다.** |

상태 클래스를 `VerifiedOpenPin` 등으로 상속하거나 모든 상태·코어를 제네릭으로 만드는 방안은 타입 표면을 크게 넓힌다. 이번 설계에서 B는 확정된 구현안이 아니라 비용을 측정할 가설이다.

### 채택 전에 필요한 좁은 수직 증명

승인 뒤 전체 호출자를 옮기기 전에 `parse_record → PinStore.read_pins → transact → 한 서비스 경로 → render/write_pins`의 타입·동작을 최소 변경으로 검증한다. 실제 저장 핀에서 제거할 수 있는 위험한 분기와 새로 생기는 변환 지점을 기록하고 diff로 비교한다. 현재 확인한 분기는 `service/trash.py`의 복원 정렬에 있는 **`pin.core.id or 0` 한 곳**이다. `PinCore.pid`의 예외 검사는 자유 파서 입력에도 쓰이는 정당한 경계이고, `LineSpan`/`Region` 분기는 위치 종류를 가르는 의미 있는 분기다. `rev or 0`은 옛 레코드의 정상적인 기본값이므로 제거 대상으로 세지 않는다. `store.top_id()`의 `None` 허용도 미완성 핀을 만드는 현재 단위 테스트가 사용한다.

최소 예상 어댑터는 (1) 저장 파서에서 래핑, (2) `sync(list[Pin])` 입력·결과 변환, (3) `render(Sequence[Pin])` 입력 변환, (4) 거래 콜백의 목록 교체·추가 때 재검증, (5) 서비스의 상태 매칭을 위한 언래핑, (6) `server.py`·위치 계산의 레코드/핀 목록 변환, (7) 테스트 저장소 픽스처 변환이다. 이는 현재 확인된 잘못된 기본값 한 곳보다 훨씬 넓다. 수직 증명에서 **두 곳 이상의 실제 위험 분기를 제거하지 못하거나, 새 변환 지점이 제거 지점보다 많으면 B를 확장하지 않고 D를 채택한다.** 타입 검사 통과만으로 B의 이득을 주장하지 않는다. 수직 증명 코드는 승인된 구현 단계에서만 작성한다.

## 조건부 타입 설계: B의 증명이 통과할 때만

`Pin`은 계속 **무손실 파서의 결과**다. `PinCore.id: int | None`, `place: LineSpan | Region | None`도 그대로 둔다. `VerifiedPin`은 파일 형식이 아니라 메모리 안의 불변 값이다. `pin: Pin`, `id: int`, `place: LineSpan | Region`을 갖고, 읽기 편의를 위해 `record`를 원래 `pin.record`에서 얻는다. `id`·`place`는 원래 객체의 `core`에서만 취하며, 저장 레코드를 복사·정규화하지 않는다. 필요하면 `state`도 `pin.state`에 위임한다. 래퍼는 임의 생성 가능한 공개 dataclass가 아니라, 검증 함수만 만들 수 있는 명시적 생성 경로를 둔다. 단순 생성자 은닉만으로 보증하지 않고, 생성 시 `id`·`place`를 검사한다.

`parse_record(raw, is_doc_key, is_actor)`는 먼저 **기존의 동일한** `fits_record()`로 확인한다. 실패하면 그대로 `Broken`; 성공하면 `parse_pin(raw)`를 호출하고 `VerifiedPin`을 만든다. 확인된 값인데 `core.id` 또는 `core.place`가 비었다면 이는 검사와 리프트의 불일치이므로 손상 줄로 조용히 돌리지 않고 테스트에서 드러나는 내부 결함으로 취급한다. `PinStore.parse`의 타입은 `Callable[[object], VerifiedPin | Broken]`, `read_pins()`·`snapshot()`·`transact()`의 라이브 목록은 `VerifiedPin`이다. `read_jsonl()`의 일반 파싱·경고·줄 번호 계약은 그대로 둔다.

검증 보장은 현재 `fits_record()`의 **기존 판정과 정확히 같아야 한다**. 특히 `id`는 `bool`을 제외한 Python 정수이며 양수 필수 조건은 새로 추가하지 않는다. 줄 위치는 절대경로의 비어 있지 않은 `file`, 정수 `lo`·`hi`, `1 <= lo <= hi`다. 영역 위치는 절대경로 `pdf`, 1 이상 정수 `page`, 숫자 네 개의 `frac`, `lo`·`hi` 부재 또는 `null`이다. `doc`은 선택이고, 현재 설정에서 사라진 유효 키도 허용한다. `rev`, `note`, `thread`, `claim` 등은 **현재 저장 검사대로** 선택이다. `id`·위치 외의 값을 새 필수 필드로 만들지 않는다. `fits_record()`가 일부 선택 필드의 모양도 검사하므로 래퍼의 의미는 단순한 두 필드 검사보다 강하다. 이 보증은 외부 `parse_pin()` 결과에는 적용하지 않는다.

```text
JSONL 줄 / 테스트의 자유로운 dict
  ├─ parse_pin(record) → Pin                 무손실, 검증 표시 없음
  └─ PinStore.parse = parse_record
       ├─ fits_record 실패 → Broken → 줄 번호·경고·후속 백업
       └─ fits_record 성공 → parse_pin → VerifiedPin(pin, id, place)
            → PinStore.read_pins / transact / snapshot
            → 셸에서 id·place 사용, 도메인 전이에는 .pin 전달
            → 다음 상태·새 핀을 검증해 거래 목록에 넣음
            → 원래 .pin.record로 기존 순서대로 저장
```

`VerifiedPin`을 받는 코드가 `OpenPin`·`ReviewPin`·`DonePin`을 구별할 때는 `verified.pin`을 패턴 매칭한다. 래퍼에 상태 전이를 중복 구현하지 않는다. 새 핀 생성, 편집·닫기·재동기화 결과는 같은 승격 경로를 거쳐 거래 목록에 넣는다. 결과가 내부 코드가 만든 레코드라도 검사 없이 `cast`하지 않는다. `sync` 협력자가 기존 `list[Pin]`을 받는 동안에는 명시적 변환 어댑터에서 호출하고 결과를 다시 검증한다. **최종 재검증은 `render()` 호출 전** 완료한다. 실패 시 렌더와 `pins.jsonl`·`pins.md`의 원자적 쓰기, `transact()`의 반환을 하지 않는다. 기존 파일의 손상 줄은 `Broken`으로 처리하지만, 거래 중 새로 만든 잘못된 핀은 **프로그램 결함**으로 예외를 전파하고 조용히 건너뛰거나 `PinNotFound`로 바꾸지 않는다. `pins.seq`는 `next_id()` 시점에 먼저 증가할 수 있으므로 이 실패는 번호 공백을 남길 수 있다. ID 재사용 금지에는 맞지만 성공 응답이나 알림·감사 이벤트를 내서는 안 된다. 이벤트를 콜백에서 메모리에 미리 쌓더라도 거래 예외 뒤에는 `emit_events()`에 도달하지 않아야 한다. 파일 쓰기 도중의 실패 창은 현재 저장소 계약 그대로이며 이 설계가 새 원자성을 약속하지 않는다.

## 호출자와 호환성

- `store.py`: `pin_index`·`next_id`·`init_seq`는 래퍼의 `id`를 쓴다. `write_pins`는 렌더 협력자에 내부 `Pin` 목록을 넘겨 먼저 `pins.md`를 만들고, 각 `verified.pin.record`를 기존 순서대로 기록한다. `read_dropped()`는 현 `TrashedPin` 계약을 유지하되, 휴지통에서 라이브 목록으로 되살릴 때는 복원 결과를 검증해 넣는다. 휴지통 전용 검증 타입은 이번 범위 밖이다.
- `service/context.py`: `load_pin`의 miss는 계속 `PinNotFound(pid)` 값이다. 찾은 값은 검증된 핀과 위치를 담고, 전이에는 내부 `Pin`을 전달한다. 손상 줄이 특정 ID처럼 보여도 읽기에서 제외되므로 그 ID의 조회가 `PinNotFound`인 현재 동작을 바꾸지 않는다.
- `service/add_edit.py`, `transitions.py`, `claim.py`, `trash.py`: 거래 목록 교체·추가에서 검증된 값을 유지한다. 반환하는 상태 타입과 HTTP 응답 매핑은 현재대로 둔다.
- `locate.py`, `pins/position.py`, `pins/render.py`, `server.py`: 저장소에서 온 핀의 필수 식별자·위치는 검증된 값으로 사용한다. 레코드만 필요한 `pins/view.py`·`mentions.py`에는 원래 `Pin` 또는 `.record`를 넘긴다. 독립적인 `parse_pin()` 호출(`pins/view.py`의 응답 상태 계산, `server.py`의 답글 판단 등)은 의도대로 무손실 경로에 남는다.
- 테스트 도우미의 `parse_pin({"id": 1})` 같은 **미완성 입력**은 저장소 픽스처로 사용할 수 없다. 저장소 테스트에는 최소 유효한 줄/영역 핀을 만들고, 미완성 레코드의 왕복 테스트는 `test_pins_model.py`에 남긴다. 실제 운영 데이터에 자동 이관을 적용하지 않는다.

## 테스트와 합격 기준

1. 무손실 파서: 말뭉치 147개와 `LEGACY`의 미완성·잘못된 선택 필드를 전부 `parse_pin()`으로 왕복하여 키·값·순서를 유지한다. 저장 바이트는 원본 JSON 공백과 비교하지 않고, 같은 입력을 기존 `dump_jsonl()`로 쓴 결과와 비교한다. 저장 검사에서 거부하는 18개도 파서 테스트에서 빠지지 않는다.
2. 저장 경계: `fits_record()`가 받은 줄·영역 핀은 `parse_pin()` 뒤에도 `id`와 `place`가 채워진다는 성질을 고정한다. `id` 누락/문자열/불리언, 위치 누락·상대경로·거꾸로 된 줄 범위·잘못된 영역은 `Broken`과 원래 줄 번호로 남는다. 현재 허용하는 `doc` 누락, `review` 누락 완료 핀, `file_rel` 누락, 모르는 필드·순서는 유지한다. B를 채택할 때에만 반환 타입을 `VerifiedPin`으로 좁힌다.
3. 거래: 기존 저장소가 같은 레코드를 쓴 바이트 및 정렬·ID 증가, 손상 줄 백업·경고, `PinNotFound`가 유지된다. B를 채택하면 새 핀·전이·재동기화·복원 결과가 검증된 목록에 들어가며, 검증을 벗어난 내부 결과는 렌더·원자적 쓰기 전에 실패하고 성공 응답·이벤트·감사는 남기지 않는다. 이미 발급된 `pins.seq` 번호의 공백은 허용하고 재사용하지 않는다.
4. 계약: `test_contract_snapshot.py`와 관련 서비스·서버 HTTP 테스트를 통과하고 저장/응답 스냅숏에 차이가 없다. 타입 검사에서 저장소 소비자가 `id`·`place`에 `None` 처리를 요구받지 않으며, 자유 파서 소비자는 여전히 요구받는다.

## 구현 순서와 비범위

승인 뒤 먼저 저장 경계의 검사·리프트 일치성과 손상 줄·말뭉치 테스트를 고정한다. B를 시도한다면 위 수직 증명 하나를 수행하고 제거 분기/변환 지점/테스트 영향을 측정한다. 채택 기준을 넘을 때만 거래·서비스·위치 계산·조립 지점으로 확장한다. 기준을 넘지 못하면 B의 실험 변경은 버리고 D로 한정하여 `id or 0`을 명시적 `pid` 접근으로 바꾼다. 마지막으로 실제 책임이 바뀐 Handbook topic만 현재형으로 갱신한다. 이 문서는 구현 계획이나 승인으로 간주하지 않는다.

범위 밖: 저장 스키마 재설계, 기존 파일 정리/이관, `fits_record()`의 허용 기준 변경, HTTP 오류 의미 변경, `PinCore`의 자유 파서용 선택 필드 제거, 휴지통의 독립적인 완전 검증 타입, 새로운 라이브러리 도입.
