# 핀 JSON 조회 VSA 이행 설계

> **상태: 구현·검증 완료.** [백엔드 VSA 점진 이행](2026-09-28-backend-vsa-migration-design.md)의 조회 묶음 첫 단계다.

## 범위

`GET /api/pins`, `GET /api/pins/{id}`, `GET /api/pins/dropped`의 쿼리 파싱, 조회 조립, 성공·거절 응답을 `features/pins/listing/`이 소유한다. 겹침·위치 추정·문서 키·공개 레코드의 기존 순수 규칙과 실행별 계산은 좁은 `ListingDeps` 계약로 받는다. 공통 처리기는 본문·신원·입장·문서 선택의 가드를 지나 기능 입구를 호출한다. `ServerApplication`의 세 조회 전달 메서드와 옛 `web` 파서·응답은 지운다.

`GET /pins.md`와 저장 시 `pins.md` 렌더는 다음 단계에서 옮긴다. 두 경로가 공유하는 저장소·겹침·레코드 위치 규칙은 지금처럼 한 곳에서만 계산한다.

## 행동과 검증

`all`·`doc` 쿼리, 전 문서에서 먼저 계산한 겹침과 선택 문서로 마지막에 거르는 순서, 단일 핀의 전체 필드, 휴지통의 같은 잠금 아래 원본·사본 조회, 만료와 그림자 항목 숨김 및 `expires_ts`를 보존한다. 조회의 줄 맞춤 쓰기와 주기적 휴지통 정리 순서도 유지한다. 기준 커밋과 별도 프로세스에서 응답·상태 파일을 비교하고, 집중·전체 게이트를 실행한다.
