# 신원 보존과 SourceRange 불변식

## 범위와 승인

보안·코딩 규칙 검토에서 발견한 신원 변형과 검증되지 않은 `SourceRange`를 수정한다. 소유자는 이 대화에서 “신원·SourceRange만 우선 수정”으로 범위를 승인했다. 원고 파일 크기와 스니펫 문자열 한도는 이 변경에서 제외한다.

## 설계

- Tailscale와 trusted-proxy의 로그인은 기존 전송 인코딩을 해독한 전체 값으로 검증한다. 표시용 이름의 정리와 로그인을 분리한다. 길이 초과, 공백, 제어 문자, 예약된 로그인은 기존 `401 unauthenticated`로 거절하고 다른 사람의 로그인으로 바꾸지 않는다. 헤더가 없는 요청의 기존 정책은 유지한다.
- `SourceRange`는 생성자에서 bool이 아닌 정수와 `1 <= lo <= hi <= len(lines)`를 보장한다. 읽은 줄은 tuple로 복사하고 값 객체를 동결해서 호출자의 목록 변경으로 범위가 무효화되지 않게 한다.
- HTTP 응답 필드와 정상 요청 결과, 토큰 인증, 역할 정책, 저장 형식은 유지한다. 외부 의존성과 기능 간 의존성을 추가하지 않는다.

## 검증과 비용

소유자 접두사로 잘리는 긴 로그인, 제어 문자 제거, 공백 제거가 권한을 상속하지 못함을 확인한다. 정상 Unicode 전송 인코딩은 보존한다. 생성자 경계와 원본 목록 변경을 회귀 테스트로 확인한다. 기존 HTTP 파서는 같은 응답을 유지해야 한다.

잘못된 신원 헤더는 인증 실패가 된다. `SourceRange.lines`를 직접 사용하는 내부 코드는 불변 sequence를 받는다. 별도 ADR은 기존 신원·범위 불변식을 복구하는 작은 수정이므로 작성하지 않는다.
