# 핀 편집 전용 필드 검사의 소유권

공통 요청 파서 `web/parse.py`에는 핀 만들기·편집만 쓰는 `note`·`kind_req`·`scope`·`assignee` 검사가 남아 있다. 네 파서를 `features/pins/editing/fields.py`로 옮겨 `input.py`와 위치 편집의 `location.py`가 직접 쓴다. 두 편집 모듈이 서로를 가져오지 않도록 작은 순수 필드 모듈을 둔다. 여러 기능이 함께 쓰는 숫자·멘션·스레드·문서 선택·파일 경계 파서는 공통 `web/parse.py`에 남긴다. 옛 파서의 전달 별칭은 남기지 않는다.

필드의 검사 순서, `InputRejected` 문장·reason, 빈 값·기본값, 담당자 후보 조회 시점과 `scope` 닫힌 값은 유지한다. 서버 응답·상태 파일·핀 규칙을 바꾸지 않는다.

기준 커밋과 변경본의 핀 추가·편집 HTTP 흐름을 별도 프로세스에서 비교하고, 오류 문구를 고친 복사본에서 비교기가 실패하는지 확인한다. 해당 파서·처리기·계약 테스트와 전체 게이트를 실행하고 Handbook의 현재 위치를 갱신한다.
