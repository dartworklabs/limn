# The viewer's stylesheet parts and script modules, in order (docs/handbook/viewer.md §뷰어 규칙을 바꿀 때).
#
# __APP_CSS__: at startup, load_viewer_html() in assemble.py joins these files in this order, byte for byte, and puts the
# result where index.html has the marker, its one <style>.
# __APP_JS__: the viewer's ES modules, in the order their top-level code runs (a let or const, a listener, an immediately
# run function). tools/build_viewer.mjs builds them with Rollup into dist/viewer.js, the one classic script the page
# loads (GET /viewer.js): before Rollup reads a module it gives it a bare import of the module listed above it, so each
# module runs after every module above it whatever they import from each other, and the build fails if the order it
# joined is not this one. Top-level code can therefore use only the let/const names of the modules above (and its own).
# Keep this order. New code goes into the module for its responsibility; a new module needs a line here and a place
# (tools/check_viewer_boundaries.mjs, §모듈 경계). Rebuild with `npm run build` and commit dist/viewer.js.
# tests/viewer/test_viewer_files.py checks that every file under css/ and js/ is listed exactly once.
#
# Format: a marker line starts its list; each following line is a path relative to this folder. "#" starts a comment.

__APP_CSS__
